# Find Peak Element - II

**Difficulty:** Medium  ·  **Topic:** Binary Search [1D, 2D Arrays, Search Space] › BS on 2D Arrays

## Problem
A peak in a 2D matrix is a cell strictly greater than its four neighbours (up, down, left, right). Cells outside the matrix are treated as `-1`, and no two adjacent cells are equal. Given an `n x m` matrix, return the coordinates `[row, col]` of any peak.

Input: mat = [[10, 20, 15], [21, 30, 14], [7, 16, 32]]
Output: [1, 1]  (30 is greater than 20, 21, 14, 16)  — [2, 2] is also a valid answer

## Approach 1: Check Every Cell
For each cell compare it with its four neighbours; return the first that beats all of them. Always finds one because a global maximum is a peak.
- **Time:** O(n * m)
- **Space:** O(1)

## Approach 2: Binary Search on Columns
Binary search over column indices. For the middle column, find the row `r` that holds its maximum element. Compare `mat[r][mid]` with its left and right neighbours:
- If it beats both, it is a peak (it already beats the cells above and below because it is the column maximum).
- If the left neighbour is larger, a peak must exist in the columns to the left (the values keep rising in that direction and cannot rise forever), so `hi = mid - 1`.
- Otherwise search to the right: `lo = mid + 1`.

Each iteration costs O(n) to find the column maximum, and there are O(log m) iterations.
- **Time:** O(n * log m)
- **Space:** O(1)

## Code (Optimal)

### C++
```cpp
class Solution {
public:
    int maxRowInColumn(const vector<vector<int>>& mat, int col) {
        int best = 0;
        for (int r = 1; r < (int)mat.size(); r++)
            if (mat[r][col] > mat[best][col]) best = r;
        return best;
    }

    vector<int> findPeakGrid(vector<vector<int>>& mat) {
        int n = mat.size(), m = mat[0].size();
        int lo = 0, hi = m - 1;
        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2;
            int r = maxRowInColumn(mat, mid);
            int left = (mid > 0) ? mat[r][mid - 1] : -1;
            int right = (mid < m - 1) ? mat[r][mid + 1] : -1;
            if (mat[r][mid] > left && mat[r][mid] > right) return {r, mid};
            if (left > mat[r][mid]) hi = mid - 1;
            else lo = mid + 1;
        }
        return {-1, -1}; // unreachable for valid input
    }
};
```

### Python
```python
from typing import List

class Solution:
    def findPeakGrid(self, mat: List[List[int]]) -> List[int]:
        n, m = len(mat), len(mat[0])

        def max_row_in_column(col: int) -> int:
            best = 0
            for r in range(1, n):
                if mat[r][col] > mat[best][col]:
                    best = r
            return best

        lo, hi = 0, m - 1
        while lo <= hi:
            mid = (lo + hi) // 2
            r = max_row_in_column(mid)
            left = mat[r][mid - 1] if mid > 0 else -1
            right = mat[r][mid + 1] if mid < m - 1 else -1
            if mat[r][mid] > left and mat[r][mid] > right:
                return [r, mid]
            if left > mat[r][mid]:
                hi = mid - 1
            else:
                lo = mid + 1
        return [-1, -1]
```

## Key Takeaways
- Extends 1D peak finding: binary search on columns, and use the column maximum so the vertical neighbours are automatically smaller.
- Moving toward the larger horizontal neighbour is safe because values cannot keep increasing forever; a peak must exist on that side.
- Treat out-of-bounds as `-1`, which is smaller than every element (all values are non-negative in the LeetCode version).
- Any peak is accepted, so different valid answers are fine.
