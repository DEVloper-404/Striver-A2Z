# Flood fill algorithm

**Difficulty:** Medium  ·  **Topic:** Graphs [Concepts & Problems] › Problems on BFS/DFS

## Problem
You are given an image as an `m × n` grid of integers, a starting pixel `(sr, sc)`, and a `color`. Recolour the starting pixel and every pixel connected to it 4-directionally through pixels of the **same original colour**, then return the modified image. This is the paint-bucket tool from any image editor.

```
Input:  image = [[1,1,1],
                 [1,1,0],
                 [1,0,1]],  sr = 1, sc = 1, color = 2
Output: [[2,2,2],
         [2,2,0],
         [2,0,1]]
```
The bottom-right `1` is not repainted because it is only diagonally adjacent to the region.

## Approach 1: The observation that makes it a graph problem
The region to repaint is defined *relatively*, not absolutely: it is every pixel reachable from `(sr, sc)` by steps between pixels sharing the **start pixel's original colour**, which must be read once before you modify anything. Read it into `startColor` first — if you compare against `image[sr][sc]` inside the loop, the very first repaint changes the comparison value and the fill stops immediately.

So the graph is: vertices = pixels whose colour equals `startColor`, edges = 4-directional adjacency. The answer is the connected component containing `(sr, sc)`, with every member's value overwritten by `color`.

**Critical edge case:** if `startColor == color`, repainting changes nothing, so a pixel never gets "marked" and the traversal revisits cells forever. Guard with an early return when the colours are already equal. This is the single most common bug in this problem.
- **Time:** O(m·n)
- **Space:** O(m·n)

## Approach 2: DFS flood fill (Optimal)
Because we overwrite each visited pixel with the new colour, the recoloured value itself acts as the visited marker — no separate `visited` matrix is needed (given the guard above).

Algorithm:
1. Let `startColor = image[sr][sc]`. If `startColor == color`, return the image unchanged.
2. `dfs(r, c)`:
   - If `(r, c)` is out of bounds, or `image[r][c] != startColor`, return.
   - Set `image[r][c] = color`.
   - Recurse into the four neighbours.
3. Call `dfs(sr, sc)` and return the image.

The check `image[r][c] != startColor` does triple duty: it stops at pixels of a different original colour (region boundary), and it stops at pixels already repainted (since they now hold `color != startColor`), so no cell is processed twice.

Dry run on the example with `startColor = 1`, `color = 2`:
- `dfs(1,1)`: paints `(1,1)` → 2. Up `(0,1)` is 1 → recurse.
  - `dfs(0,1)`: paints → 2. Up is out of bounds. Down `(1,1)` is now 2 ≠ 1, stop. Left `(0,0)` is 1 → recurse, paints it, its neighbours `(1,0)` is 1 → recurse, paints `(1,0)`; `(2,0)` is 1 → recurse, paints it; `(2,1)` is 0, stop. Right `(0,2)` is 1 → recurse, paints it; `(1,2)` is 0, stop.
- Back in `dfs(1,1)`: down `(2,1)` is 0, stop. Left `(1,0)` is already 2, stop. Right `(1,2)` is 0, stop.
- Painted set: `(0,0),(0,1),(0,2),(1,0),(1,1),(2,0)`. `(2,2)` untouched — correct, it is diagonal-only.

For very large images the recursion can go m·n deep, so the Python version below uses an explicit stack. BFS with a queue gives the identical result — the region does not care about visit order.
- **Time:** O(m·n) — each pixel is repainted at most once and inspected a constant number of times.
- **Space:** O(m·n) worst case for the stack/queue (one big region shaped like a snake).

## Code (Optimal)

### C++
```cpp
#include <vector>
using namespace std;

class Solution {
public:
    vector<vector<int>> floodFill(vector<vector<int>>& image, int sr, int sc, int color) {
        int startColor = image[sr][sc];
        if (startColor == color) return image;   // guard: otherwise infinite recursion
        dfs(image, sr, sc, startColor, color);
        return image;
    }

private:
    void dfs(vector<vector<int>>& img, int r, int c, int startColor, int color) {
        if (r < 0 || r >= (int)img.size() || c < 0 || c >= (int)img[0].size()) return;
        if (img[r][c] != startColor) return;     // boundary or already repainted
        img[r][c] = color;
        dfs(img, r - 1, c, startColor, color);
        dfs(img, r + 1, c, startColor, color);
        dfs(img, r, c - 1, startColor, color);
        dfs(img, r, c + 1, startColor, color);
    }
};
```

### Java

```java
class Solution {
    public int[][] floodFill(int[][] image, int sr, int sc, int color) {
        int startColor = image[sr][sc];
        if (startColor == color) return image;
        dfs(image, sr, sc, startColor, color);
        return image;
    }

    private void dfs(int[][] img, int r, int c, int startColor, int color) {
        if (r < 0 || r >= img.length || c < 0 || c >= img[0].length) return;
        if (img[r][c] != startColor) return;
        img[r][c] = color;
        dfs(img, r - 1, c, startColor, color);
        dfs(img, r + 1, c, startColor, color);
        dfs(img, r, c - 1, startColor, color);
        dfs(img, r, c + 1, startColor, color);
    }
}
```

### Python
```python
from typing import List

class Solution:
    def floodFill(self, image: List[List[int]], sr: int, sc: int, color: int) -> List[List[int]]:
        start_color = image[sr][sc]
        if start_color == color:
            return image

        m, n = len(image), len(image[0])
        stack = [(sr, sc)]
        image[sr][sc] = color
        dirs = [(-1, 0), (1, 0), (0, -1), (0, 1)]

        while stack:
            r, c = stack.pop()
            for dr, dc in dirs:
                nr, nc = r + dr, c + dc
                if 0 <= nr < m and 0 <= nc < n and image[nr][nc] == start_color:
                    image[nr][nc] = color      # repaint = mark visited
                    stack.append((nr, nc))
        return image
```

## Key Takeaways
- Capture the starting colour **before** the first repaint; comparing against a mutating cell breaks the fill instantly.
- If the new colour equals the old one, return early — otherwise nothing is ever marked and you loop forever.
- Repainting in place is its own visited marker, so no extra matrix is needed.
- Flood fill is the base pattern behind islands, enclaves and surrounded regions — only the boundary condition changes.
