# Find the city with the smallest number of neighbors

**Difficulty:** Hard  ·  **Topic:** Graphs [Concepts & Problems] › Shortest Path Algorithms and Problems

## Problem
There are `n` cities numbered `0 … n-1` connected by bidirectional weighted `edges[i] = [u, v, w]`, and a `distanceThreshold`. For each city, count how many other cities are reachable from it with a **total path distance ≤ distanceThreshold**. Return the city with the smallest such count; if several tie, return the one with the **largest index**.

```
Input:  n = 4, edges = [[0,1,3],[1,2,1],[1,3,4],[2,3,1]], distanceThreshold = 4
Output: 3
```
Shortest distances give: city 0 reaches {1 (3), 2 (4)} = 2 cities, city 1 reaches {0 (3), 2 (1), 3 (2)} = 3, city 2 reaches {0 (4), 1 (1), 3 (1)} = 3, city 3 reaches {1 (2), 2 (1)} = 2. The minimum count is 2, tied by cities 0 and 3, so we return the larger index, `3`.

## Approach 1: Dijkstra from every city
Run Dijkstra `n` times, once per source, and count how many finalized distances are `≤ distanceThreshold`. Perfectly correct (all weights are positive) and asymptotically fine on sparse graphs.
- **Time:** O(n · E log n)
- **Space:** O(n + E)

## Approach 2: Floyd–Warshall, then count (optimal here)

**The key observation.** The question is genuinely an *all-pairs* question — every city needs its distance to every other city. Constraints for this problem are small (`n ≤ 100`), and `n³ = 10^6` is trivial, so the simplest all-pairs routine is also the fastest to write and the fastest in practice for a dense-ish graph.

**Step 1 — build the distance matrix.** Start with `dist[i][j] = INF`, `dist[i][i] = 0`, and for each edge set `dist[u][v] = dist[v][u] = w`. If duplicate edges are possible, keep the minimum.

**Step 2 — Floyd–Warshall.** For each intermediate `k`, then each `i`, then each `j`:
`dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])`.
The reasoning is the standard one: after finishing iteration `k`, `dist[i][j]` is the cheapest route from `i` to `j` that is allowed to pass through vertices `0 … k`. Either the best route avoids `k` (old value) or it goes through `k` exactly once (the two halves, each already optimal over the smaller intermediate set). Guard against `INF + INF` overflow by skipping when either half is `INF`.

**Step 3 — count and tie-break.** For each city `i`, count `j != i` with `dist[i][j] <= distanceThreshold`. Track the best answer. The tie-break rule ("largest index wins") falls out naturally if you scan `i` from `0` upward and update whenever `count <= bestCount` — using `<=` rather than `<` means a later (larger) index overwrites an equal-count earlier one.

**Short dry run** on the example. Initial matrix has `0-1 = 3`, `1-2 = 1`, `1-3 = 4`, `2-3 = 1`, everything else `INF`. Running the `k` loop: through `k = 1`, `dist[0][2] = 3 + 1 = 4` and `dist[0][3] = 3 + 4 = 7`. Through `k = 2`, `dist[1][3]` improves to `1 + 1 = 2`, and then `dist[0][3]` improves to `dist[0][2] + dist[2][3] = 4 + 1 = 5`. Final counts within threshold `4`: city `0` reaches `1` (3) and `2` (4) but not `3` (5) → 2; city `1` reaches all three (3, 1, 2) → 3; city `2` reaches all three (4, 1, 1) → 3; city `3` reaches only `1` (2) and `2` (1), since `0` is at 5 → 2. The minimum is 2, achieved by cities `0` and `3`; the `<=` comparison keeps the later index, so we return `3`.

**When to prefer Dijkstra instead.** If `n` grows large but the graph stays sparse (`E ≪ n²`), `n` runs of Dijkstra at `O(n·E log n)` beats `O(n³)`. For this problem's limits, Floyd–Warshall wins on simplicity.
- **Time:** O(n³) for the matrix plus O(n²) for the counting
- **Space:** O(n²) for the distance matrix

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int findTheCity(int n, vector<vector<int>>& edges, int distanceThreshold) {
        const int INF = 1000000000;
        vector<vector<int>> dist(n, vector<int>(n, INF));
        for (int i = 0; i < n; i++) dist[i][i] = 0;
        for (auto& e : edges) {
            dist[e[0]][e[1]] = min(dist[e[0]][e[1]], e[2]);
            dist[e[1]][e[0]] = min(dist[e[1]][e[0]], e[2]);
        }

        for (int k = 0; k < n; k++)
            for (int i = 0; i < n; i++) {
                if (dist[i][k] == INF) continue;
                for (int j = 0; j < n; j++) {
                    if (dist[k][j] == INF) continue;
                    dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j]);
                }
            }

        int bestCity = -1, bestCount = n + 1;
        for (int i = 0; i < n; i++) {
            int cnt = 0;
            for (int j = 0; j < n; j++)
                if (i != j && dist[i][j] <= distanceThreshold) cnt++;
            if (cnt <= bestCount) {      // <= makes the larger index win ties
                bestCount = cnt;
                bestCity = i;
            }
        }
        return bestCity;
    }
};
```

### Java
```java
import java.util.*;

class Solution {
    public int findTheCity(int n, int[][] edges, int distanceThreshold) {
        final int INF = 1000000000;
        int[][] dist = new int[n][n];
        for (int[] row : dist) Arrays.fill(row, INF);
        for (int i = 0; i < n; i++) dist[i][i] = 0;
        for (int[] e : edges) {
            dist[e[0]][e[1]] = Math.min(dist[e[0]][e[1]], e[2]);
            dist[e[1]][e[0]] = Math.min(dist[e[1]][e[0]], e[2]);
        }

        for (int k = 0; k < n; k++)
            for (int i = 0; i < n; i++) {
                if (dist[i][k] == INF) continue;
                for (int j = 0; j < n; j++) {
                    if (dist[k][j] == INF) continue;
                    int cand = dist[i][k] + dist[k][j];
                    if (cand < dist[i][j]) dist[i][j] = cand;
                }
            }

        int bestCity = -1, bestCount = n + 1;
        for (int i = 0; i < n; i++) {
            int cnt = 0;
            for (int j = 0; j < n; j++)
                if (i != j && dist[i][j] <= distanceThreshold) cnt++;
            if (cnt <= bestCount) {
                bestCount = cnt;
                bestCity = i;
            }
        }
        return bestCity;
    }
}
```

### Python
```python
from typing import List

class Solution:
    def findTheCity(self, n: int, edges: List[List[int]], distanceThreshold: int) -> int:
        INF = float('inf')
        dist = [[INF] * n for _ in range(n)]
        for i in range(n):
            dist[i][i] = 0
        for u, v, w in edges:
            dist[u][v] = min(dist[u][v], w)
            dist[v][u] = min(dist[v][u], w)

        for k in range(n):
            row_k = dist[k]
            for i in range(n):
                ik = dist[i][k]
                if ik == INF:
                    continue
                row_i = dist[i]
                for j in range(n):
                    cand = ik + row_k[j]
                    if cand < row_i[j]:
                        row_i[j] = cand

        best_city, best_count = -1, n + 1
        for i in range(n):
            cnt = sum(1 for j in range(n) if j != i and dist[i][j] <= distanceThreshold)
            if cnt <= best_count:        # <= gives the largest index on a tie
                best_count, best_city = cnt, i
        return best_city
```

## Key Takeaways
- "Every node needs its distance to every other node" is the signal for an all-pairs algorithm; with `n ≤ 100`, `O(n³)` Floyd–Warshall is the least error-prone choice.
- Build the matrix symmetrically for undirected edges and take `min` on parallel edges.
- Encode the "largest index wins" tie-break by scanning upward and comparing with `<=`.
- Skip relaxation when either half is `INF` to avoid overflow with a large sentinel.
