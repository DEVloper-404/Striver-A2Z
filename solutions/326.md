# Burst balloons

**Difficulty:** Hard  ·  **Topic:** Dynamic Programming [Patterns and Problems] › MCM DP | Partition DP

## Problem
You are given `n` balloons in a row, balloon `i` painted with the number `nums[i]`. Bursting balloon `i` earns `nums[left] * nums[i] * nums[right]` coins, where `left` and `right` are the balloons *currently* adjacent to `i` (balloons already burst are gone, so neighbours shift). Out-of-range neighbours count as a balloon painted `1`. Burst all balloons and return the maximum coins you can collect.

```
Input:  nums = [3, 1, 5, 8]
Output: 167
```
(One optimal order: burst 1, then 5, then 3, then 8 → 3·1·5 + 3·5·8 + 1·3·8 + 1·8·1 = 15 + 120 + 24 + 8 = 167.)

## Approach 1: Try every order (Brute Force)

Generate every permutation of burst order and simulate. This is correct but `n!` orders is unusable beyond `n = 10`.

The deeper problem is that the naive DP idea — "partition on the FIRST balloon burst" — does not work here. If we burst balloon `k` first and split the row into `[i..k-1]` and `[k+1..j]`, those two halves are *not* independent: after everything on the left is gone, a balloon on the right can end up adjacent to something outside the range. The subproblems overlap, so the recursion is invalid.

- **Time:** O(n! · n)
- **Space:** O(n)

## Approach 2: Partition on the LAST balloon (Optimal)

**The key inversion.** Flip the question: instead of "which balloon do I burst first?", ask "which balloon in this range do I burst **last**?" If balloon `k` is the last one to go inside range `i..j`, then at the moment it pops, every other balloon in `i..j` is already gone, so its two neighbours are exactly the balloons bounding the range from outside — `a[i-1]` and `a[j+1]`. Those boundary balloons are untouched by definition of the range, so the value is known and fixed.

And now the two sides *are* independent: all of `[i..k-1]` is burst while `a[i-1]` and `a[k]` still stand as its boundary, and all of `[k+1..j]` is burst while `a[k]` and `a[j+1]` still stand. Neither half ever sees a balloon from the other half as a neighbour. That is exactly the property the first-balloon formulation lacked.

**Setup.** Pad the array with `1` on both ends: `a = [1] + nums + [1]`, so `a` has `n + 2` entries and every range `i..j` (with `1 <= i <= j <= n`) has valid neighbours `a[i-1]`, `a[j+1]`.

**The recurrence.**
```
f(i, j) = 0                                    if i > j
f(i, j) = max over k in [i, j] of
             a[i-1] * a[k] * a[j+1] + f(i, k-1) + f(k+1, j)
```
Answer: `f(1, n)`.

**Tabulation order.** `f(i, k-1)` is same row / smaller column, `f(k+1, j)` is larger row / same column → loop `i` from `n` down to `1`, `j` from `i` up to `n`.

**Dry run on `nums = [3,1,5,8]`**, so `a = [1,3,1,5,8,1]`, `n = 4`.

Single balloons (`i == j`, value = `a[i-1]*a[i]*a[i+1]`):
- `f(1,1) = 1·3·1 = 3`, `f(2,2) = 3·1·5 = 15`, `f(3,3) = 1·5·8 = 40`, `f(4,4) = 5·8·1 = 40`

Pairs:
- `f(1,2)` (bounds 1 and 5): `k=1` → `1·3·5 + f(2,2) = 15+15 = 30`; `k=2` → `1·1·5 + f(1,1) = 5+3 = 8` → **30**
- `f(2,3)` (bounds 3 and 8): `k=2` → `3·1·8 + f(3,3) = 24+40 = 64`; `k=3` → `3·5·8 + f(2,2) = 120+15 = 135` → **135**
- `f(3,4)` (bounds 1 and 1): `k=3` → `1·5·1 + f(4,4) = 5+40 = 45`; `k=4` → `1·8·1 + f(3,3) = 8+40 = 48` → **48**

Triples:
- `f(1,3)` (bounds 1 and 8): `k=1` → `1·3·8 + f(2,3) = 24+135 = 159`; `k=2` → `8 + 3 + 40 = 51`; `k=3` → `40 + f(1,2) = 70` → **159**
- `f(2,4)` (bounds 3 and 1): `k=2` → `3 + f(3,4) = 51`; `k=3` → `15 + 15 + 40 = 70`; `k=4` → `24 + f(2,3) = 159` → **159**

Full range:
- `f(1,4)` (bounds 1 and 1): `k=1` → `1·3·1 + f(2,4) = 3+159 = 162`; `k=2` → `1 + 3 + 48 = 52`; `k=3` → `5 + 30 + 40 = 75`; `k=4` → `1·8·1 + f(1,3) = 8+159 = 167` → **167**

The winner `k = 4` says balloon `8` is burst last, and unwinding `f(1,3)` says `3` is last among the first three, then `5`, then `1` — the order 1, 5, 3, 8 from the example.

- **Time:** O(n^3)
- **Space:** O(n^2)

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int maxCoins(vector<int>& nums) {
        int n = nums.size();
        vector<int> a(n + 2, 1);                 // a[0] = a[n+1] = 1
        for (int i = 0; i < n; i++) a[i + 1] = nums[i];

        // dp[i][j] = max coins from bursting all balloons in i..j
        vector<vector<int>> dp(n + 2, vector<int>(n + 2, 0));

        for (int i = n; i >= 1; i--) {
            for (int j = i; j <= n; j++) {
                int best = 0;
                for (int k = i; k <= j; k++) {
                    int coins = a[i - 1] * a[k] * a[j + 1]
                              + dp[i][k - 1] + dp[k + 1][j];
                    best = max(best, coins);
                }
                dp[i][j] = best;
            }
        }
        return dp[1][n];
    }
};
```

### Python
```python
from typing import List

class Solution:
    def maxCoins(self, nums: List[int]) -> int:
        n = len(nums)
        a = [1] + nums + [1]

        # dp[i][j] = max coins from bursting all balloons in i..j
        dp = [[0] * (n + 2) for _ in range(n + 2)]

        for i in range(n, 0, -1):
            for j in range(i, n + 1):
                best = 0
                for k in range(i, j + 1):
                    coins = a[i - 1] * a[k] * a[j + 1] + dp[i][k - 1] + dp[k + 1][j]
                    if coins > best:
                        best = coins
                dp[i][j] = best

        return dp[1][n]
```

## Key Takeaways
- Partitioning on the **first** burst is wrong because the halves stay adjacent; partitioning on the **last** burst makes them independent — recognising which end to fix is the whole trick.
- The `1` sentinels remove all boundary special-casing: `a[i-1]` and `a[j+1]` are always defined for `1 <= i <= j <= n`.
- Whenever removing an element makes neighbours merge, look for a "process it last" reformulation.
- Edge cases: `n = 1` → answer is `nums[0]`; the DP handles it since `f(1,1) = 1·nums[0]·1`.
