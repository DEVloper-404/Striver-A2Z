# Count and say

**Difficulty:** Hard  ·  **Topic:** Strings › Hard Problems

## Problem
The count-and-say sequence starts with `"1"`. Every following term is produced by *reading aloud* the previous term: scan it left to right, and for each block of identical consecutive digits write the length of the block followed by the digit itself. Given an integer `n`, return the `n`-th term as a string.

```
Input:  n = 5
Output: "111221"
```

The first five terms and how each is read:

```
1st: "1"
2nd: "11"      read "1"      as  one 1        -> 1 1
3rd: "21"      read "11"     as  two 1s       -> 2 1
4th: "1211"    read "21"     as  one 2, one 1 -> 1 2 1 1
5th: "111221"  read "1211"   as  one 1, one 2, two 1s -> 1 1 1 2 2 1
```

## Approach 1: Recursive definition, literally
The definition is recursive — term `n` is "the reading of term `n-1`" — so the most direct solution mirrors it: if `n == 1` return `"1"`, otherwise compute `countAndSay(n - 1)` and then run-length-encode it.

This is correct, and it is a fine way to first convince yourself the transformation is well defined. The only cost is `n` stack frames plus a full copy of every intermediate term. Since each term is roughly 1.3× the length of the previous one (the sequence's growth rate, Conway's constant), the strings get long fast and holding all of them alive at once is wasteful.

- **Time:** O(n · L) where L is the length of the final term
- **Space:** O(n · L) — recursion depth plus every intermediate string

## Approach 2: Optimal — iterative run-length encoding
The key observation is that we never need more than **two** terms in memory: the one we are reading and the one we are building. So convert the recursion into a loop.

Start with `cur = "1"`. Repeat `n - 1` times:

1. Set `j = 0` and start an empty string `next`.
2. Let `k` walk forward from `j` while `cur[k] == cur[j]`. When it stops, the block `cur[j..k-1]` is a maximal run of one digit, of length `k - j`.
3. Append the number `k - j` (as text) and then the digit `cur[j]` to `next`.
4. Set `j = k` and go back to step 2 until `j` reaches the end.
5. Replace `cur` with `next`.

The "maximal run" part is what makes the encoding unambiguous and the algorithm correct: because the inner loop only stops when the digit changes, no two adjacent blocks in `next` describe the same digit, and the reading of a term is unique.

**Why append the count as a string, not a single character?** For the standard sequence starting at `"1"` a run is never longer than 3, so a single digit would work. But writing `to_string(k - j)` costs nothing and keeps the code correct if the seed ever changes.

**Dry run for `n = 5`:**

- `cur = "1"`.
- Round 1: one run — `1`×`'1'` → `next = "11"`.
- Round 2: `"11"` is a single run of length 2 → `next = "21"`.
- Round 3: `"21"` has runs `"2"` and `"1"` → `"12"` + `"11"` = `"1211"`.
- Round 4: `"1211"` has runs `"1"`, `"2"`, `"11"` → `"11"` + `"12"` + `"21"` = `"111221"`.

After 4 rounds `cur = "111221"`, the 5th term.

Each round touches every character of the current term once, so the total work is proportional to the sum of all term lengths, dominated by the last one.

- **Time:** O(n · L), L = length of the n-th term (the sum of all lengths is Θ(L))
- **Space:** O(L) — only two terms alive at a time

## Code (Optimal)

### C++
```cpp
#include <string>
using namespace std;

class Solution {
public:
    string countAndSay(int n) {
        string cur = "1";
        for (int term = 2; term <= n; term++) {
            string next;
            int j = 0, len = (int)cur.size();
            while (j < len) {
                int k = j;
                while (k < len && cur[k] == cur[j]) k++;   // maximal run
                next += to_string(k - j);                  // how many
                next += cur[j];                            // of what
                j = k;
            }
            cur.swap(next);
        }
        return cur;
    }
};
```

### Java
```java
class Solution {
    public String countAndSay(int n) {
        String cur = "1";
        for (int term = 2; term <= n; term++) {
            StringBuilder next = new StringBuilder();
            int j = 0, len = cur.length();
            while (j < len) {
                int k = j;
                while (k < len && cur.charAt(k) == cur.charAt(j)) k++;  // maximal run
                next.append(k - j);          // how many
                next.append(cur.charAt(j));  // of what
                j = k;
            }
            cur = next.toString();
        }
        return cur;
    }
}
```

### Python
```python
class Solution:
    def countAndSay(self, n: int) -> str:
        cur = "1"
        for _ in range(n - 1):
            parts = []
            j, length = 0, len(cur)
            while j < length:
                k = j
                while k < length and cur[k] == cur[j]:   # maximal run
                    k += 1
                parts.append(str(k - j))                 # how many
                parts.append(cur[j])                     # of what
                j = k
            cur = "".join(parts)
        return cur
```

## Key Takeaways
- The whole problem is run-length encoding applied `n - 1` times; the only real trick is making the inner loop consume a *maximal* run so blocks never split.
- Only two terms need to exist at once, so replace the natural recursion with a loop and keep space at O(L).
- Build the result with `StringBuilder` / a list of parts rather than repeated `+=` on an immutable string, or Java and Python quietly become quadratic.
- Edge case: `n = 1` must return `"1"` — the loop body simply never runs, which handles it for free.
