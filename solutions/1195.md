# Introduction to DP

**Difficulty:** Easy  ·  **Topic:** Dynamic Programming [Patterns and Problems] › Introduction to DP

## Problem
This topic covers what dynamic programming is and the mechanical process for turning a recursive solution into an efficient one. DP applies when a problem has **overlapping subproblems** (the same smaller instance is solved again and again) and **optimal substructure** (the answer to a big instance is built from answers to smaller instances). The two standard ways of exploiting this are **memoization** (top-down: recurse, but cache each answer) and **tabulation** (bottom-up: fill a table in dependency order), followed by **space optimisation** when each state only looks a fixed distance back.

Running example — the n-th Fibonacci number, `f(n) = f(n-1) + f(n-2)`, `f(0)=0`, `f(1)=1`.

```
Input:  n = 5
Output: 5        (0, 1, 1, 2, 3, 5)
```

## Approach: recursion → memoization → tabulation → space optimisation

**Step 0: write the recursion.** Almost every DP starts as a brute-force recursion. For Fibonacci:

```
f(n) = n            if n <= 1
f(n) = f(n-1) + f(n-2)
```

Drawn as a tree for `n = 5`, this calls `f(3)` twice, `f(2)` three times, `f(1)` five times. The tree has roughly `2^n` nodes, so plain recursion is **O(2^n)** — exponential purely because it recomputes identical subproblems.

**Step 1: memoization (top-down).** The fix is one line of bookkeeping: keep an array `dp[]` initialised to a sentinel like `-1`. Before doing the work for state `n`, check `dp[n]`; if it is already computed, return it. Otherwise compute it and store it before returning.

```cpp
int f(int n, vector<int>& dp) {
    if (n <= 1) return n;
    if (dp[n] != -1) return dp[n];
    return dp[n] = f(n - 1, dp) + f(n - 2, dp);
}
```

Now each state `0..n` is computed exactly once and every later request is an O(1) lookup, so the recursion tree collapses from `2^n` nodes to `n+1` distinct states. Time drops to **O(n)**; space is **O(n)** for the array *plus* **O(n)** for the recursion stack.

The general recipe for memoizing any recursion:
1. **Identify the state** — the minimal set of changing parameters that determines the answer (here just `n`; for grid DP it is `(row, col)`; for subsequence DP it is `(index, target)`).
2. Make a `dp` array with one slot per state, filled with an impossible sentinel.
3. Return the cached value if present; otherwise compute, store, return.

**Step 2: tabulation (bottom-up).** Memoization still pays for recursion (call overhead and stack space, and it can blow the stack for large `n`). Tabulation removes the recursion by filling the same table iteratively, in an order where every dependency is already filled.

1. Write the **base cases** directly into the table: `dp[0] = 0`, `dp[1] = 1`.
2. Express the loop so that when you compute `dp[i]`, the states it needs (`dp[i-1]`, `dp[i-2]`) are already done — here simply increasing `i`.
3. The answer sits at the state the original recursion was called with: `dp[n]`.

```cpp
vector<int> dp(n + 1);
dp[0] = 0; dp[1] = 1;
for (int i = 2; i <= n; i++) dp[i] = dp[i-1] + dp[i-2];
return dp[n];
```

Time **O(n)**, space **O(n)**, no recursion stack.

**Step 3: space optimisation.** Look at the recurrence: `dp[i]` only reads `dp[i-1]` and `dp[i-2]`. Everything older is dead weight. So keep two rolling variables instead of the whole array.

```cpp
int prev2 = 0, prev1 = 1;
for (int i = 2; i <= n; i++) {
    int cur = prev1 + prev2;
    prev2 = prev1;
    prev1 = cur;
}
return n <= 1 ? n : prev1;
```

Time **O(n)**, space **O(1)**. The same trick generalises: in 2D grid DP each row depends only on the previous row, so an `O(m·n)` table shrinks to two `O(n)` rows, and often to a single row updated in place.

**Dry run for n = 5** (space-optimised): start `prev2=0, prev1=1`. `i=2`: cur=1 → (1,1). `i=3`: cur=2 → (1,2). `i=4`: cur=3 → (2,3). `i=5`: cur=5 → (3,5). Answer `prev1 = 5`. ✔

**Which one to use.** Memoization is easier to write — you translate the recursion literally and the ordering takes care of itself, which matters when the state transitions are irregular. Tabulation is faster in practice and avoids stack overflow, and it is the only form you can space-optimise. A good habit in interviews: derive the recursion, memoize it, then convert to tabulation, then optimise space — and say out loud what each step buys.
- **Time:** O(number of states × work per state) — for Fibonacci, O(n)
- **Space:** O(number of states) for the table, reducible to O(1) here

## Code (Optimal)

### C++
```cpp
#include <vector>
using namespace std;

class Solution {
public:
    // Memoized (top-down)
    int fibMemo(int n) {
        vector<int> dp(n + 1, -1);
        return solve(n, dp);
    }

    // Tabulated + space optimised (bottom-up)
    int fib(int n) {
        if (n <= 1) return n;
        int prev2 = 0, prev1 = 1;
        for (int i = 2; i <= n; i++) {
            int cur = prev1 + prev2;
            prev2 = prev1;
            prev1 = cur;
        }
        return prev1;
    }

private:
    int solve(int n, vector<int>& dp) {
        if (n <= 1) return n;
        if (dp[n] != -1) return dp[n];
        return dp[n] = solve(n - 1, dp) + solve(n - 2, dp);
    }
};
```

### Python
```python
from functools import lru_cache


class Solution:
    # Memoized (top-down)
    def fibMemo(self, n: int) -> int:
        dp = [-1] * (n + 1)

        def solve(i: int) -> int:
            if i <= 1:
                return i
            if dp[i] != -1:
                return dp[i]
            dp[i] = solve(i - 1) + solve(i - 2)
            return dp[i]

        return solve(n)

    # Tabulated + space optimised (bottom-up)
    def fib(self, n: int) -> int:
        if n <= 1:
            return n
        prev2, prev1 = 0, 1
        for _ in range(2, n + 1):
            prev2, prev1 = prev1, prev1 + prev2
        return prev1
```

## Key Takeaways
- DP = recursion + storage. If a recursion recomputes the same state, cache it; that alone turns exponential into polynomial.
- Always name the **state** first (the changing parameters). The size of the state space times the work per state is your complexity.
- Standard progression: brute recursion → memoization (O(n) time, O(n) table + O(n) stack) → tabulation (drops the stack) → space optimisation (drops the table).
- Space optimisation is possible whenever a state depends only on a bounded window of previous states — two variables for 1D, two rows for grid DP.
- Watch the pitfalls: a sentinel value (`-1`) that could be a legitimate answer, base cases written before the loop, and loop direction that guarantees dependencies are already computed.
