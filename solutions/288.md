# Frog Jump

**Difficulty:** Medium  ·  **Topic:** Dynamic Programming [Patterns and Problems] › 1D DP

## Problem
A frog starts on stone `0` and wants to reach stone `n-1`. `height[i]` is the height of stone `i`. From stone `i` the frog can jump to stone `i+1` or `i+2`, and a jump from `i` to `j` costs `|height[i] - height[j]|` energy. Return the **minimum total energy** spent to reach the last stone.

```
Input:  height = [30, 10, 60, 10, 60, 50]
Output: 40
        Best route 0 → 2 → 4 → 5:
        |60-30| + |60-60| + |50-60| = 30 + 0 + 10 = 40
```

## Approach 1: Recursion (brute force)

**Frame it from the destination.** Let `f(i)` be the minimum energy to get from stone `0` to stone `i`. The frog arrived at `i` either from `i-1` or from `i-2`, and those are the only options, so

```
f(i) = min( f(i-1) + |h[i] - h[i-1]| ,
            f(i-2) + |h[i] - h[i-2]| )
```

with `f(0) = 0` (already there, nothing spent) and `f(1) = |h[1] - h[0]|` (only one way in).

Why is taking the minimum of the two branches correct? Because the cost of the last jump depends only on which stone you jumped from, not on how you got to that stone. So the cheapest route ending at `i` via `i-1` is exactly "cheapest route to `i-1`" plus a fixed jump cost — optimal substructure holds and greedy mixing is not needed.

**Why greedy fails**, by the way: always taking the cheaper immediate jump from stone 0 in the example picks `0 → 1` (cost 20 vs 30) — which happens to be right here — but on `[10, 20, 10]` the greedy 1-step costs `10 + 10 = 20` while the direct 2-jump costs `0`. You must look ahead, hence DP.

Written as raw recursion this branches twice per call: `O(2^n)`.
- **Time:** O(2^n)
- **Space:** O(n) stack

## Approach 2: Memoization
The state is just the stone index `i`, so there are `n` states. Cache `f(i)` in `dp[i]` (sentinel `-1`), return early on a hit. Each state is computed once and does O(1) work.
- **Time:** O(n)
- **Space:** O(n) table + O(n) recursion stack

## Approach 3: Tabulation
Fill the table forward: `dp[0] = 0`; for `i = 1 … n-1`, take `dp[i-1] + |h[i]-h[i-1]|`, and if `i > 1` also consider `dp[i-2] + |h[i]-h[i-2]|`, keeping the smaller. Every dependency is already computed when we reach `i`. Answer: `dp[n-1]`.
- **Time:** O(n)
- **Space:** O(n)

## Approach 4: Two rolling variables (Optimal)

`dp[i]` reads only `dp[i-1]` and `dp[i-2]`, so keep just those two values. But careful — the recurrence also needs the **heights** at `i-1` and `i-2`, and those come from the input array, which we still have. So only the DP table shrinks.

**Algorithm.**
1. `prev2 = 0` (cost to stand on stone 0 — placeholder, only used from `i = 2`), `prev1 = 0` (cost at stone 0).
2. For `i = 1 … n-1`:
   - `oneStep = prev1 + |h[i] - h[i-1]|`
   - `twoStep = (i > 1) ? prev2 + |h[i] - h[i-2]| : INF`
   - `cur = min(oneStep, twoStep)`
   - slide: `prev2 = prev1`, `prev1 = cur`
3. Return `prev1`.

**Dry run on `[30, 10, 60, 10, 60, 50]`.**

| i | h[i] | one-step | two-step | dp[i] |
|---|---|---|---|---|
| 0 | 30 | — | — | 0 |
| 1 | 10 | 0 + \|10−30\| = 20 | — | **20** |
| 2 | 60 | 20 + \|60−10\| = 70 | 0 + \|60−30\| = 30 | **30** |
| 3 | 10 | 30 + \|10−60\| = 80 | 20 + \|10−10\| = 20 | **20** |
| 4 | 60 | 20 + \|60−10\| = 70 | 30 + \|60−60\| = 30 | **30** |
| 5 | 50 | 30 + \|50−60\| = 40 | 20 + \|50−10\| = 60 | **40** |

Answer `40`. Tracing back which branch won at each row: `dp[5]` came from `dp[4]` (one-step), `dp[4]` from `dp[2]` (two-step), `dp[2]` from `dp[0]` (two-step) — the path `0 → 2 → 4 → 5`. ✔
- **Time:** O(n)
- **Space:** O(1)

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <climits>
#include <cmath>
using namespace std;

class Solution {
public:
    int frogJump(int n, vector<int>& height) {
        if (n <= 1) return 0;
        int prev2 = 0;              // dp[i-2]
        int prev1 = 0;              // dp[i-1], starts as dp[0] = 0
        for (int i = 1; i < n; i++) {
            int oneStep = prev1 + abs(height[i] - height[i - 1]);
            int twoStep = INT_MAX;
            if (i > 1) twoStep = prev2 + abs(height[i] - height[i - 2]);
            int cur = min(oneStep, twoStep);
            prev2 = prev1;
            prev1 = cur;
        }
        return prev1;
    }
};
```

### Python
```python
from typing import List


class Solution:
    def frogJump(self, n: int, height: List[int]) -> int:
        if n <= 1:
            return 0
        prev2 = 0        # dp[i-2]
        prev1 = 0        # dp[i-1], starts as dp[0] = 0
        for i in range(1, n):
            one_step = prev1 + abs(height[i] - height[i - 1])
            two_step = float("inf")
            if i > 1:
                two_step = prev2 + abs(height[i] - height[i - 2])
            cur = min(one_step, two_step)
            prev2, prev1 = prev1, cur
        return prev1
```

## Key Takeaways
- Define the state as "min cost to *reach* stone `i`" and branch on where the last jump came from — the jump cost depends only on the two endpoints, which is what makes optimal substructure hold.
- Greedy on the cheaper immediate jump is wrong; a cheap jump now can force an expensive one later.
- Guard the `i-2` transition with `i > 1`, and use a large sentinel (not `0`) for the unavailable branch, or you will silently report cost 0.
- The table depends on a window of size 2, so O(n) space collapses to O(1) — but keep the height array, it is still needed.
