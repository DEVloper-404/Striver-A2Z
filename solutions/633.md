# Longest Bitonic Subsequence

**Difficulty:** Medium  ·  **Topic:** Dynamic Programming [Patterns and Problems] › DP on LIS

## Problem
A **bitonic** subsequence is one that first strictly increases and then strictly decreases. Given an array `arr`, return the length of its longest bitonic subsequence. By the usual convention either half may be empty, so a purely increasing or purely decreasing subsequence also counts as bitonic.

```
Input:  arr = [1, 11, 2, 10, 4, 5, 2, 1]
Output: 6      (for example [1, 11, 10, 5, 2, 1] — up to the peak 11, then down)
```

## Approach 1: Try every subsequence (Brute Force)
Enumerate all `2^n` subsequences and check whether each rises then falls. Clearly correct and clearly unusable beyond tiny `n`.

- **Time:** O(2^n · n)
- **Space:** O(n)

## Approach 2: Two LIS passes around a peak (Optimal)
The unlocking observation is that **every bitonic subsequence has a unique peak** — the single largest element, where the increase turns into the decrease. So instead of searching over subsequences, search over *which index is the peak*. Once the peak is fixed at index `i`, the two halves become completely independent:

- The rising half is the longest strictly increasing subsequence that **ends at `i`**, using only indices `< i`.
- The falling half is the longest strictly decreasing subsequence that **starts at `i`**, using only indices `> i`. Equivalently, it is the longest increasing subsequence ending at `i` when the array is read right-to-left.

Both are ordinary LIS computations, so:

1. `dp1[i]` = LIS ending at `i`, computed left to right: `dp1[i] = 1 + max{dp1[j] : j < i, arr[j] < arr[i]}`.
2. `dp2[i]` = LIS ending at `i` scanning from the right: `dp2[i] = 1 + max{dp2[j] : j > i, arr[j] < arr[i]}`. This is the longest decreasing run starting at `i` in the original direction.
3. Answer = `max over i of dp1[i] + dp2[i] - 1`. Subtract 1 because `arr[i]` itself is counted in both halves.

Because we maximise over every possible peak, and every bitonic subsequence is captured at its own peak, no candidate is missed.

**Dry run** on `[1, 11, 2, 10, 4, 5, 2, 1]`:

| i | arr[i] | dp1[i] | dp2[i] | dp1+dp2−1 |
|---|--------|--------|--------|-----------|
| 0 | 1      | 1      | 1      | 1         |
| 1 | 11     | 2      | 5      | **6**     |
| 2 | 2      | 2      | 2      | 3         |
| 3 | 10     | 3      | 4      | **6**     |
| 4 | 4      | 3      | 3      | 5         |
| 5 | 5      | 4      | 3      | **6**     |
| 6 | 2      | 2      | 2      | 3         |
| 7 | 1      | 1      | 1      | 1         |

The maximum is `6`. Peak `11` at index 1 realises it as `[1] + [11, 10, 5, 2, 1]`; peak `5` at index 5 realises a different one, `[1, 2, 4, 5] + [2, 1]`. Both have length 6.

- **Time:** O(n²)
- **Space:** O(n)

## Approach 3: Speeding the two passes to O(n log n)
Each of the two passes is a standalone LIS "ending at index i" computation, which can be done in O(n log n) with a Fenwick tree (BIT) over coordinate-compressed values, or with the patience `tails` array augmented to report the length at each index. The combination step is unchanged. This only matters for large `n`; the O(n²) version is the one usually expected in interviews.

**Variant to watch for.** Some statements demand that *both* halves be non-empty (a genuine rise **and** a genuine fall). In that case only count index `i` when `dp1[i] > 1` **and** `dp2[i] > 1`; otherwise you would accept a purely increasing sequence as bitonic.

- **Time:** O(n log n)
- **Space:** O(n)

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int longestBitonicSubsequence(vector<int>& arr) {
        int n = arr.size();
        if (n == 0) return 0;

        vector<int> dp1(n, 1), dp2(n, 1);

        // dp1[i]: longest strictly increasing subsequence ending at i
        for (int i = 1; i < n; i++)
            for (int j = 0; j < i; j++)
                if (arr[j] < arr[i]) dp1[i] = max(dp1[i], dp1[j] + 1);

        // dp2[i]: longest strictly decreasing subsequence starting at i
        for (int i = n - 2; i >= 0; i--)
            for (int j = n - 1; j > i; j--)
                if (arr[j] < arr[i]) dp2[i] = max(dp2[i], dp2[j] + 1);

        int best = 0;
        for (int i = 0; i < n; i++)
            best = max(best, dp1[i] + dp2[i] - 1);   // peak counted once
        return best;
    }
};
```

### Java
```java
import java.util.Arrays;

class Solution {
    public int longestBitonicSubsequence(int[] arr) {
        int n = arr.length;
        if (n == 0) return 0;

        int[] dp1 = new int[n];
        int[] dp2 = new int[n];
        Arrays.fill(dp1, 1);
        Arrays.fill(dp2, 1);

        for (int i = 1; i < n; i++) {
            for (int j = 0; j < i; j++) {
                if (arr[j] < arr[i]) dp1[i] = Math.max(dp1[i], dp1[j] + 1);
            }
        }
        for (int i = n - 2; i >= 0; i--) {
            for (int j = n - 1; j > i; j--) {
                if (arr[j] < arr[i]) dp2[i] = Math.max(dp2[i], dp2[j] + 1);
            }
        }

        int best = 0;
        for (int i = 0; i < n; i++) {
            best = Math.max(best, dp1[i] + dp2[i] - 1);
        }
        return best;
    }
}
```

### Python
```python
from typing import List


class Solution:
    def longestBitonicSubsequence(self, arr: List[int]) -> int:
        n = len(arr)
        if n == 0:
            return 0

        dp1 = [1] * n          # longest increasing ending at i
        dp2 = [1] * n          # longest decreasing starting at i

        for i in range(1, n):
            for j in range(i):
                if arr[j] < arr[i]:
                    dp1[i] = max(dp1[i], dp1[j] + 1)

        for i in range(n - 2, -1, -1):
            for j in range(n - 1, i, -1):
                if arr[j] < arr[i]:
                    dp2[i] = max(dp2[i], dp2[j] + 1)

        return max(dp1[i] + dp2[i] - 1 for i in range(n))
```

## Key Takeaways
- Fix the peak: every bitonic subsequence has exactly one, so maximising `dp1[i] + dp2[i] - 1` over all `i` covers all of them exactly once.
- The `-1` is essential — the peak element belongs to both the rising and falling halves and would otherwise be double counted.
- The backward pass is just LIS on the reversed array; nothing new needs to be invented.
- Read the constraints carefully: if both halves must be non-empty, restrict the maximisation to indices where `dp1[i] > 1 && dp2[i] > 1`.
