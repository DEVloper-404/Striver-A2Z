# Disjoint Set

**Difficulty:** Hard  ·  **Topic:** Graphs [Concepts & Problems] › MinimumSpanningTree/Disjoint Set and Problems

## Problem
Design a data structure that maintains a collection of disjoint sets over elements `0 … n-1` and supports two operations very fast:
- `findParent(x)` — return a representative ("leader") of the set containing `x`;
- `union(x, y)` — merge the sets containing `x` and `y`.

With those, `findParent(x) == findParent(y)` answers "are `x` and `y` in the same component?" in near-constant time, even while edges are being added.

```
Start: {0} {1} {2} {3} {4} {5} {6}
union(1,2), union(2,3), union(4,5), union(6,7 …) etc.
Query: same(1,3) -> true   (1 and 3 merged transitively)
Query: same(3,4) -> false  (different components)
```

## Approach 1: Repeated BFS/DFS for every query
Store the edges, and for each connectivity query run a traversal from `x` to see if `y` is reachable. Correct, but each query is `O(V + E)`. With `Q` queries that is `O(Q · (V + E))` — far too slow, and it does not adapt well to edges arriving online.
- **Time:** O(Q · (V + E))
- **Space:** O(V + E)

## Approach 2: Union by rank/size + path compression (optimal)

**The representation.** Each set is stored as a *tree* of parent pointers. `parent[x]` points one step towards the leader; the leader is the unique node with `parent[x] == x`. `find(x)` walks up until it reaches the leader. Merging two sets is then just "hang one leader under the other" — a single pointer write.

**Problem: naive merging makes tall trees.** If you always attach `x`'s leader under `y`'s leader, a sequence like `union(1,2), union(2,3), union(3,4), …` builds a chain of length `n`, and every `find` becomes `O(n)`. Two independent optimisations fix this.

**Optimisation 1 — union by rank (or by size).** Always attach the *shorter/smaller* tree under the *taller/bigger* one, so the result is no deeper than the taller input.
- **By rank:** `rank[x]` is an upper bound on the tree's height. Attach the lower-rank root under the higher-rank root; the height does not grow. Only when both ranks are equal does the winner's rank increase by one. Since rank only increases when two equal-rank trees merge, a tree of rank `r` contains at least `2^r` nodes, so rank ≤ `log n` and every `find` is `O(log n)`.
- **By size:** `size[x]` is the node count. Attach the smaller root under the bigger one. When a node's depth increases, the set it belongs to at least doubled, so its depth can increase at most `log n` times. Same bound, and `size` is often useful information in itself (e.g. "how big is this component?").

**Optimisation 2 — path compression.** During `find(x)`, after locating the leader, re-point every node on the path directly at the leader. The next `find` on any of them costs one hop. This flattens trees aggressively and is where most of the practical speed comes from.

**Combined cost.** With both optimisations, `m` operations on `n` elements cost `O(m · α(n))`, where `α` is the inverse Ackermann function — below 5 for any input that fits in the universe. Treat it as effectively constant.

**One caveat about `rank` under path compression.** Once you compress paths, `rank` is no longer the exact height, only an upper bound. That is fine — the merge decision only needs a consistent tie-breaking heuristic, and the bound stays valid. Never try to "fix up" ranks after a compression.

**Short dry run.** Start with each node its own leader, all ranks `0`.
- `union(1,2)`: leaders `1` and `2`, ranks equal → attach `2` under `1`, `rank[1] = 1`.
- `union(2,3)`: `find(2) = 1` (rank 1), `find(3) = 3` (rank 0) → attach `3` under `1`. Rank stays `1`.
- `union(4,5)`: attach `5` under `4`, `rank[4] = 1`.
- `union(3,4)`: `find(3) = 1` (rank 1), `find(4) = 4` (rank 1) — equal → attach `4` under `1` and bump `rank[1]` to `2`. Now `find(5)` walks `5 → 4 → 1` and, thanks to compression, rewrites `parent[5] = 1` so the next call is one hop.

**Where it is used.** Kruskal's MST (accept an edge iff its endpoints have different leaders), counting connected components online, cycle detection in an undirected graph, and every "merge things as queries stream in" problem — accounts merge, number of islands II, most stones removed, and so on.
- **Time:** O(α(n)) amortised per `find` / `union` — effectively O(1)
- **Space:** O(n) for the parent array plus the rank or size array

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <algorithm>
#include <numeric>
using namespace std;

class DisjointSet {
    vector<int> parent, rnk, sz;
public:
    explicit DisjointSet(int n) : parent(n), rnk(n, 0), sz(n, 1) {
        iota(parent.begin(), parent.end(), 0);   // every node is its own leader
    }

    int findParent(int x) {                      // with path compression
        if (parent[x] == x) return x;
        return parent[x] = findParent(parent[x]);
    }

    bool unionByRank(int a, int b) {
        a = findParent(a); b = findParent(b);
        if (a == b) return false;                // already together
        if (rnk[a] < rnk[b]) swap(a, b);         // a becomes the taller root
        parent[b] = a;
        sz[a] += sz[b];
        if (rnk[a] == rnk[b]) rnk[a]++;
        return true;
    }

    bool unionBySize(int a, int b) {
        a = findParent(a); b = findParent(b);
        if (a == b) return false;
        if (sz[a] < sz[b]) swap(a, b);           // a becomes the bigger root
        parent[b] = a;
        sz[a] += sz[b];
        return true;
    }

    bool same(int a, int b) { return findParent(a) == findParent(b); }
    int componentSize(int x) { return sz[findParent(x)]; }
};
```

### Java
```java
import java.util.*;

class DisjointSet {
    private final int[] parent, rank, size;

    public DisjointSet(int n) {
        parent = new int[n];
        rank = new int[n];
        size = new int[n];
        for (int i = 0; i < n; i++) { parent[i] = i; size[i] = 1; }
    }

    public int findParent(int x) {                 // path compression
        if (parent[x] != x) parent[x] = findParent(parent[x]);
        return parent[x];
    }

    public boolean unionByRank(int a, int b) {
        a = findParent(a); b = findParent(b);
        if (a == b) return false;
        if (rank[a] < rank[b]) { int t = a; a = b; b = t; }
        parent[b] = a;
        size[a] += size[b];
        if (rank[a] == rank[b]) rank[a]++;
        return true;
    }

    public boolean unionBySize(int a, int b) {
        a = findParent(a); b = findParent(b);
        if (a == b) return false;
        if (size[a] < size[b]) { int t = a; a = b; b = t; }
        parent[b] = a;
        size[a] += size[b];
        return true;
    }

    public boolean same(int a, int b) { return findParent(a) == findParent(b); }
    public int componentSize(int x) { return size[findParent(x)]; }
}
```

### Python
```python
class DisjointSet:
    def __init__(self, n: int) -> None:
        self.parent = list(range(n))
        self.rank = [0] * n
        self.size = [1] * n

    def find_parent(self, x: int) -> int:
        root = x
        while self.parent[root] != root:
            root = self.parent[root]
        while self.parent[x] != root:            # iterative path compression
            self.parent[x], x = root, self.parent[x]
        return root

    def union_by_rank(self, a: int, b: int) -> bool:
        a, b = self.find_parent(a), self.find_parent(b)
        if a == b:
            return False
        if self.rank[a] < self.rank[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]
        if self.rank[a] == self.rank[b]:
            self.rank[a] += 1
        return True

    def union_by_size(self, a: int, b: int) -> bool:
        a, b = self.find_parent(a), self.find_parent(b)
        if a == b:
            return False
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]
        return True

    def same(self, a: int, b: int) -> bool:
        return self.find_parent(a) == self.find_parent(b)

    def component_size(self, x: int) -> int:
        return self.size[self.find_parent(x)]
```

## Key Takeaways
- Always call `find` on **both** arguments before merging — comparing raw `parent[]` values instead of leaders is the most common bug.
- Union by rank/size bounds tree height at `O(log n)`; path compression flattens it further, and together they give amortised `O(α(n))`.
- After path compression, `rank` is only an upper bound on height, not the true height — that is by design.
- Union by **size** is preferable when the problem also asks about component sizes (largest island, network components); the merge logic is otherwise identical.
