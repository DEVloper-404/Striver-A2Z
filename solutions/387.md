# Implement Queue using Arrays

**Difficulty:** Easy  ·  **Topic:** Stack and Queues [Learning, Pre-In-Post-fix, Monotonic Stack, Implementation] › Learning

## Problem
Build a queue (first in, first out) on top of a fixed-size array. Support `push(x)` (enqueue at the back), `pop()` (dequeue from the front), `front()`, `isEmpty()` and `size()`. Return -1 for `pop`/`front` on an empty queue.

Input: `push(1), push(2), push(3), pop(), front(), size()`
Output: `1, 2, 2`

## Approach 1: Naive (shift on dequeue)
Keep elements in `arr[0..count-1]`. Push appends at index `count`. Pop returns `arr[0]` and shifts everything one slot left. Simple but pop is linear.
- **Time:** O(1) push, O(n) pop
- **Space:** O(cap)

## Approach 2: Optimal (circular array)
Track `frontIdx`, `count` and capacity `cap`. The back position is computed as `(frontIdx + count) % cap`. Wrapping with modulo lets the queue reuse slots freed at the front, so neither operation moves any element.

- `push(x)`: if `count == cap` it is full; else write `arr[(frontIdx + count) % cap] = x`, `count++`.
- `pop()`: if `count == 0` it is empty; else read `arr[frontIdx]`, advance `frontIdx = (frontIdx + 1) % cap`, `count--`.
- `front()`: `arr[frontIdx]`.

Keeping `count` (rather than only front/rear indices) makes the full-vs-empty distinction trivial.
- **Time:** O(1) per operation
- **Space:** O(cap)

## Code (Optimal)

### C++
```cpp
#include <vector>
using namespace std;

class Queue {
    vector<int> arr;
    int frontIdx, count, cap;
public:
    explicit Queue(int capacity = 1000) : arr(capacity), frontIdx(0), count(0), cap(capacity) {}

    void push(int x) {
        if (count == cap) return;                 // full
        arr[(frontIdx + count) % cap] = x;
        count++;
    }
    int pop() {
        if (count == 0) return -1;                // empty
        int val = arr[frontIdx];
        frontIdx = (frontIdx + 1) % cap;
        count--;
        return val;
    }
    int front() const { return count == 0 ? -1 : arr[frontIdx]; }
    bool isEmpty() const { return count == 0; }
    int size() const { return count; }
};
```

### Java
```java
class Queue {
    private final int[] arr;
    private int frontIdx = 0, count = 0;

    Queue(int capacity) { arr = new int[capacity]; }
    Queue() { this(1000); }

    void push(int x) {
        if (count == arr.length) return;          // full
        arr[(frontIdx + count) % arr.length] = x;
        count++;
    }
    int pop() {
        if (count == 0) return -1;                // empty
        int val = arr[frontIdx];
        frontIdx = (frontIdx + 1) % arr.length;
        count--;
        return val;
    }
    int front() { return count == 0 ? -1 : arr[frontIdx]; }
    boolean isEmpty() { return count == 0; }
    int size() { return count; }
}
```

### Python
```python
class Queue:
    def __init__(self, capacity: int = 1000):
        self.arr = [0] * capacity
        self.front_idx = 0
        self.count = 0
        self.cap = capacity

    def push(self, x: int) -> None:
        if self.count == self.cap:
            return                                # full
        self.arr[(self.front_idx + self.count) % self.cap] = x
        self.count += 1

    def pop(self) -> int:
        if self.count == 0:
            return -1                             # empty
        val = self.arr[self.front_idx]
        self.front_idx = (self.front_idx + 1) % self.cap
        self.count -= 1
        return val

    def front(self) -> int:
        return -1 if self.count == 0 else self.arr[self.front_idx]

    def is_empty(self) -> bool:
        return self.count == 0

    def size(self) -> int:
        return self.count
```

## Key Takeaways
- A circular buffer with modulo indexing gives O(1) enqueue and dequeue with no shifting.
- Storing `count` avoids the classic ambiguity where `front == rear` could mean either full or empty.
- Always compute the rear as `(front + count) % cap` rather than storing a separate rear that can drift.
- Check full before push and empty before pop.
