# Prefix to Infix Conversion

**Difficulty:** Medium  ·  **Topic:** Stack and Queues [Learning, Pre-In-Post-fix, Monotonic Stack, Implementation] › Prefix, Infix, PostFix Conversion Problems

## Problem
Given a valid **prefix** (Polish) expression, where every operator is written before its two operands and no brackets appear, reconstruct the equivalent **infix** expression with brackets that make it unambiguous. Operands are single characters and operators are `+ - * / ^`.

```
Input:  *+ab-cd
Output: ((a+b)*(c-d))
```

## Approach 1: Recursive descent from the left
Prefix is trivially parseable top-down: read one character; if it is an operand return it; if it is an operator, recursively parse the next sub-expression as `left`, then the next as `right`, and return `"(" + left + op + right + ")"`. A shared index (a pointer or a class field) advances through the string.

This is elegant and O(n) in the number of characters visited, but it needs recursion whose depth equals the tree height — up to `n/2` for a skewed expression — and languages with small stacks can overflow on long inputs.

- **Time:** O(n) visits, O(n^2) with string building
- **Space:** O(n) recursion depth.

## Approach 2: Right-to-left scan with a stack (Optimal)
The key observation is a mirror of the postfix case. In postfix, an operator's operands are *behind* it, so scanning left to right lets a stack accumulate finished pieces. In prefix, an operator's operands are *ahead* of it — so **scan the string from right to left** and the same stack discipline works.

The invariant: reading backwards, whenever we reach a character, every sub-expression to its right has already been fully assembled and sits on the stack, with the leftmost one on top.

Scan right to left:

1. **Operand** → push it as a one-character string.
2. **Operator `op`** → its two operands are the two nearest completed sub-expressions to its right. Because we pushed right-to-left, the **top of the stack is the operand that appears first (the left one)**. So pop once for `left`, pop again for `right`, and push `"(" + left + op + right + ")"`.
3. One string remains at the end: the answer.

**Note the pop order is the opposite of postfix conversions.** In postfix the first pop is the *right* operand; here the first pop is the *left* one. Getting this backwards turns `-cd` into `(d-c)`.

**Why bracket everything.** The algorithm never inspects precedence. Wrapping each combination guarantees the infix string re-parses to the same tree; without brackets, `*+ab c` would flatten into `a+b*c`, a different expression. Some brackets are redundant, none are wrong.

**Dry run on `*+ab-cd`, scanning right to left:**

| Read | Action | Stack (bottom → top) |
|---|---|---|
| `d` | push | `d` |
| `c` | push | `d`, `c` |
| `-` | left=`c`, right=`d` | `(c-d)` |
| `b` | push | `(c-d)`, `b` |
| `a` | push | `(c-d)`, `b`, `a` |
| `+` | left=`a`, right=`b` | `(c-d)`, `(a+b)` |
| `*` | left=`(a+b)`, right=`(c-d)` | `((a+b)*(c-d))` |

Notice how at the `*` step the top of the stack really is the left operand — `(a+b)` came from characters further left in the input, so it was pushed later.

- **Time:** O(n) stack operations; O(n^2) overall in the worst case because of string concatenation.
- **Space:** O(n) stack entries, O(n^2) characters in the worst case.

## Code (Optimal)

### C++
```cpp
#include <string>
#include <stack>
#include <cctype>
using namespace std;

class Solution {
public:
    string prefixToInfix(const string& s) {
        stack<string> st;
        for (int i = (int)s.size() - 1; i >= 0; i--) {
            char c = s[i];
            if (isalnum(static_cast<unsigned char>(c))) {
                st.push(string(1, c));
            } else {
                string left  = st.top(); st.pop();   // scanning backwards => top is LEFT
                string right = st.top(); st.pop();
                st.push("(" + left + c + right + ")");
            }
        }
        return st.top();
    }
};
```

### Java
```java
import java.util.*;

class Solution {
    public String prefixToInfix(String s) {
        Deque<String> st = new ArrayDeque<>();
        for (int i = s.length() - 1; i >= 0; i--) {
            char c = s.charAt(i);
            if (Character.isLetterOrDigit(c)) {
                st.push(String.valueOf(c));
            } else {
                String left = st.pop();      // top is the LEFT operand here
                String right = st.pop();
                st.push("(" + left + c + right + ")");
            }
        }
        return st.peek();
    }
}
```

### Python
```python
class Solution:
    def prefixToInfix(self, s: str) -> str:
        st = []
        for c in reversed(s):
            if c.isalnum():
                st.append(c)
            else:
                left = st.pop()           # scanning backwards => top is LEFT
                right = st.pop()
                st.append("(" + left + c + right + ")")
        return st[-1]
```

## Key Takeaways
- Prefix conversions scan **right to left**; postfix conversions scan **left to right**. Pick the direction that makes an operator's operands already available on the stack.
- Because of that direction flip, the first pop is the **left** operand in prefix problems and the **right** operand in postfix problems.
- Bracket every combination — the algorithm carries no precedence information, and redundant brackets are harmless.
- A well-formed input ends with exactly one string on the stack; more than one means the expression was malformed.
