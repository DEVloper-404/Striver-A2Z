# Number of distinct substrings in a string

**Difficulty:** Medium  ·  **Topic:** Tries › Problems

## Problem
Given a string `s`, count how many **distinct non-empty substrings** it has. A substring is a contiguous block of characters; two substrings are the same if their text is identical, regardless of where they occur.

```
Input:  s = "ababa"
Output: 9
```
The distinct substrings are `a`, `b`, `ab`, `ba`, `aba`, `bab`, `abab`, `baba`, `ababa`.

## Approach 1: Hash set of all substrings (Brute Force)

Generate every substring `s[i..j]` and insert it into a hash set; the set's size is the answer. There are O(n^2) substrings, but each one costs O(n) to build and hash, so the total work is cubic and the memory holds O(n^2) strings of average length O(n).

- **Time:** O(n^3)
- **Space:** O(n^3) characters stored

## Approach 2: Insert all suffixes into a trie (Optimal)

**Observation 1 — every substring is a prefix of a suffix.** Take any substring `s[i..j]`. It is exactly the first `j - i + 1` characters of the suffix starting at `i`. Conversely, every prefix of every suffix is a substring. So the set of substrings equals the set of prefixes of the `n` suffixes.

**Observation 2 — a trie stores each distinct prefix exactly once.** In a trie, every node other than the root corresponds to one distinct string: the concatenation of edge labels from the root to that node. Inserting a string creates a new node only when that particular prefix has never been seen before.

Put the two together: **insert all `n` suffixes into one trie, and the number of nodes created (excluding the root) is the number of distinct substrings.** No `isEnd` flags, no set of strings, no comparisons — the trie deduplicates automatically by structure.

**The algorithm.**
1. Create an empty root node and a counter `count = 0`.
2. For each start index `i` from `0` to `n-1`:
   - Set `cur = root`.
   - For each `j` from `i` to `n-1`: if `cur` has no child for `s[j]`, create it and do `count++`; then move `cur` into that child.
3. Return `count`.

Note we never materialise a substring — we just walk character by character, which is what removes the extra O(n) factor from the brute force.

**Dry run on `s = "ababa"`.**

- `i = 0`, suffix `"ababa"`: none of `a`, `ab`, `aba`, `abab`, `ababa` exist yet, so **5 new nodes** are created. `count = 5`.
- `i = 1`, suffix `"baba"`: `b`, `ba`, `bab`, `baba` are all new (the trie so far only has the `a...` branch), so **4 new nodes**. `count = 9`.
- `i = 2`, suffix `"aba"`: the walk `a → b → a` follows existing nodes the whole way, so **0 new nodes**. `count = 9`.
- `i = 3`, suffix `"ba"`: `b → a` already exists → **0 new**.
- `i = 4`, suffix `"a"`: `a` already exists → **0 new**.

Final `count = 9`, matching the hand-listed set. The repeats at `i = 2, 3, 4` cost time but no memory, which is exactly the deduplication we wanted.

**Complexity.** The double loop touches O(n^2) characters, and at most one node is created per character touched.

- **Time:** O(n^2)
- **Space:** O(n^2) nodes in the worst case (a string of all-distinct characters, e.g. `"abcd..."`)

## Code (Optimal)

### C++
```cpp
#include <string>
using namespace std;

class Solution {
    struct Node {
        Node* links[26] = {nullptr};
    };

public:
    // Counts distinct NON-EMPTY substrings. If a judge also counts the
    // empty substring, return count + 1.
    int countDistinctSubstrings(string& s) {
        Node* root = new Node();
        int n = s.size();
        int count = 0;

        for (int i = 0; i < n; i++) {
            Node* cur = root;
            for (int j = i; j < n; j++) {
                int idx = s[j] - 'a';
                if (cur->links[idx] == nullptr) {
                    cur->links[idx] = new Node();   // a brand new substring
                    count++;
                }
                cur = cur->links[idx];
            }
        }
        return count;
    }
};
```

class Solution {
    private static class Node {
        Node[] links = new Node[26];
    }

    // Counts distinct NON-EMPTY substrings; add 1 if the empty one counts.
    public int countDistinctSubstrings(String s) {
        Node root = new Node();
        int n = s.length();
        int count = 0;

        for (int i = 0; i < n; i++) {
            Node cur = root;
            for (int j = i; j < n; j++) {
                int idx = s.charAt(j) - 'a';
                if (cur.links[idx] == null) {
                    cur.links[idx] = new Node();    // a brand new substring
                    count++;
                }
                cur = cur.links[idx];
            }
        }
        return count;
    }
}

### Python
```python
class Solution:
    # Counts distinct NON-EMPTY substrings; add 1 if the empty one counts.
    def countDistinctSubstrings(self, s: str) -> int:
        root = {}
        n = len(s)
        count = 0

        for i in range(n):
            cur = root
            for j in range(i, n):
                ch = s[j]
                if ch not in cur:
                    cur[ch] = {}                    # a brand new substring
                    count += 1
                cur = cur[ch]

        return count
```

## Key Takeaways
- Every substring is a prefix of some suffix — inserting all `n` suffixes into one trie enumerates every substring exactly once.
- The answer is simply the node count (excluding the root); no `isEnd` flag is needed because we are counting prefixes, not stored words.
- Walking character by character avoids building substrings, dropping the brute force from O(n^3) to O(n^2).
- Watch the convention: some judges include the empty substring, making the answer `count + 1`. A suffix automaton or suffix array solves the same problem in O(n log n) or better when `n` is large.
