# Find minimum in Rotated Sorted Array

**Difficulty:** Easy  ·  **Topic:** Binary Search [1D, 2D Arrays, Search Space] › BS on 1D Arrays

## Problem
An array of distinct integers was sorted in ascending order and then rotated some number of times (possibly zero). Given the rotated array `nums`, return its minimum element in O(log n) time.

Input: `nums = [4, 5, 6, 7, 0, 1, 2]`
Output: `0`

Input: `nums = [11, 13, 15, 17]`
Output: `11` (no rotation, or rotated a full cycle)

## Approach 1: Linear Scan
Take the minimum over all elements. Trivially correct, but it does not use the rotated-sorted structure.

- **Time:** O(n)
- **Space:** O(1)

## Approach 2: Binary Search on the Sorted Half (Optimal)
Split the range at `mid`. One half is guaranteed to be sorted, and the minimum of a sorted half is its leftmost element. So:

1. If `nums[low] <= nums[mid]`, the left half `[low..mid]` is sorted. Its smallest value is `nums[low]`; record it as a candidate. The true minimum, if smaller, must be in the unsorted right part, so set `low = mid + 1`.
2. Otherwise the right half `[mid..high]` is sorted; its smallest value is `nums[mid]`. Record it and look in the left part: `high = mid - 1`.
3. The answer is the smallest candidate seen.

A useful shortcut: if `nums[low] <= nums[high]` the whole current range is sorted, so `nums[low]` is its minimum and you can stop early. This makes the unrotated case finish in one step.

- **Time:** O(log n)
- **Space:** O(1)

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <climits>
#include <algorithm>
using namespace std;

class Solution {
public:
    int findMin(vector<int>& nums) {
        int low = 0, high = (int)nums.size() - 1;
        int ans = INT_MAX;
        while (low <= high) {
            int mid = low + (high - low) / 2;

            if (nums[low] <= nums[high]) {          // whole range sorted
                ans = min(ans, nums[low]);
                break;
            }
            if (nums[low] <= nums[mid]) {           // left half sorted
                ans = min(ans, nums[low]);
                low = mid + 1;
            } else {                                // right half sorted
                ans = min(ans, nums[mid]);
                high = mid - 1;
            }
        }
        return ans;
    }
};
```

```python
from typing import List

class Solution:
    def findMin(self, nums: List[int]) -> int:
        low, high = 0, len(nums) - 1
        ans = float("inf")
        while low <= high:
            mid = (low + high) // 2

            if nums[low] <= nums[high]:      # whole range sorted
                ans = min(ans, nums[low])
                break
            if nums[low] <= nums[mid]:       # left half sorted
                ans = min(ans, nums[low])
                low = mid + 1
            else:                            # right half sorted
                ans = min(ans, nums[mid])
                high = mid - 1
        return ans
```

## Key Takeaways
- The minimum of a rotated sorted array is the rotation point; the sorted half never contains it unless the sorted half's first element is it, which is why we record that element and then search the other half.
- The `nums[low] <= nums[high]` early exit handles unrotated arrays and speeds up the tail of the search.
- Requires distinct values; with duplicates the endpoint comparisons become ambiguous, just like in "Search in rotated sorted array II".
- The index of this minimum is also the number of rotations the array underwent.
