# Kth Smallest and Largest element in BST

**Difficulty:** Medium  ·  **Topic:** Binary Search Trees [Concept and Problems] › Practice Problems

## Problem
Given the root of a BST and an integer `k` (1-indexed), return the k-th smallest value in the tree. The mirror question — the k-th largest — is the same problem read from the other end.

```
Input:  root = [5, 3, 6, 2, 4, null, null, 1], k = 3
Output: 3        (sorted values: 1, 2, 3, 4, 5, 6 → 3rd smallest is 3)

Input:  root = [5, 3, 6, 2, 4, null, null, 1], k = 3   (k-th LARGEST)
Output: 4        (3rd largest is 4)
```

## Approach 1: Brute Force (full inorder into an array)
Inorder traversal of a BST emits values in ascending order. Collect them into a list and return `arr[k-1]` for the k-th smallest, or `arr[n-k]` for the k-th largest.

This is easy to get right and is the version worth writing first in an interview. Its weakness is that it always walks all N nodes and stores all N values, even when `k = 1`.
- **Time:** O(N)
- **Space:** O(N)

## Approach 2: Better (inorder with a counter, stop early)
You do not need the array — you only need to know *when* you reach the k-th value. Do the inorder traversal but keep a counter. Every time you "visit" a node (the moment between finishing the left subtree and descending right), increment the counter; when it hits `k`, that node's value is the answer and you can abandon the rest of the traversal.

Why this is correct: inorder visits nodes in strictly increasing order, so the i-th visit is exactly the i-th smallest value. There is nothing to prove beyond the BST inorder property.

For the k-th **largest**, run a *reverse* inorder (right → node → left), which visits values in strictly decreasing order, and stop at the k-th visit. That is much nicer than computing the total node count and converting to `n - k + 1`.

**Dry run** for `k = 3`, k-th smallest, on the tree with root `5`, left `3` (children `2`, `4`; `2` has left child `1`), right `6`:
- Descend 5 → 3 → 2 → 1. Node `1` has no left child, so it is visited first: `count = 1`.
- Back at `2`: visited, `count = 2`. No right child.
- Back at `3`: visited, `count = 3` = k → **answer 3**, stop.

Only 4 of the 6 nodes were touched.
- **Time:** O(H + k) — the descent to the smallest node plus k visits
- **Space:** O(H) for the recursion or explicit stack

## Approach 3: Optimal iterative (explicit stack, truly early-exit)
The recursive early exit still unwinds the whole call stack, so people usually write the iterative Morris/stack version. With an explicit stack you push the whole left spine, pop a node (that pop *is* a visit), decrement `k`, and if `k` hits 0 return immediately — no unwinding, no flag variables.

Mirror it (push the right spine, then go left after popping) for the k-th largest.

If the tree is static and you must answer many such queries, the real optimisation is different: store in each node the size of its left subtree. Then a single downward walk answers each query in O(H) — if `leftSize + 1 == k` the node is the answer, if `k <= leftSize` go left, else set `k -= leftSize + 1` and go right. That is the "order statistic tree" idea and it is the standard follow-up question.
- **Time:** O(H + k)
- **Space:** O(H)

## Code (Optimal)

### C++
```cpp
// struct TreeNode { int val; TreeNode *left, *right; TreeNode(int x) ... } — standard definition
#include <stack>
using namespace std;

class Solution {
public:
    // k-th smallest: inorder (left, node, right)
    int kthSmallest(TreeNode* root, int k) {
        stack<TreeNode*> st;
        TreeNode* cur = root;
        while (cur != nullptr || !st.empty()) {
            while (cur != nullptr) { st.push(cur); cur = cur->left; }
            cur = st.top(); st.pop();
            if (--k == 0) return cur->val;      // this pop is the k-th visit
            cur = cur->right;
        }
        return -1;   // k larger than the number of nodes
    }

    // k-th largest: reverse inorder (right, node, left)
    int kthLargest(TreeNode* root, int k) {
        stack<TreeNode*> st;
        TreeNode* cur = root;
        while (cur != nullptr || !st.empty()) {
            while (cur != nullptr) { st.push(cur); cur = cur->right; }
            cur = st.top(); st.pop();
            if (--k == 0) return cur->val;
            cur = cur->left;
        }
        return -1;
    }
};
```

### Python
```python
# class TreeNode: val, left, right — standard definition

class Solution:
    def kthSmallest(self, root, k):
        st, cur = [], root
        while cur or st:
            while cur:                 # push the entire left spine
                st.append(cur)
                cur = cur.left
            cur = st.pop()             # popping == visiting, in sorted order
            k -= 1
            if k == 0:
                return cur.val
            cur = cur.right
        return -1

    def kthLargest(self, root, k):
        st, cur = [], root
        while cur or st:
            while cur:                 # mirror: push the right spine
                st.append(cur)
                cur = cur.right
            cur = st.pop()
            k -= 1
            if k == 0:
                return cur.val
            cur = cur.left
        return -1
```

## Key Takeaways
- Inorder on a BST *is* the sorted order — that single fact reduces this problem to "stop at the k-th element".
- Reverse inorder (right → node → left) gives descending order, so the k-th largest needs no node count.
- The stack version exits the instant it finds the answer, giving O(H + k) instead of O(N).
- Follow-up: if the tree is modified often and queried often, augment each node with its subtree size to get O(H) per query.
