# Kth largest element in a stream of running integers

**Difficulty:** Hard  ·  **Topic:** Heaps [Learning, Medium, Hard Problems] › Hard Problems

## Problem
Design a class `KthLargest` that is initialised with an integer `k` and an initial array `nums`. It exposes one method, `add(val)`, which appends `val` to the stream and returns the k-th largest element among everything seen so far (by sorted position, so duplicates count). The stream is guaranteed to contain at least `k` elements whenever `add` is asked for an answer.

```
Input:  KthLargest(3, [4, 5, 8, 2]); add(3); add(5); add(10); add(9); add(4)
Output: 4; 5; 5; 8; 8
```

## Approach 1: Re-sort on every add
Keep every value in a list. On each `add`, append the value, sort the list descending, and return the element at index `k - 1`. Trivially correct, but each call pays a full sort of the growing list.
- **Time:** O(n log n) per `add`, where n is the stream length so far
- **Space:** O(n)

## Approach 2: Maintain a sorted structure
Keep the values in a balanced ordered container (multiset / TreeMap). Insertion is logarithmic, but locating the k-th largest still needs either an iterator walk of `k` steps or an order-statistic tree, and the container holds every element ever seen.
- **Time:** O(log n + k) per `add`
- **Space:** O(n)

## Approach 3: Min-heap capped at k (optimal)
Only the `k` largest values seen so far can ever be the answer, and the k-th largest is the **smallest** of them. Keep exactly those `k` values in a min-heap:

- On construction, push all initial numbers, popping the minimum whenever the size exceeds `k`.
- On `add(val)`: push `val`; if the size is now `k + 1`, pop the minimum. Return the heap top.

Anything popped was beaten by at least `k` other values, so it can never come back into contention as the stream only grows.
- **Time:** O(log k) per `add`, O(n log k) to build
- **Space:** O(k)

## Code (Optimal)

### C++
```cpp
#include <bits/stdc++.h>
using namespace std;

class KthLargest {
    int k;
    priority_queue<int, vector<int>, greater<int>> minHeap;

public:
    KthLargest(int k, vector<int>& nums) : k(k) {
        for (int x : nums) add(x);
    }

    int add(int val) {
        minHeap.push(val);
        if ((int)minHeap.size() > k) minHeap.pop();
        return minHeap.top();
    }
};
```

### Java
```java
import java.util.*;

class KthLargest {
    private final int k;
    private final PriorityQueue<Integer> minHeap = new PriorityQueue<>();

    public KthLargest(int k, int[] nums) {
        this.k = k;
        for (int x : nums) add(x);
    }

    public int add(int val) {
        minHeap.offer(val);
        if (minHeap.size() > k) minHeap.poll();
        return minHeap.peek();
    }
}
```

### Python
```python
import heapq
from typing import List


class KthLargest:
    def __init__(self, k: int, nums: List[int]):
        self.k = k
        self.heap = []
        for x in nums:
            self.add(x)

    def add(self, val: int) -> int:
        heapq.heappush(self.heap, val)
        if len(self.heap) > self.k:
            heapq.heappop(self.heap)
        return self.heap[0]
```

## Key Takeaways
- A min-heap of fixed size `k` is the standard tool for "k-th largest in a stream": the heap top is the answer at all times.
- The initial array may contain fewer than `k` elements; the code handles that because the heap simply grows until it reaches `k`.
- Never store the whole stream when only the top `k` matter; memory stays O(k) regardless of how long the stream runs.
- The same design gives "k-th smallest in a stream" by switching to a max-heap.
