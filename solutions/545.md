# Valid Paranthesis Checker

**Difficulty:** Hard  ·  **Topic:** Greedy Algorithms [Easy, Medium/Hard] › Easy Problems

## Problem
Given a string containing only `(`, `)` and `*`, decide whether it can be a valid parenthesis string. Each `*` may be treated **independently** as a `(`, as a `)`, or as an empty string. Valid means every `(` has a matching `)` after it and every `)` has a matching `(` before it.

```
Input:  (*))
Output: true
```
Reading the `*` as `(` turns the string into `(())`. For contrast: `(*` is also valid (read the `*` as `)`), while `)(` and `((*` are not — the first has a `)` with nothing before it, the second leaves a `(` that nothing can close.

## Approach 1: Try all three meanings of every `*` (brute force)
Recurse over the string carrying a counter `open` of currently unmatched `(`. On `(` recurse with `open + 1`; on `)` recurse with `open - 1` (failing immediately if it goes negative); on `*` branch three ways: `open + 1`, `open - 1`, and `open` unchanged. At the end the string is valid if any branch reaches `open == 0`.

This is a direct translation of the definition and obviously correct, but with `k` stars it explores `3^k` paths. Memoising on `(index, open)` collapses it to a DP over at most `n × n` states, which is fine for moderate `n` but still quadratic in time and space.

- **Time:** O(3^n) brute force, O(n^2) memoised
- **Space:** O(n) recursion, O(n^2) with memoisation.

## Approach 2: Track the range of possible open counts (Optimal)
**Key observation.** We never need to know *which* choice each `*` made — only whether some set of choices keeps the count valid. The set of reachable "unmatched `(`" counts after any prefix is a **contiguous interval** of integers: `(` shifts the whole interval up by 1, `)` shifts it down by 1, and `*` widens it by one in both directions. Intervals are closed under all three operations, so two numbers describe the entire state.

Carry `low` (the smallest possible number of unmatched `(`, assuming every `*` so far was the most closing choice) and `high` (the largest, assuming every `*` was `(`):

- on `(` → `low++`, `high++`;
- on `)` → `low--`, `high--`;
- on `*` → `low--` (treat as `)`), `high++` (treat as `(`).

Two rules complete the algorithm:

1. **If `high < 0`, return false immediately.** `high` is the most optimistic count; if even that is negative, some `)` has appeared with nothing at all able to match it, and later characters can never repair a prefix.
2. **Clamp `low` at 0** with `low = max(low, 0)`. A negative `low` corresponds to choices that already made the prefix invalid, and those branches are simply discarded — the count can never be negative in a live branch.

At the end return `low == 0`: `0` lies inside the reachable interval `[low, high]` exactly when `low == 0` (we clamped, so `low >= 0`, and `high >= low`), meaning some assignment of the stars leaves nothing unmatched.

**Why clamping is safe.** Discarding the sub-zero part of the interval only removes assignments that are already invalid, and the surviving interval is still contiguous, so the invariant is preserved.

**Dry run on `(*))`:**

| Char | low | high | note |
|---|---|---|---|
| start | 0 | 0 | |
| `(` | 1 | 1 | |
| `*` | 0 | 2 | `*` = `)`, empty, or `(` |
| `)` | -1 → 0 | 1 | clamp `low`; `high >= 0` so continue |
| `)` | -1 → 0 | 0 | clamp again |

`low == 0` at the end → **true**, which corresponds to reading the `*` as `(` and getting `(())`.

**Counter-example `)(`:** on the first `)`, `low` and `high` both become `-1`; `high < 0` → return false immediately, as it must.

**Counter-example `((*`:** after `(`, `(`, `*` we have `low = 1`, `high = 3`. `low != 0`, so false — at least one `(` cannot be closed.

- **Time:** O(n) — a single pass with O(1) work per character.
- **Space:** O(1) — two integers, no stack.

## Code (Optimal)

### C++
```cpp
#include <string>
#include <algorithm>
using namespace std;

class Solution {
public:
    bool checkValidString(string s) {
        int low = 0, high = 0;   // reachable range of unmatched '(' counts
        for (char c : s) {
            if (c == '(') {
                low++;
                high++;
            } else if (c == ')') {
                low--;
                high--;
            } else {             // '*': ')' , empty, or '('
                low--;
                high++;
            }
            if (high < 0) return false;   // even the best case has an unmatched ')'
            low = max(low, 0);            // drop already-invalid branches
        }
        return low == 0;
    }
};
```

    public boolean checkValidString(String s) {
        int low = 0, high = 0;

### Python
```python
class Solution:
    def checkValidString(self, s: str) -> bool:
        low = high = 0            # reachable range of unmatched '(' counts
        for c in s:
            if c == '(':
                low += 1
                high += 1
            elif c == ')':
                low -= 1
                high -= 1
            else:                 # '*' can be ')', '', or '('
                low -= 1
                high += 1
            if high < 0:          # unmatched ')' even in the best case
                return False
            low = max(low, 0)     # discard already-invalid branches
        return low == 0
```

## Key Takeaways
- When a wildcard makes the state a *set* of values, check whether that set is an interval — if it is, two counters replace an exponential search.
- `high < 0` is a hard failure (a `)` with nothing to match); `low < 0` is not — it just means some branches died, so clamp it to 0.
- The final test is `low == 0`, not `high == 0`: leftover optimistic `(` from stars can always be re-read as empty.
- A single left-to-right pass suffices; the classic two-pass alternative (scan forwards treating `*` as `(`, then backwards treating `*` as `)`) is the same idea split in half.
