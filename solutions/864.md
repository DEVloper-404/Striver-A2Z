# Combination Sum

**Difficulty:** Medium  ·  **Topic:** Recursion [PatternWise] › Subsequences Pattern

## Problem
Given an array of **distinct** positive integers `candidates` and a target integer `target`, return every unique combination of candidates that sums to `target`. The same candidate may be picked an unlimited number of times, and two combinations are different only if the multiset of numbers differs (order does not matter).

```
Input:  candidates = [2, 3, 6, 7], target = 7
Output: [[2, 2, 3], [7]]
```
`[3, 2, 2]` is not listed separately because it is the same multiset as `[2, 2, 3]`.

## Approach 1: Pick / Not-pick recursion (Optimal for this problem)
The classic subsequence template is "at every index, either take the element or skip it". Combination Sum only tweaks one thing: because reuse is allowed, **taking** an element does *not* advance the index.

Define `solve(i, remaining, current)`:

1. **Base case.** If `remaining == 0`, `current` is a valid combination — record a copy of it and return. If `i == n` (ran out of candidates) return without recording; that branch failed.
2. **Pick `candidates[i]`** — only legal when `candidates[i] <= remaining`, since all numbers are positive and a negative remainder can never come back to zero. Push it onto `current`, recurse with the **same** index `i` and `remaining - candidates[i]`, then pop it (backtrack).
3. **Skip `candidates[i]`** — recurse with `i + 1` and the same `remaining`. Once we skip an index we never come back to it.

**Why this produces no duplicates.** Every combination is generated by a unique sequence of decisions read left to right: the recursion only ever moves the index forward, so a candidate that has been skipped can never reappear later. That forces every generated combination to be written in non-decreasing index order, and each multiset therefore corresponds to exactly one root-to-leaf path. `[3, 2, 2]` is impossible to produce because index 1 (the 3) is only reachable after index 0 (the 2) has been abandoned for good.

**Dry run on `[2, 3, 6, 7]`, target 7.**
- Pick 2 three times → remaining `7→5→3→1`. Picking 2 again would need `2 <= 1`, false, so we start skipping: index 1 (3 > 1), index 2, index 3 all fail, and the branch dies.
- Pick 2 twice → remaining 3, skip to index 1, pick 3 → remaining 0 → record `[2, 2, 3]`.
- Pick 2 once → remaining 5; no combination of 3/6/7 hits 5, dies.
- Skip 2 entirely → 3, 6 branches die; picking 7 → remaining 0 → record `[7]`.

- **Time:** O(2^t · k) where `t = target / min(candidates)` bounds the depth of the recursion tree and `k` is the average combination length copied into the answer.
- **Space:** O(t) for the recursion stack plus `current` (output not counted).

## Approach 2: Sort + prune (same complexity, much faster in practice)
Sort `candidates` ascending first. Then, instead of a binary pick/not-pick, loop `j` from `i` to `n-1` and recurse on `(j, remaining - candidates[j])`. Starting the loop at `j` (not `j+1`) allows reuse; never going below `i` prevents duplicates. The win is the `break`: as soon as `candidates[j] > remaining`, every later candidate is also too large in a sorted array, so the whole rest of the loop can be abandoned at once rather than being explored and rejected one at a time. On inputs with many large candidates this cuts the tree dramatically.

- **Time:** O(2^t · k) worst case, far below that with pruning.
- **Space:** O(t) recursion depth.

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    vector<vector<int>> combinationSum(vector<int>& candidates, int target) {
        sort(candidates.begin(), candidates.end());
        vector<vector<int>> res;
        vector<int> cur;
        solve(0, target, candidates, cur, res);
        return res;
    }

private:
    void solve(int start, int remaining, vector<int>& cand,
               vector<int>& cur, vector<vector<int>>& res) {
        if (remaining == 0) {
            res.push_back(cur);
            return;
        }
        for (int j = start; j < (int)cand.size(); j++) {
            if (cand[j] > remaining) break;   // sorted => all later ones fail too
            cur.push_back(cand[j]);
            solve(j, remaining - cand[j], cand, cur, res);   // j, not j+1: reuse allowed
            cur.pop_back();
        }
    }
};
```

### Java
```java
import java.util.*;

class Solution {
    public List<List<Integer>> combinationSum(int[] candidates, int target) {
        Arrays.sort(candidates);
        List<List<Integer>> res = new ArrayList<>();
        solve(0, target, candidates, new ArrayList<>(), res);
        return res;
    }

    private void solve(int start, int remaining, int[] cand,
                       List<Integer> cur, List<List<Integer>> res) {
        if (remaining == 0) {
            res.add(new ArrayList<>(cur));
            return;
        }
        for (int j = start; j < cand.length; j++) {
            if (cand[j] > remaining) break;
            cur.add(cand[j]);
            solve(j, remaining - cand[j], cand, cur, res);
            cur.remove(cur.size() - 1);
        }
    }
}
```

### Python
```python
from typing import List

class Solution:
    def combinationSum(self, candidates: List[int], target: int) -> List[List[int]]:
        candidates.sort()
        res, cur = [], []

        def solve(start: int, remaining: int) -> None:
            if remaining == 0:
                res.append(cur[:])
                return
            for j in range(start, len(candidates)):
                if candidates[j] > remaining:
                    break
                cur.append(candidates[j])
                solve(j, remaining - candidates[j])   # j allows reuse
                cur.pop()

        solve(0, target)
        return res
```

## Key Takeaways
- Unlimited reuse = recurse on the **same** index; single use = recurse on `index + 1`. That one character is the whole difference.
- Never letting the index move backwards is what guarantees uniqueness — no hash set of sorted tuples is needed.
- Sorting enables `break` on `candidates[j] > remaining`, which is the single biggest practical speedup.
- Remember to push a **copy** of `current` into the answer; the working vector is mutated on the way back up.
