# Basic Hashing

**Difficulty:** Easy  ·  **Topic:** Learn the basics › Learn Basic Hashing

## Problem
This is a theory item. Hashing is the technique of pre-computing information into a lookup table so that later queries are answered in O(1) instead of by re-scanning the data. The topic covers: array-based hashing (direct indexing), character hashing for strings, hash maps for large or arbitrary keys, how a hash function maps keys to slots, what collisions are and how they are resolved, and when a map beats an array.

Motivating query: given `arr = [1, 3, 2, 1, 3]`, answer several questions of the form "how many times does `x` appear?" without scanning the array every time.

Input: `arr = [1, 3, 2, 1, 3]`, queries `1, 4, 3`
Output: `2 0 2`

## Approach
**1. Why hash at all**
Answering `q` "count of x" queries by scanning the array costs O(n) each, O(n·q) total. If you first build a table `count[x]` in one O(n) pass, each query is O(1), so the total becomes O(n + q). Hashing = *pre-store*, then *fetch*.

**2. Array hashing (direct addressing)**
When keys are small non-negative integers (say `≤ 10^6`), use the value itself as the index of a counting array.

```cpp
int hashArr[13] = {0};             // values known to be <= 12
for (int x : arr) hashArr[x]++;    // pre-store
cout << hashArr[3];                // fetch: O(1)
```

Limits: a global array can hold roughly 10^7 ints; a local one only about 10^6 (stack size). Negative numbers or huge values cannot be indices.

**3. Character hashing**
For strings, map each character to a slot. Lowercase letters fit in `int freq[26]` with index `c - 'a'`; any ASCII character fits in `freq[256]` indexed by the character code directly.

```cpp
int freq[26] = {0};
for (char c : s) freq[c - 'a']++;
```

**4. Hash maps for everything else**
When keys are huge (`10^12`), negative, or non-integer (strings, pairs), use a map:

- `map<K,V>` (C++) / `TreeMap` (Java): balanced BST, ordered keys, O(log n) per operation, always.
- `unordered_map<K,V>` (C++) / `HashMap` (Java) / `dict` (Python): hash table, O(1) average, O(n) worst case if many keys collide.

```cpp
unordered_map<long long, int> mp;
for (long long x : arr) mp[x]++;
cout << mp[3];
```

**5. How a hash table works: the division method**
A hash function turns a key into a slot index, typically `slot = key % tableSize`. Keys 3, 13 and 23 all land in slot 3 when the table has size 10 — a *collision*.

Collisions are handled by:
- **Chaining** — each slot holds a linked list (or vector) of the keys that hashed there; look-up walks the short chain.
- **Open addressing** — probe the next slots (`slot + 1`, `slot + 2`, ...) until a free one is found.

Most operations stay O(1) as long as the table is resized when it gets crowded. The worst case O(n) happens when adversarial inputs hit the same slot; in contests with anti-hash tests, use `map` or a custom hash.

**6. Choosing**
- Small, non-negative, bounded integer keys → counting array.
- Characters → `[26]` or `[256]` array.
- Anything else → `unordered_map` / `HashMap` / `dict`; switch to `map` / `TreeMap` when you need sorted order or guaranteed O(log n).

- **Time:** O(n) to build the table; O(1) average per query with a hash table (O(log n) with an ordered map); O(1) with an array.
- **Space:** O(range of keys) for an array; O(number of distinct keys) for a map.

## Code (Optimal)

Build a frequency table once, then answer queries in O(1).

### C++
```cpp
#include <bits/stdc++.h>
using namespace std;

class Solution {
public:
    vector<int> countQueries(const vector<int>& arr, const vector<int>& queries) {
        unordered_map<int, int> freq;          // pre-store
        for (int x : arr) freq[x]++;

        vector<int> ans;
        ans.reserve(queries.size());
        for (int q : queries) {                // fetch
            auto it = freq.find(q);
            ans.push_back(it == freq.end() ? 0 : it->second);
        }
        return ans;
    }
};
```

### Java
```java
import java.util.*;

class Solution {
    public int[] countQueries(int[] arr, int[] queries) {
        Map<Integer, Integer> freq = new HashMap<>();   // pre-store
        for (int x : arr) freq.merge(x, 1, Integer::sum);

        int[] ans = new int[queries.length];
        for (int i = 0; i < queries.length; i++) {      // fetch
            ans[i] = freq.getOrDefault(queries[i], 0);
        }
        return ans;
    }
}
```

### Python
```python
from collections import Counter

class Solution:
    def countQueries(self, arr: list[int], queries: list[int]) -> list[int]:
        freq = Counter(arr)                    # pre-store
        return [freq.get(q, 0) for q in queries]   # fetch
```

## Key Takeaways
- Hashing trades one O(n) pre-processing pass for O(1) queries afterwards — the core of "pre-store, then fetch".
- Counting arrays are the fastest hash when keys are small non-negative integers; watch the 10^6 (local) / 10^7 (global) size limits.
- `unordered_map` / `HashMap` / `dict` are O(1) on average but O(n) in the worst case because of collisions; ordered maps guarantee O(log n).
- Use `find` / `count` / `getOrDefault` for look-ups so you do not accidentally insert keys.
