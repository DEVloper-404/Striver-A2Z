# Ninja and his Friends

**Difficulty:** Medium  ·  **Topic:** Dynamic Programming [Patterns and Problems] › 2D/3D DP and DP on Grids

## Problem
Given an `r × c` grid of chocolates, **two** ninjas collect them at the same time. Ninja A starts at `(0, 0)` and Ninja B starts at `(0, c-1)`. In each step both move down exactly one row, and each may shift its column by `-1`, `0` or `+1`. Both must end somewhere in the last row. Chocolates in a visited cell are collected, but if both ninjas stand on the **same cell** the chocolates there count only **once**. Return the maximum total collected.

```
Input:  grid = [[2, 3, 1, 2],
                [3, 4, 2, 2],
                [5, 6, 3, 5]]
Output: 21
        A: (0,0)=2 → (1,1)=4 → (2,1)=6   = 12
        B: (0,3)=2 → (1,3)=2 → (2,3)=5   =  9
```

## Approach 1: Solve for each ninja separately (wrong — and instructive)
The tempting shortcut is: run the standard "max path sum" DP once for A, once for B, and add the results. This is wrong, because the two paths interact — if they happen to cross on a cell, the shared chocolates were counted twice. Worse, the *best* path for A alone may force B into a poor route, so the two optimisations cannot be decoupled. The interaction has to be part of the state.

## Approach 2: Recursion on a 3-dimensional state (brute force)

**Key observation.** Both ninjas move down one row per step, so at any moment they are on the **same row**. That is what keeps the state small: instead of tracking two independent `(row, col)` pairs, we need only `(row, colA, colB)`.

Define `f(i, j1, j2)` = maximum chocolates collectable from row `i` down to the last row, given A is at `(i, j1)` and B is at `(i, j2)`.

```
// collect at the current row (once if they share the cell)
gain = (j1 == j2) ? grid[i][j1] : grid[i][j1] + grid[i][j2]

f(r-1, j1, j2) = gain                              // last row, nothing left to move to
f(i, j1, j2)   = gain + max over dj1, dj2 ∈ {-1, 0, +1}
                          of f(i+1, j1+dj1, j2+dj2)     // skipping out-of-range columns

answer = f(0, 0, c-1)
```

Each state tries `3 × 3 = 9` moves — every combination of A's shift with B's shift. Trying all nine is what makes the two paths *jointly* optimal rather than individually optimal, which is exactly what Approach 1 got wrong.

The double-counting rule is handled at the moment of collection: check `j1 == j2` before adding. Nothing else in the recurrence needs to know about it.

Raw recursion branches 9-ways for `r` levels: about `9^r` calls.
- **Time:** O(9^r)
- **Space:** O(r) recursion stack

## Approach 3: Memoization
The state space is `r × c × c`, and each state does 9 units of work — very manageable. Cache in `dp[i][j1][j2]` with sentinel `-1` (safe when chocolate counts are non-negative; otherwise use a separate `visited` array).
- **Time:** O(r · c² · 9)
- **Space:** O(r · c²) table + O(r) recursion stack

## Approach 4: Tabulation
Fill from the last row upward, mirroring the recursion's dependency direction.

1. **Base row:** for every `j1, j2`, `dp[r-1][j1][j2] = (j1 == j2) ? grid[r-1][j1] : grid[r-1][j1] + grid[r-1][j2]`.
2. **Transition:** for `i` from `r-2` down to `0`, for every `(j1, j2)`, take the max over the nine `(dj1, dj2)` pairs of `dp[i+1][j1+dj1][j2+dj2]` (skipping out-of-range columns, treating them as `-INF`), and add the current row's gain.
3. **Answer:** `dp[0][0][c-1]`.
- **Time:** O(r · c² · 9)
- **Space:** O(r · c²)

## Approach 5: Two rolling layers (Optimal)

Row `i` reads only row `i+1`, so keep two `c × c` matrices, `front` (row `i+1`) and `cur` (row `i`), swapping after each row.

**Dry run on the example** (`r = 3`, `c = 4`; row 2 = `[5,6,3,5]`, row 1 = `[3,4,2,2]`, row 0 = `[2,3,1,2]`).

*Base — `front[j1][j2]` for the last row* (rows are `j1`, columns are `j2`):
```
        j2=0  j2=1  j2=2  j2=3
j1=0  :   5    11     8    10
j1=1  :  11     6     9    11
j1=2  :   8     9     3     8
j1=3  :  10    11     8     5
```
(The diagonal is a single value because the ninjas share the cell.)

*Row 1.* We only need the four states reachable from the start, `(j1, j2) ∈ {0,1} × {2,3}`:
- `cur[1][3] = (4 + 2) + max over j1' ∈ {0,1,2}, j2' ∈ {2,3}` of `front` = `6 + 11 = 17`
- `cur[1][2] = (4 + 2) + max over j1' ∈ {0,1,2}, j2' ∈ {1,2,3}` = `6 + 11 = 17`
- `cur[0][3] = (3 + 2) + max over j1' ∈ {0,1}, j2' ∈ {2,3}` = `5 + 11 = 16`
- `cur[0][2] = (3 + 2) + max over j1' ∈ {0,1}, j2' ∈ {1,2,3}` = `5 + 11 = 16`

*Row 0.* `dp[0][0][3] = (2 + 2) + max(16, 16, 17, 17) = 4 + 17 = 21`. ✔

The `17` that won corresponds to A at `(1,1)` and B at `(1,3)`, whose best continuation `11` is A at `(2,1)`=6 and B at `(2,3)`=5 — exactly the paths quoted in the problem statement.
- **Time:** O(r · c² · 9)
- **Space:** O(c²)

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int maxChocolates(int r, int c, vector<vector<int>>& grid) {
        const int NEG = -1e8;
        // front[j1][j2] = best from row i+1 downwards
        vector<vector<int>> front(c, vector<int>(c, 0));
        for (int j1 = 0; j1 < c; j1++)
            for (int j2 = 0; j2 < c; j2++)
                front[j1][j2] = (j1 == j2) ? grid[r - 1][j1]
                                           : grid[r - 1][j1] + grid[r - 1][j2];

        for (int i = r - 2; i >= 0; i--) {
            vector<vector<int>> cur(c, vector<int>(c, 0));
            for (int j1 = 0; j1 < c; j1++) {
                for (int j2 = 0; j2 < c; j2++) {
                    int best = NEG;
                    for (int d1 = -1; d1 <= 1; d1++) {
                        for (int d2 = -1; d2 <= 1; d2++) {
                            int n1 = j1 + d1, n2 = j2 + d2;
                            if (n1 < 0 || n1 >= c || n2 < 0 || n2 >= c) continue;
                            best = max(best, front[n1][n2]);
                        }
                    }
                    int gain = (j1 == j2) ? grid[i][j1] : grid[i][j1] + grid[i][j2];
                    cur[j1][j2] = gain + best;
                }
            }
            front = cur;
        }
        return front[0][c - 1];
    }
};
```

### Python
```python
from typing import List


class Solution:
    def maxChocolates(self, r: int, c: int, grid: List[List[int]]) -> int:
        NEG = float("-inf")
        # front[j1][j2] = best from row i+1 downwards
        front = [[0] * c for _ in range(c)]
        for j1 in range(c):
            for j2 in range(c):
                front[j1][j2] = (grid[r - 1][j1] if j1 == j2
                                 else grid[r - 1][j1] + grid[r - 1][j2])

        for i in range(r - 2, -1, -1):
            cur = [[0] * c for _ in range(c)]
            for j1 in range(c):
                for j2 in range(c):
                    best = NEG
                    for d1 in (-1, 0, 1):
                        for d2 in (-1, 0, 1):
                            n1, n2 = j1 + d1, j2 + d2
                            if 0 <= n1 < c and 0 <= n2 < c:
                                best = max(best, front[n1][n2])
                    gain = grid[i][j1] if j1 == j2 else grid[i][j1] + grid[i][j2]
                    cur[j1][j2] = gain + best
            front = cur

        return front[0][c - 1]
```

## Key Takeaways
- Two agents that move in lock-step share a row, so the state is `(row, colA, colB)` — 3D, not two separate 2D problems.
- Optimising each path independently is wrong: the paths interact through the shared-cell rule and through each other's reachable columns. Enumerate all `3 × 3` joint moves.
- Handle double counting at collection time with a single `j1 == j2` check; the rest of the recurrence stays oblivious to it.
- Complexity is states × transitions = `O(r·c²·9)`, and the layer-by-layer dependency collapses space to `O(c²)`.
- The same template solves LeetCode's *Cherry Pickup II*, and (with a coordinate trick that turns "go and come back" into "two simultaneous downward paths") *Cherry Pickup I*.
