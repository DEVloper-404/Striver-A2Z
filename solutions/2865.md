# Introduction to Trees

**Difficulty:** Easy  ·  **Topic:** Binary Trees [Traversals, Medium and Hard Problems] › Traversals

## Problem
This is a theory item. It covers what a tree is, the vocabulary used for the rest of the section (root, parent, child, leaf, depth, height, subtree), what makes a tree "binary", and the common special shapes of binary trees (full, complete, perfect, balanced, degenerate). There is no input/output to compute; the goal is to be able to read any later tree problem and know exactly what the words mean.

Example of a small binary tree that the terms below refer to:

```
        1          <- root (depth 0)
      /   \
     2     3       <- depth 1
    / \     \
   4   5     6     <- leaves 4, 5, 6 (depth 2)
```

## Approach
### What is a tree?
A tree is a connected structure of `n` nodes joined by exactly `n - 1` edges with no cycles. One node is designated the **root**; every other node has exactly one **parent** and can have any number of **children**. Unlike an array or linked list, a tree branches, so it is a hierarchical rather than linear structure.

Vocabulary you will use constantly:
- **Leaf:** a node with no children (4, 5, 6 above).
- **Internal node:** any node that has at least one child.
- **Subtree:** a node together with everything below it. Node 2 with 4 and 5 forms the left subtree of 1.
- **Depth of a node:** number of edges from the root down to it. Root has depth 0.
- **Height of a node:** number of edges on the longest path from that node down to a leaf. A leaf has height 0; the tree above has height 2. (Some sources count nodes instead of edges, giving 3. Always check which convention a problem uses.)
- **Ancestor / descendant:** nodes above / below on the path to the root.

### Binary tree
A **binary tree** restricts each node to at most two children, labelled **left** and **right**. The distinction matters: a node with only a right child is a different tree from one with only a left child. Almost every problem in this step is about binary trees, and the node type is the standard:

```cpp
struct TreeNode {
    int val;
    TreeNode* left;
    TreeNode* right;
    TreeNode(int v) : val(v), left(nullptr), right(nullptr) {}
};
```

### Kinds of binary trees
- **Full (strict):** every node has 0 or 2 children, never exactly 1.
- **Complete:** all levels are filled except possibly the last, and the last level is filled from left to right with no gaps. This is the shape a heap uses, which lets it live in an array.
- **Perfect:** every internal node has 2 children and all leaves are on the same level. A perfect tree of height `h` has exactly `2^(h+1) - 1` nodes.
- **Balanced:** for every node the heights of its left and right subtrees differ by at most 1. Balanced trees keep height at O(log n), which is what makes BST operations fast.
- **Degenerate (skewed):** every node has exactly one child, so the tree is effectively a linked list of height `n - 1`. This is the worst case for recursion depth.

### Why it matters for complexity
Most tree algorithms visit every node once, so they are O(n) time. Recursive solutions also use O(h) stack space where `h` is the height: O(log n) for a balanced tree but O(n) for a skewed one. When a problem says "the tree can have up to 10^5 nodes" you should immediately think about whether a skewed input could blow the recursion stack and whether an iterative version is needed.

- **Time:** O(n) for a traversal that touches every node
- **Space:** O(h) recursion stack, where h is the tree height

## Code (Optimal)

### C++
```cpp
#include <algorithm>
using namespace std;

// Standard definition of TreeNode used across the section.
struct TreeNode {
    int val;
    TreeNode* left;
    TreeNode* right;
    TreeNode(int v) : val(v), left(nullptr), right(nullptr) {}
};

// Height in edges; an empty tree is -1 so a single node has height 0.
int height(TreeNode* root) {
    if (!root) return -1;
    return 1 + max(height(root->left), height(root->right));
}

int countNodes(TreeNode* root) {
    if (!root) return 0;
    return 1 + countNodes(root->left) + countNodes(root->right);
}
```

### Java
```java
class TreeNode {
    int val;
    TreeNode left, right;
    TreeNode(int v) { val = v; }
}

class TreeBasics {
    // Height in edges; empty tree is -1 so a single node has height 0.
    static int height(TreeNode root) {
        if (root == null) return -1;
        return 1 + Math.max(height(root.left), height(root.right));
    }

    static int countNodes(TreeNode root) {
        if (root == null) return 0;
        return 1 + countNodes(root.left) + countNodes(root.right);
    }
}
```

### Python
```python
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right


def height(root):
    # Height in edges; empty tree is -1 so a single node has height 0.
    if root is None:
        return -1
    return 1 + max(height(root.left), height(root.right))


def count_nodes(root):
    if root is None:
        return 0
    return 1 + count_nodes(root.left) + count_nodes(root.right)
```

## Key Takeaways
- A tree with `n` nodes always has `n - 1` edges and no cycles; a binary tree caps each node at two ordered children (left, right).
- Depth is measured from the root down, height from a node down to its deepest leaf. Confirm whether a problem counts edges or nodes before answering.
- Complete trees can be stored in arrays (children of index `i` at `2i+1` and `2i+2`); balanced trees keep height O(log n); skewed trees degrade to O(n) height.
- Recursion on a tree uses stack proportional to the height, so a skewed tree of 10^5 nodes can overflow a recursive solution.
