# Longest String Chain

**Difficulty:** Medium  ·  **Topic:** Dynamic Programming [Patterns and Problems] › DP on LIS

## Problem
You are given a list of `words`. Word `a` is a **predecessor** of word `b` if you can insert exactly one character anywhere in `a` (without reordering anything else) to get `b`. A **word chain** is a sequence `w1, w2, ..., wk` where each word is a predecessor of the next. Return the length of the longest possible chain; a single word is a chain of length 1.

```
Input:  words = ["a", "b", "ba", "bca", "bda", "bdca"]
Output: 4      (the chain "a" → "ba" → "bda" → "bdca")
```

## Approach 1: Sort by length, then LIS-style pairwise DP
Insertion always increases the length by exactly one, so a chain visits words of strictly increasing length — in fact of *consecutive* lengths. That immediately suggests: sort the words by length, and the problem becomes Longest Increasing Subsequence where "`arr[j] < arr[i]`" is replaced by "`words[j]` is a predecessor of `words[i]`".

`dp[i]` = the longest chain **ending at** `words[i]`. For each `i`, scan every `j < i` and, if `isPredecessor(words[j], words[i])`, take `dp[i] = max(dp[i], dp[j] + 1)`.

The predecessor test is a two-pointer walk: advance through both strings; when characters match, advance both; when they differ, advance only the pointer in the longer word and mark that the single allowed insertion has been used. If a second mismatch appears, return false. (A length difference of exactly 1 is also required.)

- **Time:** O(n² · L) where `L` is the maximum word length
- **Space:** O(n)

## Approach 2: Hash map over generated predecessors (Optimal)
The pairwise scan is wasteful. Instead of asking "which earlier word is my predecessor?", flip it around: **generate** all possible predecessors of a word and look them up.

A word of length `L` has exactly `L` predecessors — delete one character at each position. Each deleted-character string is a candidate; if it exists in our DP map, the current word extends that chain.

The algorithm:
1. Sort `words` by increasing length. This guarantees that when we process a word, every possible predecessor (which is strictly shorter) has already been processed and recorded.
2. Keep a hash map `best[word]` = longest chain ending at that word.
3. For each word `w`, start with `cur = 1`, then for every index `i` form `prev = w` with character `i` removed and, if `best` contains `prev`, set `cur = max(cur, best[prev] + 1)`.
4. Store `best[w] = cur` and track the global maximum.

The correctness rests on the sorting step: it turns "look backwards in the chain" into "look up in a map that is already complete for all shorter lengths". Duplicated words are harmless — the map just gets overwritten with the same value.

**Dry run** on `["a", "b", "ba", "bca", "bda", "bdca"]` (already length-sorted):

| word   | generated predecessors      | found in map      | best[word] |
|--------|-----------------------------|-------------------|------------|
| "a"    | ""                          | —                 | 1          |
| "b"    | ""                          | —                 | 1          |
| "ba"   | "a", "b"                    | both → 1          | 2          |
| "bca"  | "ca", "ba", "bc"            | "ba" → 2          | 3          |
| "bda"  | "da", "ba", "bd"            | "ba" → 2          | 3          |
| "bdca" | "dca", "bca", "bda", "bdc"  | "bca"→3, "bda"→3  | **4**      |

Answer: `4`.

Building each predecessor string costs O(L), and there are `L` of them, so the per-word cost is O(L²) — with `L ≤ 16` in the usual constraints, that is tiny compared to O(n · L) per word in Approach 1.

- **Time:** O(n log n + n · L²)
- **Space:** O(n · L) for the map

## Approach 3: Reconstructing the chain
If you need to print the chain rather than just its length, store a second map `from[word]` = the predecessor string that gave the best value, then walk it backwards from the word holding the maximum and reverse. This is the same `parent`-pointer technique used for printing an LIS.

- **Time:** O(n log n + n · L²)
- **Space:** O(n · L)

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <string>
#include <unordered_map>
#include <algorithm>
using namespace std;

class Solution {
public:
    int longestStrChain(vector<string>& words) {
        sort(words.begin(), words.end(),
             [](const string& a, const string& b) { return a.size() < b.size(); });

        unordered_map<string, int> best;   // word -> longest chain ending there
        int answer = 0;

        for (const string& w : words) {
            int cur = 1;
            for (int i = 0; i < (int)w.size(); i++) {
                string prev = w.substr(0, i) + w.substr(i + 1);   // delete char i
                auto it = best.find(prev);
                if (it != best.end()) cur = max(cur, it->second + 1);
            }
            best[w] = max(best[w], cur);
            answer = max(answer, cur);
        }
        return answer;
    }
};
```

### Java
```java
import java.util.Arrays;
import java.util.HashMap;
import java.util.Map;

class Solution {
    public int longestStrChain(String[] words) {
        Arrays.sort(words, (a, b) -> a.length() - b.length());

        Map<String, Integer> best = new HashMap<>();
        int answer = 0;

        for (String w : words) {
            int cur = 1;
            for (int i = 0; i < w.length(); i++) {
                String prev = w.substring(0, i) + w.substring(i + 1);
                Integer got = best.get(prev);
                if (got != null) cur = Math.max(cur, got + 1);
            }
            best.merge(w, cur, Math::max);
            answer = Math.max(answer, cur);
        }
        return answer;
    }
}
```

### Python
```python
from typing import List


class Solution:
    def longestStrChain(self, words: List[str]) -> int:
        words.sort(key=len)
        best = {}
        answer = 0
        for w in words:
            cur = 1
            for i in range(len(w)):
                prev = w[:i] + w[i + 1:]
                if prev in best:
                    cur = max(cur, best[prev] + 1)
            best[w] = max(best.get(w, 0), cur)
            answer = max(answer, cur)
        return answer
```

## Key Takeaways
- Insertion increases length by exactly 1, so a chain has strictly increasing lengths — sorting by length turns the problem into LIS with a custom "predecessor" relation.
- Generating the `L` predecessors of a word and hashing them beats scanning all earlier words; it replaces an O(n) inner loop with an O(L) one.
- The sort is what makes the map lookup valid: shorter words must already be recorded before a longer word queries them.
- Words in the input need not be related at all, so every word starts with a chain length of 1; the answer is at least 1 for any non-empty list.
