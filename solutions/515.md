# Number of operations to make network connected

**Difficulty:** Hard  ·  **Topic:** Graphs [Concepts & Problems] › MinimumSpanningTree/Disjoint Set and Problems

## Problem
There are `n` computers numbered `0 … n-1` and a list of ethernet cables `connections[i] = [a, b]` joining two of them. In one operation you may unplug a cable from anywhere and plug it in between any two computers. Return the minimum number of operations needed to make **all** computers connected, or `-1` if it is impossible.

```
Input:  n = 4, connections = [[0,1],[0,2],[1,2]]
Output: 1
```
Computers `0, 1, 2` are already connected by three cables, but only two are needed — one is redundant. Move that spare cable to link computer `3`. One operation.

## Approach 1: Count components with DFS/BFS
Build an adjacency list, run a traversal from each unvisited node to count connected components, and separately count the cables. If `cables < n - 1` return `-1`; otherwise return `components - 1`. This works and is `O(n + E)`, and is a perfectly good answer — the reasoning below applies identically.
- **Time:** O(n + E)
- **Space:** O(n + E) for the adjacency list and visited array

## Approach 2: Disjoint Set — count redundant cables and components (optimal)

**Observation 1 — the feasibility test.** Connecting `n` computers into one network needs at least `n - 1` cables, because a connected graph on `n` vertices has at least `n - 1` edges (a spanning tree). Moving cables never creates new ones, so if `connections.size() < n - 1` the answer is `-1`, full stop. This check comes first.

**Observation 2 — what a "redundant" cable is.** Process the cables one by one with a DSU. When a cable joins two computers that are **already** in the same component, it adds nothing to connectivity — it closes a cycle. That cable is free to be unplugged and reused. Every cable that merges two distinct components is load-bearing and must stay.

**Observation 3 — how many moves are needed.** Suppose after processing all cables there are `c` connected components. Joining `c` components into one takes exactly `c - 1` new links (each link reduces the component count by exactly one, and one link can never reduce it by more). So the answer is `c - 1` — provided we have at least `c - 1` spare cables to move.

**Observation 4 — why we never run out of spares.** If we have `E ≥ n - 1` cables and end up with `c` components, the load-bearing cables number exactly `n - c` (each merge consumes one component). So spares `= E - (n - c) ≥ (n - 1) - n + c = c - 1`. The initial `E ≥ n - 1` check therefore *guarantees* there are enough redundant cables, and we do not need to count them separately. That is the neat part: **the answer is simply `components - 1` once feasibility passes.**

**The algorithm.**
1. If `connections.size() < n - 1`, return `-1`.
2. Create a DSU over `n` nodes.
3. For each `[a, b]`, `union(a, b)`.
4. Count components as the number of `i` with `find(i) == i`, or maintain a counter that decrements on each successful union starting from `n`.
5. Return `components - 1`.

**Short dry run** on the example. `n = 4`, three cables, and `3 ≥ 4 - 1`, so it is feasible. Start with 4 components.
- `[0,1]`: different leaders → merge, components `3`.
- `[0,2]`: `0` and `2` differ → merge, components `2`.
- `[1,2]`: `find(1) == find(2)` already → redundant, no change, components stay `2`.
Answer `2 - 1 = 1`. ✓

**Edge cases.** `n = 1` needs `0` operations (already one component, and `0 ≥ 0` cables required). A fully connected graph gives `components = 1` and answer `0`. Self-loops and duplicate cables are handled automatically — they simply register as redundant.
- **Time:** O(n + E · α(n)) ≈ O(n + E)
- **Space:** O(n) for the DSU arrays

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <algorithm>
#include <numeric>
using namespace std;

class Solution {
    vector<int> parent, sz;
    int find(int x) { return parent[x] == x ? x : parent[x] = find(parent[x]); }
    bool unite(int a, int b) {
        a = find(a); b = find(b);
        if (a == b) return false;              // redundant cable
        if (sz[a] < sz[b]) swap(a, b);
        parent[b] = a;
        sz[a] += sz[b];
        return true;
    }
public:
    int makeConnected(int n, vector<vector<int>>& connections) {
        if ((int)connections.size() < n - 1) return -1;   // not enough cables

        parent.resize(n);
        sz.assign(n, 1);
        iota(parent.begin(), parent.end(), 0);

        int components = n;
        for (auto& c : connections)
            if (unite(c[0], c[1])) components--;

        return components - 1;
    }
};
```

### Java
```java
class Solution {
    private int[] parent, size;

    private int find(int x) {
        if (parent[x] != x) parent[x] = find(parent[x]);
        return parent[x];
    }

    private boolean unite(int a, int b) {
        a = find(a); b = find(b);
        if (a == b) return false;
        if (size[a] < size[b]) { int t = a; a = b; b = t; }
        parent[b] = a;
        size[a] += size[b];
        return true;
    }

    public int makeConnected(int n, int[][] connections) {
        if (connections.length < n - 1) return -1;

        parent = new int[n];
        size = new int[n];
        for (int i = 0; i < n; i++) { parent[i] = i; size[i] = 1; }

        int components = n;
        for (int[] c : connections) {
            if (unite(c[0], c[1])) components--;
        }
        return components - 1;
    }
}
```

### Python
```python
from typing import List

class Solution:
    def makeConnected(self, n: int, connections: List[List[int]]) -> int:
        if len(connections) < n - 1:
            return -1                       # impossible: too few cables

        parent = list(range(n))
        size = [1] * n

        def find(x: int) -> int:
            while parent[x] != x:
                parent[x] = parent[parent[x]]
                x = parent[x]
            return x

        components = n
        for a, b in connections:
            ra, rb = find(a), find(b)
            if ra == rb:
                continue                    # redundant cable, reusable
            if size[ra] < size[rb]:
                ra, rb = rb, ra
            parent[rb] = ra
            size[ra] += size[rb]
            components -= 1

        return components - 1
```

## Key Takeaways
- Feasibility is decided by a counting argument alone: `n` machines need at least `n - 1` cables, so fewer means `-1`.
- Once feasible, the answer is just `components - 1`; each move joins exactly two components.
- You do not need to count redundant cables — `E ≥ n - 1` mathematically guarantees enough spares exist.
- DSU gives components in near-linear time and handles duplicates and self-loops for free; a DFS component count works equally well.
