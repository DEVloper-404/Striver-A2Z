# Search in rotated sorted array-I

**Difficulty:** Medium  ·  **Topic:** Binary Search [1D, 2D Arrays, Search Space] › BS on 1D Arrays

## Problem
An array of distinct integers was sorted in ascending order and then rotated at some unknown pivot, so it looks like `[4, 5, 6, 7, 0, 1, 2]`. Given such an array `nums` and a `target`, return the index of `target`, or `-1` if it is not present. Aim for O(log n).

Input: `nums = [4, 5, 6, 7, 0, 1, 2], target = 0`
Output: `4`

Input: `nums = [4, 5, 6, 7, 0, 1, 2], target = 3`
Output: `-1`

## Approach 1: Linear Scan
Ignore the structure and scan every element. Always correct, but it does not use the partial ordering.

- **Time:** O(n)
- **Space:** O(1)

## Approach 2: Binary Search on the Sorted Half (Optimal)
Whenever you split a rotated sorted array at `mid`, at least one of the two halves `[low..mid]` or `[mid..high]` is fully sorted. You can tell which by comparing endpoints, and a sorted half lets you check with two comparisons whether the target lies inside it.

1. If `nums[mid] == target`, done.
2. If `nums[low] <= nums[mid]`, the left half is sorted.
   - If `nums[low] <= target < nums[mid]`, the target is inside the left half: `high = mid - 1`.
   - Otherwise it must be in the right half: `low = mid + 1`.
3. Else the right half is sorted.
   - If `nums[mid] < target <= nums[high]`, search right: `low = mid + 1`.
   - Otherwise search left: `high = mid - 1`.

Each iteration discards half the range, exactly like normal binary search, just with a slightly smarter decision rule.

- **Time:** O(log n)
- **Space:** O(1)

## Code (Optimal)

### C++
```cpp
#include <vector>
using namespace std;

class Solution {
public:
    int search(vector<int>& nums, int target) {
        int low = 0, high = (int)nums.size() - 1;
        while (low <= high) {
            int mid = low + (high - low) / 2;
            if (nums[mid] == target) return mid;

            if (nums[low] <= nums[mid]) {           // left half sorted
                if (nums[low] <= target && target < nums[mid]) high = mid - 1;
                else low = mid + 1;
            } else {                                // right half sorted
                if (nums[mid] < target && target <= nums[high]) low = mid + 1;
                else high = mid - 1;
            }
        }
        return -1;
    }
};
```

### Python
```python
from typing import List

class Solution:
    def search(self, nums: List[int], target: int) -> int:
        low, high = 0, len(nums) - 1
        while low <= high:
            mid = (low + high) // 2
            if nums[mid] == target:
                return mid

            if nums[low] <= nums[mid]:  # left half sorted
                if nums[low] <= target < nums[mid]:
                    high = mid - 1
                else:
                    low = mid + 1
            else:                       # right half sorted
                if nums[mid] < target <= nums[high]:
                    low = mid + 1
                else:
                    high = mid - 1
        return -1
```

## Key Takeaways
- Key observation: one half of any rotated sorted range is itself sorted; find it, and use its endpoints to decide where the target can be.
- The comparison `nums[low] <= nums[mid]` (with `<=`) is required so that a single-element half counts as sorted.
- Distinct values are essential here; with duplicates the endpoint comparison can be ambiguous (see the follow-up problem).
- An unrotated array is just the special case where the left half is always sorted, so the same code works.
