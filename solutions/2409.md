# Sort K sorted array

**Difficulty:** Easy  ·  **Topic:** Heaps [Learning, Medium, Hard Problems] › Medium Problems

## Problem
You are given an array of `n` integers that is "k-sorted": every element is at most `k` positions away from where it belongs in the fully sorted array. Sort the array completely, ideally faster than a general-purpose sort would.

```
Input:  arr = [6, 5, 3, 2, 8, 10, 9], k = 3
Output: [2, 3, 5, 6, 8, 9, 10]
```
Here 2 is at index 3 but belongs at index 0, a shift of exactly 3, so the promise holds.

## Approach 1: Ordinary sort
Ignore the hint and run a standard sort. Correct and often fine in practice, but it does not exploit the near-sortedness.
- **Time:** O(n log n)
- **Space:** O(1) extra

## Approach 2: Insertion sort
Because each element is within `k` of its final position, insertion sort shifts each element at most `k` times. This is good when `k` is tiny but degrades to quadratic when `k` approaches `n`.
- **Time:** O(n * k)
- **Space:** O(1)

## Approach 3: Min-heap of size k + 1 (optimal)
Key observation: the smallest element of the whole array must be in the first `k + 1` positions (it cannot be more than `k` slots away from index 0). Once it is placed, the next smallest must be among the next `k + 1` unplaced elements, and so on.

1. Push the first `k + 1` elements into a min-heap.
2. For every remaining element, pop the heap minimum into the next output slot, then push the new element.
3. When the input is exhausted, drain the heap in order.

Each element enters and leaves a heap of at most `k + 1` items once.
- **Time:** O(n log k)
- **Space:** O(k)

## Code (Optimal)

### C++
```cpp
#include <bits/stdc++.h>
using namespace std;

class Solution {
public:
    vector<int> sortKSortedArray(vector<int>& arr, int k) {
        int n = arr.size();
        priority_queue<int, vector<int>, greater<int>> minHeap;
        vector<int> result;
        result.reserve(n);

        for (int i = 0; i < n; i++) {
            minHeap.push(arr[i]);
            if ((int)minHeap.size() > k) {
                result.push_back(minHeap.top());
                minHeap.pop();
            }
        }
        while (!minHeap.empty()) {
            result.push_back(minHeap.top());
            minHeap.pop();
        }
        return result;
    }
};
```

### Java
```java
import java.util.*;

class Solution {
    public int[] sortKSortedArray(int[] arr, int k) {
        int n = arr.length;
        PriorityQueue<Integer> minHeap = new PriorityQueue<>();
        int[] result = new int[n];
        int idx = 0;

        for (int i = 0; i < n; i++) {
            minHeap.offer(arr[i]);
            if (minHeap.size() > k) {
                result[idx++] = minHeap.poll();
            }
        }
        while (!minHeap.isEmpty()) {
            result[idx++] = minHeap.poll();
        }
        return result;
    }
}
```

### Python
```python
import heapq
from typing import List


class Solution:
    def sortKSortedArray(self, arr: List[int], k: int) -> List[int]:
        min_heap = []
        result = []
        for x in arr:
            heapq.heappush(min_heap, x)
            if len(min_heap) > k:
                result.append(heapq.heappop(min_heap))
        while min_heap:
            result.append(heapq.heappop(min_heap))
        return result
```

## Key Takeaways
- A sliding min-heap of size `k + 1` is enough because the global minimum of the unplaced suffix is always within the next `k + 1` elements.
- The code pops once the heap size exceeds `k`, which is the same as holding `k + 1` elements before emitting; both phrasings are equivalent.
- If `k >= n` the approach degenerates into heap sort and still returns the correct answer, just without the speedup.
- Watch for `k = 0`: the array is already sorted and the loop simply copies it through the heap one element at a time.
