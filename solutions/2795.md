# Grid Unique Paths : DP on Grids (DP8)

**Difficulty:** Medium  ·  **Topic:** Dynamic Programming [Patterns and Problems] › 2D/3D DP and DP on Grids

## Problem
A robot stands at the top-left cell `(0,0)` of an `m × n` grid and wants to reach the bottom-right cell `(m-1, n-1)`. It may move only **right** or **down**, one cell at a time. Count the number of distinct paths.

```
Input:  m = 3, n = 3
Output: 6
        RRDD, RDRD, RDDR, DRRD, DRDR, DDRR
```

## Approach 1: Recursion (brute force)

**Think about the last move.** To stand on `(i, j)` the robot's previous cell was either `(i-1, j)` (it moved down) or `(i, j-1)` (it moved right). These two families of paths are disjoint — they differ in the final move — and together they are all paths. So

```
f(i, j) = f(i-1, j) + f(i, j-1)
f(0, 0) = 1                      // one way to "be" at the start
f(i, j) = 0 if i < 0 or j < 0    // fell off the grid
```

Written recursively from `(m-1, n-1)`, each call spawns two, and the depth is `m+n`, so the count of calls is roughly `2^(m+n)`. Every cell is recomputed many times — the classic overlapping-subproblems signal.
- **Time:** O(2^(m+n))
- **Space:** O(m+n) recursion stack

## Approach 2: Memoization
The state is the pair `(i, j)`, giving `m·n` distinct states with O(1) work each. Cache in `dp[i][j]` (sentinel `-1`) and return early on a hit.
- **Time:** O(m·n)
- **Space:** O(m·n) table + O(m+n) stack

## Approach 3: Tabulation
Fill the table row by row. Every cell in row 0 has exactly one path (keep moving right), and likewise column 0 (keep moving down), so initialise them to 1. For every other cell, `dp[i][j] = dp[i-1][j] + dp[i][j-1]`; both dependencies lie above and to the left, so a top-to-bottom, left-to-right sweep is a valid order. Answer: `dp[m-1][n-1]`.

For `m = n = 3` the table fills as
```
1 1 1
1 2 3
1 3 6
```
which reads off the answer `6`. ✔
- **Time:** O(m·n)
- **Space:** O(m·n)

## Approach 4: One rolling row (Optimal in space among DP forms)
Row `i` needs only row `i-1` and the cell to its left in the current row. Keep a single array `prev` of length `n`, initialised to all 1s (row 0), and for each subsequent row build `cur` with `cur[0] = 1` and `cur[j] = prev[j] + cur[j-1]`, then set `prev = cur`:

```cpp
vector<int> prev(n, 1);
for (int i = 1; i < m; i++) {
    vector<int> cur(n, 1);
    for (int j = 1; j < n; j++) cur[j] = prev[j] + cur[j - 1];
    prev = cur;
}
return prev[n - 1];
```
- **Time:** O(m·n)
- **Space:** O(n)

## Approach 5: Combinatorics (Optimal)

**The counting observation.** Every valid path consists of exactly `m-1` down moves and `n-1` right moves, in some order — no more, no fewer, because the robot must gain `m-1` rows and `n-1` columns and never moves backwards. So a path *is* an arrangement of a string of `m-1` D's and `n-1` R's, and distinct arrangements give distinct paths.

Counting arrangements of a multiset: choose which `m-1` of the `m+n-2` total moves are downs. Hence

```
answer = C(m+n-2, m-1) = (m+n-2)! / ((m-1)! · (n-1)!)
```

Check: `m = n = 3` gives `C(4, 2) = 6`. ✔

**Computing it without overflow.** Do not build factorials — `(m+n-2)!` overflows almost immediately. Instead multiply and divide alternately using the identity

```
C(N, r) = Π (k = 1..r) (N - r + k) / k
```

Each partial product `Π_{i<=k}` is itself a binomial coefficient, hence an exact integer, so the integer division at every step is exact and never loses precision. Choose `r = min(m-1, n-1)` to keep the loop short. Use 64-bit arithmetic for the running product.

**Dry run for `m = 3, n = 3`:** `N = 4`, `r = 2`. `k=1`: `res = 1 * (4-2+1) / 1 = 3`. `k=2`: `res = 3 * (4-2+2) / 2 = 12/2 = 6`. Answer `6`. ✔
- **Time:** O(min(m, n))
- **Space:** O(1)

## Code (Optimal)

### C++
```cpp
class Solution {
public:
    int uniquePaths(int m, int n) {
        int N = m + n - 2;
        int r = min(m - 1, n - 1);          // C(N, r) with the smaller r
        long long res = 1;
        for (int k = 1; k <= r; k++) {
            res = res * (N - r + k) / k;    // exact at every step
        }
        return (int)res;
    }
};
```

### Python
```python
class Solution:
    def uniquePaths(self, m: int, n: int) -> int:
        N = m + n - 2
        r = min(m - 1, n - 1)               # C(N, r) with the smaller r
        res = 1
        for k in range(1, r + 1):
            res = res * (N - r + k) // k    # exact at every step
        return res
```

## Key Takeaways
- Path counting on a grid is the additive recurrence `dp[i][j] = dp[i-1][j] + dp[i][j-1]`, derived by splitting on the last move.
- The first row and first column are all 1s — that is the base case, and forgetting it is the most common bug.
- The DP is `O(m·n)` time and drops to `O(n)` space with a single rolling row.
- Because every path is a fixed multiset of `m-1` downs and `n-1` rights, the answer is the binomial `C(m+n-2, m-1)` — `O(min(m,n))` time, `O(1)` space.
- Compute binomials by alternating multiply/divide, never by materialising factorials, to avoid overflow; the intermediate values stay exact integers.
- The combinatorial shortcut evaporates the moment obstacles appear — then only the DP works (see *Unique Paths II*).
