# Binary Tree Representation in Java

**Difficulty:** Easy  ·  **Topic:** Binary Trees [Traversals, Medium and Hard Problems] › Traversals

## Problem
This is a theory item about how a binary tree actually lives in memory. It covers the linked node representation (a `Node` class with `data`, `left` and `right` references) that virtually every interview problem uses, how to build a small tree by hand, and the alternative array representation used by heaps. The Java version is the focus, but the same structure is shown in C++ and Python.

Example tree that the snippets below construct:

```
      1
     / \
    2   3
   / \
  4   5
```

Input: build the tree above
Output: preorder print `1 2 4 5 3` (proves the links are wired correctly)

## Approach
### Linked representation (the default)
Each node is an object holding a value plus two references to its children. A missing child is `null`. The whole tree is reachable from a single `root` reference, and an empty tree is just `root == null`.

```java
class Node {
    int data;
    Node left, right;

    Node(int data) {
        this.data = data;
        left = right = null;
    }
}
```

Building a tree is nothing more than allocating nodes and assigning the references:

```java
Node root = new Node(1);
root.left = new Node(2);
root.right = new Node(3);
root.left.left = new Node(4);
root.left.right = new Node(5);
```

Java handles memory for you; in C++ you allocate with `new` and are responsible for deleting nodes, and in Python a plain class with three attributes does the same job. LeetCode's `TreeNode` is this exact shape with the field named `val` instead of `data`.

### Array representation (for complete trees)
If the tree is complete (every level full except possibly the last, filled left to right), it can be stored in a flat array with the root at index 0. For a node at index `i`:
- left child is at `2*i + 1`
- right child is at `2*i + 2`
- parent is at `(i - 1) / 2`

The tree above would become `[1, 2, 3, 4, 5]`. This is how binary heaps are implemented. For a sparse or skewed tree this representation wastes a lot of slots (a skewed tree of `n` nodes needs an array of size about `2^n`), which is why the linked representation is the general-purpose choice.

### Why the representation matters
Every traversal problem in this step assumes the linked form: you receive a `root` reference and follow `left` / `right` pointers. Understanding that each node owns its subtree is what makes recursion natural: "solve for `root.left`, solve for `root.right`, combine".

- **Time:** O(n) to build a tree of n nodes (one allocation per node)
- **Space:** O(n) for the nodes themselves

## Code (Optimal)

### C++
```cpp
#include <iostream>
using namespace std;

struct Node {
    int data;
    Node* left;
    Node* right;
    Node(int d) : data(d), left(nullptr), right(nullptr) {}
};

void preorder(Node* node) {
    if (!node) return;
    cout << node->data << ' ';
    preorder(node->left);
    preorder(node->right);
}

int main() {
    Node* root = new Node(1);
    root->left = new Node(2);
    root->right = new Node(3);
    root->left->left = new Node(4);
    root->left->right = new Node(5);

    preorder(root);   // prints: 1 2 4 5 3
    cout << '\n';
    return 0;
}
```

### Java
```java
class Node {
    int data;
    Node left, right;

    Node(int data) {
        this.data = data;
        left = right = null;
    }
}

public class BinaryTree {
    Node root;

    static void preorder(Node node) {
        if (node == null) return;
        System.out.print(node.data + " ");
        preorder(node.left);
        preorder(node.right);
    }

    public static void main(String[] args) {
        BinaryTree tree = new BinaryTree();
        tree.root = new Node(1);
        tree.root.left = new Node(2);
        tree.root.right = new Node(3);
        tree.root.left.left = new Node(4);
        tree.root.left.right = new Node(5);

        preorder(tree.root);   // prints: 1 2 4 5 3
        System.out.println();
    }
}
```

### Python
```python
class Node:
    def __init__(self, data):
        self.data = data
        self.left = None
        self.right = None


def preorder(node):
    if node is None:
        return
    print(node.data, end=" ")
    preorder(node.left)
    preorder(node.right)


if __name__ == "__main__":
    root = Node(1)
    root.left = Node(2)
    root.right = Node(3)
    root.left.left = Node(4)
    root.left.right = Node(5)

    preorder(root)   # prints: 1 2 4 5 3
    print()
```

## Key Takeaways
- The standard representation is a node object with a value and two child references; a `null` child means the subtree is empty, and `root == null` means the whole tree is empty.
- Building a tree by hand is just allocating nodes and wiring `left` / `right`; there is no separate "tree" data structure beyond the root reference.
- Complete trees can be packed into an array with children at `2i+1` and `2i+2`, but that layout wastes space on skewed trees, so linked nodes are the default.
- LeetCode's `TreeNode` is the same class with `val` instead of `data`; get comfortable reading both names.
