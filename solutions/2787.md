# Post-order Traversal of Binary Tree using 1 stack

**Difficulty:** Easy  ·  **Topic:** Binary Trees [Traversals, Medium and Hard Problems] › Traversals

## Problem
Return the postorder traversal (Left, Right, Root) of a binary tree iteratively using only one stack, so that extra space is proportional to the tree's height rather than its size. The difficulty is that when you return to a node on the stack you must know whether you came back from its left subtree (go process the right one) or from its right subtree (emit the node).

Input: `root = [1, 2, 3, 4, 5, null, 6]`
```
      1
     / \
    2   3
   / \   \
  4   5   6
```
Output: `[4, 5, 2, 6, 3, 1]`

## Approach 1: Two stacks
Run a Root, Right, Left preorder with stack 1, pushing each popped node onto stack 2, then pop stack 2 to reverse the order. Simple, but the second stack grows to hold all n nodes.
- **Time:** O(n)
- **Space:** O(n)

## Approach 2: One stack with a "last visited" pointer (optimal)
Keep a `curr` pointer, a stack, and a `prev` pointer that remembers the node most recently emitted.

1. While `curr` is non-null, push it and move left (descend the left spine, like iterative inorder).
2. When `curr` is null, peek at the top node `t`.
   - If `t` has a right child and that child is not `prev`, the right subtree has not been done yet: set `curr = t.right` and continue with step 1.
   - Otherwise both children are finished (or absent): record `t`, pop it, and set `prev = t`.
3. Repeat while `curr` is non-null or the stack is non-empty.

The `prev` check is what distinguishes "arriving from the left" from "arriving from the right". If we just finished `t.right`, then `prev == t.right`, so we must not go right again. Each node is pushed once and popped once, and the stack never holds more than a root-to-node path.
- **Time:** O(n)
- **Space:** O(h)

## Approach 3: One stack without `prev` (alternative)
Another way is to move a node to the stack while going left; when stuck, peek at the top's right child. If it is null, pop and emit, and keep popping while the just-emitted node is the right child of the new top. Otherwise move into the right child. It is the same idea expressed as a nested loop; the `prev` version above is easier to reason about.
- **Time:** O(n)
- **Space:** O(h)

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <stack>
using namespace std;

// struct TreeNode { int val; TreeNode *left; TreeNode *right; ... } — standard definition

class Solution {
public:
    vector<int> postorderTraversal(TreeNode* root) {
        vector<int> res;
        stack<TreeNode*> st;
        TreeNode* curr = root;
        TreeNode* prev = nullptr;
        while (curr || !st.empty()) {
            if (curr) {
                st.push(curr);
                curr = curr->left;                   // descend left spine
            } else {
                TreeNode* top = st.top();
                if (top->right && top->right != prev) {
                    curr = top->right;               // right subtree not done yet
                } else {
                    res.push_back(top->val);         // children done, emit
                    prev = top;
                    st.pop();
                }
            }
        }
        return res;
    }
};
```

### Java
```java
import java.util.*;

// class TreeNode { int val; TreeNode left, right; ... } — standard definition

class Solution {
    public List<Integer> postorderTraversal(TreeNode root) {
        List<Integer> res = new ArrayList<>();
        Deque<TreeNode> st = new ArrayDeque<>();
        TreeNode curr = root, prev = null;
        while (curr != null || !st.isEmpty()) {
            if (curr != null) {
                st.push(curr);
                curr = curr.left;                    // descend left spine
            } else {
                TreeNode top = st.peek();
                if (top.right != null && top.right != prev) {
                    curr = top.right;                // right subtree not done yet
                } else {
                    res.add(top.val);                // children done, emit
                    prev = top;
                    st.pop();
                }
            }
        }
        return res;
    }
}
```

### Python
```python
# class TreeNode: val, left, right — standard definition

class Solution:
    def postorderTraversal(self, root):
        res = []
        stack = []
        curr, prev = root, None
        while curr or stack:
            if curr:
                stack.append(curr)
                curr = curr.left                     # descend left spine
            else:
                top = stack[-1]
                if top.right and top.right is not prev:
                    curr = top.right                 # right subtree not done yet
                else:
                    res.append(top.val)              # children done, emit
                    prev = stack.pop()
        return res
```

## Key Takeaways
- Postorder needs to know whether you are returning from the left or right child; the `prev` (last emitted) pointer answers that in O(1).
- Compare `top.right != prev` before descending right, otherwise the right subtree is entered twice and the loop never ends.
- The stack holds only the current root-to-node path, so space is O(h), which beats the two-stack O(n).
- Use pointer identity (`is not` in Python, `!=` on references in Java/C++), not value comparison, since duplicate values are allowed.
