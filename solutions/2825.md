# Prim's Algorithm

**Difficulty:** Hard  ·  **Topic:** Graphs [Concepts & Problems] › MinimumSpanningTree/Disjoint Set and Problems

## Problem
Given a connected, undirected, weighted graph with `V` vertices given as an adjacency list (`adj[u]` holds pairs `{v, w}`), build a **minimum spanning tree**: a set of `V - 1` edges that connects every vertex with the smallest possible total weight. Return the total weight (and, if asked, the list of chosen edges).

```
Input:  V = 5
        edges: (0,1,2) (0,2,1) (1,2,1) (2,3,2) (1,4,2) (3,4,1)
Output: 5
```
One MST is `{0-2 (1), 1-2 (1), 3-4 (1), 1-4 (2)}`, total `5`.

## Approach 1: Try every subset of edges
Enumerate all subsets of `E` edges, keep those of size `V - 1` that connect all vertices, and take the cheapest. Correct but hopeless: `2^E` subsets.
- **Time:** O(2^E · V)
- **Space:** O(E)

## Approach 2: Prim's algorithm with a min-heap (optimal)

**The key observation — the cut property.** Take any split of the vertices into "already in my tree" (`S`) and "not yet" (`V∖S`). The cheapest edge crossing that split can always be part of some MST. So we never need to look at the whole graph at once: we can grow one tree, and at each step just pick the cheapest edge leaving it.

**Why this is safe (sketch).** Suppose an MST `T` avoids the cheapest crossing edge `e`. Adding `e` to `T` creates one cycle, which must cross the cut again through some other edge `f`. Since `e` is the cheapest crosser, `w(e) ≤ w(f)`, so deleting `f` and keeping `e` gives a spanning tree of no greater weight. Hence a greedy pick is never a mistake.

**Turning that into an algorithm.** We need "the cheapest edge leaving the current tree" efficiently, and a min-heap gives it to us. Each heap entry is `{weight, node, parent}`, meaning "we could attach `node` to the tree via `parent` for cost `weight`".

1. Push `{0, 0, -1}` — start anywhere; the choice of start vertex does not affect the MST weight.
2. Pop the smallest entry `{w, u, p}`. If `u` is already `visited`, this entry is stale — a cheaper way into `u` was already used — so discard it and continue.
3. Otherwise mark `u` visited, add `w` to the running total, and record the edge `(p, u)` if `p != -1`.
4. For every neighbour `(v, wt)` of `u` with `v` not visited, push `{wt, v, u}`. We deliberately do **not** try to update an existing heap entry; pushing a duplicate and lazily skipping visited pops is simpler and asymptotically identical.
5. Stop when the heap is empty. If the graph is connected, exactly `V` nodes are marked and exactly `V - 1` edges are recorded.

**Why the "skip if visited" check is the crux.** Without it, a node could be added twice and you would count more than `V - 1` edges. The heap may hold several entries for the same node (one per discovered incoming edge); only the first pop — which by heap order carries the smallest weight — is honoured.

**Short dry run** on the example, starting at `0`.
- Pop `{0, 0, -1}`: visit `0`, total `0`. Push `{2, 1, 0}`, `{1, 2, 0}`.
- Pop `{1, 2, 0}`: visit `2`, total `1`, edge `0-2`. Push `{1, 1, 2}`, `{2, 3, 2}`.
- Pop `{1, 1, 2}`: visit `1`, total `2`, edge `2-1`. Push `{2, 4, 1}`. (The old `{2, 1, 0}` entry is now stale.)
- Pop `{2, 3, 2}` or `{2, 4, 1}` — say `{2, 3, 2}`: visit `3`, total `4`, edge `2-3`. Push `{1, 4, 3}`.
- Pop `{1, 4, 3}`: visit `4`, total `5`, edge `3-4`.
- Remaining pops (`{2, 1, 0}`, `{2, 4, 1}`) hit visited nodes and are skipped. Total `5`, four edges. ✓

**Prim's vs Kruskal's.** Prim's grows a single connected tree and reads the adjacency list directly, which suits dense graphs. Kruskal's sorts all edges and merges components with a DSU. Same weight, different bookkeeping.
- **Time:** O(E log E) — each edge is pushed at most once and every heap operation is logarithmic
- **Space:** O(V + E) for the visited array and the heap

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <queue>
#include <tuple>
using namespace std;

class Solution {
public:
    // adj[u] = list of {v, weight}; returns MST total weight
    int spanningTree(int V, vector<vector<pair<int,int>>>& adj) {
        vector<bool> visited(V, false);
        // {weight, node, parent}
        priority_queue<tuple<int,int,int>, vector<tuple<int,int,int>>,
                       greater<tuple<int,int,int>>> pq;
        pq.push({0, 0, -1});

        int total = 0, taken = 0;
        while (!pq.empty() && taken < V) {
            auto [w, u, p] = pq.top();
            pq.pop();
            if (visited[u]) continue;      // stale entry: cheaper edge already used
            visited[u] = true;
            total += w;
            taken++;
            for (auto& [v, wt] : adj[u])
                if (!visited[v]) pq.push({wt, v, u});
        }
        return total;
    }
};
```

### Java
```java
import java.util.*;

class Solution {
    // adj.get(u) = list of int[]{v, weight}
    public int spanningTree(int V, List<List<int[]>> adj) {
        boolean[] visited = new boolean[V];
        // {weight, node, parent}
        PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> Integer.compare(a[0], b[0]));
        pq.add(new int[]{0, 0, -1});

        int total = 0, taken = 0;
        while (!pq.isEmpty() && taken < V) {
            int[] cur = pq.poll();
            int w = cur[0], u = cur[1];
            if (visited[u]) continue;
            visited[u] = true;
            total += w;
            taken++;
            for (int[] e : adj.get(u)) {
                if (!visited[e[0]]) pq.add(new int[]{e[1], e[0], u});
            }
        }
        return total;
    }
}
```

### Python
```python
import heapq
from typing import List, Tuple

class Solution:
    # adj[u] = list of (v, weight)
    def spanningTree(self, V: int, adj: List[List[Tuple[int, int]]]) -> int:
        visited = [False] * V
        pq = [(0, 0, -1)]                 # (weight, node, parent)
        total = taken = 0

        while pq and taken < V:
            w, u, _p = heapq.heappop(pq)
            if visited[u]:
                continue                  # stale entry
            visited[u] = True
            total += w
            taken += 1
            for v, wt in adj[u]:
                if not visited[v]:
                    heapq.heappush(pq, (wt, v, u))
        return total
```

## Key Takeaways
- Prim's is the cut property executed greedily: repeatedly take the cheapest edge leaving the tree built so far.
- The heap holds *candidate attachments*, so duplicates are normal — the `if (visited[u]) continue` guard is what keeps the result a tree.
- Any starting vertex gives the same MST weight; only the recorded edge set may differ when weights tie.
- Track a `parent` in each heap entry if you need the actual MST edges, not just the total weight; a disconnected graph is detected by ending with fewer than `V` visited nodes.
