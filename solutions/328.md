# Minimum cost to cut the stick

**Difficulty:** Hard  ·  **Topic:** Dynamic Programming [Patterns and Problems] › MCM DP | Partition DP

## Problem
A wooden stick of length `n` is marked at positions given in the array `cuts`. You must perform every cut, in any order you like. The cost of one cut equals the length of the stick piece you are currently cutting, and after a cut that piece splits into two independent pieces. Return the minimum total cost of performing all the cuts.

```
Input:  n = 7, cuts = [1, 3, 4, 5]
Output: 16
```
(One optimal order is 3 → 5 → 1 → 4, costing 7 + 4 + 3 + 2 = 16.)

## Approach 1: Try every order (Brute Force)

The cost of a cut depends on which piece it lands in, which depends on what was cut before — so the order genuinely matters and there is no greedy rule (cutting nearest the middle first is *not* always optimal). A brute force would try all `m!` permutations of the cuts, simulating each. With `m` up to 100 this is hopeless, but it tells us what state we actually need.

- **Time:** O(m! · m)
- **Space:** O(m)

## Approach 2: Partition DP over cut indices (Optimal)

**Observation 1 — a piece is described by its two ends.** Once you fix a piece of stick, the cost of cutting inside it depends only on that piece's length and which cut marks lie inside. It does not matter how the piece came to exist. So a piece is fully described by a contiguous range of cut marks.

**Observation 2 — sort the cuts and add sentinels.** The cuts arrive in arbitrary order, but a piece is a contiguous segment of the stick, so the marks inside it are contiguous *only after sorting*. Sorting is therefore mandatory. Then prepend `0` and append `n` so that every piece's two ends are themselves entries of the array. After this, `c = [0, 1, 3, 4, 5, 7]` for the example.

**Observation 3 — think about the FIRST cut in a piece, not the last.** Whatever order we choose inside a piece spanning `c[i-1] .. c[j+1]`, one cut happens first, and it costs the full length `c[j+1] - c[i-1]`. That first cut at index `k` splits the piece into two independent pieces holding marks `i..k-1` and `k+1..j`, which are then solved on their own.

**The recurrence.** Let `f(i, j)` = minimum cost to make all cuts with indices `i..j`, on the piece spanning from `c[i-1]` to `c[j+1]`.

```
f(i, j) = 0                                                  if i > j (no cuts left)
f(i, j) = (c[j+1] - c[i-1]) + min over k in [i, j] of
              f(i, k-1) + f(k+1, j)
```

The length term is pulled out of the loop because *every* choice of first cut pays it.

**Tabulation order.** `f(i, k-1)` sits in the same row with a smaller column; `f(k+1, j)` sits in a larger row with the same column. So iterate `i` from `m` down to `1` and `j` from `i` up to `m`. The answer is `f(1, m)`.

**Dry run on `n = 7, cuts = [1,3,4,5]`**, with `c = [0,1,3,4,5,7]` and `m = 4`.

Single cuts (`i == j`) — cost is just the enclosing piece's length:
- `f(1,1) = c[2]-c[0] = 3`, `f(2,2) = c[3]-c[1] = 3`, `f(3,3) = c[4]-c[2] = 2`, `f(4,4) = c[5]-c[3] = 3`

Two cuts:
- `f(1,2)`: length `c[3]-c[0] = 4`; both cut choices give `4 + 3 = 7` → **7**
- `f(2,3)`: length `c[4]-c[1] = 4`; `k=2` → `4 + f(3,3) = 6`; `k=3` → `4 + f(2,2) = 7` → **6**
- `f(3,4)`: length `c[5]-c[2] = 4`; `k=3` → `4 + f(4,4) = 7`; `k=4` → `4 + f(3,3) = 6` → **6**

Three cuts:
- `f(1,3)`: length `5`; `k=1` → `5 + f(2,3) = 11`; `k=2` → `5 + f(1,1) + f(3,3) = 5+3+2 = 10`; `k=3` → `5 + f(1,2) = 12` → **10**
- `f(2,4)`: length `6`; every `k` gives `6 + 6 = 12` → **12**

All four cuts:
- `f(1,4)`: length `7`; `k=1` → `7 + f(2,4) = 19`; `k=2` → `7 + f(1,1) + f(3,4) = 7+3+6 = 16`; `k=3` → `7 + f(1,2) + f(4,4) = 7+7+3 = 17`; `k=4` → `7 + f(1,3) = 17` → **16**

The winning `k = 2` corresponds to cutting at position 3 first, exactly the order quoted in the example.

- **Time:** O(m^3), where `m = cuts.size()`
- **Space:** O(m^2)

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <algorithm>
#include <climits>
using namespace std;

class Solution {
public:
    int minCost(int n, vector<int>& cuts) {
        int m = cuts.size();
        vector<int> c;
        c.push_back(0);
        for (int x : cuts) c.push_back(x);
        c.push_back(n);
        sort(c.begin(), c.end());               // c has m + 2 entries

        // dp[i][j] = min cost to make cuts i..j on piece c[i-1] .. c[j+1]
        vector<vector<int>> dp(m + 2, vector<int>(m + 2, 0));

        for (int i = m; i >= 1; i--) {
            for (int j = i; j <= m; j++) {
                int best = INT_MAX;
                for (int k = i; k <= j; k++) {
                    best = min(best, dp[i][k - 1] + dp[k + 1][j]);
                }
                dp[i][j] = (c[j + 1] - c[i - 1]) + best;
            }
        }
        return dp[1][m];
    }
};
```

### Java
```java
import java.util.Arrays;

class Solution {
    public int minCost(int n, int[] cuts) {
        int m = cuts.length;
        int[] c = new int[m + 2];
        c[0] = 0;
        System.arraycopy(cuts, 0, c, 1, m);
        c[m + 1] = n;
        Arrays.sort(c);

        int[][] dp = new int[m + 2][m + 2];

        for (int i = m; i >= 1; i--) {
            for (int j = i; j <= m; j++) {
                int best = Integer.MAX_VALUE;
                for (int k = i; k <= j; k++) {
                    best = Math.min(best, dp[i][k - 1] + dp[k + 1][j]);
                }
                dp[i][j] = (c[j + 1] - c[i - 1]) + best;
            }
        }
        return dp[1][m];
    }
}
```

### Python
```python
from typing import List

class Solution:
    def minCost(self, n: int, cuts: List[int]) -> int:
        m = len(cuts)
        c = sorted([0] + cuts + [n])            # m + 2 entries

        # dp[i][j] = min cost to make cuts i..j on piece c[i-1] .. c[j+1]
        dp = [[0] * (m + 2) for _ in range(m + 2)]

        for i in range(m, 0, -1):
            for j in range(i, m + 1):
                best = min(dp[i][k - 1] + dp[k + 1][j] for k in range(i, j + 1))
                dp[i][j] = (c[j + 1] - c[i - 1]) + best

        return dp[1][m]
```

## Key Takeaways
- Sorting the cuts plus adding the `0` and `n` sentinels is what turns "a piece of stick" into "a contiguous index range" — the whole DP depends on it.
- Here we partition on the **first** cut, not the last: every first choice pays the same piece length, so that term factors out of the minimum.
- `dp[i][k-1]` and `dp[k+1][j]` need the `0` row/column guards, which is why the table is `(m+2) x (m+2)` and zero-initialised.
- Edge case: `cuts` empty → answer 0; duplicate cut positions would add zero-length pieces, so deduplicate if the constraints allow them.
