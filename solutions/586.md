# Infix to Postfix Conversion

**Difficulty:** Medium  ·  **Topic:** Stack and Queues [Learning, Pre-In-Post-fix, Monotonic Stack, Implementation] › Prefix, Infix, PostFix Conversion Problems

## Problem
An **infix** expression writes the operator between its operands (`a + b`) and needs brackets and precedence rules to be unambiguous. A **postfix** (Reverse Polish) expression writes the operator after its operands (`a b +`) and needs neither. Given a valid infix string built from single-character operands, the operators `+ - * / ^`, and round brackets, produce the equivalent postfix string.

```
Input:  a+b*(c^d-e)
Output: abcd^e-*+
```

## Approach 1: Repeatedly bracket the highest-precedence operator
By hand you can fully parenthesise the expression — `(a+(b*((c^d)-e)))` — and then rewrite each bracketed pair `(X op Y)` as `X Y op`, innermost first. This is a correct mental model and worth doing once to see *why* the output is ordered the way it is, but as an algorithm it means rescanning the whole string for the current innermost bracket, which is quadratic and fiddly to code.

- **Time:** O(n^2)
- **Space:** O(n)

## Approach 2: Single pass with an operator stack — shunting yard (Optimal)
The insight is that **operands appear in the same relative order in infix and postfix**; only the operators move. So operands can be emitted the instant they are read, and the only real question is *when* to emit each operator. An operator must be emitted as soon as both of its operands are complete — that is, just before we meet an operator that cannot bind more tightly than it. So we park operators on a stack and pop them at exactly that moment.

Give each operator a precedence: `+ -` → 1, `* /` → 2, `^` → 3 (and `^` is right-associative, the others are left-associative).

Scan the infix string left to right:

1. **Operand** (letter or digit): append it straight to the output. Its position is already final.
2. **`(`**: push it. It acts as a fence — nothing below it may be popped until the matching `)` arrives.
3. **`)`**: pop and output operators until a `(` is on top, then discard the `(`. Everything inside the bracket is now fully resolved.
4. **Operator `op`**: while the stack top is an operator that must be applied *first* — i.e. its precedence is higher than `op`'s, or equal precedence with `op` left-associative — pop it to the output. Then push `op`. For right-associative `^`, equal precedence does **not** pop, so `a^b^c` correctly becomes `abc^^` rather than `ab^c^`.
5. **End of input**: pop everything remaining to the output.

**Why the popping rule is correct.** When we are about to push `op`, the operator on top of the stack is still waiting for its right operand. If the top binds at least as tightly as `op`, then the operand we just emitted belongs to the top operator, not to `op` — so the top is complete and must be output now. If the top binds more loosely, it is still waiting for a bigger sub-expression that `op` will help build, so it stays.

**Dry run on `a+b*(c^d-e)`** (output on the left, stack top on the right):

| Read | Action | Output | Stack |
|---|---|---|---|
| `a` | operand | `a` | |
| `+` | stack empty | `a` | `+` |
| `b` | operand | `ab` | `+` |
| `*` | top `+` (1) < 2, no pop | `ab` | `+ *` |
| `(` | push fence | `ab` | `+ * (` |
| `c` | operand | `abc` | `+ * (` |
| `^` | top is `(`, no pop | `abc` | `+ * ( ^` |
| `d` | operand | `abcd` | `+ * ( ^` |
| `-` | pop `^` (3 > 1); stop at `(` | `abcd^` | `+ * ( -` |
| `e` | operand | `abcd^e` | `+ * ( -` |
| `)` | pop till `(` | `abcd^e-` | `+ *` |
| end | pop all | `abcd^e-*+` | |

- **Time:** O(n) — every character is pushed and popped at most once.
- **Space:** O(n) for the stack in the worst case (`((((a...`).

## Code (Optimal)

### C++
```cpp
#include <string>
#include <stack>
#include <cctype>
using namespace std;

class Solution {
public:
    string infixToPostfix(const string& s) {
        stack<char> st;
        string out;
        for (char c : s) {
            if (isalnum(static_cast<unsigned char>(c))) {
                out.push_back(c);                       // operands keep their order
            } else if (c == '(') {
                st.push(c);
            } else if (c == ')') {
                while (!st.empty() && st.top() != '(') { out.push_back(st.top()); st.pop(); }
                if (!st.empty()) st.pop();              // discard '('
            } else {                                    // an operator
                while (!st.empty() && st.top() != '(' && shouldPop(st.top(), c)) {
                    out.push_back(st.top());
                    st.pop();
                }
                st.push(c);
            }
        }
        while (!st.empty()) { out.push_back(st.top()); st.pop(); }
        return out;
    }

private:
    int prec(char op) {
        if (op == '^') return 3;
        if (op == '*' || op == '/') return 2;
        if (op == '+' || op == '-') return 1;
        return 0;
    }
    // pop the stack top before pushing `cur`?
    bool shouldPop(char top, char cur) {
        if (prec(top) > prec(cur)) return true;
        if (prec(top) < prec(cur)) return false;
        return cur != '^';                              // equal precedence: pop unless right-associative
    }
};
```

### Java
```java
import java.util.*;

class Solution {
    public String infixToPostfix(String s) {
        Deque<Character> st = new ArrayDeque<>();
        StringBuilder out = new StringBuilder();
        for (char c : s.toCharArray()) {
            if (Character.isLetterOrDigit(c)) {
                out.append(c);
            } else if (c == '(') {
                st.push(c);
            } else if (c == ')') {
                while (!st.isEmpty() && st.peek() != '(') out.append(st.pop());
                if (!st.isEmpty()) st.pop();
            } else {
                while (!st.isEmpty() && st.peek() != '(' && shouldPop(st.peek(), c)) {
                    out.append(st.pop());
                }
                st.push(c);
            }
        }
        while (!st.isEmpty()) out.append(st.pop());
        return out.toString();
    }

    private int prec(char op) {
        if (op == '^') return 3;
        if (op == '*' || op == '/') return 2;
        if (op == '+' || op == '-') return 1;
        return 0;
    }

    private boolean shouldPop(char top, char cur) {
        if (prec(top) > prec(cur)) return true;
        if (prec(top) < prec(cur)) return false;
        return cur != '^';
    }
}
```

### Python
```python
class Solution:
    def infixToPostfix(self, s: str) -> str:
        prec = {'^': 3, '*': 2, '/': 2, '+': 1, '-': 1}

        def should_pop(top: str, cur: str) -> bool:
            if prec[top] > prec[cur]:
                return True
            if prec[top] < prec[cur]:
                return False
            return cur != '^'          # equal precedence: '^' is right-associative

        st, out = [], []
        for c in s:
            if c.isalnum():
                out.append(c)
            elif c == '(':
                st.append(c)
            elif c == ')':
                while st and st[-1] != '(':
                    out.append(st.pop())
                if st:
                    st.pop()
            else:
                while st and st[-1] != '(' and should_pop(st[-1], c):
                    out.append(st.pop())
                st.append(c)
        while st:
            out.append(st.pop())
        return "".join(out)
```

## Key Takeaways
- Operands come out in input order; only operators are delayed — that single fact reduces the whole problem to "when do I release an operator?".
- Pop while the stack top binds at least as tightly, except for right-associative `^`, where equal precedence must **not** pop.
- `(` is a fence with precedence 0: never pop past it, and never emit it.
- Don't forget the final drain of the stack, and remember postfix needs no brackets at all — they vanish in the conversion.
