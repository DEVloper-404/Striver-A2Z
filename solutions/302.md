# Best time to buy and sell stock II

**Difficulty:** Medium  ·  **Topic:** Dynamic Programming [Patterns and Problems] › DP on Stocks

## Problem
Given `prices[i]` = the price of a stock on day `i`, you may buy and sell **as many times as you like**, but you can hold at most one share at a time — you must sell before you buy again. Return the maximum total profit. Buying and selling on the same day is allowed and simply yields nothing.

```
Input:  prices = [7, 1, 5, 3, 6, 4]
Output: 7      (buy at 1 sell at 5 → +4, buy at 3 sell at 6 → +3)
```

## Approach 1: Recursion with a "can I buy?" flag (Brute Force)
Walk the days left to right carrying one bit of state: do I currently hold a share or not?

Let `f(i, canBuy)` = the best profit obtainable from day `i` onward.

- If `canBuy` is true, either **buy today** (`-prices[i] + f(i+1, false)`) or **skip** (`f(i+1, true)`).
- If `canBuy` is false, either **sell today** (`+prices[i] + f(i+1, true)`) or **hold** (`f(i+1, false)`).
- Base case `f(n, ·) = 0`.

This is correct — it enumerates every legal trading schedule — but branches twice per day.

- **Time:** O(2^n)
- **Space:** O(n) recursion depth

## Approach 2: DP over the two states (Optimal)
There are only `2n` distinct states, so memoise, then flip to bottom-up. Because day `i` reads only day `i+1`, we can collapse the table to two scalars:

- `hold` = best balance while owning a share.
- `free` = best balance while owning nothing.

Sweeping days from the end (or, equivalently, from the front) gives:
```
newHold = max(hold, free - prices[i])     // keep the share, or buy today out of the free balance
newFree = max(free, hold + prices[i])     // stay out, or sell the share today
```
The critical difference from the single-transaction version is the `free - prices[i]` term: after selling we return to the `free` state with real accumulated profit, and that profit is available to fund the next purchase. That single change is what "unlimited transactions" means in this framework.

Start with `hold = -prices[0]` (or `-infinity` before day 0) and `free = 0`, and answer with `free` at the end — ending while still holding a share is never better than having sold it.

**Dry run** on `[7, 1, 5, 3, 6, 4]`, processing front to back:

| day | price | hold           | free            |
|-----|-------|----------------|-----------------|
| 0   | 7     | −7             | 0               |
| 1   | 1     | max(−7, 0−1)=−1| max(0, −7+1)=0  |
| 2   | 5     | max(−1, 0−5)=−1| max(0, −1+5)=4  |
| 3   | 3     | max(−1, 4−3)=1 | max(4, −1+3)=4  |
| 4   | 6     | max(1, 4−6)=1  | max(4, 1+6)=**7**|
| 5   | 4     | max(1, 7−4)=3  | max(7, 1+4)=7   |

Answer: `7`.

- **Time:** O(n)
- **Space:** O(1)

## Approach 3: Greedy — collect every upward step
There is an elegant shortcut. Any profitable trade from day `i` to day `j` telescopes into the sum of consecutive daily differences:
`prices[j] - prices[i] = (prices[i+1]-prices[i]) + (prices[i+2]-prices[i+1]) + ... + (prices[j]-prices[j-1])`.

So the total profit of *any* schedule is a sum of some daily differences, and since transactions are unlimited we are free to pick exactly the positive ones and skip the negative ones. Therefore:

```
profit = Σ max(0, prices[i] - prices[i-1])
```

On the example that is `0 + 4 + 0 + 3 + 0 = 7` — the same answer, computed in one line. This works *only* because there is no transaction limit, no fee and no cooldown; the moment any of those appear, fall back to the state DP.

- **Time:** O(n)
- **Space:** O(1)

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int maxProfit(vector<int>& prices) {
        int n = prices.size();
        if (n < 2) return 0;
        int hold = -prices[0];   // best balance while owning a share
        int free = 0;            // best balance while owning nothing
        for (int i = 1; i < n; i++) {
            int prevHold = hold, prevFree = free;
            hold = max(prevHold, prevFree - prices[i]);
            free = max(prevFree, prevHold + prices[i]);
        }
        return free;
    }
};
```

### Python
```python
from typing import List


class Solution:
    def maxProfit(self, prices: List[int]) -> int:
        if len(prices) < 2:
            return 0
        hold = -prices[0]
        free = 0
        for price in prices[1:]:
            hold, free = max(hold, free - price), max(free, hold + price)
        return free
```

## Key Takeaways
- One bit of state ("do I hold a share?") plus one sweep solves the whole unlimited-transaction family.
- The difference from the one-transaction version is a single term: buying subtracts from the *accumulated* profit (`free - price`) instead of from zero.
- The greedy "sum of positive daily gains" is not a different algorithm — it is the same DP, and it only stays valid without fees, cooldowns, or a transaction cap.
- Always finish in the `free` state; holding a share at the end can never beat having sold it.
