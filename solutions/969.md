# Next Greater Element - 2

**Difficulty:** Medium  ·  **Topic:** Stack and Queues [Learning, Pre-In-Post-fix, Monotonic Stack, Implementation] › Monotonic Stack/Queue Problems [VVV. Imp]

## Problem
Given a circular array `nums`, return an array where position `i` holds the first element strictly greater than `nums[i]` when you walk rightwards from `i` and wrap around to the start if needed. If no such element exists anywhere in the array, put `-1`.

```
Input:  nums = [2, 10, 12, 1, 11]
Output: [10, 12, -1, 11, 12]
```
For the last element 11, the search wraps and finds 12 at index 2.

## Approach 1: Brute Force
For each `i`, check indices `(i+1) % n, (i+2) % n, ..., (i+n-1) % n` and stop at the first larger value.
- **Time:** O(n²)
- **Space:** O(1) extra

## Approach 2: Monotonic Stack over a Doubled Index Range (Optimal)
Treat the array as if it were written twice (`nums` followed by `nums` again), but never actually build the second copy — just iterate `i` from `2n-1` down to `0` and access `nums[i % n]`.

Keep a stack of values that is strictly decreasing from bottom to top. At each step:
1. Pop while top ≤ `nums[i % n]`.
2. If `i < n`, record the answer for index `i` as the top (or `-1` if empty).
3. Push `nums[i % n]`.

The first pass over indices `2n-1 .. n` only fills the stack so that when we reach the real indices `n-1 .. 0`, the elements that wrap around are already available.
- **Time:** O(n) — each of the 2n visits does amortised O(1) stack work
- **Space:** O(n) for the stack

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <stack>
using namespace std;

class Solution {
public:
    vector<int> nextGreaterElements(vector<int>& nums) {
        int n = nums.size();
        vector<int> ans(n, -1);
        stack<int> st;
        for (int i = 2 * n - 1; i >= 0; --i) {
            int cur = nums[i % n];
            while (!st.empty() && st.top() <= cur) st.pop();
            if (i < n) ans[i] = st.empty() ? -1 : st.top();
            st.push(cur);
        }
        return ans;
    }
};
```

### Java
```java
import java.util.*;

class Solution {
    public int[] nextGreaterElements(int[] nums) {
        int n = nums.length;
        int[] ans = new int[n];
        Arrays.fill(ans, -1);
        Deque<Integer> st = new ArrayDeque<>();
        for (int i = 2 * n - 1; i >= 0; i--) {
            int cur = nums[i % n];
            while (!st.isEmpty() && st.peek() <= cur) st.pop();
            if (i < n) ans[i] = st.isEmpty() ? -1 : st.peek();
            st.push(cur);
        }
        return ans;
    }
}
```

### Python
```python
from typing import List

class Solution:
    def nextGreaterElements(self, nums: List[int]) -> List[int]:
        n = len(nums)
        ans = [-1] * n
        st = []
        for i in range(2 * n - 1, -1, -1):
            cur = nums[i % n]
            while st and st[-1] <= cur:
                st.pop()
            if i < n:
                ans[i] = st[-1] if st else -1
            st.append(cur)
        return ans
```

## Key Takeaways
- Circular problems are often solved by conceptually doubling the array and using `i % n` — no extra copy needed.
- Only record answers during the second half (`i < n`); the first half just warms up the stack.
- The maximum element always gets `-1`, which is the sanity check for your output.
