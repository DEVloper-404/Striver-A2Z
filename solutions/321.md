# Partition equal subset sum

**Difficulty:** Hard  ·  **Topic:** Dynamic Programming [Patterns and Problems] › DP on Subsequences

## Problem
Given an array `nums` of positive integers, decide whether it can be split into **two subsets whose sums are equal**. Every element must go to exactly one of the two sides. Return `true` or `false`.

```
Input:  nums = [1, 5, 11, 5]
Output: true
        {11} and {1, 5, 5} — both sum to 11
```
```
Input:  nums = [1, 2, 3, 5]
Output: false
        Total is 11, which is odd — no equal split can exist
```

## Approach 1: Try every partition (brute force)
Each element independently goes left or right, so there are `2^n` assignments. Enumerate them, compute both sums, and check equality. Correct, but exponential.
- **Time:** O(2^n · n)
- **Space:** O(n)

## Approach 2: Reduce to Subset Sum (the key insight)

**Two reductions turn this into a problem we already know.**

*Reduction 1 — one subset determines the other.* If the two parts have sums `S1` and `S2` with `S1 = S2`, and the whole array sums to `total = S1 + S2`, then each part sums to `total / 2`. Conversely, if **any** subset sums to `total / 2`, its complement automatically sums to `total - total/2 = total/2` as well, so a valid partition exists. So:

> "Can the array be split into two equal halves?" ⟺ "Does some subset sum to `total / 2`?"

That is exactly the Subset Sum problem, and it needs only *one* sum to be tracked instead of two.

*Reduction 2 — the parity shortcut.* If `total` is **odd**, `total / 2` is not an integer, so no split can exist and we can return `false` immediately without any DP. This one line kills half the inputs (and it is the reason the second example above is `false` before we ever build a table).

**The Subset Sum recurrence.** With `target = total / 2` and `f(i, t)` = "can we make sum `t` from `nums[0..i]`":

```
f(i, 0) = true                                     // empty subset
f(0, t) = (nums[0] == t)
f(i, t) = f(i-1, t)                                // don't take nums[i]
          OR (t >= nums[i] && f(i-1, t - nums[i])) // take it
```

Only the *remaining* target matters, never which elements were used — that is what keeps the state two-dimensional.
- **Time:** O(2^n) as raw recursion
- **Space:** O(n) recursion stack

## Approach 3: Memoization / tabulation
Memoize on `(i, t)`: `n × (target+1)` states, O(1) work each. Or tabulate a boolean table: set `dp[i][0] = true` for all `i`, `dp[0][nums[0]] = true`, then fill

```
dp[i][t] = dp[i-1][t] || (t >= nums[i] && dp[i-1][t - nums[i]])
```

and read `dp[n-1][target]`.
- **Time:** O(n · total/2)
- **Space:** O(n · total/2)

## Approach 4: One rolling boolean row, swept right to left (Optimal)

Row `i` reads only row `i-1`, so one boolean array `dp[0..target]` is enough — `dp[t]` meaning "sum `t` is reachable with the elements processed so far".

**The direction matters.** For each new value `x`, iterate `t` from `target` **down to** `x` and set `dp[t] |= dp[t-x]`. Going downward guarantees `dp[t-x]` still reflects the state *before* `x` was introduced, so `x` is used at most once. An ascending sweep would let `x` be reused repeatedly (unbounded knapsack), which would happily "partition" `[1, 3]` by pretending there are three 1s.

**Algorithm.**
1. `total = sum(nums)`. If `total` is odd, return `false`.
2. `target = total / 2`; `dp = [false] * (target+1)`; `dp[0] = true`.
3. For each `x` in `nums`: for `t = target` down to `x`: `dp[t] = dp[t] || dp[t-x]`. Return `true` early if `dp[target]` is set.
4. Return `dp[target]`.

**Dry run on `[1, 5, 11, 5]`.** `total = 22`, even, so `target = 11`.

| after processing | reachable sums ≤ 11 |
|---|---|
| start | {0} |
| 1 | {0, 1} |
| 5 | {0, 1, 5, 6} |
| 11 | {0, 1, 5, 6, **11**} |

`dp[11]` is true after the third element, so we return `true` without even looking at the last `5`. The subset that achieved it is `{11}`, and its complement `{1, 5, 5}` also sums to 11. ✔

**Contrast with `[1, 2, 3, 5]`:** `total = 11` is odd, so we return `false` at step 1 — no table is ever allocated.
- **Time:** O(n · total/2) — pseudo-polynomial
- **Space:** O(total/2)

**Practical micro-optimisation.** Because the array is boolean, the inner loop can be replaced by a shifted OR on a bitset: `bits |= bits << x`, then test bit `target`. That divides the constant factor by the machine word size (64), which matters when `total` is large.

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <numeric>
using namespace std;

class Solution {
public:
    bool canPartition(vector<int>& nums) {
        int total = accumulate(nums.begin(), nums.end(), 0);
        if (total % 2 != 0) return false;           // odd total can never split evenly
        int target = total / 2;

        vector<char> dp(target + 1, false);
        dp[0] = true;                               // empty subset
        for (int x : nums) {
            // descending sweep so each element is used at most once
            for (int t = target; t >= x; t--) {
                if (dp[t - x]) dp[t] = true;
            }
            if (dp[target]) return true;            // early exit
        }
        return dp[target];
    }
};
```

### Python
```python
from typing import List


class Solution:
    def canPartition(self, nums: List[int]) -> bool:
        total = sum(nums)
        if total % 2 != 0:                          # odd total can never split evenly
            return False
        target = total // 2

        dp = [False] * (target + 1)
        dp[0] = True                                # empty subset
        for x in nums:
            # descending sweep so each element is used at most once
            for t in range(target, x - 1, -1):
                if dp[t - x]:
                    dp[t] = True
            if dp[target]:
                return True                         # early exit
        return dp[target]
```

## Key Takeaways
- Recognise the reduction: an equal-sum partition exists **iff** some subset sums to `total / 2`, because the complement is forced. One target, not two.
- The odd-total check is a free O(n) rejection — do it before allocating anything.
- The core is the 0/1 pick / not-pick subsequence DP on state `(index, remaining sum)`.
- With a single rolling array, sweep the target **downward**; an ascending sweep reuses elements and gives wrong answers.
- Complexity is pseudo-polynomial `O(n · total)`; it is fast when the numbers are small and hopeless when they are astronomically large.
- Close relatives that use the identical table: minimum subset-sum difference, count of subsets with a given sum, and Target Sum (`+/-` assignment).
