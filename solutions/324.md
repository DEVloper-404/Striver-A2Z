# Target sum

**Difficulty:** Hard  ·  **Topic:** Dynamic Programming [Patterns and Problems] › DP on Subsequences

## Problem
Given an array of non-negative integers `nums` and an integer `target`, put a `+` or a `-` in front of every element and concatenate them into an expression. Count how many of the 2^n sign assignments evaluate to exactly `target`.

```
Input:  nums = [1, 1, 1, 1, 1], target = 3
Output: 5
Explanation: exactly one element gets a minus sign, and there are 5 choices for which.

Input:  nums = [1], target = 1
Output: 1
```

## Approach 1: Brute Force (enumerate all sign choices)
Recurse over indices carrying the running value; at each index branch on `+nums[i]` and `-nums[i]`. At the end, count the leaves whose running value equals `target`. Correct, but 2^n leaves make it unusable past n ≈ 25.

- **Time:** O(2^n)
- **Space:** O(n)

## Approach 2: Reduce to counting subsets with a fixed sum

**The key transformation.** Let `P` be the set of elements that receive `+`, and `N` the set that receives `-`. Write `sp = sum(P)` and `sn = sum(N)`. Then

```
sp - sn = target
sp + sn = total          (every element is in exactly one of P, N)
```

Subtracting the first equation from the second gives `2·sn = total - target`, so

```
sn = (total - target) / 2
```

Every sign assignment corresponds to exactly one choice of the negative set `N`, so **the answer is the number of subsets whose sum is `(total - target) / 2`.** A whole exponential search collapses into the standard "count subsets with sum K" DP.

**Guards.** If `total - target` is negative, or is odd, no integer `sn` exists and the answer is 0. Since `target` may be negative, `total - target` can exceed `total`; the negativity check also covers `target > total`.

- **Time:** O(n) for the reduction
- **Space:** O(1)

## Approach 3: Optimal (count subsets with sum = target', tabulated)

Let `K = (total - target) / 2` and define

`dp[i][t] = number of subsets of nums[0..i] whose sum is exactly t`

- **Transition:** `dp[i][t] = dp[i-1][t] + (t >= nums[i] ? dp[i-1][t - nums[i]] : 0)` — skip the element, or take it and reduce the target.
- **Base row:** `dp[0][0] = 1`, then `dp[0][nums[0]] += 1` if it fits. The `+=` (not `=`) matters: when `nums[0] == 0` both writes hit cell 0, giving 2, which is correct because a zero can be signed `+` or `-` and change nothing. Each zero doubles the count of valid expressions, and the transition propagates that on its own.
- **Answer:** `dp[n-1][K]`.

Only the previous row is read, so two rolling arrays of size `K+1` suffice.

**Dry run on nums = [1,1,1,1,1], target = 3.** `total = 5`, so `K = (5 - 3)/2 = 1`. We need subsets summing to 1 — there are 5 of them (each single element). Those are exactly the 5 ways to pick which element gets the minus sign, matching the expected output. The DP table (columns t = 0, 1):

| after element | t=0 | t=1 |
|---|---|---|
| 1 | 1 | 1 |
| 1 | 1 | 2 |
| 1 | 1 | 3 |
| 1 | 1 | 4 |
| 1 | 1 | 5 |

- **Time:** O(n · K)
- **Space:** O(K)

## Code (Optimal)

### C++
```cpp
class Solution {
public:
    int findTargetSumWays(vector<int>& nums, int target) {
        int total = 0;
        for (int x : nums) total += x;

        if (total - target < 0 || (total - target) % 2 != 0) return 0;
        int K = (total - target) / 2;

        int n = nums.size();
        vector<int> prev(K + 1, 0), cur(K + 1, 0);
        prev[0] = 1;
        if (nums[0] <= K) prev[nums[0]] += 1;

        for (int i = 1; i < n; i++) {
            for (int t = 0; t <= K; t++) {
                int notTake = prev[t];
                int take = (t >= nums[i]) ? prev[t - nums[i]] : 0;
                cur[t] = notTake + take;
            }
            prev = cur;
        }
        return prev[K];
    }
};
```

### Python
```python
class Solution:
    def findTargetSumWays(self, nums, target):
        total = sum(nums)

        if total - target < 0 or (total - target) % 2 != 0:
            return 0
        K = (total - target) // 2

        n = len(nums)
        prev = [0] * (K + 1)
        prev[0] = 1
        if nums[0] <= K:
            prev[nums[0]] += 1

        for i in range(1, n):
            cur = [0] * (K + 1)
            for t in range(K + 1):
                not_take = prev[t]
                take = prev[t - nums[i]] if t >= nums[i] else 0
                cur[t] = not_take + take
            prev = cur

        return prev[K]
```

## Key Takeaways
- Signing elements `+`/`-` is the same as choosing a negative subset; solving `sp + sn = total`, `sp - sn = target` gives the single target `(total - target) / 2`.
- Reject early when `total - target` is negative or odd — otherwise you index a negative-size array.
- Zeros double the answer each time, and the `+=` base row plus the ordinary transition encode that without a special case.
- Structurally identical to "Count partitions with given difference"; only the algebra to derive the target differs.
