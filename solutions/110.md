# Construct a BT from Preorder and Inorder

**Difficulty:** Hard  ·  **Topic:** Binary Trees [Traversals, Medium and Hard Problems] › Hard Problems

## Problem
Given the preorder and inorder traversals of a binary tree with distinct values, rebuild the tree and return its root.

Input: preorder = [3, 9, 20, 15, 7], inorder = [9, 3, 15, 20, 7]
Output: [3, 9, 20, null, null, 15, 7]

Input: preorder = [-1], inorder = [-1]
Output: [-1]

## Approach 1: Brute Force (linear search for the root each time)
The first preorder element is the root. Scan inorder linearly to find it; everything to its left is the left subtree, everything to its right is the right subtree. Slice both arrays accordingly and recurse. The linear scan and array slicing make each level cost O(N).
- **Time:** O(N²) in the worst case (skewed tree)
- **Space:** O(N²) if slices are copied, O(N) with index ranges

## Approach 2: Optimal (hash map + index ranges)
Precompute `inIdx[value] = position in inorder`. Recurse with four indices `(preStart, preEnd, inStart, inEnd)`:
1. Root is `preorder[preStart]`. Find `mid = inIdx[root]`.
2. `leftSize = mid - inStart`.
3. Left subtree uses `preorder[preStart+1 .. preStart+leftSize]` and `inorder[inStart .. mid-1]`.
4. Right subtree uses `preorder[preStart+leftSize+1 .. preEnd]` and `inorder[mid+1 .. inEnd]`.

No arrays are copied and the root lookup is O(1).
- **Time:** O(N)
- **Space:** O(N) for the map plus O(H) recursion

## Code (Optimal)

### C++
```cpp
// struct TreeNode { int val; TreeNode *left; TreeNode *right; TreeNode(int x) ... } — standard definition
#include <vector>
#include <unordered_map>
using namespace std;

class Solution {
    unordered_map<int,int> inIdx;

    TreeNode* build(vector<int>& pre, int ps, int pe, vector<int>& in, int is, int ie) {
        if (ps > pe || is > ie) return nullptr;
        TreeNode* root = new TreeNode(pre[ps]);
        int mid = inIdx[pre[ps]];
        int leftSize = mid - is;
        root->left  = build(pre, ps + 1, ps + leftSize, in, is, mid - 1);
        root->right = build(pre, ps + leftSize + 1, pe, in, mid + 1, ie);
        return root;
    }
public:
    TreeNode* buildTree(vector<int>& preorder, vector<int>& inorder) {
        for (int i = 0; i < (int)inorder.size(); ++i) inIdx[inorder[i]] = i;
        return build(preorder, 0, preorder.size() - 1, inorder, 0, inorder.size() - 1);
    }
};
```

### Java
```java
// class TreeNode { int val; TreeNode left, right; TreeNode(int x) ... } — standard definition
import java.util.*;

class Solution {
    private Map<Integer, Integer> inIdx = new HashMap<>();

    private TreeNode build(int[] pre, int ps, int pe, int[] in, int is, int ie) {
        if (ps > pe || is > ie) return null;
        TreeNode root = new TreeNode(pre[ps]);
        int mid = inIdx.get(pre[ps]);
        int leftSize = mid - is;
        root.left  = build(pre, ps + 1, ps + leftSize, in, is, mid - 1);
        root.right = build(pre, ps + leftSize + 1, pe, in, mid + 1, ie);
        return root;
    }

    public TreeNode buildTree(int[] preorder, int[] inorder) {
        for (int i = 0; i < inorder.length; i++) inIdx.put(inorder[i], i);
        return build(preorder, 0, preorder.length - 1, inorder, 0, inorder.length - 1);
    }
}
```

### Python
```python
# class TreeNode: val, left, right — standard definition

class Solution:
    def buildTree(self, preorder, inorder):
        in_idx = {v: i for i, v in enumerate(inorder)}

        def build(ps, pe, is_, ie):
            if ps > pe or is_ > ie:
                return None
            root = TreeNode(preorder[ps])
            mid = in_idx[root.val]
            left_size = mid - is_
            root.left = build(ps + 1, ps + left_size, is_, mid - 1)
            root.right = build(ps + left_size + 1, pe, mid + 1, ie)
            return root

        return build(0, len(preorder) - 1, 0, len(inorder) - 1)
```

## Key Takeaways
- Preorder hands you the root; inorder tells you the size of the left subtree, which is all you need to carve up both arrays.
- Store inorder positions in a hash map once; that alone drops the complexity from quadratic to linear.
- Pass index ranges instead of slicing arrays to avoid O(N) copies per call.
- Distinct values are required; with duplicates the inorder lookup is ambiguous.
