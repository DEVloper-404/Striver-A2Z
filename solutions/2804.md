# Subset sum equal to target (DP- 14)

**Difficulty:** Hard  ·  **Topic:** Dynamic Programming [Patterns and Problems] › DP on Subsequences

## Problem
Given an array `arr` of `n` non-negative integers and a number `target`, decide whether **some subset** of `arr` sums to exactly `target`. Return `true` or `false`. The subset may be empty, and elements may not be reused.

```
Input:  arr = [3, 34, 4, 12, 5, 2], target = 9
Output: true
        {4, 5} sums to 9  (so does {3, 4, 2})
```
```
Input:  arr = [1, 2, 7], target = 6
Output: false
```

## Approach 1: Generate every subset (brute force)
There are `2^n` subsets; enumerate them with recursion or with a bitmask over `0 … 2^n - 1`, sum each, and check against `target`. Guaranteed correct, hopeless beyond `n ≈ 25`.
- **Time:** O(2^n · n)
- **Space:** O(n)

## Approach 2: Pick / not-pick recursion (the DP-on-subsequences template)

**The key move** is to stop thinking about "subsets" and start thinking about a sequence of binary decisions. Process elements one at a time. At index `i` there are exactly two choices, and they partition all subsets:

- **Take `arr[i]`** — then the rest must make up `target - arr[i]`.
- **Skip `arr[i]`** — then the rest must still make up `target`.

So with `f(i, t)` = "can we form sum `t` using only elements `arr[0..i]`":

```
f(i, 0)  = true                              // empty subset works for any i
f(0, t)  = (arr[0] == t)                     // only one element available
f(i, t)  = f(i-1, t)                         // skip
           OR  (t >= arr[i] && f(i-1, t - arr[i]))   // take
```

Two details that matter:

1. The `t == 0` base case must be checked **before** the `i == 0` base case, otherwise `arr = [5], target = 0` returns false when the empty subset is a valid answer.
2. The guard `t >= arr[i]` must come before the recursive "take" call — a negative remaining target is meaningless (and would index out of the table in the tabulated version).

Each call branches in two and the depth is `n`, so raw recursion is `O(2^n)` — but notice that the *second* parameter only ever takes values in `0..target`, which is why memoization collapses it.

**Why the two parameters are enough.** The only thing the remaining elements need to know about the decisions made so far is how much sum is still required. Which specific elements were picked is irrelevant. That is the whole reason this problem is polynomial in `target` rather than exponential in `n`.
- **Time:** O(2^n)
- **Space:** O(n) recursion stack

## Approach 3: Memoization
States are `(i, t)` with `i < n` and `t <= target`, so `n · (target+1)` of them, each doing O(1) work. Store in `dp[i][t]` with `-1` = unknown, `0` = false, `1` = true.
- **Time:** O(n · target)
- **Space:** O(n · target) table + O(n) recursion stack

## Approach 4: Tabulation
Build a boolean table `dp[i][t]` meaning "using `arr[0..i]`, is sum `t` reachable?".

1. `dp[i][0] = true` for every `i` (empty subset).
2. `dp[0][arr[0]] = true` if `arr[0] <= target`.
3. For `i = 1 … n-1` and `t = 1 … target`:
   `dp[i][t] = dp[i-1][t] || (t >= arr[i] && dp[i-1][t - arr[i]])`
4. Answer: `dp[n-1][target]`.
- **Time:** O(n · target)
- **Space:** O(n · target)

## Approach 5: One rolling row, swept right to left (Optimal)

Row `i` reads only row `i-1`, so a single boolean array of length `target+1` suffices. The subtlety is the sweep direction.

If you update `dp[t] |= dp[t - arr[i]]` going **left to right**, then `dp[t - arr[i]]` may have already been updated *in this same row*, meaning `arr[i]` gets used twice — that turns the problem into unbounded knapsack. Sweeping **right to left** (`t` from `target` down to `arr[i]`) guarantees `dp[t - arr[i]]` still holds the previous row's value, so each element is used at most once. This is the single most important implementation detail in the whole 0/1-knapsack family.

**Algorithm.**
1. `dp[0] = true`, all other entries `false`.
2. For each `x` in `arr`: for `t = target` down to `x`: `dp[t] = dp[t] || dp[t - x]`.
3. Return `dp[target]`.

**Dry run on `arr = [3, 34, 4, 12, 5, 2]`, `target = 9`.** Writing only the reachable sums:

| after processing | reachable sums ≤ 9 |
|---|---|
| start | {0} |
| 3 | {0, 3} |
| 34 | {0, 3} (34 > 9, loop body never runs) |
| 4 | {0, 3, 4, 7} |
| 12 | {0, 3, 4, 7} |
| 5 | {0, 3, 4, 5, 7, 8, **9**} |
| 2 | {0, 2, 3, 4, 5, 6, 7, 8, 9} |

`dp[9]` becomes true when `5` is processed — reached as `4 + 5`. Answer `true`. ✔ Note how the descending sweep at `x = 5` reads `dp[4]`, which was set in the *previous* round (by the element `4`), not in the current one.
- **Time:** O(n · target)
- **Space:** O(target)

*(Complexity note: `O(n · target)` is **pseudo-polynomial** — it is linear in the numeric value of `target`, not in its number of digits. Subset Sum is NP-complete, so no truly polynomial algorithm is known.)*

## Code (Optimal)

### C++
```cpp
#include <vector>
using namespace std;

class Solution {
public:
    bool subsetSumToK(int n, int target, vector<int>& arr) {
        vector<char> dp(target + 1, false);
        dp[0] = true;                          // empty subset
        for (int i = 0; i < n; i++) {
            int x = arr[i];
            // descending sweep: each element is used at most once
            for (int t = target; t >= x; t--) {
                if (dp[t - x]) dp[t] = true;
            }
            if (dp[target]) return true;       // early exit
        }
        return dp[target];
    }
};
```

### Python
```python
from typing import List


class Solution:
    def subsetSumToK(self, n: int, target: int, arr: List[int]) -> bool:
        dp = [False] * (target + 1)
        dp[0] = True                           # empty subset
        for x in arr:
            # descending sweep: each element is used at most once
            for t in range(target, x - 1, -1):
                if dp[t - x]:
                    dp[t] = True
            if dp[target]:
                return True                    # early exit
        return dp[target]
```

## Key Takeaways
- The DP-on-subsequences template: state `(index, remaining target)`, transition = **pick** (subtract the value) **or** **not-pick** (leave it). Everything in this family — partition, count subsets, minimum difference, target sum, 0/1 knapsack — is a variation on it.
- Only the *remaining sum* need be remembered, not which elements were chosen; that is what makes the state 2D instead of exponential.
- Check the `t == 0 → true` base case before the `i == 0` case, or the empty subset is lost.
- With one rolling array, iterate `t` **downward**. An upward sweep silently allows reusing an element and solves unbounded knapsack instead.
- The complexity is pseudo-polynomial: fine when `target` is small, useless when the numbers are huge (Subset Sum is NP-complete).
