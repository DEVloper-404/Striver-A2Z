# Rod Cutting Problem | (DP - 24)

**Difficulty:** Hard  ·  **Topic:** Dynamic Programming [Patterns and Problems] › DP on Subsequences

## Problem
A rod of length `N` can be cut into pieces of integer lengths. You are given an array `price` of size `N` where `price[i]` is the money you get for a piece of length `i + 1`. Cut the rod (or leave it whole) so that the total price of the pieces is maximised, and return that maximum.

```
Input:  N = 5, price = [2, 5, 7, 8, 10]
Output: 12
Explanation: cut into 2 + 3 -> 5 + 7 = 12. Better than 5 (=10), 1+4 (=2+8=10),
             or 1+1+1+1+1 (=10).
```

## Approach 1: Brute Force (recursive cuts)
Try every first cut: chop off a piece of length `L` for `L = 1..N`, collect `price[L-1]`, and recursively solve the remaining rod of length `N - L`. Take the best over all `L`. Correct, but it explores every composition of `N`, which is 2^(N-1) of them.

- **Time:** O(2^N)
- **Space:** O(N)

## Approach 2: Recognise it as unbounded knapsack

**The key observation.** Pieces of the same length can be cut any number of times, and the total of the piece lengths must not exceed `N`. That is precisely an unbounded knapsack:

- item `i` = a piece of length `i + 1`
- weight = `i + 1`
- value = `price[i]`
- capacity = `N`

One extra fact makes it slightly nicer than general knapsack: the piece lengths are `1, 2, …, N`, and length 1 is always available, so the capacity is always usable exactly — the optimal solution never leaves the rod partly uncut. But we do not need to rely on that; the standard knapsack recurrence handles it.

At index `i` with remaining rod length `rod`:
- **Not take:** `f(i-1, rod)` — never cut a piece of length `i+1` again.
- **Take:** `price[i] + f(i, rod - (i+1))` — cut one such piece and **stay at `i`**, because more pieces of the same length are allowed.

Base case at `i = 0`: only length-1 pieces exist, so cut `rod` of them for `rod * price[0]`.

- **Time:** O(N²) once memoised
- **Space:** O(N²) table + O(N) stack

## Approach 3: Optimal (tabulation, one rolling array)

`dp[i][rod] = best price obtainable from a rod of length rod using piece lengths 1..i+1`

- **Base row:** `dp[0][rod] = rod * price[0]`.
- **Transition:** `dp[i][rod] = max(dp[i-1][rod], price[i] + dp[i][rod - (i+1)])` when `i+1 <= rod`, else just `dp[i-1][rod]`. The take branch reads the current row, giving unlimited reuse.
- **Answer:** `dp[N-1][N]`.

Collapse to one array of size `N+1` and, for each piece length `len = 1..N`, sweep `rod` from `len` up to `N` doing `dp[rod] = max(dp[rod], price[len-1] + dp[rod - len])`. Sweeping upward is what allows repeated pieces of the same length; sweeping downward would restrict each length to one use, which is a different (and wrong) problem.

**Dry run on price = [2, 5, 7, 8, 10], N = 5.** Start `dp = [0,0,0,0,0,0]`.
- len 1 (price 2): `dp = [0, 2, 4, 6, 8, 10]` — all-ones cutting.
- len 2 (price 5): `dp[2] = max(4, 5+dp[0]) = 5`; `dp[3] = max(6, 5+dp[1]) = 7`; `dp[4] = max(8, 5+dp[2]) = 10`; `dp[5] = max(10, 5+dp[3]) = 12`. Now `[0,2,5,7,10,12]`.
- len 3 (price 7): `dp[3] = max(7, 7+dp[0]) = 7`; `dp[4] = max(10, 7+dp[1]) = max(10, 9) = 10`; `dp[5] = max(12, 7+dp[2]) = max(12, 12) = 12`.
- len 4 (price 8): `dp[4] = max(10, 8+dp[0]) = 10`; `dp[5] = max(12, 8+dp[1]) = max(12, 10) = 12`.
- len 5 (price 10): `dp[5] = max(12, 10+dp[0]) = 12`.

Final answer `dp[5] = 12`, achieved by the 2 + 3 cut — and notice how the len-3 step confirmed 12 via `7 + dp[2] = 7 + 5`, i.e. one piece of length 3 plus one of length 2.

- **Time:** O(N²)
- **Space:** O(N)

## Code (Optimal)

### C++
```cpp
class Solution {
public:
    int cutRod(vector<int>& price, int n) {
        vector<int> dp(n + 1, 0);

        for (int len = 1; len <= n; len++)                 // piece length
            for (int rod = len; rod <= n; rod++)           // upward -> reuse allowed
                dp[rod] = max(dp[rod], price[len - 1] + dp[rod - len]);

        return dp[n];
    }
};
```

### Java
```java
class Solution {
    public int cutRod(int[] price, int n) {
        int[] dp = new int[n + 1];

        for (int len = 1; len <= n; len++)
            for (int rod = len; rod <= n; rod++)
                dp[rod] = Math.max(dp[rod], price[len - 1] + dp[rod - len]);

        return dp[n];
    }
}
```

### Python
```python
class Solution:
    def cutRod(self, price, n):
        dp = [0] * (n + 1)

        for length in range(1, n + 1):
            p = price[length - 1]
            for rod in range(length, n + 1):
                cand = p + dp[rod - length]
                if cand > dp[rod]:
                    dp[rod] = cand

        return dp[n]
```

## Key Takeaways
- Rod cutting is unbounded knapsack in disguise: piece length is the weight, `price[i]` the value, rod length the capacity.
- Mind the off-by-one: `price[i]` is the price of a piece of length `i + 1`, so the 1-D loop indexes `price[len - 1]`.
- Upward capacity sweep = unlimited copies of each piece length. Downward would be 0/1 and give a smaller, wrong answer.
- Because a piece of length 1 always exists, the whole rod is always consumed — a useful sanity check when debugging.
