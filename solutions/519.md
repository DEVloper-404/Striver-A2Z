# Cheapest flight within K stops

**Difficulty:** Hard  ·  **Topic:** Graphs [Concepts & Problems] › Shortest Path Algorithms and Problems

## Problem
There are `n` cities numbered `0..n-1` and a list `flights` where `[from, to, price]` is a one-way flight. Given `src`, `dst` and an integer `k`, return the cheapest price to fly from `src` to `dst` using **at most `k` stops** (that is, at most `k + 1` flights). Return `-1` if no such itinerary exists.

```
Input:  n = 4, flights = [[0,1,100], [1,2,100], [2,0,100], [1,3,600], [2,3,200]],
        src = 0, dst = 3, k = 1
Output: 700
```
The cheapest itinerary overall is `0 → 1 → 2 → 3` at 400, but it uses 2 stops. With at most 1 stop the best is `0 → 1 → 3` for `100 + 600 = 700`.

## Approach 1: Plain Dijkstra (why it is wrong here)
Dijkstra finds the cheapest route ignoring the stop limit, so it would return 400 in the example. Worse, patching it by storing only the cheapest cost per city is *unsound*: a costlier route may use fewer flights and be the only one that can still legally reach `dst`. The stop count is a second dimension of the state, and any correct solution must track it.

## Approach 2: Dijkstra over the state `(city, stops)`
Make the state a pair and key the priority queue by **stops** rather than cost, since stops are the hard constraint. Keep `minStops[city]`, and only expand a state if it reaches the city with fewer stops than seen before. This works, but the heap adds a `log` factor that buys nothing — see below.

- **Time:** O(E·K·log(...))
- **Space:** O(n·K)

## Approach 3: Level-by-level BFS on stops (Optimal)

**Key observation.** Because the constraint counts *flights*, process the graph in layers: all itineraries with 0 flights, then 1 flight, then 2, and so on, stopping after `k + 1` layers. A plain FIFO queue already advances in exactly this order, so the heap is unnecessary — the queue is naturally sorted by the quantity we must bound.

Within a layer we simply keep the cheapest cost found so far for each city, in an array `cost[]`. We relax an edge `u -> v` only when `costSoFar + price < cost[v]`; that prunes strictly-worse states without ever pruning a state that could still be useful, because all states in the queue share the same "flights used" budget progression.

**Algorithm.**
1. Build the adjacency list `adj[from] = {(to, price), ...}`.
2. `cost[src] = 0`, everything else `∞`. Queue holds `(stopsUsed, city, costSoFar)`, seeded with `(0, src, 0)`.
3. Process the queue. Pop `(stops, u, c)`. If `stops > k` we may not take another flight, so skip expanding it.
4. For each edge `u -> v` with price `p`: if `c + p < cost[v]`, set `cost[v] = c + p` and push `(stops + 1, v, c + p)`.
5. Return `cost[dst]` (or `-1` if still infinite).

Because the queue is FIFO and every push increases `stops` by exactly one, entries come out in non-decreasing order of `stops` — the classic BFS-level property. That is what makes the `stops > k` cut-off safe: once we start seeing states beyond the budget, nothing useful remains.

**Why the `cost[v]` pruning is safe.** A state is dropped only when another itinerary reaches the same city more cheaply. Could the dropped, more expensive state be better later because it used fewer flights? No: since the queue is processed in stop order, the cheaper value stored in `cost[v]` was recorded at a stop count less than or equal to the current one, so it dominates on both dimensions.

**Dry run** on the example with `k = 1`:
- Push `(0, 0, 0)`. Pop it; `stops = 0 ≤ 1`. Edge `0→1` (100): `cost[1] = 100`, push `(1, 1, 100)`.
- Pop `(1, 1, 100)`; `stops = 1 ≤ 1`, so one more flight is allowed. Edge `1→2` (100): `cost[2] = 200`, push `(2, 2, 200)`. Edge `1→3` (600): `cost[3] = 700`, push `(2, 3, 700)`.
- Pop `(2, 2, 200)`: `stops = 2 > 1` → cannot fly again. This is exactly where the cheap `2→3` (200) route, which would give 400, is correctly rejected for exceeding the stop budget.
- Pop `(2, 3, 700)`: also beyond the budget, no expansion.
- Return `cost[3] = 700` ✓

**Bellman-Ford view.** An equivalent formulation: run exactly `k + 1` rounds of edge relaxation, each round computing distances using one more flight, always relaxing from a *snapshot* of the previous round's array (otherwise a single round could chain two flights). Same complexity, and it is the classic answer when the graph is given as an edge list.

- **Time:** O(K · E) — each of the `k + 1` layers relaxes each edge at most once
- **Space:** O(n + E) for the graph and cost array, O(n·K) worst case for the queue

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <queue>
#include <climits>
using namespace std;

class Solution {
public:
    int findCheapestPrice(int n, vector<vector<int>>& flights, int src, int dst, int k) {
        vector<vector<pair<int,int>>> adj(n);
        for (auto& f : flights) adj[f[0]].push_back({f[1], f[2]});

        vector<int> cost(n, INT_MAX);
        cost[src] = 0;
        queue<tuple<int,int,int>> q;          // {stops, node, costSoFar}
        q.push({0, src, 0});

        while (!q.empty()) {
            auto [stops, u, c] = q.front(); q.pop();
            if (stops > k) continue;          // no flight budget left
            for (auto& [v, p] : adj[u]) {
                if (c + p < cost[v]) {
                    cost[v] = c + p;
                    q.push({stops + 1, v, c + p});
                }
            }
        }
        return cost[dst] == INT_MAX ? -1 : cost[dst];
    }
};
```

### Java
```java
import java.util.*;

class Solution {
    public int findCheapestPrice(int n, int[][] flights, int src, int dst, int k) {
        List<List<int[]>> adj = new ArrayList<>();
        for (int i = 0; i < n; i++) adj.add(new ArrayList<>());
        for (int[] f : flights) adj.get(f[0]).add(new int[]{f[1], f[2]});

        int[] cost = new int[n];
        Arrays.fill(cost, Integer.MAX_VALUE);
        cost[src] = 0;

        Queue<int[]> q = new ArrayDeque<>();   // {stops, node, costSoFar}
        q.add(new int[]{0, src, 0});

        while (!q.isEmpty()) {
            int[] cur = q.poll();
            int stops = cur[0], u = cur[1], c = cur[2];
            if (stops > k) continue;
            for (int[] e : adj.get(u)) {
                int v = e[0], p = e[1];
                if (c + p < cost[v]) {
                    cost[v] = c + p;
                    q.add(new int[]{stops + 1, v, c + p});
                }
            }
        }
        return cost[dst] == Integer.MAX_VALUE ? -1 : cost[dst];
    }
}
```

### Python
```python
from collections import deque
from typing import List

class Solution:
    def findCheapestPrice(self, n: int, flights: List[List[int]],
                          src: int, dst: int, k: int) -> int:
        adj = [[] for _ in range(n)]
        for a, b, p in flights:
            adj[a].append((b, p))

        INF = float("inf")
        cost = [INF] * n
        cost[src] = 0
        q = deque([(0, src, 0)])              # (stops, node, cost_so_far)

        while q:
            stops, u, c = q.popleft()
            if stops > k:
                continue
            for v, p in adj[u]:
                if c + p < cost[v]:
                    cost[v] = c + p
                    q.append((stops + 1, v, c + p))

        return -1 if cost[dst] == INF else cost[dst]
```

## Key Takeaways
- The stop limit turns the state into `(city, flights used)`; storing only the cheapest cost per city is wrong.
- BFS by layers keeps the queue sorted by the constrained quantity (flights), so no priority queue is needed — O(K·E).
- "At most `k` stops" means at most `k + 1` edges; getting that off-by-one wrong is the most common bug here.
- Equivalent formulation: `k + 1` rounds of Bellman-Ford relaxation, each round reading a snapshot of the previous round's distances.
