# Number of ways to arrive at destination

**Difficulty:** Hard  ·  **Topic:** Graphs [Concepts & Problems] › Shortest Path Algorithms and Problems

## Problem
You are given `n` intersections labelled `0` to `n-1` and a list of bidirectional roads `roads[i] = [u, v, time]`. You start at intersection `0` and want to reach intersection `n-1`. Count how many distinct paths take the **minimum possible total time**. Because the count can be huge, return it modulo `10^9 + 7`.

```
Input:  n = 7, roads = [[0,6,7],[0,1,2],[1,2,3],[1,3,3],[6,3,3],
                        [3,5,1],[6,5,1],[2,5,1],[0,4,5],[4,6,2]]
Output: 4
```
The shortest time from `0` to `6` is `7`, and exactly four different routes achieve it (the direct road `0→6`, plus `0→4→6`, `0→1→2→5→6`, `0→1→3→5→6`).

## Approach 1: Enumerate every path (brute force)
Do a DFS from `0`, carrying the accumulated time, and record the time of every path that reaches `n-1`. Afterwards, find the smallest recorded time and count how many paths matched it. This is obviously correct but the number of simple paths in a dense graph is exponential, so it dies well before the constraint limits.
- **Time:** O(number of paths), exponential in the worst case
- **Space:** O(n) recursion depth plus the list of path times

## Approach 2: Dijkstra carrying a path counter (optimal)

**The key observation.** Dijkstra already computes `dist[node]` = shortest time to reach `node`. The number of shortest paths obeys a simple recurrence on top of it: a shortest path to `v` must end with some edge `(u, v)` that itself lies on a shortest path, i.e. `dist[u] + w == dist[v]`. So

```
ways[v] = sum of ways[u] over all edges (u,v) with dist[u] + w == dist[v]
```

with `ways[0] = 1` (the empty path). This is a DP over the *shortest-path DAG* — the subgraph of edges that satisfy the tightness condition. That subgraph is acyclic because every edge strictly increases `dist` (weights are positive), so the recurrence is well founded and has no circular dependency.

**Why we can compute it inside Dijkstra.** Dijkstra pops nodes in non-decreasing order of final distance. When we pop `u`, `dist[u]` is already final, so every predecessor of any node on the shortest-path DAG is finalized before its successors. Therefore updating `ways` at relaxation time is safe.

**The algorithm.**
1. Build an adjacency list; set `dist[0] = 0`, `ways[0] = 1`, everything else `dist = ∞`, `ways = 0`.
2. Push `(0, 0)` into a min-heap keyed by distance.
3. Pop `(d, u)`. If `d > dist[u]`, this is a stale heap entry — skip it.
4. For each neighbour `(v, w)`:
   - **Strictly better** (`d + w < dist[v]`): we found a brand-new best time. Set `dist[v] = d + w`, reset `ways[v] = ways[u]` (every shortest way of reaching `u` extends to exactly one way of reaching `v`), and push `v`.
   - **Equally good** (`d + w == dist[v]`): another family of shortest paths arrives. Do `ways[v] = (ways[v] + ways[u]) % MOD`. Do **not** push `v` again — its distance did not change, so nothing downstream needs re-examination beyond what is already queued.
   - Otherwise ignore the edge.
5. Answer is `ways[n-1]`.

**Short dry run** on the example. Start: `dist[0]=0, ways[0]=1`. Popping `0` sets `dist[1]=2 (ways 1)`, `dist[4]=5 (ways 1)`, `dist[6]=7 (ways 1)`. Popping `1` (d=2) sets `dist[2]=5 (ways 1)` and `dist[3]=5 (ways 1)`. Popping `4` (d=5) relaxes `6` with `5+2 = 7 == dist[6]`, so `ways[6] = 1 + 1 = 2`. Popping `2` (d=5) sets `dist[5]=6 (ways 1)`; popping `3` (d=5) gives `5+1 = 6 == dist[5]`, so `ways[5] = 1 + 1 = 2`. Popping `5` (d=6) gives `6+1 = 7 == dist[6]`, so `ways[6] = 2 + 2 = 4`. Final answer `4`.

**Overflow note.** Times can be up to `10^9` and paths up to `n-1` edges, so distances must be stored in 64-bit. Counts are kept modulo `10^9 + 7`, but comparisons of distances must use the true (unmodded) values.
- **Time:** O(E log V) — one Dijkstra pass
- **Space:** O(V + E) for the graph, distance array, count array and heap

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <queue>
#include <climits>
using namespace std;

class Solution {
public:
    int countPaths(int n, vector<vector<int>>& roads) {
        const long long MOD = 1000000007LL;
        vector<vector<pair<int, long long>>> adj(n);
        for (auto& r : roads) {
            adj[r[0]].push_back({r[1], (long long)r[2]});
            adj[r[1]].push_back({r[0], (long long)r[2]});
        }

        vector<long long> dist(n, LLONG_MAX), ways(n, 0);
        dist[0] = 0;
        ways[0] = 1;

        priority_queue<pair<long long, int>, vector<pair<long long, int>>,
                       greater<pair<long long, int>>> pq;
        pq.push({0LL, 0});

        while (!pq.empty()) {
            auto [d, u] = pq.top();
            pq.pop();
            if (d > dist[u]) continue;             // stale entry
            for (auto& [v, w] : adj[u]) {
                long long nd = d + w;
                if (nd < dist[v]) {
                    dist[v] = nd;
                    ways[v] = ways[u];
                    pq.push({nd, v});
                } else if (nd == dist[v]) {
                    ways[v] = (ways[v] + ways[u]) % MOD;
                }
            }
        }
        return (int)(ways[n - 1] % MOD);
    }
};
```

### Java
```java
import java.util.*;

class Solution {
    public int countPaths(int n, int[][] roads) {
        final long MOD = 1_000_000_007L;
        List<long[]>[] adj = new List[n];
        for (int i = 0; i < n; i++) adj[i] = new ArrayList<>();
        for (int[] r : roads) {
            adj[r[0]].add(new long[]{r[1], r[2]});
            adj[r[1]].add(new long[]{r[0], r[2]});
        }

        long[] dist = new long[n];
        long[] ways = new long[n];
        Arrays.fill(dist, Long.MAX_VALUE);
        dist[0] = 0;
        ways[0] = 1;

        PriorityQueue<long[]> pq = new PriorityQueue<>((a, b) -> Long.compare(a[0], b[0]));
        pq.add(new long[]{0, 0});

        while (!pq.isEmpty()) {
            long[] top = pq.poll();
            long d = top[0];
            int u = (int) top[1];
            if (d > dist[u]) continue;
            for (long[] e : adj[u]) {
                int v = (int) e[0];
                long nd = d + e[1];
                if (nd < dist[v]) {
                    dist[v] = nd;
                    ways[v] = ways[u];
                    pq.add(new long[]{nd, v});
                } else if (nd == dist[v]) {
                    ways[v] = (ways[v] + ways[u]) % MOD;
                }
            }
        }
        return (int) (ways[n - 1] % MOD);
    }
}
```

### Python
```python
import heapq
from typing import List

class Solution:
    def countPaths(self, n: int, roads: List[List[int]]) -> int:
        MOD = 10 ** 9 + 7
        adj = [[] for _ in range(n)]
        for u, v, w in roads:
            adj[u].append((v, w))
            adj[v].append((u, w))

        dist = [float('inf')] * n
        ways = [0] * n
        dist[0] = 0
        ways[0] = 1

        pq = [(0, 0)]
        while pq:
            d, u = heapq.heappop(pq)
            if d > dist[u]:
                continue
            for v, w in adj[u]:
                nd = d + w
                if nd < dist[v]:
                    dist[v] = nd
                    ways[v] = ways[u]
                    heapq.heappush(pq, (nd, v))
                elif nd == dist[v]:
                    ways[v] = (ways[v] + ways[u]) % MOD
        return ways[n - 1] % MOD
```

## Key Takeaways
- Counting shortest paths = DP on the shortest-path DAG, the subgraph of edges where `dist[u] + w == dist[v]`.
- On a strict improvement **overwrite** the counter; on a tie **add** to it — mixing these up is the classic bug.
- Only push a node when its distance actually decreases; pushing on ties can blow up the heap and double-count.
- Keep distances in 64-bit and apply the modulus only to the counts, never to the distances used for comparison.
