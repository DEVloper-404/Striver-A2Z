# Subsets I

**Difficulty:** Medium  ·  **Topic:** Recursion [PatternWise] › Subsequences Pattern

## Problem
Given an array `nums` of `n` integers, generate **all `2^n` subsets** (the power set) and return the **sum of each subset**, in any order. The empty subset counts and contributes `0`. Input is small (`n <= 20` typically), so producing every subset is acceptable.

```
Input:  nums = [3, 1, 2]
Output: [0, 2, 1, 3, 3, 5, 4, 6]     (sums of {}, {2}, {1}, {1,2}, {3}, {3,2}, {3,1}, {3,1,2})
```
The same recursion returns the subsets themselves if you collect the elements instead of accumulating a running sum.

## Approach 1: Pick / not-pick recursion (Optimal)
This is the purest form of the subsequence pattern. Stand at index `i` and ask a single yes/no question: *is `nums[i]` in the subset?* Both answers are legal and independent of everything else, so recursing on both covers exactly the `2^n` possibilities — one per root-to-leaf path in a perfect binary tree of depth `n`.

Define `solve(i, sum)`:

1. **Base case** `i == n`: every element has been decided, so `sum` is the sum of one complete subset. Append it to the answer and return.
2. **Take** `nums[i]`: recurse with `solve(i + 1, sum + nums[i])`.
3. **Leave** `nums[i]`: recurse with `solve(i + 1, sum)`.

Notice that we never need to store the subset at all — carrying the running `sum` down the recursion is enough, and it is why this version needs only O(n) auxiliary space. If you *do* want the elements, push `nums[i]` before the take-branch and pop it right after (backtracking), then copy the working list at the base case.

**Why exactly `2^n` results and no duplicates or omissions:** every subset corresponds to a unique bit pattern of take/leave decisions, and the recursion enumerates every bit pattern exactly once. Equal *sums* can of course repeat (see `3` twice in the example above) — that is expected; we are listing subsets, not distinct sums.

**Dry run on `[3, 1, 2]`.** The tree is depth 3. Following the take-branch first: `3` taken → `1` taken → `2` taken gives `6`; backing off the last decision gives `4`; then dropping `1` gives `5` and `3`; then dropping `3` entirely gives `3`, `1`, `2`, `0`. Read in the recursion's own order (take-first) the output is `[6, 4, 5, 3, 3, 1, 2, 0]`; the leave-first order gives the listing shown above. Both are valid since order is unconstrained.

- **Time:** O(2^n) — one leaf per subset, O(1) work per node.
- **Space:** O(n) for the recursion stack (the output list of `2^n` sums is not counted).

## Approach 2: Bitmask iteration (no recursion)
Since `n` is small, each subset can be named by an integer mask in `[0, 2^n)`, where bit `j` means "`nums[j]` is included". Loop over all masks; for each, loop over the `n` bits, add `nums[j]` whenever bit `j` is set, and push the total.

This is easy to reason about and avoids stack depth entirely, but it costs an extra factor of `n` because each mask re-scans all bits. (You can recover O(2^n) with the trick `sum[mask] = sum[mask without lowest set bit] + nums[index of lowest set bit]`, at the price of an O(2^n) table.)

- **Time:** O(2^n · n)
- **Space:** O(1) auxiliary.

## Code (Optimal)

### C++
```cpp
#include <vector>
using namespace std;

class Solution {
public:
    vector<int> subsetSums(vector<int>& nums) {
        vector<int> res;
        res.reserve(1 << nums.size());
        solve(0, 0, nums, res);
        return res;
    }

private:
    void solve(int i, int sum, vector<int>& nums, vector<int>& res) {
        if (i == (int)nums.size()) {
            res.push_back(sum);
            return;
        }
        solve(i + 1, sum + nums[i], nums, res);   // take nums[i]
        solve(i + 1, sum, nums, res);             // leave nums[i]
    }
};
```

### Java
```java
import java.util.*;

class Solution {
    public List<Integer> subsetSums(int[] nums) {
        List<Integer> res = new ArrayList<>();
        solve(0, 0, nums, res);
        return res;
    }

    private void solve(int i, int sum, int[] nums, List<Integer> res) {
        if (i == nums.length) {
            res.add(sum);
            return;
        }
        solve(i + 1, sum + nums[i], nums, res);   // take
        solve(i + 1, sum, nums, res);             // leave
    }
}
```

### Python
```python
from typing import List

class Solution:
    def subsetSums(self, nums: List[int]) -> List[int]:
        res: List[int] = []
        n = len(nums)

        def solve(i: int, total: int) -> None:
            if i == n:
                res.append(total)
                return
            solve(i + 1, total + nums[i])   # take
            solve(i + 1, total)             # leave

        solve(0, 0)
        return res
```

## Key Takeaways
- Pick / not-pick at every index is the base template every subsequence problem specialises: Combination Sum adds reuse, Subsets II adds duplicate skipping, subset-sum-equals-K adds a target check.
- Carrying an accumulator (the running sum) down the recursion is cheaper than building and copying a list at every leaf.
- Don't forget the empty subset — it is the leaf reached by taking the "leave" branch `n` times, and its sum is `0`.
- The output has `2^n` entries no matter what, so exponential time is unavoidable; only the auxiliary space (O(n)) is worth optimising.
