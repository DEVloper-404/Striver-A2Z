# Unique paths II

**Difficulty:** Medium  ·  **Topic:** Dynamic Programming [Patterns and Problems] › 2D/3D DP and DP on Grids

## Problem
An `m × n` grid contains obstacles: `grid[i][j] == 1` means the cell is blocked, `0` means it is free. A robot starts at `(0,0)` and moves only **right** or **down** to reach `(m-1, n-1)`, never stepping on a blocked cell. Count the distinct paths. If the start or the end is blocked, the answer is `0`.

```
Input:  grid = [[0, 0, 0],
                [0, 1, 0],
                [0, 0, 0]]
Output: 2
        Right-Right-Down-Down and Down-Down-Right-Right
        (the middle cell is blocked, killing the other four routes)
```

## Approach 1: Recursion (brute force)

Start from the same "split on the last move" idea as the obstacle-free version, and add one rule for blocked cells.

```
f(i, j) = 0                        if i < 0 or j < 0        (off the grid)
f(i, j) = 0                        if grid[i][j] == 1       (blocked: no path can end here)
f(0, 0) = 1                        (if it is not blocked)
f(i, j) = f(i-1, j) + f(i, j-1)    otherwise
```

The single new line is the obstacle check, and it is worth understanding *why* returning `0` is exactly right: `f(i, j)` counts paths that *terminate at* `(i, j)`. If the cell is blocked, no legal path can terminate there, so the count is zero — and because every path through that cell would have had to stop there first, all such paths are automatically excluded from every downstream cell too. Blocked cells act as zeroes that propagate naturally through the additive recurrence.

Note the ordering inside the recursion: check the obstacle **before** the `(0,0)` base case, otherwise a blocked start cell would wrongly return 1.
- **Time:** O(2^(m+n))
- **Space:** O(m+n) recursion stack

## Approach 2: Memoization
State = `(i, j)`, so `m·n` states with O(1) work each. Cache in `dp[i][j]` initialised to `-1`.
- **Time:** O(m·n)
- **Space:** O(m·n) table + O(m+n) stack

## Approach 3: Tabulation
Sweep top-to-bottom, left-to-right so that `dp[i-1][j]` and `dp[i][j-1]` are ready when needed:

```
for i in 0..m-1:
  for j in 0..n-1:
      if grid[i][j] == 1:        dp[i][j] = 0
      elif i == 0 and j == 0:    dp[i][j] = 1
      else:
          up   = (i > 0) ? dp[i-1][j] : 0
          left = (j > 0) ? dp[i][j-1] : 0
          dp[i][j] = up + left
```

Notice we *cannot* pre-fill row 0 and column 0 with 1s as in the obstacle-free problem: an obstacle anywhere in row 0 makes every cell to its right unreachable. The recurrence above handles that automatically — the blocked cell becomes 0, and each cell after it adds `0 + 0`.

**Dry run on the example.**

| | j=0 | j=1 | j=2 |
|---|---|---|---|
| **i=0** | 1 | 1 | 1 |
| **i=1** | 1 | 0 (blocked) | 1 |
| **i=2** | 1 | 1 | **2** |

Row 1: `dp[1][0] = 1` (from above), `dp[1][1] = 0` because it is blocked, `dp[1][2] = dp[0][2] + dp[1][1] = 1 + 0 = 1`. Row 2: `dp[2][0] = 1`, `dp[2][1] = dp[1][1] + dp[2][0] = 0 + 1 = 1`, `dp[2][2] = dp[1][2] + dp[2][1] = 1 + 1 = 2`. Answer **2**. ✔
- **Time:** O(m·n)
- **Space:** O(m·n)

## Approach 4: One rolling row (Optimal)

Row `i` reads only row `i-1` (the "from above" term) and the current row's own left neighbour. So one array of length `n` is enough. Even better, update it **in place** left to right: at the moment we write index `j`, `dp[j]` still holds the previous row's value (up) and `dp[j-1]` already holds the current row's value (left) — exactly the two terms we need.

**Algorithm.**
1. `dp = array of n zeros`.
2. For `i = 0 … m-1`, for `j = 0 … n-1`:
   - if `grid[i][j] == 1` → `dp[j] = 0`
   - else if `i == 0 && j == 0` → `dp[j] = 1`
   - else → `dp[j] = dp[j] (up, 0 when i == 0) + (j > 0 ? dp[j-1] : 0)`
3. Return `dp[n-1]`.

Starting the array at all zeros makes the `i == 0` case work without a branch: for the first row, `dp[j]` is still 0, so each cell only inherits from its left neighbour, which is what we want.

Combinatorics (`C(m+n-2, m-1)`) no longer applies — obstacles destroy the symmetry that made every move-ordering valid — so the DP is genuinely the optimal approach here.
- **Time:** O(m·n)
- **Space:** O(n)

## Code (Optimal)

### C++
```cpp
#include <vector>
using namespace std;

class Solution {
public:
    int uniquePathsWithObstacles(vector<vector<int>>& grid) {
        int m = grid.size(), n = grid[0].size();
        if (grid[0][0] == 1 || grid[m - 1][n - 1] == 1) return 0;

        vector<int> dp(n, 0);
        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (grid[i][j] == 1) {
                    dp[j] = 0;                       // blocked: nothing ends here
                } else if (i == 0 && j == 0) {
                    dp[j] = 1;                       // start cell
                } else {
                    int left = (j > 0) ? dp[j - 1] : 0;
                    dp[j] = dp[j] + left;            // dp[j] currently = row above
                }
            }
        }
        return dp[n - 1];
    }
};
```

### Python
```python
from typing import List


class Solution:
    def uniquePathsWithObstacles(self, grid: List[List[int]]) -> int:
        m, n = len(grid), len(grid[0])
        if grid[0][0] == 1 or grid[m - 1][n - 1] == 1:
            return 0

        dp = [0] * n
        for i in range(m):
            for j in range(n):
                if grid[i][j] == 1:
                    dp[j] = 0                        # blocked: nothing ends here
                elif i == 0 and j == 0:
                    dp[j] = 1                        # start cell
                else:
                    left = dp[j - 1] if j > 0 else 0
                    dp[j] = dp[j] + left             # dp[j] currently = row above
        return dp[n - 1]
```

## Key Takeaways
- Same recurrence as plain Unique Paths, plus one rule: a blocked cell contributes `0`, which then propagates through the sums automatically.
- Check the obstacle **before** the start-cell base case, or a blocked `(0,0)` returns 1.
- Do not pre-fill row 0 / column 0 with 1s — an obstacle in them cuts off everything after it; let the recurrence compute them.
- In-place single-array update works because `dp[j]` holds "up" and `dp[j-1]` holds "left" at exactly the right moment during a left-to-right sweep.
- The `C(m+n-2, m-1)` combinatorial shortcut is invalid once obstacles exist; DP is the only general answer.
