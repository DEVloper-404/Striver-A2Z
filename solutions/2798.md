# Stock Buy and Sell

**Difficulty:** Medium  ·  **Topic:** Solve Problems on Arrays [Easy -> Medium -> Hard] › Medium

## Problem
`prices[i]` is the price of a stock on day `i`. You may buy once and sell once, and the sale must happen on a day after the purchase. Return the maximum profit you can make; if no profitable transaction exists return 0 (do not trade).

```
Input:  prices = [7, 1, 5, 3, 6, 4]
Output: 5        (buy at 1 on day 1, sell at 6 on day 4)
```

## Approach 1: Brute Force
For every buy day `i`, look at every later day `j > i` and compute `prices[j] - prices[i]`. Keep the largest difference (and at least 0).
- **Time:** O(n²)
- **Space:** O(1)

## Approach 2: Track the Minimum So Far (Optimal)
The best sale on day `i` is `prices[i]` minus the cheapest price seen on any earlier day. So sweep left to right keeping `minSoFar`; at each day compute the profit if we sold today, update the answer, and then lower `minSoFar` if today's price is cheaper. One pass, constant memory.
- **Time:** O(n)
- **Space:** O(1)

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <algorithm>
#include <climits>
using namespace std;

class Solution {
public:
    int maxProfit(vector<int>& prices) {
        int minSoFar = INT_MAX, best = 0;
        for (int p : prices) {
            best = max(best, p - minSoFar);
            minSoFar = min(minSoFar, p);
        }
        return best;
    }
};
```

### Python
```python
from typing import List

class Solution:
    def maxProfit(self, prices: List[int]) -> int:
        min_so_far = float("inf")
        best = 0
        for p in prices:
            best = max(best, p - min_so_far)
            min_so_far = min(min_so_far, p)
        return best
```

## Key Takeaways
- "Best of (something today) minus (best of something earlier)" is a one-pass prefix-minimum pattern.
- Update the profit *before* updating the minimum so buying and selling on the same day is impossible.
- Start `best` at 0 so a strictly decreasing price list returns 0 rather than a negative number.
- Guard against `INT_MAX` subtraction: on the first iteration `p - INT_MAX` is negative and safe, but never reverse the operand order.
