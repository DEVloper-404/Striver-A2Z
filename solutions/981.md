# Z function

**Difficulty:** Hard  ·  **Topic:** Strings › Hard Problems

## Problem
For a string `s` of length `n`, the **Z array** stores at every index `i` the length of the longest substring starting at `i` that is also a prefix of `s`. Formally, `z[i]` = the largest `k` such that `s[0..k-1] == s[i..i+k-1]`. By convention `z[0] = n` (the whole string is trivially its own prefix). Compute the Z array in O(n), then use it to find every occurrence of a pattern in a text.

```
Input:  s = "aabxaayaab"
Output: z = [10, 1, 0, 0, 2, 1, 0, 3, 1, 0]
```

Read a couple of entries to see the definition in action: `z[4] = 2` because `s[4..5] = "aa"` matches the prefix `"aa"` but `s[6] = 'y'` breaks the third character. `z[7] = 3` because `s[7..9] = "aab"` matches the prefix `"aab"` and then the string ends.

## Approach 1: Brute Force — compare from every index
For each `i`, walk `j` forward from 0 while `s[j] == s[i + j]` and record how far you got.

Correct and two lines long, but on a string like `"aaaa…a"` every index matches almost to the end, so the total work is `n + (n-1) + (n-2) + …` = Θ(n²). The inefficiency is that these comparisons repeat information we have already established: if we know `s[4..9]` matches the prefix, we already know a lot about what sits at index 5, 6, 7… and re-scanning throws that away.

- **Time:** O(n²)
- **Space:** O(n)

## Approach 2: Optimal — the Z-box (maintain `[l, r]`)

### The invariant
Keep a half-open window `[l, r)` — the **Z-box** — which is the match interval that reaches furthest right among all we have discovered so far. Its defining property is:

```
s[l .. r-1]  ==  s[0 .. r-l-1]     (the box is a verbatim copy of a prefix of s)
```

We process indices left to right and update `[l, r]` whenever a match extends past the current `r`.

### Using the box to skip work
Suppose we are at index `i` and `i < r`, so `i` lies inside the box. Because the box is a verbatim copy of a prefix, the character at `i` corresponds to the character at position `i - l` in that prefix. So whatever we learned at index `i - l` transfers here — with one caveat.

Let `k = i - l`. Two cases:

- **`z[k] < r - i`.** The match at `k` ends strictly before the box does, so the entire match plus the mismatching character that terminated it are all inside the box, and the box is an exact copy. Therefore `z[i] = z[k]` exactly, and no comparison is needed at all.
- **`z[k] >= r - i`.** The match at `k` would run past the right edge of the box. We can only trust the copied part, so we start with `z[i] = r - i` and then **extend by brute force** past `r`.

Both cases are captured by initialising `z[i] = min(r - i, z[i - l])` and then running the naive extension loop; in the first case the loop immediately fails and costs O(1).

If `i >= r` we know nothing, so `z[i]` starts at 0 and we extend naively from scratch.

Finally, if `i + z[i] > r`, this match reaches further right than the current box, so set `l = i`, `r = i + z[i]`.

### Why it is linear
Every iteration of the inner extension loop compares a character strictly to the right of `r` and, on success, pushes `r` one step right. Since `r` only ever increases and is bounded by `n`, the inner loop runs at most `n` times *in total across the whole algorithm*. The outer loop is `n` iterations. Total O(n).

### Dry run on `s = "aabxaayaab"`
- `z[0] = 10`, box empty (`l = r = 0`).
- `i=1`: `i >= r`, compare naively: `s[0]='a'` vs `s[1]='a'` ✓, `s[1]='a'` vs `s[2]='b'` ✗ → `z[1]=1`. Box becomes `[1, 2]`.
- `i=2`: `i >= r`(2 ≥ 2), naive: `s[0]='a'` vs `s[2]='b'` ✗ → `z[2]=0`.
- `i=3`: naive: `'a'` vs `'x'` ✗ → `z[3]=0`.
- `i=4`: naive: `"aa"` matches, `s[2]='b'` vs `s[6]='y'` ✗ → `z[4]=2`. Box becomes `[4, 6]`.
- `i=5`: inside box, `k = 5-4 = 1`, `z[1]=1`, `r-i = 1` → start at `min(1,1)=1`, try to extend: `s[1]='a'` vs `s[6]='y'` ✗ → `z[5]=1`.
- `i=6`: `k=2`, `z[2]=0`, `r-i=0` → start at 0, `s[0]='a'` vs `s[6]='y'` ✗ → `z[6]=0`.
- `i=7`: outside box, naive: `"aab"` matches then string ends → `z[7]=3`. Box becomes `[7, 10]`.
- `i=8`: inside box, `k=1`, `z[1]=1 < r-i=2` → copied directly, `z[8]=1`, **zero comparisons**.
- `i=9`: `k=2`, `z[2]=0 < r-i=1` → `z[9]=0`, zero comparisons.

That gives `[10,1,0,0,2,1,0,3,1,0]`, matching the expected output — and notice the last two entries came for free.

### Pattern matching with Z
To find `pat` inside `text`, build `combined = pat + '#' + text` where `#` is a character appearing in neither string. Compute the Z array of `combined`. Wherever `z[i] == pat.length()`, the pattern occurs in the text at index `i - pat.length() - 1`. The separator is essential: without it a Z value could run past the end of the pattern into the text and overcount.

- **Time:** O(n) to build the Z array; O(n + m) for pattern matching
- **Space:** O(n) for the Z array (plus O(n + m) for the concatenated string)

## Code (Optimal)

### C++
```cpp
#include <string>
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    // z[i] = length of the longest common prefix of s and s[i..]
    vector<int> zFunction(const string& s) {
        int n = (int)s.size();
        vector<int> z(n, 0);
        if (n == 0) return z;
        z[0] = n;

        int l = 0, r = 0;                 // the Z-box: s[l..r-1] == s[0..r-l-1]
        for (int i = 1; i < n; i++) {
            if (i < r) z[i] = min(r - i, z[i - l]);   // reuse the mirrored answer
            while (i + z[i] < n && s[z[i]] == s[i + z[i]]) z[i]++;   // extend past r
            if (i + z[i] > r) { l = i; r = i + z[i]; }               // new furthest box
        }
        return z;
    }

    // All starting indices of pat in text, via pat + '#' + text.
    vector<int> search(const string& text, const string& pat) {
        int m = (int)pat.size();
        vector<int> res;
        if (m == 0 || m > (int)text.size()) return res;

        vector<int> z = zFunction(pat + '#' + text);
        for (int i = m + 1; i < (int)z.size(); i++)
            if (z[i] == m) res.push_back(i - m - 1);
        return res;
    }
};
```

import java.util.*;

class Solution {
    // z[i] = length of the longest common prefix of s and s[i..]
    public int[] zFunction(String s) {

        int[] z = new int[n];

### Python
```python
from typing import List


class Solution:
    def z_function(self, s: str) -> List[int]:
        """z[i] = length of the longest common prefix of s and s[i:]."""
        n = len(s)
        z = [0] * n
        if n == 0:
            return z
        z[0] = n

        l = r = 0                          # the Z-box: s[l:r] == s[0:r-l]
        for i in range(1, n):
            if i < r:
                z[i] = min(r - i, z[i - l])       # reuse the mirrored answer
            while i + z[i] < n and s[z[i]] == s[i + z[i]]:
                z[i] += 1                          # extend past r
            if i + z[i] > r:
                l, r = i, i + z[i]                 # new furthest box
        return z

    def search(self, text: str, pat: str) -> List[int]:
        """All starting indices of pat in text, via pat + '#' + text."""
        m = len(pat)
        if m == 0 or m > len(text):
            return []
        z = self.z_function(pat + "#" + text)
        return [i - m - 1 for i in range(m + 1, len(z)) if z[i] == m]
```

## Key Takeaways
- `z[i]` answers "how much of the prefix restarts here?" — the Z-box `[l, r]` is just a memo of the furthest-right prefix copy found so far.
- `z[i] = min(r - i, z[i - l])` is safe because the box is a verbatim prefix copy; anything beyond `r` is unverified and must be compared for real.
- Linearity comes from `r` being monotonically non-decreasing: every extra character comparison advances `r`, so there are at most `n` of them overall.
- For pattern search, concatenate `pat + separator + text` with a separator that occurs in neither string, or matches can bleed across the boundary.
