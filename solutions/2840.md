# Kth smallest element in an array [use priority queue]

**Difficulty:** Medium  ·  **Topic:** Heaps [Learning, Medium, Hard Problems] › Medium Problems

## Problem
Given an integer array `nums` and an integer `k` (`1 <= k <= n`), return the element that would sit at index `k - 1` if the array were sorted in ascending order. Duplicates count as separate positions. The problem asks you to use a priority queue (heap).

```
Input:  nums = [7, 10, 4, 3, 20, 15], k = 3
Output: 7
```
Sorted: `3 4 7 10 15 20`, and the third value is 7.

## Approach 1: Sort
Sort ascending and return `nums[k - 1]`. Correct, but sorts everything even though only one position matters.
- **Time:** O(n log n)
- **Space:** O(1) extra

## Approach 2: Max-heap of size k (optimal for heaps)
Mirror the "k-th largest" trick. Keep a **max**-heap that holds the `k` smallest elements seen so far. Push each element; if the heap grows beyond `k`, pop the largest. After the scan the heap holds exactly the `k` smallest values, and its top (the largest among them) is the k-th smallest.

Why it works: an element that gets evicted is larger than at least `k` other elements, so it cannot be among the k smallest.
- **Time:** O(n log k)
- **Space:** O(k)

## Approach 3: Quickselect
Partition around a pivot (smaller elements to the left). If the pivot lands at index `k - 1` it is the answer; otherwise recurse into the side that contains index `k - 1`. Expected linear time, but not heap-based, so it is a bonus rather than the intended solution here.
- **Time:** O(n) average
- **Space:** O(1) extra

## Code (Optimal)

### C++
```cpp
#include <bits/stdc++.h>
using namespace std;

class Solution {
public:
    int kthSmallest(vector<int>& nums, int k) {
        priority_queue<int> maxHeap; // holds the k smallest so far
        for (int x : nums) {
            maxHeap.push(x);
            if ((int)maxHeap.size() > k) maxHeap.pop();
        }
        return maxHeap.top();
    }
};
```

### Java
```java
import java.util.*;

class Solution {
    public int kthSmallest(int[] nums, int k) {
        PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Collections.reverseOrder());
        for (int x : nums) {
            maxHeap.offer(x);
            if (maxHeap.size() > k) maxHeap.poll();
        }
        return maxHeap.peek();
    }
}
```

### Python
```python
import heapq
from typing import List


class Solution:
    def kthSmallest(self, nums: List[int], k: int) -> int:
        # heapq is a min-heap, so store negated values to simulate a max-heap
        max_heap = []
        for x in nums:
            heapq.heappush(max_heap, -x)
            if len(max_heap) > k:
                heapq.heappop(max_heap)
        return -max_heap[0]
```

## Key Takeaways
- k-th **smallest** uses a **max**-heap of size k; k-th **largest** uses a **min**-heap of size k. The heap top is always the "boundary" element.
- Capping the heap at k elements keeps every push/pop at O(log k) instead of O(log n).
- Python's `heapq` only offers a min-heap; negate values (or wrap them in a tuple) to get max-heap behaviour.
- When `k == n` the answer is simply the maximum, and when `k == 1` it is the minimum; the same code handles both.
