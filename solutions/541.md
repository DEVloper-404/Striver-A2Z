# Assign Cookies

**Difficulty:** Easy  ·  **Topic:** Dynamic Programming [Patterns and Problems] › DP on Subsequences

## Problem
Each child `i` has a greed factor `g[i]` — the smallest cookie size that will satisfy them. Each cookie `j` has a size `s[j]`. A child can be given at most one cookie, and is content only if `s[j] >= g[i]`. Return the maximum number of content children.

```
Input:  g = [1, 2, 3], s = [1, 1]
Output: 1
Explanation: Both cookies have size 1, so only the child with greed 1 can be satisfied.

Input:  g = [1, 2], s = [1, 2, 3]
Output: 2
```

## Approach 1: Brute Force (try every assignment)
For each child, scan the remaining cookies for one that fits and mark it used. Doing this without any ordering does not guarantee an optimum — feeding a huge cookie to a barely-greedy child can waste it. To be safe you would have to try all matchings, which is factorial in the worst case.

- **Time:** exponential (O(n!) in the worst case)
- **Space:** O(n)

## Approach 2: Optimal (sort both, two pointers, greedy)

**The key observation.** Suppose the least greedy child can be satisfied at all. Then giving them the *smallest* cookie that fits is never worse than any other choice. Why? Any larger cookie that would have fit this child also fits every child with greater or equal greed, so handing over the small cookie keeps the more useful large ones in reserve. This is a classic exchange argument: take any optimal assignment, and if it gives that child a bigger cookie, swap in the smallest fitting one — the swapped-out cookie can still cover whoever it covered before, so the count does not drop.

Applying the argument repeatedly gives the algorithm: process children from least greedy to most greedy, and always hand out the smallest unused cookie that satisfies the current child.

**The algorithm.**
1. Sort `g` ascending and `s` ascending.
2. Keep two pointers, `child = 0` into `g` and `cookie = 0` into `s`.
3. While both pointers are in range:
   - If `s[cookie] >= g[child]`, this cookie satisfies this child. Count it and advance **both** pointers.
   - Otherwise the cookie is too small for the least greedy remaining child, so it is too small for everyone left. Discard it: advance `cookie` only.
4. The number of times we advanced both pointers is the answer.

Each iteration moves at least one pointer forward, so the scan is linear after sorting.

**Dry run on g = [1, 2, 3], s = [1, 1].**
- child=0 (greed 1), cookie=0 (size 1): 1 >= 1, satisfy. count = 1, child=1, cookie=1.
- child=1 (greed 2), cookie=1 (size 1): 1 < 2, cookie is useless. cookie=2.
- cookie pointer is out of range → stop. Answer 1.

**Dry run on g = [1, 2], s = [1, 2, 3].**
- greed 1 vs size 1 → satisfy, count 1.
- greed 2 vs size 2 → satisfy, count 2.
- children exhausted → answer 2 (cookie of size 3 goes unused, which is fine).

- **Time:** O(n log n + m log m) for sorting, O(n + m) for the scan
- **Space:** O(1) beyond the sorting

## Code (Optimal)

### C++
```cpp
class Solution {
public:
    int findContentChildren(vector<int>& g, vector<int>& s) {
        sort(g.begin(), g.end());
        sort(s.begin(), s.end());

        int child = 0, cookie = 0;
        while (child < (int)g.size() && cookie < (int)s.size()) {
            if (s[cookie] >= g[child]) child++;   // this cookie satisfies this child
            cookie++;                             // the cookie is consumed either way
        }
        return child;
    }
};
```

### Python
```python
class Solution:
    def findContentChildren(self, g, s):
        g.sort()
        s.sort()

        child = cookie = 0
        while child < len(g) and cookie < len(s):
            if s[cookie] >= g[child]:
                child += 1          # satisfied
            cookie += 1             # cookie used or discarded
        return child
```

## Key Takeaways
- Sorting both arrays turns a matching problem into a single linear sweep — the classic "sort then two pointers" greedy.
- The exchange argument is the proof: giving the least greedy child the smallest fitting cookie never blocks a later child.
- Advance the cookie pointer unconditionally; a cookie too small for the least greedy remaining child is too small for all of them.
- The answer is just the child pointer at the end, so no separate counter is needed. Empty `g` or `s` returns 0 naturally.
