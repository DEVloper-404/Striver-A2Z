# Swim in Rising Water

**Difficulty:** Medium  ·  **Topic:** Graphs [Concepts & Problems] › MinimumSpanningTree/Disjoint Set and Problems

## Problem
You are given an `n × n` grid where `grid[r][c]` is the elevation of that square. Rain falls: at time `t` the water level everywhere is `t`, and you may swim from a square to a 4-directionally adjacent square only if **both** squares have elevation `≤ t`. Starting at `(0, 0)` at time `0`, return the least time `t` at which you can reach `(n-1, n-1)`. Swimming itself takes no time.

```
Input:  grid = [[0,2],[1,3]]
Output: 3
```
At `t = 0` you are stuck on `(0,0)`. At `t = 1` you can reach `(1,0)`. Only at `t = 3` is `(1,1)` submerged enough to enter, so the answer is `3`.

## Approach 1: Binary search on the answer + BFS
The predicate "can I reach the end when the water level is `t`?" is **monotone**: if a path exists at level `t`, the same path works at any level above `t`. So binary search `t` over `[grid[0][0], n²-1]` and, for each candidate, run a BFS/DFS that may only step on cells with elevation `≤ t`. This is a clean and very common technique for "minimize the maximum" problems.
- **Time:** O(n² log(n²)) = O(n² log n)
- **Space:** O(n²)

## Approach 2: Dijkstra on "minimize the maximum" (optimal)

**The key observation — reframe the cost function.** The time to finish a path is not the *sum* of its elevations, it is the **maximum** elevation along it (you must wait for the highest square on the route to be covered, and everything before it is already passable by then). So the task is: over all paths from `(0,0)` to `(n-1,n-1)`, minimise the maximum cell value. This is called the *minimax path* or *bottleneck shortest path*.

**Why Dijkstra still applies.** Ordinary Dijkstra relaxes with `dist[v] = dist[u] + w`. Swap the `+` for a `max`:

```
cost[v] = min over neighbours u of  max(cost[u], grid[v])
```

Dijkstra's correctness only needs the relaxation operator to be **monotone and non-decreasing** — extending a path must never make it cheaper. `max` satisfies that just as `+` does (with non-negative weights), so the same greedy "pop the smallest tentative cost, it is final" argument goes through unchanged.

**The algorithm.**
1. Min-heap of `(cost, r, c)`; push `(grid[0][0], 0, 0)`. Keep a `visited` grid.
2. Pop the smallest `(t, r, c)`. Skip it if already visited; otherwise mark it visited.
3. If `(r, c)` is the bottom-right cell, **return `t`** — because the heap pops in non-decreasing order of cost, the first time we reach the target we have the minimum possible bottleneck.
4. Otherwise, for each unvisited in-bounds neighbour `(nr, nc)`, push `(max(t, grid[nr][nc]), nr, nc)`. The `max` is the whole trick: entering a taller cell raises the required time; entering a shorter one costs nothing extra.

**Short dry run** on `[[0,2],[1,3]]`.
- Push `(0, 0, 0)`. Pop it; not the target. Neighbours: `(1,0)` with `max(0, 1) = 1`, `(0,1)` with `max(0, 2) = 2`. Heap: `(1,1,0), (2,0,1)`.
- Pop `(1, 1, 0)`. Not the target. Neighbour `(1,1)` costs `max(1, 3) = 3`. Push.
- Pop `(2, 0, 1)`. Not the target. Neighbour `(1,1)` costs `max(2, 3) = 3`; push (a duplicate, harmless).
- Pop `(3, 1, 1)` — the target. Return `3`. ✓

**Approach 3 — DSU by elevation (worth knowing).** Since all values `0 … n²-1` are distinct, sort the cells by elevation and "activate" them one at a time, unioning each newly activated cell with its already-activated neighbours. The answer is the elevation at which `(0,0)` and `(n-1,n-1)` first land in the same component. This is Kruskal's on the grid and runs in `O(n² α(n²))` after the counting sort — even a touch faster, and it explains why this problem sits in the MST section: the minimax path between two nodes is exactly the path between them in the minimum spanning tree.
- **Time:** O(n² log n) for the Dijkstra version
- **Space:** O(n²) for the heap and visited grid

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <algorithm>
#include <queue>
#include <tuple>
using namespace std;

class Solution {
public:
    int swimInWater(vector<vector<int>>& grid) {
        int n = grid.size();
        vector<vector<char>> visited(n, vector<char>(n, 0));
        const int dr[4] = {-1, 1, 0, 0};
        const int dc[4] = {0, 0, -1, 1};

        // min-heap of {time, row, col}
        priority_queue<tuple<int,int,int>, vector<tuple<int,int,int>>,
                       greater<tuple<int,int,int>>> pq;
        pq.push({grid[0][0], 0, 0});

        while (!pq.empty()) {
            auto [t, r, c] = pq.top();
            pq.pop();
            if (visited[r][c]) continue;
            visited[r][c] = 1;
            if (r == n - 1 && c == n - 1) return t;
            for (int d = 0; d < 4; d++) {
                int nr = r + dr[d], nc = c + dc[d];
                if (nr < 0 || nr >= n || nc < 0 || nc >= n) continue;
                if (visited[nr][nc]) continue;
                pq.push({max(t, grid[nr][nc]), nr, nc});   // bottleneck cost
            }
        }
        return -1;   // unreachable on a valid grid
    }
};
```

### Java
```java
import java.util.*;

class Solution {
    public int swimInWater(int[][] grid) {
        int n = grid.length;
        boolean[][] visited = new boolean[n][n];
        int[] dr = {-1, 1, 0, 0};
        int[] dc = {0, 0, -1, 1};

        // {time, row, col}
        PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> Integer.compare(a[0], b[0]));
        pq.add(new int[]{grid[0][0], 0, 0});

        while (!pq.isEmpty()) {
            int[] cur = pq.poll();
            int t = cur[0], r = cur[1], c = cur[2];
            if (visited[r][c]) continue;
            visited[r][c] = true;
            if (r == n - 1 && c == n - 1) return t;
            for (int d = 0; d < 4; d++) {
                int nr = r + dr[d], nc = c + dc[d];
                if (nr < 0 || nr >= n || nc < 0 || nc >= n) continue;
                if (visited[nr][nc]) continue;
                pq.add(new int[]{Math.max(t, grid[nr][nc]), nr, nc});
            }
        }
        return -1;
    }
}
```

### Python
```python
import heapq
from typing import List

class Solution:
    def swimInWater(self, grid: List[List[int]]) -> int:
        n = len(grid)
        visited = [[False] * n for _ in range(n)]
        pq = [(grid[0][0], 0, 0)]           # (time, row, col)

        while pq:
            t, r, c = heapq.heappop(pq)
            if visited[r][c]:
                continue
            visited[r][c] = True
            if r == n - 1 and c == n - 1:
                return t
            for nr, nc in ((r - 1, c), (r + 1, c), (r, c - 1), (r, c + 1)):
                if 0 <= nr < n and 0 <= nc < n and not visited[nr][nc]:
                    heapq.heappush(pq, (max(t, grid[nr][nc]), nr, nc))
        return -1
```

## Key Takeaways
- The path cost here is a **maximum**, not a sum — swapping `+` for `max` in Dijkstra's relaxation solves minimax/bottleneck path problems directly.
- Popping in non-decreasing cost order means the first arrival at the target is already optimal, so you can return immediately.
- The `visited` check on pop handles the duplicate heap entries created by pushing without decrease-key.
- Two good alternatives: binary search the water level plus a reachability BFS, or Kruskal-style DSU activating cells in elevation order — the latter shows this is really an MST bottleneck query.
