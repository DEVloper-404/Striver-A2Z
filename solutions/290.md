# House robber

**Difficulty:** Medium  ·  **Topic:** Dynamic Programming [Patterns and Problems] › 1D DP

## Problem
Houses are arranged in a **circle**: house `0` and house `n-1` are neighbours. Each house `i` holds `nums[i]` money. You cannot rob two adjacent houses (the alarm goes off), and because of the circle that includes robbing the first and the last together. Return the maximum money you can collect.

```
Input:  nums = [2, 3, 2]
Output: 3
        Robbing houses 0 and 2 (2 + 2 = 4) is illegal — they are adjacent
        on the circle — so the best legal choice is house 1 alone.
```

## Approach 1: Recursion with a "did I take the first house?" flag (brute force)
The circular constraint couples the two ends, so a naive fix is to carry an extra boolean through the recursion: while deciding house `n-1`, you must know whether house `0` was taken. That doubles the state space and makes the recursion awkward, and without memoization it is still `O(2^n)`. It works, but there is a much cleaner reformulation.
- **Time:** O(2^n)
- **Space:** O(n) recursion stack

## Approach 2: Split into two linear problems (Optimal)

**The key observation.** In any valid selection, houses `0` and `n-1` are *never both* robbed. So every valid selection falls into at least one of two cases:

- **Case A — house `n-1` is not robbed.** Then the whole choice lives inside the sub-array `nums[0 … n-2]`, and inside that sub-array the ends are no longer neighbours. It is a plain linear House Robber.
- **Case B — house `0` is not robbed.** Then everything lives inside `nums[1 … n-1]`, again a plain linear problem.

The answer is `max(caseA, caseB)`.

Two things to convince yourself of:

1. **Nothing is missed.** Any legal circular selection omits at least one of the two ends (it cannot contain both), so it appears in Case A, or Case B, or both.
2. **Nothing illegal is counted.** Each case runs on a *contiguous* sub-array whose first and last elements are not adjacent in the circle, so the linear "no two adjacent" rule is exactly the right rule there. A selection valid in Case A can never contain `n-1`, hence can never pair `0` with `n-1`.

Selections that omit both ends are counted in both cases — that is harmless, since we take a maximum, not a sum.

**The linear helper.** For a plain row of houses, the standard pick/skip DP applies: at index `i`, either take `nums[i]` and add the best answer up to `i-2`, or skip it and keep the best answer up to `i-1`.

```
prev2 = 0, prev1 = 0
for each value v in the segment:
    cur   = max(v + prev2, prev1)
    prev2 = prev1
    prev1 = cur
answer = prev1
```
Starting both variables at `0` handles the empty prefix cleanly and works even for a one-element segment.

**Edge case.** If `n == 1` there is no circle to speak of — return `nums[0]`. (Otherwise `nums[0 … n-2]` would be empty and `nums[1 … n-1]` too, and you'd return 0.)

**Dry run on `[2, 3, 2]`.**
- Case A on `[2, 3]`: `v=2` → cur = max(2+0, 0) = 2, state (0,2); `v=3` → cur = max(3+0, 2) = 3. Result **3**.
- Case B on `[3, 2]`: `v=3` → cur = 3, state (0,3); `v=2` → cur = max(2+0, 3) = 3. Result **3**.
- Answer `max(3, 3) = 3`. ✔ The greedy-looking `2 + 2 = 4` is correctly rejected because indices 0 and 2 touch on the circle.

A second check on `[1, 2, 3, 1]`: Case A on `[1,2,3]` gives 4 (houses 0 and 2); Case B on `[2,3,1]` gives 3. Answer 4. ✔
- **Time:** O(n) — two linear scans.
- **Space:** O(1) — a couple of rolling variables per scan (O(n) if you materialise the sub-arrays; slicing by index avoids that).

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
    // best non-adjacent sum over nums[lo..hi] inclusive
    int robLine(const vector<int>& nums, int lo, int hi) {
        int prev2 = 0, prev1 = 0;
        for (int i = lo; i <= hi; i++) {
            int cur = max(nums[i] + prev2, prev1);
            prev2 = prev1;
            prev1 = cur;
        }
        return prev1;
    }

public:
    int rob(vector<int>& nums) {
        int n = nums.size();
        if (n == 0) return 0;
        if (n == 1) return nums[0];
        int skipLast  = robLine(nums, 0, n - 2);
        int skipFirst = robLine(nums, 1, n - 1);
        return max(skipLast, skipFirst);
    }
};
```

### Java
```java
class Solution {
    // best non-adjacent sum over nums[lo..hi] inclusive
    private int robLine(int[] nums, int lo, int hi) {
        int prev2 = 0, prev1 = 0;
        for (int i = lo; i <= hi; i++) {
            int cur = Math.max(nums[i] + prev2, prev1);
            prev2 = prev1;
            prev1 = cur;
        }
        return prev1;
    }

    public int rob(int[] nums) {
        int n = nums.length;
        if (n == 0) return 0;
        if (n == 1) return nums[0];
        int skipLast  = robLine(nums, 0, n - 2);
        int skipFirst = robLine(nums, 1, n - 1);
        return Math.max(skipLast, skipFirst);
    }
}
```

### Python
```python
from typing import List


class Solution:
    def rob(self, nums: List[int]) -> int:
        n = len(nums)
        if n == 0:
            return 0
        if n == 1:
            return nums[0]

        def rob_line(lo: int, hi: int) -> int:
            # best non-adjacent sum over nums[lo..hi] inclusive
            prev2 = prev1 = 0
            for i in range(lo, hi + 1):
                prev2, prev1 = prev1, max(nums[i] + prev2, prev1)
            return prev1

        return max(rob_line(0, n - 2), rob_line(1, n - 1))
```

## Key Takeaways
- A circular constraint that only couples the two ends is usually removed by **case-splitting on one end**, turning one hard problem into two easy linear ones.
- The two cases overlap (selections omitting both ends), which is fine because we take a max, and together they cover every legal selection.
- The linear core is the standard pick/skip recurrence `dp[i] = max(nums[i] + dp[i-2], dp[i-1])`, space-optimised to two variables.
- Handle `n == 1` separately — both sub-arrays would otherwise be empty and the answer would come out as 0.
- Same pattern shows up in circular-array problems generally (e.g. maximum circular subarray sum), where you split on whether the wrap-around is used.
