# Graph Representation | Java

**Difficulty:** Easy  ·  **Topic:** Graphs [Concepts & Problems] › Learning

## Problem
This item covers how to store a graph in Java: reading the usual input format quickly, building an adjacency matrix or an adjacency list with the collections framework, dealing with directed/undirected and weighted edges, and knowing the Java-specific pitfalls (list initialisation, autoboxing, slow `Scanner`).

Standard input format: first line `n m` (nodes numbered `1..n`, and `m` edges), then `m` lines of `u v`.

```
Input:
4 4
1 2
1 3
2 4
3 4

Adjacency list built:
1 -> [2, 3]
2 -> [1, 4]
3 -> [1, 4]
4 -> [2, 3]
```

## Approach: choosing and building the representation in Java

**Adjacency matrix.** A plain 2-D array `int[][] adj = new int[n + 1][n + 1]` (Java zero-fills it for you). `adj[u][v] = 1` marks an edge, or store the weight instead of 1.

```java
int[][] adj = new int[n + 1][n + 1];
adj[u][v] = 1;
adj[v][u] = 1;                 // undirected: both directions
```
Edge existence is an O(1) array read, but the memory is O(N²) — at `n = 10^5` that is far beyond any heap. Use it only for small dense graphs.

**Adjacency list.** The idiomatic form is `List<List<Integer>>`. The Java-specific gotcha is that the outer list starts *empty*: you must explicitly create each inner list before touching it, or you get an `IndexOutOfBoundsException`.

```java
List<List<Integer>> adj = new ArrayList<>();
for (int i = 0; i <= n; i++) adj.add(new ArrayList<>());   // must not skip this

adj.get(u).add(v);
adj.get(v).add(u);             // remove for a directed graph
```
Memory is O(N + 2M) and iterating `adj.get(u)` costs `degree(u)`, so a full traversal is O(N + M).

**Performance-minded alternative.** `List<Integer>` boxes every neighbour into an `Integer` object, which costs memory and cache misses. For large graphs an array of `int` arrays is noticeably faster: count each node's degree in a first pass, allocate `int[degree]` per node, then fill in a second pass. Same asymptotics, far less overhead. `ArrayList<Integer>` is fine up to roughly 10^5–10^6 edges; beyond that consider the array version.

**Directed graphs.** Add only `adj.get(u).add(v)`. If the algorithm needs the reverse graph too (indegrees for Kahn's topological sort, or Kosaraju's SCC), build a second list in the same loop.

**Weighted graphs.** Store a small pair type. `int[]` of length 2 is the lightest option and works directly with a `PriorityQueue` comparator:

```java
List<List<int[]>> adj = new ArrayList<>();      // each entry: {neighbour, weight}
adj.get(u).add(new int[]{v, w});
adj.get(v).add(new int[]{u, w});                // undirected

for (int[] e : adj.get(u)) { int v = e[0], w = e[1]; ... }
```
A small `Pair`/`Edge` class is more readable; `int[]` is faster.

**Input speed.** `Scanner` is convenient but slow — it can take seconds on 10^5+ tokens. For anything large use `BufferedReader` with `StringTokenizer`:

```java
BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
StringTokenizer st = new StringTokenizer(br.readLine());
int n = Integer.parseInt(st.nextToken()), m = Integer.parseInt(st.nextToken());
```
Likewise, build output in a `StringBuilder` and print once rather than calling `System.out.println` inside a loop.

**Indexing.** Creating `n + 1` inner lists and ignoring index 0 matches 1-indexed input with no arithmetic; use `n` lists for 0-indexed problems.

- **Time:** O(N + M) to read and build a list; O(N²) to allocate a matrix
- **Space:** O(N + 2M) for an undirected adjacency list; O(N²) for a matrix

## Code (Optimal)

### C++
```cpp
// The same adjacency list, written with STL containers.
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n, m; cin >> n >> m;

    vector<vector<int>> adj(n + 1);
    for (int i = 0; i < m; i++) {
        int u, v; cin >> u >> v;
        adj[u].push_back(v);
        adj[v].push_back(u);
    }

    for (int u = 1; u <= n; u++) {
        cout << u << " ->";
        for (int v : adj[u]) cout << ' ' << v;
        cout << '\n';
    }
    return 0;
}
```

### Java
```java
import java.io.*;
import java.util.*;

public class Main {
    public static void main(String[] args) throws IOException {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        StringTokenizer st = new StringTokenizer(br.readLine());
        int n = Integer.parseInt(st.nextToken());     // nodes 1..n
        int m = Integer.parseInt(st.nextToken());     // number of edges

        List<List<Integer>> adj = new ArrayList<>();
        for (int i = 0; i <= n; i++) adj.add(new ArrayList<>());   // create every inner list

        for (int i = 0; i < m; i++) {
            st = new StringTokenizer(br.readLine());
            int u = Integer.parseInt(st.nextToken());
            int v = Integer.parseInt(st.nextToken());
            adj.get(u).add(v);
            adj.get(v).add(u);                        // delete for a directed graph
        }

        StringBuilder sb = new StringBuilder();
        for (int u = 1; u <= n; u++) sb.append(u).append(" -> ").append(adj.get(u)).append('\n');
        System.out.print(sb);
    }
}
```

### Python
```python
# The same adjacency list, written with Python lists.
import sys

def main():
    data = sys.stdin.read().split()
    n, m = int(data[0]), int(data[1])
    idx = 2

    adj = [[] for _ in range(n + 1)]
    for _ in range(m):
        u, v = int(data[idx]), int(data[idx + 1])
        idx += 2
        adj[u].append(v)
        adj[v].append(u)

    out = []
    for u in range(1, n + 1):
        out.append(f"{u} -> {adj[u]}")
    print("\n".join(out))

if __name__ == "__main__":
    main()
```

## Key Takeaways
- `List<List<Integer>>` is the default; remember that Java does not create the inner lists for you — the `for (i = 0; i <= n; i++) adj.add(new ArrayList<>())` loop is mandatory.
- Undirected edges go into two lists, directed edges into one; weighted edges are stored as `int[]{neighbour, weight}` or a small `Edge` class.
- Use `BufferedReader` + `StringTokenizer` and a `StringBuilder` for output — `Scanner` and per-line `println` are the usual cause of TLE on graph inputs.
- Adjacency matrix (`int[n+1][n+1]`) buys O(1) edge lookups at O(N²) memory; only worth it for small dense graphs.
