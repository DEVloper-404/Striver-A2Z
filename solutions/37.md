# Two Sum

**Difficulty:** Easy  ·  **Topic:** Solve Problems on Arrays [Easy -> Medium -> Hard] › Medium

## Problem
Given an integer array `nums` and an integer `target`, find two different positions `i` and `j` such that `nums[i] + nums[j] == target` and return them as a pair of indices. Exactly one valid answer is guaranteed and you may not use the same element twice. A common variant only asks whether such a pair exists (return YES/NO).

```
Input:  nums = [2, 6, 5, 8, 11], target = 14
Output: [1, 3]        (6 + 8 = 14)
```

## Approach 1: Brute Force
Try every unordered pair `(i, j)` with `i < j` and check whether the two values add up to `target`. The first pair that matches is the answer. Simple, but it re-examines the same elements many times.
- **Time:** O(n²)
- **Space:** O(1)

## Approach 2: Sort + Two Pointers
Sort a copy of the array (keeping original indices attached). Put one pointer at the left end and one at the right end. If the current sum is too small, move the left pointer right; if it is too big, move the right pointer left; if it matches, done. This works because after sorting, moving a pointer changes the sum in a predictable direction. Good for the YES/NO variant; for the index variant you must carry the original indices through the sort.
- **Time:** O(n log n)
- **Space:** O(n) for the index-tagged copy (O(1) if only YES/NO is needed and in-place sort is allowed)

## Approach 3: Hash Map (Optimal)
Walk the array once. For the current value `x`, the partner we need is `target - x`. If that partner has already been seen, we have the answer; otherwise store `x -> index` in a hash map and continue. Inserting *after* the lookup guarantees we never pair an element with itself.
- **Time:** O(n) average
- **Space:** O(n)

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <unordered_map>
using namespace std;

class Solution {
public:
    vector<int> twoSum(vector<int>& nums, int target) {
        unordered_map<int, int> seen; // value -> index
        for (int i = 0; i < (int)nums.size(); ++i) {
            int need = target - nums[i];
            auto it = seen.find(need);
            if (it != seen.end()) return {it->second, i};
            seen[nums[i]] = i;
        }
        return {-1, -1}; // no pair (not expected per constraints)
    }
};
```

### Java
```java
import java.util.HashMap;
import java.util.Map;

class Solution {
    public int[] twoSum(int[] nums, int target) {
        Map<Integer, Integer> seen = new HashMap<>();
        for (int i = 0; i < nums.length; i++) {
            int need = target - nums[i];
            if (seen.containsKey(need)) {
                return new int[]{seen.get(need), i};
            }
            seen.put(nums[i], i);
        }
        return new int[]{-1, -1};
    }
}
```

### Python
```python
from typing import List

class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        seen = {}  # value -> index
        for i, x in enumerate(nums):
            need = target - x
            if need in seen:
                return [seen[need], i]
            seen[x] = i
        return [-1, -1]
```

## Key Takeaways
- "Find a partner for the current element" problems almost always reduce to a hash lookup of `target - x`.
- Insert into the map only after checking, so an element is never matched with itself (e.g. target 8 with a single 4).
- The two-pointer method needs sorting, which destroys indices; use it when only existence is asked or when the array is already sorted.
- Negative numbers and duplicates are handled naturally by the map approach.
