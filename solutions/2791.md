# Morris Preorder Traversal of a Binary Tree

**Difficulty:** Hard  ·  **Topic:** Binary Trees [Traversals, Medium and Hard Problems] › Hard Problems

## Problem
Return the preorder traversal (root, left, right) of a binary tree using O(1) extra space: no recursion and no explicit stack. The Morris technique achieves this by temporarily rewiring the tree with "threads" that are removed before the function returns.

Input: root = [1, null, 2, 3]
Output: [1, 2, 3]

Input: root = [1, 2, 3, 4, 5]
Output: [1, 2, 4, 5, 3]

## Approach 1: Recursion or explicit stack
The usual preorder: visit the node, recurse left, recurse right. Or push root on a stack; pop, record, push right then left. Both are O(N) time but O(H) space for the call stack or the explicit stack.
- **Time:** O(N)
- **Space:** O(H)

## Approach 2: Optimal (Morris traversal with threads)
Walk with a `cur` pointer starting at the root:
1. If `cur` has no left child, record `cur` and move to `cur.right`.
2. Otherwise find the inorder predecessor of `cur`: the rightmost node of the left subtree (`pred`).
   - If `pred.right` is null, this is the first visit. Record `cur` **now** (that is what makes it preorder rather than inorder), set `pred.right = cur` as a thread back, and go left.
   - If `pred.right == cur`, the thread exists, meaning the left subtree is done. Remove the thread (`pred.right = null`) and go right.

Every edge is walked at most a constant number of times (once going down, once as part of a predecessor search, once via thread), so the total is linear, and the tree is restored to its original shape.
- **Time:** O(N)
- **Space:** O(1)

## Code (Optimal)

### C++
```cpp
// struct TreeNode { int val; TreeNode *left; TreeNode *right; ... } — standard definition
#include <vector>
using namespace std;

class Solution {
public:
    vector<int> preorderTraversal(TreeNode* root) {
        vector<int> out;
        TreeNode* cur = root;
        while (cur) {
            if (!cur->left) {
                out.push_back(cur->val);
                cur = cur->right;
            } else {
                TreeNode* pred = cur->left;
                while (pred->right && pred->right != cur) pred = pred->right;
                if (!pred->right) {
                    out.push_back(cur->val);   // visit before descending left
                    pred->right = cur;
                    cur = cur->left;
                } else {
                    pred->right = nullptr;
                    cur = cur->right;
                }
            }
        }
        return out;
    }
};
```

import java.util.*;

class Solution {
    public List<Integer> preorderTraversal(TreeNode root) {
        List<Integer> out = new ArrayList<>();
        TreeNode cur = root;
        while (cur != null) {
            if (cur.left == null) {
                out.add(cur.val);
                cur = cur.right;
            } else {
                TreeNode pred = cur.left;
                while (pred.right != null && pred.right != cur) pred = pred.right;
                if (pred.right == null) {
                    out.add(cur.val);          // visit before descending left
                    pred.right = cur;
                    cur = cur.left;
                } else {
                    pred.right = null;
                    cur = cur.right;
                }
            }
        }
        return out;
    }
}

                    pred = pred.right

## Key Takeaways
- Morris preorder differs from Morris inorder in exactly one line: record the node when creating the thread, not when removing it.
- The thread `pred.right = cur` lets you return to the parent without a stack; always remove it so the tree is left intact.
- Time is still O(N) because each predecessor search re-walks edges at most once overall.
- Not safe if other threads read the tree concurrently, since it mutates structure temporarily.
