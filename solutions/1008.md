# Task Scheduler

**Difficulty:** Medium  ·  **Topic:** Heaps [Learning, Medium, Hard Problems] › Medium Problems

## Problem
You are given a list of tasks, each labelled by an uppercase letter, and a cooldown `n`. The CPU runs one task per unit of time, and two runs of the **same** letter must be separated by at least `n` units (other tasks or idle slots may fill the gap). Return the minimum total time to finish every task.

```
Input:  tasks = ["A","A","A","B","B","B"], n = 2
Output: 8
```
One valid schedule: `A B idle A B idle A B`.

## Approach 1: Greedy simulation with a max-heap
The task with the most remaining copies is the one most likely to force idle time, so always run it first. Simulate in rounds of length `n + 1`:

1. Count each letter and push all non-zero counts into a max-heap.
2. Pop up to `n + 1` tasks from the heap (these fill one round). Decrement each count and remember the ones still above zero.
3. Push the remembered counts back. If the heap is now empty, add only the number of tasks actually run in this round; otherwise add the full `n + 1` (the rest of the round is idle time).
4. Repeat until the heap is empty.

The alphabet has at most 26 letters, so every heap operation is effectively constant.
- **Time:** O(T) where T is the total time returned (bounded by O(m * n) with m = number of tasks), heap work is O(26 log 26) per round
- **Space:** O(26) = O(1)

## Approach 2: Counting formula (optimal)
Let `maxFreq` be the highest count and `numMax` be how many letters share that count. Lay out the most frequent letter first: it creates `maxFreq - 1` gaps, each of width `n`. Letters tied at `maxFreq` occupy one slot in every gap and also extend the final row. That skeleton needs `(maxFreq - 1) * (n + 1) + numMax` slots. Every other letter has a smaller count and fits into the remaining gap slots without creating new idles.

If the skeleton is *smaller* than the number of tasks, the gaps are already full and there is no idle time at all, so the answer is just `tasks.length`. Hence:

```
answer = max(tasks.length, (maxFreq - 1) * (n + 1) + numMax)
```
- **Time:** O(m) to count frequencies
- **Space:** O(26) = O(1)

## Code (Optimal)

### C++
```cpp
#include <bits/stdc++.h>
using namespace std;

class Solution {
public:
    int leastInterval(vector<char>& tasks, int n) {
        int freq[26] = {0};
        for (char c : tasks) freq[c - 'A']++;

        int maxFreq = 0;
        for (int f : freq) maxFreq = max(maxFreq, f);

        int numMax = 0;
        for (int f : freq) if (f == maxFreq) numMax++;

        int skeleton = (maxFreq - 1) * (n + 1) + numMax;
        return max((int)tasks.size(), skeleton);
    }
};
```

### Java
```java
class Solution {
    public int leastInterval(char[] tasks, int n) {
        int[] freq = new int[26];
        for (char c : tasks) freq[c - 'A']++;

        int maxFreq = 0;
        for (int f : freq) maxFreq = Math.max(maxFreq, f);

        int numMax = 0;
        for (int f : freq) if (f == maxFreq) numMax++;

        int skeleton = (maxFreq - 1) * (n + 1) + numMax;
        return Math.max(tasks.length, skeleton);
    }
}
```

### Python
```python
from collections import Counter
from typing import List


class Solution:
    def leastInterval(self, tasks: List[str], n: int) -> int:
        freq = Counter(tasks)
        max_freq = max(freq.values())
        num_max = sum(1 for f in freq.values() if f == max_freq)
        skeleton = (max_freq - 1) * (n + 1) + num_max
        return max(len(tasks), skeleton)
```

## Key Takeaways
- The most frequent task dictates the shape of the schedule; everything else fills its gaps.
- The `max(len(tasks), skeleton)` step is essential: when there are many distinct tasks, no idle slots are needed and the formula alone would under-count.
- The heap simulation is the general technique for "schedule with cooldown" problems; the formula is a shortcut that works because all tasks are identical in length.
- `n = 0` means no cooldown and the answer is simply the number of tasks; the formula still returns that.
