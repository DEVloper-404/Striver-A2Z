# Construct the Binary Tree from Postorder and Inorder Traversal

**Difficulty:** Hard  ·  **Topic:** Binary Trees [Traversals, Medium and Hard Problems] › Hard Problems

## Problem
Given the inorder and postorder traversals of a binary tree with distinct values, rebuild the tree and return its root.

Input: inorder = [9, 3, 15, 20, 7], postorder = [9, 15, 7, 20, 3]
Output: [3, 9, 20, null, null, 15, 7]

Input: inorder = [-1], postorder = [-1]
Output: [-1]

## Approach 1: Brute Force (linear scan + slicing)
The last postorder element is the root. Find it in inorder by scanning; the elements before it form the left subtree, the ones after form the right subtree. The left subtree's postorder is the first `leftSize` elements of postorder, and the right subtree's is the next block (excluding the final root). Recurse on sliced arrays.
- **Time:** O(N²) worst case
- **Space:** O(N²) with copies, O(N) with index ranges

## Approach 2: Optimal (hash map + index ranges)
Precompute `inIdx[value]`. Recurse with `(inStart, inEnd, postStart, postEnd)`:
1. Root is `postorder[postEnd]`; `mid = inIdx[root]`.
2. `leftSize = mid - inStart`.
3. Left subtree: `inorder[inStart .. mid-1]`, `postorder[postStart .. postStart+leftSize-1]`.
4. Right subtree: `inorder[mid+1 .. inEnd]`, `postorder[postStart+leftSize .. postEnd-1]`.

This mirrors the preorder version, just reading the root from the back.
- **Time:** O(N)
- **Space:** O(N) map plus O(H) recursion

## Code (Optimal)

### C++
```cpp
// struct TreeNode { int val; TreeNode *left; TreeNode *right; TreeNode(int x) ... } — standard definition
#include <vector>
#include <unordered_map>
using namespace std;

class Solution {
    unordered_map<int,int> inIdx;

    TreeNode* build(vector<int>& in, int is, int ie, vector<int>& post, int ps, int pe) {
        if (is > ie || ps > pe) return nullptr;
        TreeNode* root = new TreeNode(post[pe]);
        int mid = inIdx[post[pe]];
        int leftSize = mid - is;
        root->left  = build(in, is, mid - 1, post, ps, ps + leftSize - 1);
        root->right = build(in, mid + 1, ie, post, ps + leftSize, pe - 1);
        return root;
    }
public:
    TreeNode* buildTree(vector<int>& inorder, vector<int>& postorder) {
        for (int i = 0; i < (int)inorder.size(); ++i) inIdx[inorder[i]] = i;
        return build(inorder, 0, inorder.size() - 1, postorder, 0, postorder.size() - 1);
    }
};
```

### Java
```java
// class TreeNode { int val; TreeNode left, right; TreeNode(int x) ... } — standard definition
import java.util.*;

class Solution {
    private Map<Integer, Integer> inIdx = new HashMap<>();

    private TreeNode build(int[] in, int is, int ie, int[] post, int ps, int pe) {
        if (is > ie || ps > pe) return null;
        TreeNode root = new TreeNode(post[pe]);
        int mid = inIdx.get(post[pe]);
        int leftSize = mid - is;
        root.left  = build(in, is, mid - 1, post, ps, ps + leftSize - 1);
        root.right = build(in, mid + 1, ie, post, ps + leftSize, pe - 1);
        return root;
    }

    public TreeNode buildTree(int[] inorder, int[] postorder) {
        for (int i = 0; i < inorder.length; i++) inIdx.put(inorder[i], i);
        return build(inorder, 0, inorder.length - 1, postorder, 0, postorder.length - 1);
    }
}
```

### Python
```python
# class TreeNode: val, left, right — standard definition

class Solution:
    def buildTree(self, inorder, postorder):
        in_idx = {v: i for i, v in enumerate(inorder)}

        def build(is_, ie, ps, pe):
            if is_ > ie or ps > pe:
                return None
            root = TreeNode(postorder[pe])
            mid = in_idx[root.val]
            left_size = mid - is_
            root.left = build(is_, mid - 1, ps, ps + left_size - 1)
            root.right = build(mid + 1, ie, ps + left_size, pe - 1)
            return root

        return build(0, len(inorder) - 1, 0, len(postorder) - 1)
```

## Key Takeaways
- Postorder's last element is the root; inorder splits the rest into left and right.
- The left subtree occupies the first `leftSize` positions of postorder, the right subtree the block just before the root.
- A hash map of inorder positions plus index ranges gives O(N) time with no array copying.
- An alternate trick: consume postorder from the back and build right subtree before left; the index-range version above is easier to get correct under pressure.
