# Flattening of LL

**Difficulty:** Hard  ·  **Topic:** Learn LinkedList [Single LL, Double LL, Medium, Hard Problems] › Hard Problems of LL

## Problem
You are given a special linked list where every node has two pointers: `next` points to the next node of the top-level list, and `child` (often called `bottom`) points to a vertical list hanging below that node. Every vertical list is already sorted, and the top-level nodes are sorted by their head values. Flatten the whole structure into a single sorted list that uses only the `child` pointer (all `next` pointers become null).

Input:
```
5 -> 10 -> 19 -> 28
|     |     |     |
7     20    22    35
|           |     |
8           50    40
|                 |
30                45
```
Output: `5 -> 7 -> 8 -> 10 -> 19 -> 20 -> 22 -> 28 -> 30 -> 35 -> 40 -> 45 -> 50`

## Approach 1: Collect, sort, rebuild
Traverse every top-level node, and for each one walk down its child chain, pushing every value into an array. Sort the array and build a fresh vertical list from it. This ignores the fact that the sub-lists are already sorted and allocates a full copy.
- **Time:** O(N log N) where N is the total number of nodes
- **Space:** O(N)

## Approach 2: Merge the vertical lists one by one, right to left
Because every vertical list is sorted, joining two of them is just the "merge two sorted lists" routine on the `child` pointer. Flatten recursively: flatten everything to the right of the current node first, then merge the current node's vertical list with that flattened result.

1. Base case: if `head` is null or `head->next` is null, it is already flat.
2. Recursively flatten `head->next` to get a single sorted vertical list `rightPart`.
3. Merge `head`'s vertical list with `rightPart` using a dummy node and two pointers, linking through `child` and setting `next` to null on every node placed.
4. Return the merged head.

Each merge costs the combined length of the two lists. If there are `k` top-level nodes with total `N` nodes, the merges cost O(N · k) in the worst case (the growing merged list is re-scanned on every step), which is still fine for typical constraints. Using a min-heap over the `k` list heads brings this to O(N log k), but the merge version is the one interviewers expect.
- **Time:** O(N · k) worst case, where k is the number of top-level nodes
- **Space:** O(k) recursion depth (O(1) extra otherwise)

## Code (Optimal)

### C++
```cpp
// struct Node { int data; Node *next; Node *child;
//               Node(int x) : data(x), next(nullptr), child(nullptr) {} }; // standard definition
class Solution {
    Node* merge(Node* a, Node* b) {
        Node dummy(0);
        Node* tail = &dummy;
        while (a && b) {
            if (a->data < b->data) { tail->child = a; a = a->child; }
            else                   { tail->child = b; b = b->child; }
            tail = tail->child;
            tail->next = nullptr;
        }
        tail->child = a ? a : b;
        // clear stray next pointers on the remaining chain
        for (Node* p = tail->child; p; p = p->child) p->next = nullptr;
        return dummy.child;
    }
public:
    Node* flatten(Node* head) {
        if (!head || !head->next) return head;
        Node* rightPart = flatten(head->next);
        head->next = nullptr;
        return merge(head, rightPart);
    }
};
```

### Java
```java
// class Node { int data; Node next, child; Node(int d) { data = d; } } // standard definition
class Solution {
    private Node merge(Node a, Node b) {
        Node dummy = new Node(0), tail = dummy;
        while (a != null && b != null) {
            if (a.data < b.data) { tail.child = a; a = a.child; }
            else                 { tail.child = b; b = b.child; }
            tail = tail.child;
            tail.next = null;
        }
        tail.child = (a != null) ? a : b;
        for (Node p = tail.child; p != null; p = p.child) p.next = null;
        return dummy.child;
    }

    public Node flatten(Node head) {
        if (head == null || head.next == null) return head;
        Node rightPart = flatten(head.next);
        head.next = null;
        return merge(head, rightPart);
    }
}
```

### Python
```python
# class Node:
#     def __init__(self, data):
#         self.data = data
#         self.next = None
#         self.child = None
# (standard definition)
class Solution:
    def _merge(self, a, b):
        dummy = Node(0)
        tail = dummy
        while a and b:
            if a.data < b.data:
                tail.child, a = a, a.child
            else:
                tail.child, b = b, b.child
            tail = tail.child
            tail.next = None
        tail.child = a if a else b
        p = tail.child
        while p:
            p.next = None
            p = p.child
        return dummy.child

    def flatten(self, head):
        if head is None or head.next is None:
            return head
        right_part = self.flatten(head.next)
        head.next = None
        return self._merge(head, right_part)
```

## Key Takeaways
- The structure is really `k` sorted lists; flattening is repeated "merge two sorted lists" along the `child` pointer.
- Recursing to the right first lets each step merge just two lists: the current column and the already-flat remainder.
- Null out `next` on every node you place, otherwise the output still has dangling horizontal links.
- Do not sort; the input order is the whole point, and sorting throws away the O(N log N) → near-linear win.
