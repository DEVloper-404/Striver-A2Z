# Fractional Knapsack

**Difficulty:** Medium  ·  **Topic:** Greedy Algorithms [Easy, Medium/Hard] › Easy Problems

## Problem
You are given `n` items, item `i` having weight `w[i]` and value `v[i]`, and a bag that can carry total weight `W`. Unlike 0/1 knapsack you may take **any fraction** of an item, receiving that same fraction of its value. Maximise the total value carried.

```
Input:  W = 50, items = [(w=10, v=60), (w=20, v=100), (w=30, v=120)]
Output: 240.0
```
Take the first two items whole (30 kg, 160) and 20/30 of the third (80), giving 240.

## Approach 1: Sort by value, or by weight
Two natural-looking greedy rules both fail. Picking the highest **value** first ignores how much room it eats: an item worth 120 that fills the whole bag can be worse than three items worth 60 each. Picking the lightest item first ignores how much value that room buys. In the example above, "highest value first" takes the 30 kg / 120 item, then the 20 kg / 100 item, for 220 — less than the optimum of 240.

The lesson is that neither value nor weight alone captures what we are optimising; we care about value **per unit of capacity spent**.

- **Time:** O(n log n)
- **Space:** O(1) — but the answer is wrong.

## Approach 2: Sort by value/weight ratio, fill greedily (Optimal)
**Key observation.** Every kilogram of capacity is interchangeable. If some kilogram of the bag is filled by material worth `r1` per kg while material worth `r2 > r1` per kg is still available outside the bag, swap them: replace that kilogram of the low-ratio item with a kilogram of the high-ratio one. The weight is unchanged and the value strictly increases, so the original packing was not optimal. Hence an optimal packing always fills the bag with the highest-ratio material first — which is exactly the greedy rule. Fractions are what make this exchange always legal; in 0/1 knapsack you cannot cut an item, the exchange argument breaks, and you need DP instead.

**Algorithm.**
1. Sort items by `v[i] / w[i]` in **descending** order.
2. Walk the sorted list with `remaining = W` and `total = 0.0`:
   - if `w[i] <= remaining`, take the whole item: `total += v[i]`, `remaining -= w[i]`;
   - otherwise take the fraction that fits: `total += v[i] * (remaining / w[i])`, set `remaining = 0` and stop — the bag is full and no further item can improve anything.
3. Return `total`.

At most one item is ever split — the one where the capacity runs out.

**Dry run on the example.** Ratios are `60/10 = 6`, `100/20 = 5`, `120/30 = 4`, already in descending order.
- Item 1: weight 10 ≤ 50, take it all. total = 60, remaining = 40.
- Item 2: weight 20 ≤ 40, take it all. total = 160, remaining = 20.
- Item 3: weight 30 > 20, take `20/30 = 2/3` of it: `120 × 2/3 = 80`. total = **240**, remaining = 0, stop.

**Implementation note on comparing ratios.** Comparing `v1/w1 < v2/w2` with floating point can misorder near-equal ratios. Cross-multiplying — compare `v1 * w2` against `v2 * w1` using 64-bit integers — is exact and avoids division entirely in the comparator.

- **Time:** O(n log n), dominated by the sort; the fill pass is O(n).
- **Space:** O(1) auxiliary if sorting in place (O(n) if you build an array of ratio pairs).

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <algorithm>
using namespace std;

// Item { int value, weight; } is the standard definition used by this problem.
struct Item {
    int value;
    int weight;
};

class Solution {
public:
    double fractionalKnapsack(int W, vector<Item>& items) {
        // descending value/weight, compared by cross-multiplication to stay exact
        sort(items.begin(), items.end(), [](const Item& a, const Item& b) {
            return (long long)a.value * b.weight > (long long)b.value * a.weight;
        });

        double total = 0.0;
        int remaining = W;
        for (const Item& it : items) {
            if (it.weight <= remaining) {
                total += it.value;
                remaining -= it.weight;
            } else {
                total += (double)it.value * remaining / it.weight;  // split this one
                break;                                              // bag is full
            }
        }
        return total;
    }
};
```

class Solution {

    static class Item {
        int value, weight;
        Item(int value, int weight) { this.value = value; this.weight = weight; }

    public double fractionalKnapsack(int W, Item[] items) {

                total += it.value;
                remaining -= it.weight;

                break;
            }
        }
        return total;
    }
}

### Python
```python
from typing import List, Tuple

class Solution:
    # items is a list of (value, weight) pairs
    def fractionalKnapsack(self, W: int, items: List[Tuple[int, int]]) -> float:
        items = sorted(items, key=lambda it: it[0] / it[1], reverse=True)

        total = 0.0
        remaining = W
        for value, weight in items:
            if weight <= remaining:
                total += value
                remaining -= weight
            else:
                total += value * remaining / weight   # take the fitting fraction
                break
        return total
```

## Key Takeaways
- Greedy works here because capacity is divisible: any kilogram can be exchanged for a higher-ratio kilogram, which is the exchange-argument proof of optimality.
- Sort by **value/weight**, not by value and not by weight — both of those single-criterion rules are provably wrong.
- Exactly one item gets split, and it is always the one where the remaining capacity runs out; break immediately afterwards.
- Removing the fraction (0/1 knapsack) destroys the argument entirely — that variant needs dynamic programming, not greed.
