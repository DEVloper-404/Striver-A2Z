# Print 1 to N using Recursion

**Difficulty:** Easy  ·  **Topic:** Learn the basics › Learn Basic Recursion

## Problem
Given an integer `N`, print the integers `1, 2, ..., N` in increasing order using recursion (no loops).

Input: `N = 5`
Output: `1 2 3 4 5`

## Approach 1: Forward recursion with a counter
Use `solve(i, n)`: if `i > n` return; otherwise print `i` and call `solve(i + 1, n)`. The printing happens *before* the recursive call, so the numbers appear in ascending order as the stack grows.

- **Time:** O(n)
- **Space:** O(n) recursion depth

## Approach 2: Backtracking — print after the call
If you are only allowed to pass `n` (no counter), recurse first and print on the way back: `solve(n)` calls `solve(n - 1)` and *then* prints `n`. Because the deepest frame (`n = 1`) prints first, the output is still `1 2 ... N`. This "do the work after the recursive call returns" idea is the essence of backtracking.

Trace for `n = 3`: `solve(3)` → `solve(2)` → `solve(1)` → `solve(0)` returns → print 1 → print 2 → print 3.

- **Time:** O(n)
- **Space:** O(n) stack

## Code (Optimal)

### C++
```cpp
#include <iostream>
using namespace std;

void printOneToN(int n) {
    if (n == 0) return;
    printOneToN(n - 1);       // handle 1..n-1 first
    cout << n << ' ';         // then print n on the way back
}

int main() {
    printOneToN(5);
    cout << '\n';
    return 0;
}
```

### Java
```java
public class Main {
    static void printOneToN(int n) {
        if (n == 0) return;
        printOneToN(n - 1);           // handle 1..n-1 first
        System.out.print(n + " ");    // then print n on the way back
    }

    public static void main(String[] args) {
        printOneToN(5);
        System.out.println();
    }
}
```

### Python
```python
def print_one_to_n(n: int) -> None:
    if n == 0:
        return
    print_one_to_n(n - 1)   # handle 1..n-1 first
    print(n, end=" ")       # then print n on the way back

if __name__ == "__main__":
    print_one_to_n(5)
    print()
```

## Key Takeaways
- Work placed *before* the recursive call happens on the way down; work placed *after* it happens on the way back up. Swapping the two lines reverses the output.
- The backtracking version needs only one parameter; the counter version needs two but is easier to reason about.
- Depth is O(n), so prefer a loop for very large `n` in production code.
