# Letter Combinations of a Phone Number

**Difficulty:** Hard  ·  **Topic:** Recursion [PatternWise] › Subsequences Pattern

## Problem
On an old telephone keypad each digit from `2` to `9` maps to a group of letters (`2 → abc`, `3 → def`, …, `7 → pqrs`, `8 → tuv`, `9 → wxyz`). Given a string of such digits, return every letter string that the number could spell. The answer may be in any order; an empty input string produces an empty list (not a list containing `""`).

```
Input:  digits = "23"
Output: ["ad", "ae", "af", "bd", "be", "bf", "cd", "ce", "cf"]
```

## Approach 1: Iterative build-up (BFS over prefixes)
Keep a list of partial strings, starting with `[""]`. For each digit in turn, replace the list with a new list containing `prefix + ch` for every existing `prefix` and every letter `ch` of that digit. After processing all digits the list holds the full answer.

This is a clean, recursion-free formulation, and it is easy to see it is exhaustive: after `i` digits the list contains exactly the combinations of the first `i` digits. Its drawback is memory — every intermediate level is materialised in full, so a 4-digit input holds all 3, then 9, then 27, then 81 strings simultaneously, and each concatenation copies the whole prefix.

- **Time:** O(4^n · n) — up to `4^n` strings, each built with O(n) character copies.
- **Space:** O(4^n · n) including intermediate levels.

## Approach 2: Backtracking, one digit per recursion level (Optimal)
The key observation: the digits are **independent choices made in a fixed order**. Digit 0 picks one of its 3–4 letters, digit 1 picks one of its letters, and so on. That is a depth-`n` tree where the branching factor at level `i` is the number of letters on `digits[i]`, and every root-to-leaf path is exactly one answer. Unlike subset problems there is no "skip" option — every digit *must* contribute exactly one letter — so the recursion is a loop over letters rather than a binary take/leave.

Define `solve(index, path)` where `path` is a mutable buffer:

1. **Base case** `index == digits.size()`: `path` now has one letter per digit, so it is a complete combination — append a copy to the answer and return.
2. Otherwise look up `letters = map[digits[index] - '0']`. For each character `ch` in `letters`: append `ch` to `path`, recurse with `index + 1`, then remove `ch` (backtrack) so the buffer is restored for the next sibling.

Backtracking with a single shared buffer is what keeps auxiliary space at O(n): only one path is alive at a time, and strings are copied only at leaves, where a copy is genuinely needed.

**Why there are no duplicates:** two different answers must differ at some position `i`, which means they took different branches at level `i` of the tree — different leaves. Conversely each leaf yields one string. So the map from leaves to answers is a bijection.

**Dry run on `"23"`.** Level 0 iterates `a, b, c`; level 1 iterates `d, e, f`.
- `path = "a"` → `"ad"` recorded, backtrack to `"a"` → `"ae"`, → `"af"`; pop back to `""`.
- `path = "b"` → `"bd", "be", "bf"`; then `c` → `"cd", "ce", "cf"`.

Nine leaves = 3 × 3, which matches the expected output.

**Edge case:** the empty input. Without a guard, the base case fires immediately at `index == 0` and pushes `""`, giving `[""]` instead of `[]`. Handle it with an early return.

- **Time:** O(4^n · n) where `n = digits.length()` — `4^n` is the loose bound from digits `7` and `9`; the `n` factor is copying each finished string.
- **Space:** O(n) for the recursion stack and the path buffer (output excluded).

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <string>
using namespace std;

class Solution {
public:
    vector<string> letterCombinations(string digits) {
        vector<string> res;
        if (digits.empty()) return res;          // must return [], not [""]
        string path;
        path.reserve(digits.size());
        solve(0, digits, path, res);
        return res;
    }

private:
    const vector<string> map_ = {
        "", "", "abc", "def", "ghi", "jkl", "mno", "pqrs", "tuv", "wxyz"
    };

    void solve(int index, const string& digits, string& path, vector<string>& res) {
        if (index == (int)digits.size()) {
            res.push_back(path);
            return;
        }
        const string& letters = map_[digits[index] - '0'];
        for (char ch : letters) {
            path.push_back(ch);
            solve(index + 1, digits, path, res);
            path.pop_back();                     // backtrack
        }
    }
};
```

### Java
```java
import java.util.*;

class Solution {
    private static final String[] MAP = {
        "", "", "abc", "def", "ghi", "jkl", "mno", "pqrs", "tuv", "wxyz"
    };

    public List<String> letterCombinations(String digits) {
        List<String> res = new ArrayList<>();
        if (digits == null || digits.isEmpty()) return res;
        solve(0, digits, new StringBuilder(), res);
        return res;
    }

    private void solve(int index, String digits, StringBuilder path, List<String> res) {
        if (index == digits.length()) {
            res.add(path.toString());
            return;
        }
        String letters = MAP[digits.charAt(index) - '0'];
        for (int i = 0; i < letters.length(); i++) {
            path.append(letters.charAt(i));
            solve(index + 1, digits, path, res);
            path.deleteCharAt(path.length() - 1);   // backtrack
        }
    }
}
```

### Python
```python
from typing import List

class Solution:
    def letterCombinations(self, digits: str) -> List[str]:
        if not digits:
            return []

        mapping = ["", "", "abc", "def", "ghi", "jkl", "mno", "pqrs", "tuv", "wxyz"]
        res: List[str] = []
        path: List[str] = []
        n = len(digits)

        def solve(index: int) -> None:
            if index == n:
                res.append("".join(path))
                return
            for ch in mapping[int(digits[index])]:
                path.append(ch)
                solve(index + 1)
                path.pop()

        solve(0)
        return res
```

## Key Takeaways
- This is the "one mandatory choice per position" flavour of backtracking: loop over the options at level `i`, recurse to `i + 1`, undo. There is no skip branch.
- Use a single mutable buffer plus explicit undo instead of passing new strings down — O(n) space instead of O(depth × length).
- The empty-input case is the classic wrong answer here: guard it before recursing.
- Digits `7` and `9` have four letters, so the count of answers is `∏ len(letters[d])`, bounded by `4^n` — expect exponential output and don't try to beat it.
