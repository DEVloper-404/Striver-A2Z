# Edit distance

**Difficulty:** Hard  ·  **Topic:** Dynamic Programming [Patterns and Problems] › DP on Strings

## Problem
Given two strings `word1` and `word2`, return the minimum number of single-character operations needed to turn `word1` into `word2`. The allowed operations are **insert** a character, **delete** a character, and **replace** a character. This quantity is the classic Levenshtein distance.

```
Input:  word1 = "horse", word2 = "ros"
Output: 3
```
One optimal script: `horse → rorse` (replace `h`→`r`), `rorse → rose` (delete `r`), `rose → ros` (delete `e`).

## Approach 1: Recursion on suffix/prefix pairs (Brute Force)
The observation that unlocks the problem: we only ever need to look at the **last characters** of the two prefixes we are currently reconciling. Whatever the optimal edit script is, its final effect on the last character of `word1` is one of only four things.

Let `f(i, j)` = minimum operations to convert `word1[0..i)` into `word2[0..j)`.

1. If `word1[i-1] == word2[j-1]`, the two last characters already agree. There is never a reason to spend an operation on them, so `f(i, j) = f(i-1, j-1)` — align them for free and recurse on the shorter prefixes.
2. Otherwise we must pay exactly one operation, and there are three ways to spend it:
   - **Replace** `word1[i-1]` with `word2[j-1]`: cost `1 + f(i-1, j-1)`.
   - **Delete** `word1[i-1]`: cost `1 + f(i-1, j)` — one character of `word1` is consumed, `word2` is untouched.
   - **Insert** `word2[j-1]` at the end of `word1`: cost `1 + f(i, j-1)` — it immediately matches and is consumed, `word1` is untouched.
   Take the minimum of the three.

Base cases fall out naturally: `f(0, j) = j` (insert all `j` remaining characters) and `f(i, 0) = i` (delete all `i` remaining characters).

- **Time:** O(3^(n+m))
- **Space:** O(n + m) recursion depth

## Approach 2: Tabulation
There are only `(n+1) × (m+1)` distinct states, so fill a table bottom-up instead of recursing. Row 0 is `0,1,2,...,m` and column 0 is `0,1,2,...,n`; every other cell uses the recurrence above, reading only cells above, to the left, and diagonally up-left — all already computed when we sweep row by row.

**Dry run** for `word1 = "horse"`, `word2 = "ros"`:

```
        ""  r  o  s
   ""    0  1  2  3
   h     1  1  2  3
   o     2  2  1  2
   r     3  2  2  2
   s     4  3  3  2
   e     5  4  4  3
```
Read a couple of cells to see the logic. At (`ho`, `ro`) the last characters `o` and `o` match, so we copy the diagonal value `1`. At (`hor`, `ro`) nothing matches, so it is `1 + min(2, 1, 2) = 2` — the `1` came from the "delete `r`" direction. The bottom-right cell, `3`, is the answer.

- **Time:** O(n · m)
- **Space:** O(n · m)

## Approach 3: Two rolling rows (Optimal in space)
Every cell reads only the current row's left neighbour and the previous row's same/left column, so two arrays of length `m+1` are enough. Keep `prev` for row `i-1` and build `cur` for row `i`, seeding `cur[0] = i` (converting a prefix of length `i` into the empty string always costs `i` deletions). Swap the arrays at the end of each row.

This drops the memory from O(n·m) to O(m), which matters when both strings are long. If you also need to *print* the edit script you must keep the full table (or re-run a divide-and-conquer variant), since the compressed version forgets the path.

- **Time:** O(n · m)
- **Space:** O(m)

## Code (Optimal)

### C++
```cpp
#include <string>
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int minDistance(string word1, string word2) {
        int n = word1.size(), m = word2.size();
        vector<int> prev(m + 1), cur(m + 1);
        for (int j = 0; j <= m; j++) prev[j] = j;   // convert "" -> word2[0..j)

        for (int i = 1; i <= n; i++) {
            cur[0] = i;                             // convert word1[0..i) -> ""
            for (int j = 1; j <= m; j++) {
                if (word1[i - 1] == word2[j - 1]) {
                    cur[j] = prev[j - 1];           // free match
                } else {
                    int replaceOp = prev[j - 1];
                    int deleteOp  = prev[j];
                    int insertOp  = cur[j - 1];
                    cur[j] = 1 + min(replaceOp, min(deleteOp, insertOp));
                }
            }
            prev = cur;
        }
        return prev[m];
    }
};
```

### Java
```java
class Solution {
    public int minDistance(String word1, String word2) {
        int n = word1.length(), m = word2.length();
        int[] prev = new int[m + 1];
        int[] cur = new int[m + 1];
        for (int j = 0; j <= m; j++) prev[j] = j;

        for (int i = 1; i <= n; i++) {
            cur[0] = i;
            for (int j = 1; j <= m; j++) {
                if (word1.charAt(i - 1) == word2.charAt(j - 1)) {
                    cur[j] = prev[j - 1];
                } else {
                    cur[j] = 1 + Math.min(prev[j - 1], Math.min(prev[j], cur[j - 1]));
                }
            }
            int[] tmp = prev;
            prev = cur;
            cur = tmp;
        }
        return prev[m];
    }
}
```

### Python
```python
class Solution:
    def minDistance(self, word1: str, word2: str) -> int:
        n, m = len(word1), len(word2)
        prev = list(range(m + 1))
        for i in range(1, n + 1):
            cur = [i] + [0] * m
            for j in range(1, m + 1):
                if word1[i - 1] == word2[j - 1]:
                    cur[j] = prev[j - 1]
                else:
                    cur[j] = 1 + min(prev[j - 1],   # replace
                                     prev[j],       # delete
                                     cur[j - 1])    # insert
            prev = cur
        return prev[m]
```

## Key Takeaways
- Matching characters cost nothing: copy the diagonal. Mismatches always cost exactly 1 plus the best of three neighbours.
- Remember the direction each neighbour represents — diagonal = replace, up = delete, left = insert — it makes reconstructing the actual edit script straightforward.
- The base row and column are `0..m` and `0..n`, not zeros; those represent pure insertion/deletion of an entire string.
- The distance is symmetric: `edit(a, b) == edit(b, a)`, because insert and delete swap roles.
