# Topo Sort

**Difficulty:** Hard  ·  **Topic:** Graphs [Concepts & Problems] › Topo Sort and Problems

## Problem
Given a Directed Acyclic Graph (DAG) with `V` vertices and an adjacency list `adj`, produce a **topological ordering**: a linear arrangement of all vertices such that for every directed edge `u -> v`, `u` appears before `v`. Any valid ordering is accepted. Topological order only exists for a DAG — a cycle makes it impossible, because the nodes of a cycle would each have to precede the other.

```
Input:  V = 6, edges = [[5,0], [5,2], [4,0], [4,1], [2,3], [3,1]]
Output: 5 4 2 3 1 0        // one valid answer; 4 5 2 3 1 0 is also valid
```

## Approach: DFS + reversed finish order (Optimal)

**Key observation.** Think about what DFS does at a node `u`: it fully explores every vertex reachable from `u` and only *then* returns from `u`. So at the moment DFS finishes `u`, every node that must come after `u` in the ordering is already finished. If we push each node onto a stack at the moment we finish it, the nodes that finish last sit on top — and those are exactly the nodes with nothing before them. Popping the stack therefore gives a valid topological order.

Equivalently: **order the vertices by decreasing DFS finish time.**

**Algorithm.**
1. Keep a `visited[]` array and an empty stack.
2. For every vertex `i` that is unvisited, run `dfs(i)`. (Multiple roots are needed because a DAG can be disconnected, and even when connected there is usually more than one source.)
3. `dfs(u)`: mark `u` visited; recurse into each unvisited neighbour; **after** the loop finishes, `push(u)`.
4. When all DFS calls are done, pop the stack into a list — that list is the answer.

**Why it is correct.** Take any edge `u -> v` and consider when DFS first reaches `u`.
- If `v` is unvisited at that time, DFS recurses into `v` and finishes `v` before returning from `u`. So `v` is pushed first, sits lower in the stack, and comes out later than `u`. Correct.
- If `v` is already visited, then in a DAG `v` must already be *finished* (it cannot still be on the path, since an unfinished `v` reachable back to `u` would mean a cycle). Again `v` was pushed earlier and is popped later. Correct.

So every edge points forward in the popped order.

**Dry run** on the example above, starting the outer loop at 0:
- `dfs(0)`: 0 has no outgoing edges → push 0. Stack: `[0]`.
- `dfs(1)`: no outgoing edges → push 1. Stack: `[0,1]`.
- `dfs(2)`: goes to 3, from 3 to 1 (visited), so push 3, then push 2. Stack: `[0,1,3,2]`.
- `dfs(3)` already visited, skip. `dfs(4)`: neighbours 0 and 1 visited → push 4. Stack: `[0,1,3,2,4]`.
- `dfs(5)`: neighbours 0 and 2 visited → push 5. Stack: `[0,1,3,2,4,5]`.
- Popping gives `5 4 2 3 1 0`. Check a few edges: `5` before `0` ✓, `2` before `3` ✓, `3` before `1` ✓.

- **Time:** O(V + E) — one DFS over the whole graph
- **Space:** O(V) for the stack and visited array, plus O(V) recursion depth

*(Kahn's algorithm — repeatedly removing vertices of in-degree 0 with a BFS queue — is the iterative alternative and has the same complexity. It has the extra benefit of detecting cycles: see "Topological sort or Kahn's algorithm".)*

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <stack>
using namespace std;

class Solution {
    void dfs(int u, vector<vector<int>>& adj, vector<int>& visited, stack<int>& st) {
        visited[u] = 1;
        for (int v : adj[u]) {
            if (!visited[v]) dfs(v, adj, visited, st);
        }
        st.push(u);              // push only after all descendants are done
    }

public:
    vector<int> topoSort(int V, vector<vector<int>>& adj) {
        vector<int> visited(V, 0);
        stack<int> st;
        for (int i = 0; i < V; i++) {
            if (!visited[i]) dfs(i, adj, visited, st);
        }
        vector<int> order;
        order.reserve(V);
        while (!st.empty()) {
            order.push_back(st.top());
            st.pop();
        }
        return order;
    }
};
```

### Java
```java
import java.util.*;

class Solution {
    private void dfs(int u, List<List<Integer>> adj, boolean[] visited, Deque<Integer> st) {
        visited[u] = true;
        for (int v : adj.get(u)) {
            if (!visited[v]) dfs(v, adj, visited, st);
        }
        st.push(u);
    }

    public int[] topoSort(int V, List<List<Integer>> adj) {
        boolean[] visited = new boolean[V];
        Deque<Integer> st = new ArrayDeque<>();
        for (int i = 0; i < V; i++) {
            if (!visited[i]) dfs(i, adj, visited, st);
        }
        int[] order = new int[V];
        for (int i = 0; i < V; i++) order[i] = st.pop();
        return order;
    }
}
```

### Python
```python
import sys
from typing import List

class Solution:
    def topoSort(self, V: int, adj: List[List[int]]) -> List[int]:
        sys.setrecursionlimit(10 ** 6)
        visited = [False] * V
        stack: List[int] = []

        def dfs(u: int) -> None:
            visited[u] = True
            for v in adj[u]:
                if not visited[v]:
                    dfs(v)
            stack.append(u)

        for i in range(V):
            if not visited[i]:
                dfs(i)
        return stack[::-1]
```

## Key Takeaways
- Topological order = vertices sorted by **decreasing DFS finish time**; pushing on the way out of the recursion and reversing does exactly that.
- Push after the neighbour loop, never before — pushing on entry gives a wrong order.
- Only DAGs have a topological order; plain DFS topo sort assumes acyclicity and will silently output garbage on a cyclic graph, so pair it with cycle detection when acyclicity is not guaranteed.
- Start DFS from every unvisited vertex: a DAG usually has several sources and may be disconnected.
