# Infix to Prefix Conversion

**Difficulty:** Medium  ·  **Topic:** Stack and Queues [Learning, Pre-In-Post-fix, Monotonic Stack, Implementation] › Prefix, Infix, PostFix Conversion Problems

## Problem
Convert a valid **infix** expression (operator between operands, with brackets and precedence) into the equivalent **prefix** / Polish form, where every operator is written *before* its two operands and no brackets are needed. Operands are single characters; operators are `+ - * / ^`.

```
Input:  (a-b/c)*(a/k-l)
Output: *-a/bc-/akl
```

## Approach 1: Build an expression tree, then pre-order it
Parse the infix expression into a binary expression tree (operators as internal nodes, operands as leaves), then read it in **pre-order** (node, left, right) to get prefix; an in-order walk would give back infix and a post-order walk would give postfix. This makes the relationship between the three notations obvious, but writing a correct precedence-aware parser is much more work than the stack method below, and it costs O(n) extra nodes.

- **Time:** O(n)
- **Space:** O(n) for the tree plus recursion.

## Approach 2: Reverse, convert to postfix, reverse again (Optimal)
The clean trick relies on a symmetry: **prefix is the mirror image of postfix**. Reversing a prefix expression gives something with the operator last — postfix-shaped — for the *reversed* operand order. So:

1. **Reverse the infix string**, swapping every `(` with `)` and vice versa (a reversed `(a-b)` would otherwise read `)b-a(`, which is not a valid bracketing).
2. **Run the standard infix-to-postfix shunting-yard** on that reversed string.
3. **Reverse the result.**

**The one subtlety: associativity flips.** In the reversed string the operands of each operator appear in swapped order, so a left-associative operator behaves like a right-associative one and vice versa. Concretely, in the reversed pass:
- for `+ - * /` (left-associative in the original), an equal-precedence top must **not** be popped — use strict `>`;
- for `^` (right-associative in the original), an equal-precedence top **must** be popped — use `>=`.

That is exactly inverted from ordinary infix-to-postfix. It is easy to check on two tiny cases. `a-b-c` should give `--abc`, i.e. `(a-b)-c`. Reversed it is `c-b-a`; with strict `>` the second `-` pops nothing, so the operands come out as `cba` and both `-` are drained at the end, giving `cba--`; reversing that yields `--abc`. ✓ If we had popped on equality we would get `cb-a-`, which reverses to `-a-bc` = `a-(b-c)` — wrong. Symmetrically `a^b^c` must give `^a^bc`; reversed `c^b^a` with `>=` pops the first `^`, producing `cb^a^`, which reverses to `^a^bc`. ✓

**Dry run on `(a-b/c)*(a/k-l)`.** Reversed with swapped brackets: `(l-k/a)*(c/b-a)`.
- `(` push; `l` → out `l`; `-` push; `k` → `lk`; `/` (2 > 1) push; `a` → `lka`; `)` pops `/` then `-` → `lka/-`, discards `(`.
- `*` : stack empty, push.
- `(` push; `c` → `lka/-c`; `/` push; `b` → `...cb`; `-` pops `/` → `lka/-cb/`, push `-`; `a` → `lka/-cb/a`; `)` pops `-` → `lka/-cb/a-`.
- End: pop `*` → `lka/-cb/a-*`.

Reverse that string: `*-a/bc-/akl`. That is the expected prefix output.

Reading it back to check: `* ( - a (/ b c) ) ( - (/ a k) l )` = `(a - b/c) * (a/k - l)`. ✓

- **Time:** O(n) — three linear passes.
- **Space:** O(n) for the stack and the reversed copy.

## Code (Optimal)

### C++
```cpp
#include <string>
#include <stack>
#include <algorithm>
#include <cctype>
using namespace std;

class Solution {
public:
    string infixToPrefix(string s) {
        // 1) reverse and swap brackets
        reverse(s.begin(), s.end());
        for (char& c : s) {
            if (c == '(') c = ')';
            else if (c == ')') c = '(';
        }
        // 2) infix -> postfix with flipped associativity
        stack<char> st;
        string out;
        for (char c : s) {
            if (isalnum(static_cast<unsigned char>(c))) {
                out.push_back(c);
            } else if (c == '(') {
                st.push(c);
            } else if (c == ')') {
                while (!st.empty() && st.top() != '(') { out.push_back(st.top()); st.pop(); }
                if (!st.empty()) st.pop();
            } else {
                while (!st.empty() && st.top() != '(' && shouldPop(st.top(), c)) {
                    out.push_back(st.top());
                    st.pop();
                }
                st.push(c);
            }
        }
        while (!st.empty()) { out.push_back(st.top()); st.pop(); }
        // 3) reverse back
        reverse(out.begin(), out.end());
        return out;
    }

private:
    int prec(char op) {
        if (op == '^') return 3;
        if (op == '*' || op == '/') return 2;
        if (op == '+' || op == '-') return 1;
        return 0;
    }
    bool shouldPop(char top, char cur) {
        if (prec(top) > prec(cur)) return true;
        if (prec(top) < prec(cur)) return false;
        return cur == '^';       // associativity is inverted on the reversed string
    }
};
```

### Java
```java
import java.util.*;

class Solution {
    public String infixToPrefix(String s) {
        StringBuilder rev = new StringBuilder();
        for (int i = s.length() - 1; i >= 0; i--) {
            char c = s.charAt(i);
            if (c == '(') c = ')';
            else if (c == ')') c = '(';
            rev.append(c);
        }

        Deque<Character> st = new ArrayDeque<>();
        StringBuilder out = new StringBuilder();
        for (int i = 0; i < rev.length(); i++) {
            char c = rev.charAt(i);
            if (Character.isLetterOrDigit(c)) {
                out.append(c);
            } else if (c == '(') {
                st.push(c);
            } else if (c == ')') {
                while (!st.isEmpty() && st.peek() != '(') out.append(st.pop());
                if (!st.isEmpty()) st.pop();
            } else {
                while (!st.isEmpty() && st.peek() != '(' && shouldPop(st.peek(), c)) {
                    out.append(st.pop());
                }
                st.push(c);
            }
        }
        while (!st.isEmpty()) out.append(st.pop());
        return out.reverse().toString();
    }

    private int prec(char op) {
        if (op == '^') return 3;
        if (op == '*' || op == '/') return 2;
        if (op == '+' || op == '-') return 1;
        return 0;
    }

    private boolean shouldPop(char top, char cur) {
        if (prec(top) > prec(cur)) return true;
        if (prec(top) < prec(cur)) return false;
        return cur == '^';
    }
}
```

### Python
```python
class Solution:
    def infixToPrefix(self, s: str) -> str:
        swap = {'(': ')', ')': '('}
        rev = [swap.get(c, c) for c in reversed(s)]

        prec = {'^': 3, '*': 2, '/': 2, '+': 1, '-': 1}

        def should_pop(top: str, cur: str) -> bool:
            if prec[top] > prec[cur]:
                return True
            if prec[top] < prec[cur]:
                return False
            return cur == '^'        # associativity inverted on the reversed string

        st, out = [], []
        for c in rev:
            if c.isalnum():
                out.append(c)
            elif c == '(':
                st.append(c)
            elif c == ')':
                while st and st[-1] != '(':
                    out.append(st.pop())
                if st:
                    st.pop()
            else:
                while st and st[-1] != '(' and should_pop(st[-1], c):
                    out.append(st.pop())
                st.append(c)
        while st:
            out.append(st.pop())
        return "".join(reversed(out))
```

## Key Takeaways
- Prefix is postfix read backwards, so *reverse → postfix → reverse* is the whole algorithm; there is no separate rule set to memorise.
- Swap `(` and `)` while reversing, otherwise the bracket structure of the reversed string is invalid.
- Associativity inverts on the reversed string: strict `>` for `+ - * /`, `>=` for `^`. Getting this backwards silently breaks only chained same-precedence operators, so test `a-b-c` and `a^b^c`.
- All three notations describe the same expression tree: pre-order = prefix, in-order = infix, post-order = postfix.
