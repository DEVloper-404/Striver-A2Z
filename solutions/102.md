# Delete a node in BST

**Difficulty:** Medium  ·  **Topic:** Binary Search Trees [Concept and Problems] › Practice Problems

## Problem
Given the root of a BST and a `key`, delete the node holding `key` (if it exists) and return the root of the updated tree. The tree must still be a valid BST afterwards.

```
Input:  root = [5, 3, 6, 2, 4, null, 7], key = 3
Output: [5, 4, 6, 2, null, null, 7]     (3 is replaced by its successor 4)

Input:  root = [5, 3, 6, 2, 4, null, 7], key = 0
Output: [5, 3, 6, 2, 4, null, 7]        (key absent — tree unchanged)
```

## Approach 1: Rebuild the tree
Collect the inorder traversal, drop `key` from the sorted array, and build a fresh BST from what remains. Always correct, but it discards the existing structure and touches every node.
- **Time:** O(N)
- **Space:** O(N)

## Approach 2: Optimal (find the node, then patch the hole by case)
Deletion splits into two phases: **find** the node (a standard O(H) BST descent), then **remove** it while preserving the ordering. The removal has three cases, and the third is the only interesting one.

**Case 1 — the node is a leaf.** Nothing depends on it. Its parent's pointer becomes null. Ordering is trivially preserved.

**Case 2 — the node has exactly one child.** Everything in that child's subtree already sits on the correct side of every ancestor (the deleted node was just a pass-through on the search path). So splice the node out: the parent points directly at the single child.

**Case 3 — the node has two children.** We cannot just promote a child, because the other child has nowhere to go. The fix uses a fact about the inorder ordering: the value that can legally take this node's place is either its **inorder predecessor** (the maximum of the left subtree) or its **inorder successor** (the minimum of the right subtree). Either one is, by construction, greater than everything in the left subtree and less than everything in the right subtree — exactly the constraint the deleted value satisfied. So:
1. Find the successor `s` = leftmost node of `node->right`.
2. Copy `s->val` into `node`.
3. Recursively delete `s` from the right subtree. Crucially, `s` is the leftmost node so it has **no left child**, which means this recursive deletion always lands in Case 1 or Case 2 — the recursion cannot cascade.

The cleanest way to write all of this is to let the recursion re-link pointers for you: `deleteNode(node, key)` returns the new root of that subtree, and the caller writes `node->left = deleteNode(node->left, key)`. That removes the need to track parent pointers.

**Dry run** on `[5, 3, 6, 2, 4, null, 7]` deleting `3`:
- At `5`: `3 < 5` → recurse into the left subtree, assign back to `5->left`.
- At `3`: match. It has two children (`2` and `4`) → Case 3.
- Successor = leftmost of the right subtree `{4}` = `4`.
- Copy `4` into the node (it now reads `4`, with children `2` and `4`).
- Delete `4` from the right subtree: that node is a leaf → returns null, so the right child becomes null.
- Final subtree: `4` with left child `2`. Full tree inorder: `2 4 5 6 7` — sorted, and `3` is gone. ✔

- **Time:** O(H) — the search path plus one walk to find the successor, both bounded by the height
- **Space:** O(H) recursion stack (O(1) if written iteratively with parent pointers)

## Code (Optimal)

### C++
```cpp
// struct TreeNode { int val; TreeNode *left, *right; TreeNode(int x) ... } — standard definition

class Solution {
    TreeNode* minNode(TreeNode* node) {          // leftmost node = smallest value
        while (node->left) node = node->left;
        return node;
    }
public:
    TreeNode* deleteNode(TreeNode* root, int key) {
        if (root == nullptr) return nullptr;

        if (key < root->val) {
            root->left = deleteNode(root->left, key);
        } else if (key > root->val) {
            root->right = deleteNode(root->right, key);
        } else {
            // Case 1 & 2: zero or one child — splice the node out.
            if (root->left == nullptr)  { TreeNode* r = root->right; delete root; return r; }
            if (root->right == nullptr) { TreeNode* l = root->left;  delete root; return l; }

            // Case 3: two children — replace with the inorder successor.
            TreeNode* succ = minNode(root->right);
            root->val = succ->val;
            root->right = deleteNode(root->right, succ->val);
        }
        return root;
    }
};
```

### Java
```java
// class TreeNode { int val; TreeNode left, right; TreeNode(int x) ... } — standard definition

class Solution {
    private TreeNode minNode(TreeNode node) {
        while (node.left != null) node = node.left;
        return node;
    }

    public TreeNode deleteNode(TreeNode root, int key) {
        if (root == null) return null;

        if (key < root.val) {
            root.left = deleteNode(root.left, key);
        } else if (key > root.val) {
            root.right = deleteNode(root.right, key);
        } else {
            if (root.left == null)  return root.right;   // 0 or 1 child
            if (root.right == null) return root.left;

            TreeNode succ = minNode(root.right);         // 2 children
            root.val = succ.val;
            root.right = deleteNode(root.right, succ.val);
        }
        return root;
    }
}
```

### Python
```python
# class TreeNode: val, left, right — standard definition

class Solution:
    def deleteNode(self, root, key):
        if root is None:
            return None

        if key < root.val:
            root.left = self.deleteNode(root.left, key)
        elif key > root.val:
            root.right = self.deleteNode(root.right, key)
        else:
            if root.left is None:            # 0 or 1 child: splice out
                return root.right
            if root.right is None:
                return root.left

            succ = root.right                # 2 children: inorder successor
            while succ.left:
                succ = succ.left
            root.val = succ.val
            root.right = self.deleteNode(root.right, succ.val)

        return root
```

## Key Takeaways
- Three cases, and only the two-children case needs thought: replace the value with the inorder successor (min of right subtree) or predecessor (max of left subtree).
- The successor has no left child by definition, so the follow-up deletion is always a cheap leaf/one-child case — the recursion depth stays O(H).
- Returning the (possibly new) subtree root from the recursive call and assigning it back is what re-links parents without storing parent pointers.
- Edge cases: deleting the root, deleting a key that is not present (return the tree unchanged), and an empty tree.
