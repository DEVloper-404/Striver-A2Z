# MST theory

**Difficulty:** Easy  ·  **Topic:** Graphs [Concepts & Problems] › MinimumSpanningTree/Disjoint Set and Problems

## Problem
This topic covers what a **spanning tree** and a **minimum spanning tree (MST)** are, what properties they have, and which algorithms compute them. Given a connected, undirected, weighted graph with `V` vertices and `E` edges, a spanning tree is a subset of edges that keeps every vertex connected while forming a tree (no cycles). The MST is the spanning tree whose total edge weight is smallest.

```
Graph (V = 5):
  0 --2-- 1
  0 --1-- 2
  1 --1-- 2
  2 --2-- 3
  1 --2-- 4
  3 --1-- 4

One MST: edges (0-2, w=1), (1-2, w=1), (3-4, w=1), (1-4, w=2)
Total weight = 5
```

## Approach: The definitions, the properties, and the two standard algorithms

**Spanning tree.** A subgraph that (a) contains **all `V` vertices**, (b) is **connected**, and (c) has **exactly `V - 1` edges**. Any two of those three conditions force the third. With `V - 1` edges and full connectivity there is no room for a cycle, so a spanning tree is always acyclic — that is why it is called a tree. A graph normally has many spanning trees; a complete graph on `V` vertices has `V^(V-2)` of them (Cayley's formula).

**Minimum spanning tree.** Among all spanning trees, the one minimising the sum of edge weights. The MST is not necessarily unique: if two edges share a weight, swapping them may give a different tree of the same total cost. The *weight* of the MST, however, is unique.

**Why greedy works — the cut property.** Split the vertices into any two non-empty groups (a *cut*). The cheapest edge crossing that cut is safe: some MST contains it. Sketch: suppose an MST `T` omits that cheapest crossing edge `e`. Adding `e` to `T` creates exactly one cycle, and that cycle must cross the cut a second time via some edge `f`. Since `e` is the cheapest crossing edge, `weight(e) ≤ weight(f)`, so swapping `f` out for `e` gives a spanning tree no heavier than `T`. This single property is what licenses both standard algorithms to make locally cheapest choices and still land on a global optimum.

**The mirror image — the cycle property.** In any cycle, the strictly heaviest edge cannot be in any MST: remove it and the rest of the cycle still connects its endpoints, more cheaply. Kruskal's rejection step is exactly this rule in action.

**Prim's algorithm — grow one tree.** Start from any vertex and maintain a set `S` of vertices already in the tree. Repeatedly pick the cheapest edge leaving `S` (this is the cut property applied to the cut `S | V∖S`) and pull its far endpoint into `S`. A min-heap keyed by "cheapest known edge into the tree" makes each step `O(log V)`.

```cpp
// heart of Prim's: pop cheapest, mark visited, push its unvisited neighbours
auto [w, node, parent] = pq.top(); pq.pop();
if (visited[node]) continue;
visited[node] = true; total += w;
for (auto [nxt, wt] : adj[node]) if (!visited[nxt]) pq.push({wt, nxt, node});
```

**Kruskal's algorithm — merge many trees.** Sort all edges by weight ascending. Scan them and accept an edge whenever its two endpoints are in **different** components, using a Disjoint Set Union to test and merge; reject it otherwise (accepting would close a cycle, and by the cycle property that edge is the heaviest on it). Stop after `V - 1` accepted edges.

```python
edges.sort(key=lambda e: e[2])
for u, v, w in edges:
    if dsu.find(u) != dsu.find(v):
        dsu.union(u, v)
        total += w
```

**Which to use.** Prim's with a heap is `O(E log V)` and is natural on an adjacency list, especially for dense graphs. Kruskal's is `O(E log E)` dominated by the sort and is natural when you already have an edge list. Both give the same total weight.

**Disconnected input.** If the graph is not connected there is no spanning *tree*; you get a **minimum spanning forest** — one MST per component, and Kruskal's ends with fewer than `V - 1` accepted edges. Checking that count is the usual way to detect disconnection.

- **Time:** O(E log V) with Prim's + heap, O(E log E) with Kruskal's + DSU
- **Space:** O(V + E) for the adjacency list / edge list and the auxiliary structure

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <algorithm>
#include <queue>
#include <numeric>
using namespace std;

// Kruskal's MST weight. edges[i] = {u, v, w}, 0-indexed, undirected.
class Solution {
    vector<int> parent, rnk;
    int find(int x) { return parent[x] == x ? x : parent[x] = find(parent[x]); }
    bool unite(int a, int b) {
        a = find(a); b = find(b);
        if (a == b) return false;
        if (rnk[a] < rnk[b]) swap(a, b);
        parent[b] = a;
        if (rnk[a] == rnk[b]) rnk[a]++;
        return true;
    }
public:
    int mstWeight(int V, vector<vector<int>>& edges) {
        parent.resize(V); rnk.assign(V, 0);
        iota(parent.begin(), parent.end(), 0);
        sort(edges.begin(), edges.end(),
             [](const vector<int>& a, const vector<int>& b) { return a[2] < b[2]; });
        int total = 0, used = 0;
        for (auto& e : edges) {
            if (unite(e[0], e[1])) { total += e[2]; used++; }
        }
        return used == V - 1 ? total : -1;   // -1 => graph is disconnected
    }
};
```

### Java
```java
import java.util.*;

class Solution {
    private int[] parent, rank;

    private int find(int x) {
        if (parent[x] != x) parent[x] = find(parent[x]);
        return parent[x];
    }

    private boolean unite(int a, int b) {
        a = find(a); b = find(b);
        if (a == b) return false;
        if (rank[a] < rank[b]) { int t = a; a = b; b = t; }
        parent[b] = a;
        if (rank[a] == rank[b]) rank[a]++;
        return true;
    }

    public int mstWeight(int V, int[][] edges) {
        parent = new int[V];
        rank = new int[V];
        for (int i = 0; i < V; i++) parent[i] = i;
        Arrays.sort(edges, (a, b) -> Integer.compare(a[2], b[2]));
        int total = 0, used = 0;
        for (int[] e : edges) {
            if (unite(e[0], e[1])) { total += e[2]; used++; }
        }
        return used == V - 1 ? total : -1;
    }
}
```

### Python
```python
from typing import List

class Solution:
    def mstWeight(self, V: int, edges: List[List[int]]) -> int:
        parent = list(range(V))
        rank = [0] * V

        def find(x: int) -> int:
            while parent[x] != x:
                parent[x] = parent[parent[x]]     # path halving
                x = parent[x]
            return x

        def unite(a: int, b: int) -> bool:
            a, b = find(a), find(b)
            if a == b:
                return False
            if rank[a] < rank[b]:
                a, b = b, a
            parent[b] = a
            if rank[a] == rank[b]:
                rank[a] += 1
            return True

        total = used = 0
        for u, v, w in sorted(edges, key=lambda e: e[2]):
            if unite(u, v):
                total += w
                used += 1
        return total if used == V - 1 else -1      # -1 => disconnected
```

## Key Takeaways
- A spanning tree has all `V` vertices, is connected, and has exactly `V - 1` edges; the MST is the cheapest such tree.
- The **cut property** (cheapest edge across any cut is safe) is the single fact that justifies both Prim's and Kruskal's greedy choices.
- The **cycle property** (heaviest edge on a cycle is never in an MST) is what Kruskal's rejection step is doing.
- MSTs are not unique when weights repeat, but the total weight is; a disconnected graph yields a spanning *forest*, detectable by accepting fewer than `V - 1` edges.
