# Triangle

**Difficulty:** Medium  ·  **Topic:** Dynamic Programming [Patterns and Problems] › 2D/3D DP and DP on Grids

## Problem
You are given a triangular array where row `i` has exactly `i+1` entries. Starting at the single cell of the top row, you repeatedly move to one of the two cells directly below: from `(i, j)` you may go to `(i+1, j)` or `(i+1, j+1)`. Return the minimum possible sum of the numbers on a path from top to bottom.

```
Input:  triangle = [[2],
                    [3, 4],
                    [6, 5, 7],
                    [4, 1, 8, 3]]
Output: 11
        Path 2 → 3 → 5 → 1 = 11
```

## Approach 1: Top-down recursion (brute force)

**Reading the geometry.** A triangle is a grid whose row `i` is cut off after column `i`. Standing at `(i, j)`, "below" means keeping the same column (moving down the left edge of the cell) or increasing it by one (moving down-right). Nothing else is reachable, and the start is fixed at `(0, 0)`.

Define `f(i, j)` = minimum sum of a path that starts at `(i, j)` and reaches the **bottom row**. Split on the first move:

```
f(n-1, j) = triangle[n-1][j]                                  // already at the bottom
f(i, j)   = triangle[i][j] + min( f(i+1, j), f(i+1, j+1) )
answer    = f(0, 0)
```

Why define it *forward* from a cell to the bottom instead of backwards? Because in this problem the **start is fixed and the end is free**. Defining `f` as "cost from here to the bottom" makes the base case a plain copy of the last row and the answer a single cell, `f(0,0)`. The reverse formulation ("cost from the top to here") also works, but then the answer is a `min` over the whole last row — slightly more bookkeeping. Either is fine; being deliberate about which end is fixed is the actual skill.

Correctness: the cost of standing on `(i, j)` is `triangle[i][j]` no matter how you continue, so the cheapest completion through a given child is that child's own optimum plus a constant — optimal substructure.

Raw recursion re-explores shared subtrees (both `(i,j)` and `(i,j-1)` call `f(i+1, j)`), giving about `2^n` calls.
- **Time:** O(2^n)
- **Space:** O(n) recursion stack

## Approach 2: Memoization
State = `(i, j)` with `j <= i`, so about `n²/2` states, O(1) work each. Cache in `dp[i][j]`. Careful with the sentinel: triangle values may be negative, so `-1` is a poor "not computed" marker — use a `visited` flag or `INT_MAX`.
- **Time:** O(n²)
- **Space:** O(n²) table + O(n) stack

## Approach 3: Bottom-up tabulation
Fill from the bottom row upward, which matches the dependency direction (`row i` needs `row i+1`):

```
dp[n-1][j] = triangle[n-1][j]                for all j
for i = n-2 down to 0:
    for j = 0 .. i:
        dp[i][j] = triangle[i][j] + min(dp[i+1][j], dp[i+1][j+1])
answer = dp[0][0]
```

Note that `dp[i+1][j+1]` is always in range when `j <= i`, because row `i+1` has `i+2` entries — so no boundary check is needed at all. That is a small but pleasant consequence of the triangular shape.
- **Time:** O(n²)
- **Space:** O(n²)

## Approach 4: One rolling row, updated in place (Optimal)

Row `i` reads only row `i+1`, so a single array of length `n` suffices. And here — unlike the falling-path problem — an **in-place** update is safe if we sweep `j` from left to right: when we write index `j`, the array still holds row `i+1` at positions `j` and `j+1` (only positions `< j` have been overwritten), and those are exactly the two values we need.

**Algorithm.**
1. `dp = copy of the last row` (length `n`).
2. For `i = n-2` down to `0`: for `j = 0 … i`, set `dp[j] = triangle[i][j] + min(dp[j], dp[j+1])`.
3. Return `dp[0]`.

**Dry run on the example** (`n = 4`).

- Start: `dp = [4, 1, 8, 3]` (bottom row).
- `i = 2`, `triangle[2] = [6, 5, 7]`:
  - `j=0`: `6 + min(4, 1) = 7`
  - `j=1`: `5 + min(1, 8) = 6`
  - `j=2`: `7 + min(8, 3) = 10`
  - `dp = [7, 6, 10, 3]` (the trailing `3` is stale and never read again)
- `i = 1`, `triangle[1] = [3, 4]`:
  - `j=0`: `3 + min(7, 6) = 9`
  - `j=1`: `4 + min(6, 10) = 10`
  - `dp = [9, 10, 10, 3]`
- `i = 0`, `triangle[0] = [2]`:
  - `j=0`: `2 + min(9, 10) = 11`

Return `dp[0] = 11`. ✔ Tracing the choices: at the top we took the left child (9), at row 1 we took the right child (6 from index 1), at row 2 we took the right child (1) — the path `2 → 3 → 5 → 1`.
- **Time:** O(n²) — you must look at every cell at least once, so this is asymptotically optimal.
- **Space:** O(n)

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int minimumTotal(vector<vector<int>>& triangle) {
        int n = triangle.size();
        vector<int> dp = triangle[n - 1];              // start from the bottom row
        for (int i = n - 2; i >= 0; i--) {
            for (int j = 0; j <= i; j++) {
                // dp[j], dp[j+1] still hold row i+1 at this moment
                dp[j] = triangle[i][j] + min(dp[j], dp[j + 1]);
            }
        }
        return dp[0];
    }
};
```

### Java
```java
import java.util.List;

class Solution {
    public int minimumTotal(List<List<Integer>> triangle) {
        int n = triangle.size();
        int[] dp = new int[n];
        for (int j = 0; j < n; j++) dp[j] = triangle.get(n - 1).get(j);

        for (int i = n - 2; i >= 0; i--) {
            for (int j = 0; j <= i; j++) {
                // dp[j], dp[j+1] still hold row i+1 at this moment
                dp[j] = triangle.get(i).get(j) + Math.min(dp[j], dp[j + 1]);
            }
        }
        return dp[0];
    }
}
```

### Python
```python
from typing import List


class Solution:
    def minimumTotal(self, triangle: List[List[int]]) -> int:
        n = len(triangle)
        dp = list(triangle[-1])                        # start from the bottom row
        for i in range(n - 2, -1, -1):
            for j in range(i + 1):
                # dp[j], dp[j+1] still hold row i+1 at this moment
                dp[j] = triangle[i][j] + min(dp[j], dp[j + 1])
        return dp[0]
```

## Key Takeaways
- Fixed start, free end ⇒ define the DP as "cost from this cell to the end" so the base case is the last row and the answer is one cell.
- Direction of iteration must follow the dependency: bottom row first, then upward.
- The triangular shape guarantees `j+1` is in range on the row below, so no boundary checks are needed.
- In-place single-array update is safe here because the recurrence reads `dp[j]` and `dp[j+1]` while sweeping left to right; it would *not* be safe if it also read `dp[j-1]` of the old row.
- Choose the sentinel for memoization carefully when values can be negative — `-1` may be a valid answer.
