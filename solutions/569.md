# Merge K sorted Lists

**Difficulty:** Hard  ·  **Topic:** Heaps [Learning, Medium, Hard Problems] › Medium Problems

## Problem
You are given an array of `k` singly linked lists, each already sorted in ascending order. Merge all of them into one sorted linked list and return its head. Some lists may be empty, and the whole array may be empty.

```
Input:  lists = [[1, 4, 5], [1, 3, 4], [2, 6]]
Output: [1, 1, 2, 3, 4, 4, 5, 6]
```

## Approach 1: Collect and sort
Walk every list, dump all values into an array, sort it, and rebuild a linked list. Simple, but it throws away the fact that each list is already sorted. With `N` total nodes:
- **Time:** O(N log N)
- **Space:** O(N)

## Approach 2: Merge lists one at a time
Merge list 1 with list 2 (standard two-pointer merge), then merge the result with list 3, and so on. The running merged list keeps growing, so later merges are expensive: the total work is roughly `N * k` in the worst case (each node is touched up to `k` times).
- **Time:** O(N * k)
- **Space:** O(1) extra (reusing nodes)

## Approach 3: Min-heap of list heads (optimal)
At any moment the next node of the merged output must be the smallest among the current heads of the `k` lists. Keep those heads in a min-heap keyed by value:

1. Push the head of every non-empty list.
2. Pop the smallest node, append it to the output tail, and push that node's `next` if it exists.
3. Repeat until the heap is empty.

Every node is pushed and popped exactly once, and the heap never holds more than `k` nodes.
- **Time:** O(N log k)
- **Space:** O(k) for the heap

(Divide-and-conquer pairwise merging achieves the same O(N log k) with O(log k) recursion depth; the heap version is the natural one for this section.)

## Code (Optimal)

### C++
```cpp
#include <bits/stdc++.h>
using namespace std;

// struct ListNode { int val; ListNode *next; ListNode(int x) : val(x), next(nullptr) {} };
// (standard LeetCode definition)

class Solution {
public:
    ListNode* mergeKLists(vector<ListNode*>& lists) {
        auto cmp = [](ListNode* a, ListNode* b) { return a->val > b->val; };
        priority_queue<ListNode*, vector<ListNode*>, decltype(cmp)> minHeap(cmp);

        for (ListNode* head : lists) {
            if (head) minHeap.push(head);
        }

        ListNode dummy(0);
        ListNode* tail = &dummy;
        while (!minHeap.empty()) {
            ListNode* node = minHeap.top();
            minHeap.pop();
            tail->next = node;
            tail = node;
            if (node->next) minHeap.push(node->next);
        }
        return dummy.next;
    }
};
```

### Java
```java
import java.util.*;

// class ListNode { int val; ListNode next; ListNode(int x) { val = x; } }
// (standard LeetCode definition)

class Solution {
    public ListNode mergeKLists(ListNode[] lists) {
        PriorityQueue<ListNode> minHeap = new PriorityQueue<>((a, b) -> a.val - b.val);
        for (ListNode head : lists) {
            if (head != null) minHeap.offer(head);
        }

        ListNode dummy = new ListNode(0);
        ListNode tail = dummy;
        while (!minHeap.isEmpty()) {
            ListNode node = minHeap.poll();
            tail.next = node;
            tail = node;
            if (node.next != null) minHeap.offer(node.next);
        }
        return dummy.next;
    }
}
```

### Python
```python
import heapq
from typing import List, Optional

# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next
# (standard LeetCode definition)


class Solution:
    def mergeKLists(self, lists: List[Optional[ListNode]]) -> Optional[ListNode]:
        # Store (value, list index, node); the index breaks ties so that
        # ListNode objects never get compared directly.
        heap = []
        for i, head in enumerate(lists):
            if head:
                heapq.heappush(heap, (head.val, i, head))

        dummy = ListNode(0)
        tail = dummy
        while heap:
            val, i, node = heapq.heappop(heap)
            tail.next = node
            tail = node
            if node.next:
                heapq.heappush(heap, (node.next.val, i, node.next))
        return dummy.next
```

## Key Takeaways
- The heap only ever needs the current front of each list, so its size is bounded by `k`, not by the total node count.
- Push `node.next` right after popping `node`; forgetting that step silently drops the rest of a list.
- Skip null heads before pushing; an empty `lists` array or all-empty lists should return `None`/`nullptr`.
- In Python, include a tie-breaker (the list index) in the heap tuple so equal values never trigger a comparison between node objects.
