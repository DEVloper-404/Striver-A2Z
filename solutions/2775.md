# Inorder Successor/Predecessor in BST

**Difficulty:** Medium  ·  **Topic:** Binary Search Trees [Concept and Problems] › Practice Problems

## Problem
Given the root of a BST and a node `p` in it, find:
- the **inorder successor** — the node with the smallest value strictly greater than `p.val`;
- the **inorder predecessor** — the node with the largest value strictly less than `p.val`.

Return `null` if it does not exist (the successor of the maximum, the predecessor of the minimum).

```
Input:  root = [8, 5, 12, 3, 7, 10, 15], p = 7
Output: successor = 8, predecessor = 5

Input:  root = [8, 5, 12, 3, 7, 10, 15], p = 15
Output: successor = null, predecessor = 12
```

## Approach 1: Brute Force (inorder list)
Produce the inorder traversal into an array (which is sorted), find `p` in it, and take the neighbours at index `+1` and `-1`.

Correct and easy to reason about, but it visits every node and stores every value.
- **Time:** O(N)
- **Space:** O(N)

## Approach 2: Better (inorder traversal remembering the previous node)
Traverse inorder while keeping a pointer `prev` to the last visited node. When you arrive at `p`, `prev` is the predecessor; the very next node visited after `p` is the successor. One pass, no array.

Still O(N) in the worst case because the traversal does not exploit the ordering to skip subtrees.
- **Time:** O(N)
- **Space:** O(H)

## Approach 3: Optimal (guided descent, remember the best candidate)
This is the same *remember-then-descend* pattern as floor/ceil, and the reasoning is worth spelling out.

**Successor.** We want the smallest value that is still `> p.val`. Standing at a node with value `v`:
- If `v <= p.val`, then `v` is disqualified, and so is everything in its **left** subtree (all smaller than `v`, hence also `<= p.val`). Discard both and move right.
- If `v > p.val`, then `v` is a valid candidate — record it. But there might be a *smaller* valid value, and any such value must be in `v`'s **left** subtree (everything to the right of `v` is bigger than `v`). So save `v` and move left.

Each recorded candidate is strictly smaller than the previous one (we always move into the left subtree of the node we just recorded), so the last recorded value is the minimum over all valid values — exactly the successor. If nothing was ever recorded, `p.val` is the maximum and there is no successor.

**Predecessor** is the exact mirror: when `v >= p.val` move left; when `v < p.val` record `v` and move right.

**Dry run** for the successor of `7` in `[8, 5, 12, 3, 7, 10, 15]`:

| Node | Compare with 7 | Action | candidate |
|------|----------------|--------|-----------|
| 8  | 8 > 7  | record 8, go left | 8 |
| 5  | 5 ≤ 7  | discard 5 and its left subtree, go right | 8 |
| 7  | 7 ≤ 7  | discard, go right | 8 |
| null | — | stop | **8** |

Answer `8`. ✔ Note how the strict `<=` at node `7` is what makes the successor *strictly* greater — using `<` there would wrongly return `p` itself.

Predecessor of `7`: at `8`, `8 >= 7` → go left; at `5`, `5 < 7` → record 5, go right; at `7`, `7 >= 7` → go left → null. Answer `5`. ✔

**Special case worth knowing:** if the node `p` has a right child, its successor is simply the leftmost node of that right subtree — no candidate tracking needed. The general loop above already produces this result, which is why the deletion algorithm for BSTs can use that shortcut directly.
- **Time:** O(H) — O(log N) balanced, O(N) skewed
- **Space:** O(1)

## Code (Optimal)

### C++
```cpp
// struct TreeNode { int val; TreeNode *left, *right; TreeNode(int x) ... } — standard definition

class Solution {
public:
    TreeNode* inorderSuccessor(TreeNode* root, TreeNode* p) {
        TreeNode* ans = nullptr;
        TreeNode* cur = root;
        while (cur != nullptr) {
            if (cur->val > p->val) {
                ans = cur;            // valid; a smaller valid value can only be on the left
                cur = cur->left;
            } else {
                cur = cur->right;     // cur and its left subtree are all <= p->val
            }
        }
        return ans;
    }

    TreeNode* inorderPredecessor(TreeNode* root, TreeNode* p) {
        TreeNode* ans = nullptr;
        TreeNode* cur = root;
        while (cur != nullptr) {
            if (cur->val < p->val) {
                ans = cur;            // valid; a larger valid value can only be on the right
                cur = cur->right;
            } else {
                cur = cur->left;
            }
        }
        return ans;
    }
};
```

### Python
```python
# class TreeNode: val, left, right — standard definition

class Solution:
    def inorderSuccessor(self, root, p):
        ans, cur = None, root
        while cur:
            if cur.val > p.val:
                ans = cur          # candidate; look left for a tighter one
                cur = cur.left
            else:
                cur = cur.right    # cur and everything left of it is <= p.val
        return ans

    def inorderPredecessor(self, root, p):
        ans, cur = None, root
        while cur:
            if cur.val < p.val:
                ans = cur          # candidate; look right for a tighter one
                cur = cur.right
            else:
                cur = cur.left
        return ans
```

## Key Takeaways
- Successor/predecessor is the same *record-a-candidate-then-descend* template as floor and ceil — only the strictness of the comparison differs.
- Strictness matters: using `>` (not `>=`) for the successor is what prevents returning `p` itself.
- Shortcut worth remembering: if `p` has a right child, the successor is the leftmost node of that subtree; if `p` has a left child, the predecessor is the rightmost node of it.
- The candidate-tracking loop handles the no-right-child case too, which is why it needs neither parent pointers nor a full traversal.
