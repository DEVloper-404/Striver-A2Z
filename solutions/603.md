# Largest Divisible Subset

**Difficulty:** Medium  ·  **Topic:** Dynamic Programming [Patterns and Problems] › DP on LIS

## Problem
Given a set of **distinct** positive integers `nums`, return the largest subset `S` such that for **every pair** `(a, b)` in `S`, either `a % b == 0` or `b % a == 0`. If several subsets tie for the largest size, return any of them.

```
Input:  nums = [1, 16, 7, 8, 4]
Output: [1, 4, 8, 16]
```
Every pair inside that answer divides one way or the other: 4 divides 8 and 16, 8 divides 16, 1 divides everything.

## Approach 1: Enumerate every subset (Brute Force)
Generate all `2^n` subsets and check the pairwise divisibility condition for each, keeping the largest valid one. Correct, hopeless beyond `n ≈ 20`.

- **Time:** O(2^n · n²)
- **Space:** O(n)

## Approach 2: Sort, then LIS with a divisibility test (Optimal)
The problem looks like it needs to check `O(k²)` pairs, but one observation collapses that to a single check.

**Key observation.** Sort `nums` ascending. Now suppose we build the subset in sorted order and only ever require that each new element is divisible by the element added immediately before it. Divisibility is **transitive**: if `a | b` and `b | c` then `a | c`. So a chain `a₁ | a₂ | ... | a_k` automatically satisfies the condition for *every* pair, not just consecutive ones. Checking neighbours is enough.

That reduces the problem to exactly the shape of Longest Increasing Subsequence, with `arr[j] < arr[i]` replaced by `nums[i] % nums[j] == 0`.

The algorithm:
1. Sort `nums` ascending. (Without sorting, transitivity gives us nothing — we need the chain to be built in increasing order so that "divisible by the previous one" is well defined.)
2. `dp[i]` = size of the largest divisible subset whose **largest element is `nums[i]`**. Initialise all to 1.
3. For each `i`, look at every `j < i`: if `nums[i] % nums[j] == 0` and `dp[j] + 1 > dp[i]`, set `dp[i] = dp[j] + 1` and `parent[i] = j`.
4. Take the index with the maximum `dp` and backtrack through `parent` to print the subset, then reverse.

**Dry run** on `[1, 16, 7, 8, 4]` → sorted `[1, 4, 7, 8, 16]`:

| i | nums[i] | checks                                  | dp[i] | parent[i] |
|---|---------|-----------------------------------------|-------|-----------|
| 0 | 1       | —                                       | 1     | −1        |
| 1 | 4       | 4%1=0 → dp 2                            | 2     | 0         |
| 2 | 7       | 7%1=0 → dp 2; 7%4≠0                     | 2     | 0         |
| 3 | 8       | 8%1=0 → 2; 8%4=0 → dp[1]+1 = **3**      | 3     | 1         |
| 4 | 16      | 16%4=0 → 3; 16%8=0 → dp[3]+1 = **4**    | 4     | 3         |

Maximum is `dp[4] = 4`. Backtrack `4 → 3 → 1 → 0`, collecting `16, 8, 4, 1`; reversed that is `[1, 4, 8, 16]`.

Note the values are guaranteed distinct by the problem statement, which keeps the strict-chain reasoning clean; with duplicates you would need to handle `x % x == 0` explicitly.

- **Time:** O(n²) plus O(n log n) for the sort
- **Space:** O(n) for `dp` and `parent`

## Approach 3: Why the O(n log n) LIS trick does not transfer
It is tempting to hope for the binary-search speedup used in plain LIS. It does not apply: that method depends on the comparison being a **total order** (`tails` stays sorted, so a binary search is meaningful). Divisibility is only a *partial* order — 4 and 7 are incomparable — so there is no single "smallest tail" to keep, and no sorted structure to search. O(n²) is the practical bound here.

- **Time:** O(n²)
- **Space:** O(n)

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    vector<int> largestDivisibleSubset(vector<int>& nums) {
        int n = nums.size();
        if (n == 0) return {};
        sort(nums.begin(), nums.end());

        vector<int> dp(n, 1), parent(n, -1);
        int best = 0;
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < i; j++) {
                if (nums[i] % nums[j] == 0 && dp[j] + 1 > dp[i]) {
                    dp[i] = dp[j] + 1;
                    parent[i] = j;
                }
            }
            if (dp[i] > dp[best]) best = i;
        }

        vector<int> result;
        for (int i = best; i != -1; i = parent[i]) result.push_back(nums[i]);
        reverse(result.begin(), result.end());
        return result;
    }
};
```

### Java
```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.Collections;
import java.util.List;

class Solution {
    public List<Integer> largestDivisibleSubset(int[] nums) {
        int n = nums.length;
        List<Integer> result = new ArrayList<>();
        if (n == 0) return result;
        Arrays.sort(nums);

        int[] dp = new int[n];
        int[] parent = new int[n];
        Arrays.fill(dp, 1);
        Arrays.fill(parent, -1);

        int best = 0;
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < i; j++) {
                if (nums[i] % nums[j] == 0 && dp[j] + 1 > dp[i]) {
                    dp[i] = dp[j] + 1;
                    parent[i] = j;
                }
            }
            if (dp[i] > dp[best]) best = i;
        }

        for (int i = best; i != -1; i = parent[i]) result.add(nums[i]);
        Collections.reverse(result);
        return result;
    }
}
```

### Python
```python
from typing import List


class Solution:
    def largestDivisibleSubset(self, nums: List[int]) -> List[int]:
        n = len(nums)
        if n == 0:
            return []
        nums.sort()

        dp = [1] * n
        parent = [-1] * n
        best = 0
        for i in range(n):
            for j in range(i):
                if nums[i] % nums[j] == 0 and dp[j] + 1 > dp[i]:
                    dp[i] = dp[j] + 1
                    parent[i] = j
            if dp[i] > dp[best]:
                best = i

        result = []
        i = best
        while i != -1:
            result.append(nums[i])
            i = parent[i]
        return result[::-1]
```

## Key Takeaways
- Sorting plus transitivity of divisibility means you only need to test the *previous* element of the chain, not all pairs — that is the whole trick.
- The recurrence is LIS with `<` swapped for `% == 0`; the reconstruction with a `parent` array is identical too.
- The binary-search LIS optimisation does not carry over, because divisibility is a partial order.
- Sorting is mandatory: on unsorted input, "divisible by the previous element" no longer implies the pairwise condition.
