# Postfix to Infix Conversion

**Difficulty:** Easy  ·  **Topic:** Stack and Queues [Learning, Pre-In-Post-fix, Monotonic Stack, Implementation] › Prefix, Infix, PostFix Conversion Problems

## Problem
Given a valid **postfix** expression (each operator follows its two operands, no brackets), rebuild the equivalent **infix** expression, inserting brackets so the result is unambiguous. Operands are single characters and operators are `+ - * / ^`.

```
Input:  ab*c+
Output: ((a*b)+c)
```

## Approach 1: Recursive parse from the right
A postfix string can be parsed from the end: the last character is the top-level operator, its right sub-expression is the postfix chunk immediately before it, and its left sub-expression is the chunk before that. Finding where each chunk starts means scanning backwards while tracking how many operands are still owed, which works but is easy to get wrong and re-reads the string.

- **Time:** O(n^2) in a naive implementation
- **Space:** O(n) recursion depth.

## Approach 2: Stack of partial expressions (Optimal)
Postfix is designed to be evaluated by a stack, and conversion is the same process with **strings instead of numbers**. Instead of pushing computed values, push the *infix text* of each completed sub-expression.

The invariant is: at every point in the scan, the stack holds the infix forms of all sub-expressions that are finished but not yet consumed by an operator, in left-to-right order.

Scan the postfix string left to right:

1. **Operand** → push it as a one-character string. A lone operand is already a valid infix expression.
2. **Operator `op`** → it applies to the two most recently completed sub-expressions. Pop once to get `right` (the top of the stack is the *second* operand, because it was pushed later), pop again to get `left`. Push the string `"(" + left + op + right + ")"`.
3. At the end exactly one string remains on the stack — the whole expression.

**Why the pop order matters.** In `a b -`, we push `a` then `b`, so the first pop returns `b`. If you assemble `"(" + first_pop + op + second_pop + ")"` you get `(b-a)`, which is a different expression for any non-commutative operator. Always name the first pop `right`.

**Why brackets around every operation.** We do not track precedence at all here; wrapping each combination guarantees the reconstructed infix parses back to the same tree. `ab+c*` becomes `((a+b)*c)`, and dropping the inner brackets would wrongly give `a+b*c`. The brackets are redundant in some places, but never wrong.

**Dry run on `ab*c+`:**

| Read | Action | Stack (bottom → top) |
|---|---|---|
| `a` | push | `a` |
| `b` | push | `a`, `b` |
| `*` | right=`b`, left=`a` | `(a*b)` |
| `c` | push | `(a*b)`, `c` |
| `+` | right=`c`, left=`(a*b)` | `((a*b)+c)` |

The single remaining entry `((a*b)+c)` is the answer.

- **Time:** O(n^2) in the worst case because of the string concatenations (each of the up to `n/2` operators can copy an O(n)-length string); O(n) operations otherwise.
- **Space:** O(n^2) worst case for the strings on the stack, O(n) entries.

## Code (Optimal)

### C++
```cpp
#include <string>
#include <stack>
#include <cctype>
using namespace std;

class Solution {
public:
    string postfixToInfix(const string& s) {
        stack<string> st;
        for (char c : s) {
            if (isalnum(static_cast<unsigned char>(c))) {
                st.push(string(1, c));
            } else {
                string right = st.top(); st.pop();   // pushed later => right operand
                string left  = st.top(); st.pop();
                st.push("(" + left + c + right + ")");
            }
        }
        return st.top();
    }
};
```

### Java
```java
import java.util.*;

class Solution {
    public String postfixToInfix(String s) {
        Deque<String> st = new ArrayDeque<>();
        for (char c : s.toCharArray()) {
            if (Character.isLetterOrDigit(c)) {
                st.push(String.valueOf(c));
            } else {
                String right = st.pop();
                String left = st.pop();
                st.push("(" + left + c + right + ")");
            }
        }
        return st.peek();
    }
}
```

### Python
```python
class Solution:
    def postfixToInfix(self, s: str) -> str:
        st = []
        for c in s:
            if c.isalnum():
                st.append(c)
            else:
                right = st.pop()          # pushed later => right operand
                left = st.pop()
                st.append("(" + left + c + right + ")")
        return st[-1]
```

## Key Takeaways
- Converting postfix is just evaluating it with strings: push operands, and on an operator pop two and push the combined text.
- The **first** pop is the right operand — swapping them breaks `-`, `/` and `^`.
- Bracket every combination; precedence is then irrelevant and the output always re-parses to the original tree.
- A well-formed postfix string leaves exactly one item on the stack; anything else means the input was invalid.
