# Hashing In Strings | Theory

**Difficulty:** Easy  ·  **Topic:** Strings › Hard Problems

## Problem
This topic covers **string hashing**: turning a string (or any substring of it) into a single number so that comparing two pieces of text becomes an integer comparison instead of a character-by-character scan. It underpins Rabin–Karp pattern matching, duplicate-substring detection, palindrome checks, and "longest common substring" binary searches.

The concrete capability we build: after O(n) preprocessing of a string `s`, answer `hash(l, r)` — the hash of the substring `s[l..r]` — in **O(1)**, so any two substrings can be compared in constant time.

```
Input:  s = "abcabc", compare s[0..2] with s[3..5]
Output: equal  (both hash to the same value; "abc" == "abc")
```

## Approach: Polynomial rolling hash and prefix hashes

### 1. The idea: read the string as a number in base B
Treat each character as a digit and the string as a number written in some base `B`. For `s = s₀s₁…s_{n-1}`:

```
H(s) = s₀·B^(n-1) + s₁·B^(n-2) + … + s_{n-1}·B^0   (mod M)
```

This is exactly how you would read `"532"` as five hundred thirty-two, only with letters as digits. Two properties make it useful:

- **Position matters.** `"ab"` and `"ba"` get different values, unlike a naive "sum of character codes". This is why a polynomial is used instead of a symmetric function.
- **It extends left to right.** Appending a character multiplies by `B` and adds the new digit — the same as shifting a decimal number one place and writing a new digit.

### 2. Prefix hashes give O(1) substring hashes
Define `h[i]` as the hash of the first `i` characters, with `h[0] = 0`:

```
h[i + 1] = (h[i] · B + s[i]) mod M
```

Because `h[r+1]` is the number for `s[0..r]` and `h[l]` is the number for `s[0..l-1]`, the prefix `s[0..l-1]` sits in the *high-order positions* of `h[r+1]`, shifted left by exactly `r - l + 1` places. Subtract it out:

```
hash(l, r) = ( h[r+1] − h[l] · B^(r−l+1) ) mod M
```

Precomputing `p[k] = B^k mod M` alongside `h` makes each query one multiply and one subtract. Take care to add `M` back before returning, since the subtraction can go negative in languages with signed remainder (C++, Java).

**Dry run on `s = "abcabc"` conceptually:** `h[3]` encodes `"abc"`. `h[6]` encodes `"abcabc"` = `H("abc")·B³ + H("abc")`. Then `hash(3,5) = h[6] − h[3]·p[3] = H("abc")`, which equals `hash(0,2) = h[3]`. The two substrings compare equal, as they should.

### 3. Choosing B and M
- **B** should be larger than the alphabet size and coprime-ish to `M`. For lowercase letters, `B = 31` or `131` are common; for arbitrary bytes use `256` or a random value in `[100, 10^6]`.
- **M** should be a large prime, e.g. `1_000_000_007` or `1_000_000_009`. Keep `B · M` inside 64 bits (both above are well under 2^31, and 2^31 · 2^30 fits in a signed 64-bit integer), otherwise the intermediate multiply overflows.
- Map characters to values starting at 1, not 0, if you ever hash strings that may differ only by leading `'a'`s — with `'a' → 0`, the strings `"a"`, `"aa"`, `"aaa"` all hash to 0.

### 4. Collisions, and how to survive them
Distinct strings can share a hash. With a single modulus around 10^9 and `q` comparisons, the birthday bound puts the failure probability near `q² / (2M)` — fine for a few thousand comparisons, risky for 10^6. Two standard defences:

- **Verify on match.** When hashes agree, do one direct character comparison. This is what Rabin–Karp does; it keeps the algorithm *always correct* and only costs time in the rare false-positive case.
- **Double hashing.** Carry two independent (B, M) pairs and treat the pair as the hash. The effective modulus becomes ~10^18, which makes accidental collisions negligible.

Also note: fixed public parameters are attackable. On adversarial judges, pick `B` randomly at runtime so no one can craft anti-hash tests.

### 5. Rolling a fixed-length window
For a sliding window of fixed length `m` you do not even need prefix arrays. Given the hash of `s[i..i+m-1]`, drop the leading character and add the trailing one:

```
next = ( (cur − s[i]·B^(m−1)) · B + s[i+m] ) mod M
```

This O(1) update is the "rolling" in rolling hash and is exactly the engine of Rabin–Karp.

- **Time:** O(n) preprocessing, O(1) per substring hash query
- **Space:** O(n) for the prefix-hash and power arrays

## Code (Optimal)

### C++
```cpp
#include <string>
#include <vector>
using namespace std;

// Polynomial prefix hashing: O(n) build, O(1) substring hash.
struct StringHash {
    static const long long MOD = 1000000007LL;
    static const long long BASE = 131;
    vector<long long> h, p;   // h[i] = hash of s[0..i-1], p[i] = BASE^i

    explicit StringHash(const string& s) {
        int n = (int)s.size();
        h.assign(n + 1, 0);
        p.assign(n + 1, 1);
        for (int i = 0; i < n; i++) {
            h[i + 1] = (h[i] * BASE + (s[i] - 'a' + 1)) % MOD;
            p[i + 1] = (p[i] * BASE) % MOD;
        }
    }

    // hash of s[l..r], both inclusive, 0-indexed
    long long get(int l, int r) const {
        long long res = (h[r + 1] - h[l] * p[r - l + 1]) % MOD;
        if (res < 0) res += MOD;   // signed remainder can go negative
        return res;
    }

    bool sameSubstring(int l1, int r1, int l2, int r2) const {
        if (r1 - l1 != r2 - l2) return false;
        return get(l1, r1) == get(l2, r2);
    }
};
```

### Java
```java
// Polynomial prefix hashing: O(n) build, O(1) substring hash.
class StringHash {
    private static final long MOD = 1_000_000_007L;
    private static final long BASE = 131;
    private final long[] h, p;   // h[i] = hash of s[0..i-1], p[i] = BASE^i

    StringHash(String s) {
        int n = s.length();
        h = new long[n + 1];
        p = new long[n + 1];
        p[0] = 1;
        for (int i = 0; i < n; i++) {
            h[i + 1] = (h[i] * BASE + (s.charAt(i) - 'a' + 1)) % MOD;
            p[i + 1] = (p[i] * BASE) % MOD;
        }
    }

    // hash of s[l..r], both inclusive, 0-indexed
    long get(int l, int r) {
        long res = (h[r + 1] - h[l] * p[r - l + 1] % MOD) % MOD;
        if (res < 0) res += MOD;   // signed remainder can go negative
        return res;
    }

    boolean sameSubstring(int l1, int r1, int l2, int r2) {
        if (r1 - l1 != r2 - l2) return false;
        return get(l1, r1) == get(l2, r2);
    }
}
```

### Python
```python
class StringHash:
    """Polynomial prefix hashing: O(n) build, O(1) substring hash."""

    MOD = 1_000_000_007
    BASE = 131

    def __init__(self, s: str):
        n = len(s)
        self.h = [0] * (n + 1)   # h[i] = hash of s[0..i-1]
        self.p = [1] * (n + 1)   # p[i] = BASE^i
        for i, ch in enumerate(s):
            self.h[i + 1] = (self.h[i] * self.BASE + (ord(ch) - ord('a') + 1)) % self.MOD
            self.p[i + 1] = (self.p[i] * self.BASE) % self.MOD

    def get(self, l: int, r: int) -> int:
        """Hash of s[l..r], both inclusive, 0-indexed."""
        return (self.h[r + 1] - self.h[l] * self.p[r - l + 1]) % self.MOD

    def same_substring(self, l1: int, r1: int, l2: int, r2: int) -> bool:
        if r1 - l1 != r2 - l2:
            return False
        return self.get(l1, r1) == self.get(l2, r2)
```

## Key Takeaways
- A polynomial hash reads the string as a base-`B` number, so order matters — that is the whole reason a plain character sum is useless.
- Prefix hashes plus a power table turn any substring comparison into O(1); the formula `h[r+1] − h[l]·B^(r−l+1)` is worth memorising.
- Map characters to values starting at **1**, keep `B·M` inside 64 bits, and add `M` back after subtraction in C++/Java.
- Hashing is probabilistic: either verify a match with a direct comparison (Rabin–Karp) or use double hashing; randomise `B` on adversarial judges.
