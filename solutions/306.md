# Distinct subsequences

**Difficulty:** Hard  ·  **Topic:** Dynamic Programming [Patterns and Problems] › DP on Strings

## Problem
Given two strings `s` and `t`, count how many **distinct subsequences of `s` are exactly equal to `t`**. A subsequence is formed by deleting zero or more characters of `s` without reordering the rest. Two subsequences are considered different if they use a different set of index positions, even when the resulting strings look identical.

```
Input:  s = "rabbbit", t = "rabbit"
Output: 3
```
The three ways come from `s` having three `b`s in a row; `t` needs only two of them, so we can drop the 1st, the 2nd, or the 3rd `b`.

## Approach 1: Recursion over two pointers (Brute Force)
The key observation is that building `t` out of `s` is a sequence of independent *choices*, one per character of `s`: either that character is used as the next character of `t`, or it is skipped.

Let `f(i, j)` = the number of ways to form `t[0..j]` using only `s[0..i]` (both indices scanning from the right). At position `i`:

1. If `s[i] == t[j]`, we have two genuinely different options — **match** them (recurse on `f(i-1, j-1)`) or **skip** `s[i]` and try to match `t[j]` with an earlier character (recurse on `f(i-1, j)`). The answer is the sum, because these two families of index sets are disjoint: one uses index `i`, the other does not.
2. If `s[i] != t[j]`, the only option is to skip `s[i]`: `f(i-1, j)`.

Base cases:
- `j < 0`: the whole of `t` has been matched, so we found exactly one valid way → return 1.
- `i < 0` but `j >= 0`: `s` is exhausted while `t` still has characters left → return 0.

This is correct but explores an exponential number of subsets.

- **Time:** O(2^n)
- **Space:** O(n + m) recursion stack

## Approach 2: Memoization / Tabulation
The recursion only ever depends on the pair `(i, j)`, and there are only `n × m` such pairs, so the overlapping subproblems can be cached.

Switching to bottom-up with 1-based lengths is cleaner. Let `dp[i][j]` = number of ways to form the **prefix** `t[0..j)` using the prefix `s[0..i)`.

- `dp[i][0] = 1` for every `i` — the empty string `t` can always be formed in exactly one way (delete everything).
- `dp[0][j] = 0` for `j > 0` — a non-empty `t` cannot be formed from an empty `s`.
- Transition: `dp[i][j] = dp[i-1][j] + (s[i-1] == t[j-1] ? dp[i-1][j-1] : 0)`.

**Dry run** on `s = "bbg"`, `t = "bg"` (rows = prefixes of `s`, columns = prefixes of `t`):

```
            ""   b    bg
""           1   0    0
"b"          1   1    0     (s[0]='b' matches t[0])
"bb"         1   2    0     (either b can play the role of t's 'b')
"bbg"        1   2    2     (g matches t[1]; dp = dp[bb][b] = 2)
```
Answer `dp[3][2] = 2`, which matches the two index sets `{0,2}` and `{1,2}`.

- **Time:** O(n · m)
- **Space:** O(n · m)

## Approach 3: One-dimensional rolling array (Optimal)
Row `i` only reads row `i-1`, so a single array of length `m+1` suffices. The trick is the **iteration direction**: if we sweep `j` from high to low, then when we compute `dp[j]` the entry `dp[j-1]` has not been overwritten yet and still holds the previous row's value — exactly what the recurrence needs.

Initialise `dp[0] = 1` and everything else `0`. For each character of `s`, loop `j` from `m` down to `1` and do `dp[j] += dp[j-1]` whenever `s[i-1] == t[j-1]`. The final answer is `dp[m]`.

A small but important practical note: intermediate counts can overflow 32-bit arithmetic on adversarial inputs, so accumulate in a 64-bit type (or `unsigned int`, which wraps predictably) even though the final answer is guaranteed to fit in an `int`.

- **Time:** O(n · m)
- **Space:** O(m)

## Code (Optimal)

### C++
```cpp
#include <string>
#include <vector>
using namespace std;

class Solution {
public:
    int numDistinct(string s, string t) {
        int n = s.size(), m = t.size();
        if (m > n) return 0;
        // dp[j] = ways to build t[0..j) from the prefix of s processed so far
        vector<unsigned long long> dp(m + 1, 0);
        dp[0] = 1;                       // empty target: exactly one way
        for (int i = 1; i <= n; i++) {
            // walk backwards so dp[j-1] still holds the previous row
            for (int j = min(i, m); j >= 1; j--) {
                if (s[i - 1] == t[j - 1]) dp[j] += dp[j - 1];
            }
        }
        return (int)dp[m];
    }
};
```

### Java
```java
class Solution {
    public int numDistinct(String s, String t) {
        int n = s.length(), m = t.length();
        if (m > n) return 0;
        long[] dp = new long[m + 1];
        dp[0] = 1;
        for (int i = 1; i <= n; i++) {
            for (int j = Math.min(i, m); j >= 1; j--) {
                if (s.charAt(i - 1) == t.charAt(j - 1)) {
                    dp[j] += dp[j - 1];
                }
            }
        }
        return (int) dp[m];
    }
}
```

### Python
```python
class Solution:
    def numDistinct(self, s: str, t: str) -> int:
        n, m = len(s), len(t)
        if m > n:
            return 0
        dp = [0] * (m + 1)
        dp[0] = 1
        for i in range(1, n + 1):
            for j in range(min(i, m), 0, -1):
                if s[i - 1] == t[j - 1]:
                    dp[j] += dp[j - 1]
        return dp[m]
```

## Key Takeaways
- The "take it or leave it" split is what makes the count additive: the two branches use disjoint sets of indices, so no subsequence is counted twice.
- `dp[i][0] = 1` (empty target) is the base case that seeds the whole table; forgetting it yields all zeros.
- When compressing 2D → 1D and the recurrence reads `dp[i-1][j-1]`, iterate the inner loop **backwards**.
- Counts grow fast — use 64-bit accumulation to avoid signed overflow on intermediate values.
