# Minimum number of bracket reversals to make an expression balanced

**Difficulty:** Hard  ·  **Topic:** Strings › Hard Problems

## Problem
You are given a string that contains only the characters `{` and `}`. In one move you may flip any single character (turn a `{` into a `}` or vice versa). Return the minimum number of flips needed to make the expression balanced, meaning every opening brace has a matching closing brace that appears after it. If the string can never be balanced, return `-1`.

```
Input:  s = "}{{}}{{{"
Output: 3
```

```
Input:  s = "{{{"
Output: -1     (odd length can never balance)
```

## Approach 1: Brute Force — try every subset of flips
Since any character may be flipped, one could enumerate all `2^n` flip subsets, apply each, test the result with a normal balanced-brackets check, and keep the smallest number of flips that produced a balanced string.

This is obviously correct but hopeless in practice: `n = 40` already means a trillion subsets. It is worth stating only because it makes the target crystal clear — we want the *cheapest repair*, not just any repair.

- **Time:** O(2^n · n)
- **Space:** O(n)

## Approach 2: Cancel matched pairs with a stack
The real insight is that **already-matched pairs are irrelevant**. If a `{` is immediately followed (after everything between them cancels out) by a `}`, that pair is fine and no flip will ever be spent on it. So push characters onto a stack and pop whenever the top is `{` and the current character is `}`.

Whatever survives on the stack has a very specific shape. It can never contain a `{` sitting below a `}` — that combination would have cancelled. So the leftover string always looks like

```
} } } ... } { { { ... {
   m closers      n openers
```

Now the problem shrinks to: given `m` stray closers followed by `n` stray openers, how few flips fix them?

Look at the closers alone: `}}`. Flip the first one and you get `{}`, which is balanced — **one flip repairs two stray closers**. If `m` is odd, the last lonely `}` still needs its own flip, so closers cost `ceil(m/2)`. By the mirror argument, openers cost `ceil(n/2)`. The two groups never interfere, because every closer sits to the left of every opener and flipping inside one group cannot help the other.

Total answer = `ceil(m/2) + ceil(n/2)`.

Feasibility: a balanced string must have equal counts of each brace, so its length is even. If `s.length()` is odd, return `-1` immediately.

- **Time:** O(n)
- **Space:** O(n) for the stack

## Approach 3: Optimal — two counters, no stack
The stack never actually needs to store characters; we only care about *how many* items of each kind it ends with. Track two integers while scanning left to right:

1. `open` — how many unmatched `{` we are currently carrying.
2. `close` — how many `}` have already failed to find a partner.

For each character:
- `{` → `open++` (it is available for a future closer).
- `}` → if `open > 0`, this closer consumes one opener, so `open--`. Otherwise there is nothing to its left to match, so it is permanently stray: `close++`.

After the scan, `open` is exactly the number of stray openers and `close` the number of stray closers, i.e. the `n` and `m` from Approach 2. The answer is `(open + 1) / 2 + (close + 1) / 2` using integer division (that expression is the ceiling of a half).

**Dry run on `"}{{}}{{{"`:**

| i | char | action | open | close |
|---|------|--------|------|-------|
| 0 | `}`  | no opener available → stray | 0 | 1 |
| 1 | `{`  | open++ | 1 | 1 |
| 2 | `{`  | open++ | 2 | 1 |
| 3 | `}`  | matches → open-- | 1 | 1 |
| 4 | `}`  | matches → open-- | 0 | 1 |
| 5 | `{`  | open++ | 1 | 1 |
| 6 | `{`  | open++ | 2 | 1 |
| 7 | `{`  | open++ | 3 | 1 |

`open = 3`, `close = 1`. Answer = `ceil(3/2) + ceil(1/2) = 2 + 1 = 3`. Matches the expected output.

A useful sanity check: `open + close` always has the same parity as the string length, so when the length is even both `open` and `close` are even or both are odd — the formula never produces a half-flip.

- **Time:** O(n) — one pass
- **Space:** O(1)

## Code (Optimal)

### C++
```cpp
#include <string>
using namespace std;

class Solution {
public:
    int countMinReversals(const string& s) {
        int n = (int)s.size();
        if (n % 2 != 0) return -1;   // odd length can never be balanced

        int open = 0;    // unmatched '{' so far
        int close = 0;   // '}' that found no partner

        for (char c : s) {
            if (c == '{') {
                open++;
            } else {
                if (open > 0) open--;   // this '}' cancels an earlier '{'
                else close++;           // permanently stray
            }
        }
        // ceil(open/2) + ceil(close/2)
        return (open + 1) / 2 + (close + 1) / 2;
    }
};
```

### Python
```python
class Solution:
    def countMinReversals(self, s: str) -> int:
        n = len(s)
        if n % 2 != 0:
            return -1                 # odd length can never be balanced

        open_cnt = 0                  # unmatched '{' so far
        close_cnt = 0                 # '}' that found no partner

        for c in s:
            if c == '{':
                open_cnt += 1
            elif open_cnt > 0:
                open_cnt -= 1         # this '}' cancels an earlier '{'
            else:
                close_cnt += 1        # permanently stray

        # ceil(open/2) + ceil(close/2)
        return (open_cnt + 1) // 2 + (close_cnt + 1) // 2
```

## Key Takeaways
- Matched pairs are noise; cancel them first and the residue is always `}}}...{{{`, which makes the cost formula obvious.
- Two flips' worth of work collapses into one: `}}` needs a single flip, so each group costs `ceil(count / 2)`, not `count`.
- The stack is only ever counting, so replace it with two integers for O(1) space.
- Guard the odd-length case up front — it is the only `-1` scenario, and forgetting it makes the formula silently return a wrong positive number.
