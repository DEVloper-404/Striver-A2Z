# Detect a cycle in a directed graph

**Difficulty:** Hard  ·  **Topic:** Graphs [Concepts & Problems] › Topo Sort and Problems

## Problem
Given a directed graph with `V` vertices (`0..V-1`) and its adjacency list, determine whether it contains a directed cycle. Here we solve it with **Kahn's algorithm (BFS topological sort)** rather than DFS.

```
Input:  V = 4, edges = [[0,1], [1,2], [2,3], [3,1]]
Output: true          // 1 -> 2 -> 3 -> 1

Input:  V = 4, edges = [[0,1], [0,2], [1,3], [2,3]]
Output: false         // a diamond, still acyclic
```

## Approach 1: DFS with a recursion-path flag
Run DFS keeping `visited[]` and `pathVisited[]`. An edge into a node still on the current recursion stack is a back edge and proves a cycle. Correct and O(V + E), but recursive and easy to get wrong (you must reset `pathVisited` on backtrack).

## Approach 2: Kahn's algorithm — count how many vertices can be ordered (Optimal)

**Key observation.** A directed graph has a topological ordering **if and only if** it is acyclic. So instead of hunting for a cycle directly, try to build a topological ordering and see whether it covers every vertex. Kahn's algorithm gives us that count almost for free.

Why does a cycle block the ordering? Take any cycle `c1 -> c2 -> ... -> ck -> c1`. Each `ci` has a predecessor that also lies on the cycle. For `ci` to be output, that predecessor must be output first — and so on around the loop, which means `c1` must be output before itself. Impossible. Concretely in Kahn's terms: the in-degree of every cycle vertex is at least 1 from another cycle vertex, and that unit is only removed when the predecessor is popped, which never happens. So no cycle vertex ever reaches in-degree 0, and none is ever enqueued.

**Algorithm.**
1. Build `indeg[v]` = number of incoming edges, by scanning all adjacency lists.
2. Enqueue every vertex with `indeg == 0`.
3. Maintain a counter. While the queue is not empty: pop `u`, increment the counter, and for every neighbour `v` decrement `indeg[v]`, enqueuing `v` when it hits 0.
4. If `counter == V`, every vertex got ordered → **no cycle**. If `counter < V`, the leftover vertices are precisely those trapped in or downstream-blocked by cycles → **cycle exists**.

**Dry run** on `0->1, 1->2, 2->3, 3->1`:
- In-degrees: `0:0`, `1:2` (from 0 and 3), `2:1`, `3:1`.
- Queue `[0]`. Pop 0, count = 1; `indeg[1]` drops to 1, not 0, so nothing is pushed.
- Queue empty. count = 1 < 4 → cycle detected. Vertices 1, 2, 3 are exactly the cycle.

Contrast with the diamond `0->1, 0->2, 1->3, 2->3`: in-degrees `0:0, 1:1, 2:1, 3:2`. Pop 0 → push 1 and 2; pop 1 → `indeg[3]` = 1; pop 2 → `indeg[3]` = 0, push 3; pop 3. count = 4 = V → no cycle. Note that a node reachable by two different paths is not a cycle, and the in-degree bookkeeping handles that automatically.

- **Time:** O(V + E)
- **Space:** O(V) for `indeg` and the queue

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <queue>
using namespace std;

class Solution {
public:
    bool isCyclic(int V, vector<vector<int>>& adj) {
        vector<int> indeg(V, 0);
        for (int u = 0; u < V; u++)
            for (int v : adj[u]) indeg[v]++;

        queue<int> q;
        for (int i = 0; i < V; i++)
            if (indeg[i] == 0) q.push(i);

        int placed = 0;
        while (!q.empty()) {
            int u = q.front(); q.pop();
            placed++;
            for (int v : adj[u]) {
                if (--indeg[v] == 0) q.push(v);
            }
        }
        return placed != V;      // some vertex never reached in-degree 0
    }
};
```

### Java
```java
import java.util.*;

class Solution {
    public boolean isCyclic(int V, List<List<Integer>> adj) {
        int[] indeg = new int[V];
        for (int u = 0; u < V; u++)
            for (int v : adj.get(u)) indeg[v]++;

        Queue<Integer> q = new ArrayDeque<>();
        for (int i = 0; i < V; i++)
            if (indeg[i] == 0) q.add(i);

        int placed = 0;
        while (!q.isEmpty()) {
            int u = q.poll();
            placed++;
            for (int v : adj.get(u)) {
                if (--indeg[v] == 0) q.add(v);
            }
        }
        return placed != V;
    }
}
```

### Python
```python
from collections import deque
from typing import List

class Solution:
    def isCyclic(self, V: int, adj: List[List[int]]) -> bool:
        indeg = [0] * V
        for u in range(V):
            for v in adj[u]:
                indeg[v] += 1

        q = deque(i for i in range(V) if indeg[i] == 0)
        placed = 0
        while q:
            u = q.popleft()
            placed += 1
            for v in adj[u]:
                indeg[v] -= 1
                if indeg[v] == 0:
                    q.append(v)

        return placed != V
```

## Key Takeaways
- "Directed graph is acyclic" ⟺ "a topological ordering exists", so Kahn's vertex count is a cycle test.
- Cycle vertices never reach in-degree 0 because each is blocked by another cycle vertex.
- This works on disconnected graphs without any extra outer loop: all sources are seeded at once.
- Careful — this test is for *directed* graphs only; undirected cycle detection needs DSU or DFS with a parent check.
