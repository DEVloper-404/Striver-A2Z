# Bellman Ford Algorithm

**Difficulty:** Hard  ·  **Topic:** Graphs [Concepts & Problems] › Shortest Path Algorithms and Problems

## Problem
Given a directed, weighted graph with `V` vertices and an edge list `edges[i] = [u, v, w]` (weights may be **negative**), compute the shortest distance from a given source `S` to every vertex. If the graph contains a negative-weight cycle reachable in the relaxation process, report it (conventionally by returning `[-1]`). Unreachable vertices get a sentinel like `10^8`.

```
Input:  V = 6, S = 0
        edges = [[3,2,6],[5,3,1],[0,1,5],[1,5,-3],[1,2,-2],[3,4,-2],[2,4,3]]
Output: [0, 5, 3, 3, 1, 2]
```

## Approach 1: Dijkstra — and why it fails here
Dijkstra's correctness rests on the assumption that once a node is popped with the smallest tentative distance, no later path can improve it. That is only true when all weights are non-negative: a longer prefix can never get *cheaper* by adding more edges. With a negative edge, a node finalized early can later be improved through a detour, so Dijkstra can return wrong answers. It also cannot detect negative cycles. We need a different technique.
- **Time:** O(E log V) but **incorrect** with negative weights

## Approach 2: Bellman–Ford — relax all edges V−1 times (optimal for this setting)

**The key observation.** In a graph with `V` vertices, any shortest path that exists uses at most `V - 1` edges — if it used `V` or more it would repeat a vertex, i.e. contain a cycle, and removing that cycle cannot make the path longer (assuming no negative cycle). So the shortest path is built out of at most `V - 1` edges.

**Why relaxing all edges repeatedly works.** Define "relaxing edge `(u, v, w)`" as `if dist[u] + w < dist[v]: dist[v] = dist[u] + w`. Claim: **after the `k`-th full pass over all edges, `dist[v]` is correct for every vertex whose shortest path uses at most `k` edges.** Proof sketch by induction: it holds for `k = 0` (only the source, distance 0). If the shortest path to `v` is `S → … → u → v` with `k` edges, then the prefix to `u` has `k - 1` edges and is correct after pass `k - 1`; the `k`-th pass relaxes `(u, v, w)` somewhere and fixes `dist[v]`. Since paths need at most `V - 1` edges, `V - 1` passes settle everything — **regardless of the order in which edges appear in the list**. That order-independence is exactly why we do a fixed number of full sweeps instead of the greedy pop order Dijkstra uses.

**Negative-cycle detection.** Run one extra, `V`-th pass. If any edge can still be relaxed, some distance is still shrinking after `V - 1` passes, which is impossible in a graph without negative cycles. So a successful relaxation on pass `V` proves a negative cycle is reachable from the source. Report it.

**The algorithm.**
1. `dist[S] = 0`, all others `= INF` (use a large sentinel like `10^8`, and guard against relaxing from an `INF` node, otherwise `INF + (-2)` looks like an improvement).
2. Repeat `V - 1` times: for each edge `(u, v, w)`, if `dist[u] != INF && dist[u] + w < dist[v]`, set `dist[v] = dist[u] + w`.
3. One more sweep: if any edge still relaxes, return `[-1]`.
4. Otherwise return `dist`.

**Short dry run** on the example (edges in the given order).
- Pass 1: `0→1` gives `dist[1] = 5`; `1→5` gives `dist[5] = 2`; `1→2` gives `dist[2] = 3`; `2→4` gives `dist[4] = 6`. (`5→3` and `3→…` did not fire yet because they appear before `dist[5]` was set.)
- Pass 2: `5→3` gives `dist[3] = 2 + 1 = 3`; `3→4` gives `dist[4] = 3 - 2 = 1`; `3→2` would give `9`, no improvement.
- Pass 3 onwards: nothing changes. Final `[0, 5, 3, 3, 1, 2]`, and the `V`-th pass relaxes nothing, so no negative cycle.

**Practical tweak.** Break out early if a full pass makes no change — that is a valid stopping condition and speeds up typical graphs a lot without affecting correctness.
- **Time:** O(V · E)
- **Space:** O(V) for the distance array (the edge list is the input)

## Code (Optimal)

### C++
```cpp
#include <vector>
using namespace std;

class Solution {
public:
    // edges[i] = {u, v, w}, directed
    vector<int> bellmanFord(int V, vector<vector<int>>& edges, int S) {
        const int INF = 100000000;
        vector<int> dist(V, INF);
        dist[S] = 0;

        for (int pass = 0; pass < V - 1; pass++) {
            bool changed = false;
            for (auto& e : edges) {
                int u = e[0], v = e[1], w = e[2];
                if (dist[u] != INF && dist[u] + w < dist[v]) {
                    dist[v] = dist[u] + w;
                    changed = true;
                }
            }
            if (!changed) break;          // already settled
        }

        for (auto& e : edges) {           // V-th pass: negative cycle check
            int u = e[0], v = e[1], w = e[2];
            if (dist[u] != INF && dist[u] + w < dist[v]) return {-1};
        }
        return dist;
    }
};
```

### Python
```python
from typing import List

class Solution:
    def bellmanFord(self, V: int, edges: List[List[int]], S: int) -> List[int]:
        INF = 10 ** 8
        dist = [INF] * V
        dist[S] = 0

        for _ in range(V - 1):
            changed = False
            for u, v, w in edges:
                if dist[u] != INF and dist[u] + w < dist[v]:
                    dist[v] = dist[u] + w
                    changed = True
            if not changed:
                break

        for u, v, w in edges:            # V-th pass detects a negative cycle
            if dist[u] != INF and dist[u] + w < dist[v]:
                return [-1]
        return dist
```

## Key Takeaways
- Bellman–Ford is the tool when weights can be negative; Dijkstra's greedy finalization assumption breaks there.
- `V - 1` sweeps suffice because a shortest path has at most `V - 1` edges; a successful relaxation on the `V`-th sweep proves a negative cycle.
- Always guard `dist[u] != INF` before relaxing, or a negative edge out of an unreachable node corrupts the array.
- For an undirected graph, add both directions — and note that a single undirected negative edge is itself a negative cycle.
