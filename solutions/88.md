# Search in rotated sorted array-II

**Difficulty:** Medium  ·  **Topic:** Binary Search [1D, 2D Arrays, Search Space] › BS on 1D Arrays

## Problem
A non-decreasing array (duplicates allowed) was rotated at an unknown pivot. Given the rotated array `nums` and a `target`, return `true` if `target` is present and `false` otherwise.

Input: `nums = [2, 5, 6, 0, 0, 1, 2], target = 0`
Output: `true`

Input: `nums = [2, 5, 6, 0, 0, 1, 2], target = 3`
Output: `false`

## Approach 1: Linear Scan
Check every element. This is the guaranteed fallback and is what the worst case of the optimal method degrades to.

- **Time:** O(n)
- **Space:** O(1)

## Approach 2: Binary Search with Duplicate Shrinking (Optimal)
The version-I trick, "one half is always sorted", relies on being able to tell which half is sorted from `nums[low]`, `nums[mid]`, `nums[high]`. Duplicates break that: if `nums[low] == nums[mid] == nums[high]`, for example `[1, 0, 1, 1, 1]`, you cannot tell where the rotation point is.

The fix is small: when all three are equal, the elements at `low` and `high` are copies of `nums[mid]`, and since `nums[mid] != target` at that point, they cannot be the answer. Discard both (`low++`, `high--`) and continue. In every other case the version-I logic applies unchanged.

1. If `nums[mid] == target`, return `true`.
2. If `nums[low] == nums[mid] == nums[high]`, shrink both ends and continue.
3. Else if the left half is sorted, check whether the target is in it and narrow accordingly.
4. Else the right half is sorted; do the mirror check.

- **Time:** O(log n) on average; O(n) in the worst case when the array is mostly one repeated value (each shrink step removes only two elements)
- **Space:** O(1)

## Code (Optimal)

### C++
```cpp
#include <vector>
using namespace std;

class Solution {
public:
    bool search(vector<int>& nums, int target) {
        int low = 0, high = (int)nums.size() - 1;
        while (low <= high) {
            int mid = low + (high - low) / 2;
            if (nums[mid] == target) return true;

            if (nums[low] == nums[mid] && nums[mid] == nums[high]) {
                low++; high--;
                continue;
            }

            if (nums[low] <= nums[mid]) {           // left half sorted
                if (nums[low] <= target && target < nums[mid]) high = mid - 1;
                else low = mid + 1;
            } else {                                // right half sorted
                if (nums[mid] < target && target <= nums[high]) low = mid + 1;
                else high = mid - 1;
            }
        }
        return false;
    }
};
```

### Python
```python
from typing import List

class Solution:
    def search(self, nums: List[int], target: int) -> bool:
        low, high = 0, len(nums) - 1
        while low <= high:
            mid = (low + high) // 2
            if nums[mid] == target:
                return True

            if nums[low] == nums[mid] == nums[high]:
                low += 1
                high -= 1
                continue

            if nums[low] <= nums[mid]:  # left half sorted
                if nums[low] <= target < nums[mid]:
                    high = mid - 1
                else:
                    low = mid + 1
            else:                       # right half sorted
                if nums[mid] < target <= nums[high]:
                    low = mid + 1
                else:
                    high = mid - 1
        return False
```

## Key Takeaways
- Duplicates can make `nums[low] == nums[mid] == nums[high]`, which hides which half is sorted; shrinking both ends by one is safe because neither end can be the target at that moment.
- The worst case is O(n) (think `[1,1,1,1,1,1,2]`), so this problem cannot guarantee logarithmic time; interviewers expect you to say so.
- Apart from the equal-ends guard, the code is identical to the distinct-values version, so learn version I well first.
- Return a boolean here, not an index, because with duplicates there may be several valid indices.
