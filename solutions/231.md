# Count Palindromic Subsequences

**Difficulty:** Medium  ·  **Topic:** Strings › Hard Problems

## Problem
Given a string `s`, count how many of its non-empty subsequences are palindromes. A subsequence is obtained by deleting zero or more characters without reordering the rest. Two subsequences are counted separately when they use different sets of positions, even if they spell the same text. Because the count grows exponentially, return it modulo 10⁹+7.

```
Input:  s = "abcb"
Output: 6
```

The six are the four single characters `a`, `b`(index 1), `c`, `b`(index 3), plus `bb` (indices 1,3) and `bcb` (indices 1,2,3).

## Approach 1: Brute Force — enumerate every subsequence
A string of length `n` has `2ⁿ − 1` non-empty subsequences. Generate each one with a bitmask or recursion, test whether it reads the same forwards and backwards, and count the successes.

This is unambiguously correct and useful for validating a DP on small inputs, but `2ⁿ · n` work dies past `n ≈ 20`. The reason it is wasteful is that the same inner regions get rebuilt and re-tested over and over — a classic signal that overlapping subproblems are hiding underneath.

- **Time:** O(2ⁿ · n)
- **Space:** O(n) recursion depth

## Approach 2: Optimal — interval DP with inclusion–exclusion

### Defining the state
Let `dp[i][j]` = the number of non-empty palindromic subsequences inside `s[i..j]`. The answer is `dp[0][n-1]`. Intervals are the natural state here because a palindrome is defined by its two ends, and peeling off both ends leaves a smaller interval — the exact structure the recurrence needs.

**Base case:** `dp[i][i] = 1` — a single character is a palindrome all by itself.

### The recurrence, derived
Take an interval `[i, j]` and split its palindromic subsequences by whether they use the endpoints.

Every palindromic subsequence of `[i, j]` either avoids index `i`, avoids index `j`, or uses both. "Avoids `i`" means it lives in `[i+1, j]`, and "avoids `j`" means it lives in `[i, j-1]`. Adding those two counts double-counts everything that avoids *both*, i.e. everything in `[i+1, j-1]`. So by inclusion–exclusion:

```
(subsequences that skip at least one endpoint) = dp[i+1][j] + dp[i][j-1] − dp[i+1][j-1]
```

Now what about subsequences that use **both** endpoints? Such a subsequence starts with `s[i]` and ends with `s[j]`, so it can only be a palindrome if `s[i] == s[j]`.

- **Case `s[i] != s[j]`.** No subsequence can use both ends, so the inclusion–exclusion count is the whole answer:
  ```
  dp[i][j] = dp[i+1][j] + dp[i][j-1] − dp[i+1][j-1]
  ```

- **Case `s[i] == s[j]`.** Now wrapping *any* palindrome of the inner interval `[i+1, j-1]` with the matching pair produces a palindrome — that is `dp[i+1][j-1]` more — plus the two-character palindrome `s[i]s[j]` on its own, which corresponds to wrapping the *empty* middle. So we add `dp[i+1][j-1] + 1`:
  ```
  dp[i][j] = (dp[i+1][j] + dp[i][j-1] − dp[i+1][j-1]) + dp[i+1][j-1] + 1
           =  dp[i+1][j] + dp[i][j-1] + 1
  ```
  The subtracted term cancels, which is why the equal-endpoint case looks deceptively simple. It is worth remembering *why* the `−dp[i+1][j-1]` disappears rather than memorising the two formulas.

### Fill order
`dp[i][j]` depends on `dp[i+1][j]`, `dp[i][j-1]`, and `dp[i+1][j-1]` — all strictly shorter intervals. So iterate by increasing interval length (or equivalently, `i` descending and `j` ascending). When `j = i + 1` the inner interval `[i+1, j-1]` is empty and contributes 0, which the base initialisation already gives.

### Dry run on `s = "abcb"`
Length-1: `dp[0][0] = dp[1][1] = dp[2][2] = dp[3][3] = 1`.

Length-2:
- `dp[0][1]` (`a`,`b` differ): `1 + 1 − 0 = 2` → `a`, `b`.
- `dp[1][2]` (`b`,`c` differ): `2`.
- `dp[2][3]` (`c`,`b` differ): `2`.

Length-3:
- `dp[0][2]` (`a` vs `c`, differ): `dp[1][2] + dp[0][1] − dp[1][1] = 2 + 2 − 1 = 3` → `a`, `b`, `c`.
- `dp[1][3]` (`b` == `b`): `dp[2][3] + dp[1][2] + 1 = 2 + 2 + 1 = 5` → `b`, `c`, `b`, `bb`, `bcb`. ✓

Length-4:
- `dp[0][3]` (`a` vs `b`, differ): `dp[1][3] + dp[0][2] − dp[1][2] = 5 + 3 − 2 = 6`. ✓

### Modular arithmetic warning
Under a modulus the subtraction in the unequal-endpoint branch can go negative in C++ and Java, so normalise with `((x % MOD) + MOD) % MOD`. This is the single most common bug in this problem — a negative intermediate silently poisons every larger interval.

### Space optimisation
Only rows `i` and `i+1` are ever read, so the table can be collapsed to two 1-D arrays of length `n` when `i` runs downward, cutting space from O(n²) to O(n). The version below keeps the full table for readability.

- **Time:** O(n²) — one constant-work transition per interval
- **Space:** O(n²), reducible to O(n)

## Code (Optimal)

### C++
```cpp
#include <string>
#include <vector>
using namespace std;

class Solution {
public:
    int countPalindromicSubsequences(const string& s) {
        const long long MOD = 1000000007LL;
        int n = (int)s.size();
        if (n == 0) return 0;

        // dp[i][j] = number of non-empty palindromic subsequences in s[i..j]
        vector<vector<long long>> dp(n, vector<long long>(n, 0));
        for (int i = 0; i < n; i++) dp[i][i] = 1;

        for (int len = 2; len <= n; len++) {
            for (int i = 0; i + len - 1 < n; i++) {
                int j = i + len - 1;
                long long inner = (len > 2) ? dp[i + 1][j - 1] : 0;
                if (s[i] == s[j]) {
                    // the -inner from inclusion-exclusion cancels the +inner from wrapping
                    dp[i][j] = (dp[i + 1][j] + dp[i][j - 1] + 1) % MOD;
                } else {
                    long long v = dp[i + 1][j] + dp[i][j - 1] - inner;
                    dp[i][j] = ((v % MOD) + MOD) % MOD;   // subtraction can go negative
                }
            }
        }
        return (int)dp[0][n - 1];
    }
};
```

### Java
```java
class Solution {
    public int countPalindromicSubsequences(String s) {
        final long MOD = 1_000_000_007L;
        int n = s.length();
        if (n == 0) return 0;

        // dp[i][j] = number of non-empty palindromic subsequences in s[i..j]
        long[][] dp = new long[n][n];
        for (int i = 0; i < n; i++) dp[i][i] = 1;

        for (int len = 2; len <= n; len++) {
            for (int i = 0; i + len - 1 < n; i++) {
                int j = i + len - 1;
                long inner = (len > 2) ? dp[i + 1][j - 1] : 0;
                if (s.charAt(i) == s.charAt(j)) {
                    // the -inner from inclusion-exclusion cancels the +inner from wrapping
                    dp[i][j] = (dp[i + 1][j] + dp[i][j - 1] + 1) % MOD;
                } else {
                    long v = dp[i + 1][j] + dp[i][j - 1] - inner;
                    dp[i][j] = ((v % MOD) + MOD) % MOD;   // subtraction can go negative
                }
            }
        }
        return (int) dp[0][n - 1];
    }
}
```

### Python
```python
class Solution:
    def countPalindromicSubsequences(self, s: str) -> int:
        MOD = 1_000_000_007
        n = len(s)
        if n == 0:
            return 0

        # dp[i][j] = number of non-empty palindromic subsequences in s[i..j]
        dp = [[0] * n for _ in range(n)]
        for i in range(n):
            dp[i][i] = 1

        for length in range(2, n + 1):
            for i in range(0, n - length + 1):
                j = i + length - 1
                inner = dp[i + 1][j - 1] if length > 2 else 0
                if s[i] == s[j]:
                    # the -inner from inclusion-exclusion cancels the +inner from wrapping
                    dp[i][j] = (dp[i + 1][j] + dp[i][j - 1] + 1) % MOD
                else:
                    dp[i][j] = (dp[i + 1][j] + dp[i][j - 1] - inner) % MOD

        return dp[0][n - 1] % MOD
```

## Key Takeaways
- Interval DP is the right frame whenever "both ends" decide the answer; here `dp[i][j]` over substrings turns an exponential search into O(n²).
- The two branches come from one inclusion–exclusion identity — when `s[i] == s[j]` the `−dp[i+1][j-1]` is exactly cancelled by the palindromes formed by wrapping the inner ones.
- Normalise negative values after the subtraction under a modulus; this is the classic silent failure in C++/Java.
- This counts subsequences by **position**, so repeated text is counted more than once. If a problem instead asks for *distinct* palindromic strings (LeetCode 730) or only length-5 palindromes (LeetCode 2484), the state must change — do not reuse this recurrence blindly.
