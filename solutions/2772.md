# Merge 2 BST's

**Difficulty:** Hard  ·  **Topic:** Binary Search Trees [Concept and Problems] › Practice Problems

## Problem
Given the roots of two Binary Search Trees, merge them and return all their values in sorted (ascending) order. Duplicates across the two trees are kept.

```
Input:  root1 = [5, 3, 6], root2 = [2, 1, 7]
Output: [1, 2, 3, 5, 6, 7]

Input:  root1 = [], root2 = [4, 2, 5]
Output: [2, 4, 5]
```

(The same machinery also lets you build a *balanced* BST from the merged list — see the last section.)

## Approach 1: Brute Force (concatenate and sort)
Traverse both trees in any order, dump all values into one array, and sort it.

Correct, but it throws away the fact that each tree already gives you a sorted sequence for free.
- **Time:** O((N+M) log(N+M)) because of the sort
- **Space:** O(N+M)

## Approach 2: Better (two inorder arrays + merge)
Inorder traversal of a BST is sorted. So take the inorder of tree 1 into array `A` and of tree 2 into array `B`, then merge the two sorted arrays with the standard two-pointer merge from merge sort: compare `A[i]` and `B[j]`, append the smaller, advance that pointer; when one runs out, append the rest of the other.

This drops the log factor entirely — the sort was redundant.
- **Time:** O(N + M)
- **Space:** O(N + M) for the two arrays plus O(H1 + H2) traversal stacks

## Approach 3: Optimal auxiliary space (two BST iterators / controlled recursion)
The two-array version is already linear in time, so the only thing left to improve is the *auxiliary* space: we materialise both trees fully before emitting a single value. We can avoid that with the **BST iterator** idea.

A BST iterator is a stack-based inorder traversal frozen mid-flight. It holds only the current left spine:
- `pushAll(node)`: push `node`, then `node->left`, then its left child, and so on. The stack top is now the smallest unvisited value in that subtree.
- `next()`: pop the top (that is the next value in sorted order), then `pushAll(popped->right)` so that the popped node's right subtree is queued up correctly.
- `hasNext()`: the stack is non-empty.

Each node is pushed once and popped once across the whole traversal, so `next()` is O(1) *amortised*, and the stack never holds more than `H` nodes.

Now run **two** such iterators, one per tree, and do the merge-sort merge on them instead of on arrays:

1. While both iterators have a next value, peek at both tops and pop the smaller one into the output.
2. When one iterator is exhausted, drain the other.

Because each iterator yields values in ascending order and we always take the global minimum of the two fronts, the output is sorted. Equal values are fine — take either (taking from tree 1 first keeps it stable).

**Dry run** on `root1 = [5, 3, 6]` and `root2 = [2, 1, 7]`:
- Iterator 1 stack after init: `[5, 3]` (top `3`). Iterator 2: `[2, 1]` (top `1`).
- Compare fronts `3` vs `1` → take `1`. It2 pops `1`, pushes nothing (no right child); top is now `2`.
- `3` vs `2` → take `2`. It2 pops `2`, pushes the right spine of `7` → stack `[7]`.
- `3` vs `7` → take `3`. It1 pops `3`, no right child; top is `5`.
- `5` vs `7` → take `5`. It1 pops `5`, pushes `6` → top `6`.
- `6` vs `7` → take `6`. It1 now empty.
- Drain It2 → take `7`.
- Output `[1, 2, 3, 5, 6, 7]`. ✔

Auxiliary space is O(H1 + H2) for the two stacks instead of O(N + M) for the arrays (the output list itself is of course still O(N+M), but that is the required answer, not scratch space).

**Follow-up — returning a balanced BST.** If the problem asks for a merged *tree* rather than a list, take the sorted merged array and build a height-balanced BST from it: the middle element becomes the root, the left half builds the left subtree, the right half the right subtree, recursively. That is O(N+M) and yields height O(log(N+M)).
- **Time:** O(N + M)
- **Space:** O(H1 + H2) auxiliary, plus the O(N + M) output

## Code (Optimal)

### C++
```cpp
// struct TreeNode { int val; TreeNode *left, *right; TreeNode(int x) ... } — standard definition
#include <vector>
#include <stack>
using namespace std;

class BSTIterator {
    stack<TreeNode*> st;
    void pushAll(TreeNode* node) {          // push the left spine
        while (node) { st.push(node); node = node->left; }
    }
public:
    BSTIterator(TreeNode* root) { pushAll(root); }
    bool hasNext() const { return !st.empty(); }
    int  peek()    const { return st.top()->val; }
    int  next() {
        TreeNode* node = st.top(); st.pop();
        pushAll(node->right);               // queue the right subtree's left spine
        return node->val;
    }
};

class Solution {
public:
    vector<int> mergeTwoBST(TreeNode* root1, TreeNode* root2) {
        BSTIterator it1(root1), it2(root2);
        vector<int> merged;
        while (it1.hasNext() && it2.hasNext()) {
            if (it1.peek() <= it2.peek()) merged.push_back(it1.next());
            else                          merged.push_back(it2.next());
        }
        while (it1.hasNext()) merged.push_back(it1.next());
        while (it2.hasNext()) merged.push_back(it2.next());
        return merged;
    }
};
```

### Java
```java
// class TreeNode { int val; TreeNode left, right; TreeNode(int x) ... } — standard definition
import java.util.*;

class BSTIterator {
    private final Deque<TreeNode> st = new ArrayDeque<>();

    BSTIterator(TreeNode root) { pushAll(root); }

    private void pushAll(TreeNode node) {
        while (node != null) { st.push(node); node = node.left; }
    }

    boolean hasNext() { return !st.isEmpty(); }
    int peek() { return st.peek().val; }
    int next() {
        TreeNode node = st.pop();
        pushAll(node.right);
        return node.val;
    }
}

class Solution {
    public List<Integer> mergeTwoBST(TreeNode root1, TreeNode root2) {
        BSTIterator it1 = new BSTIterator(root1), it2 = new BSTIterator(root2);
        List<Integer> merged = new ArrayList<>();
        while (it1.hasNext() && it2.hasNext()) {
            if (it1.peek() <= it2.peek()) merged.add(it1.next());
            else                          merged.add(it2.next());
        }
        while (it1.hasNext()) merged.add(it1.next());
        while (it2.hasNext()) merged.add(it2.next());
        return merged;
    }
}
```

### Python
```python
# class TreeNode: val, left, right — standard definition

class BSTIterator:
    def __init__(self, root):
        self.st = []
        self._push_all(root)

    def _push_all(self, node):          # push the whole left spine
        while node:
            self.st.append(node)
            node = node.left

    def has_next(self):
        return len(self.st) > 0

    def peek(self):
        return self.st[-1].val

    def next(self):
        node = self.st.pop()
        self._push_all(node.right)      # right subtree becomes the new front
        return node.val


class Solution:
    def mergeTwoBST(self, root1, root2):
        it1, it2 = BSTIterator(root1), BSTIterator(root2)
        merged = []
        while it1.has_next() and it2.has_next():
            if it1.peek() <= it2.peek():
                merged.append(it1.next())
            else:
                merged.append(it2.next())
        while it1.has_next():
            merged.append(it1.next())
        while it2.has_next():
            merged.append(it2.next())
        return merged
```

## Key Takeaways
- Each BST already hands you a sorted stream via inorder — never sort, just merge.
- A BST iterator is an inorder traversal paused on a stack holding only the left spine: O(1) amortised `next()` and O(H) space.
- Running two iterators side by side turns "merge two BSTs" into the merge step of merge sort, with O(H1+H2) auxiliary space instead of O(N+M).
- If a merged *tree* is required, build it from the middle of the merged sorted array recursively to get a height-balanced result.
