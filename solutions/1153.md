# Introduction to BST

**Difficulty:** Easy  ·  **Topic:** Binary Search Trees [Concept and Problems] › Concepts

## Problem
This topic covers what a Binary Search Tree (BST) is, the ordering invariant that defines it, why that invariant makes search, insert, and delete fast, and the pitfalls (duplicates, degenerate shapes) that every BST problem in this section relies on.

Input: insert the keys 8, 3, 10, 1, 6 in that order into an empty BST
Output:
```
      8
     / \
    3   10
   / \
  1   6
```
Inorder traversal of the result: 1 3 6 8 10 (sorted).

## Approach: The BST invariant and what it buys you
**Definition.** A BST is a binary tree in which, for every node, all keys in the left subtree are strictly smaller than the node's key and all keys in the right subtree are strictly larger. The rule applies to *entire subtrees*, not just immediate children. A tree where each node only compares against its direct children can still violate the property further down.

**Consequence 1: inorder is sorted.** Left, root, right visits keys in ascending order. Many BST problems (validate BST, kth smallest, recover swapped nodes) are just inorder traversal in disguise.

**Consequence 2: search is a single root-to-leaf walk.** At each node compare with the target: equal means found, smaller means go left, larger means go right. You never need to look at the other side. The cost is proportional to the height H.

**Consequence 3: insert is search plus one link.** Walk down as in search until you reach a null pointer, then attach the new node there. The tree stays a valid BST.

**Height matters.** For N nodes, a balanced BST has H ≈ log₂N, so search/insert/delete are O(log N). Inserting already-sorted keys produces a single chain (a "degenerate" BST) where H = N and every operation degrades to O(N). Self-balancing variants (AVL, Red-Black) fix this but are not required for the problems in this sheet.

**Duplicates.** The classic definition forbids them. When a problem allows duplicates, it will state a convention (usually "duplicates go to the right" or "≤ on the left"). Read the constraint carefully before coding comparisons.

**Min and max.** The minimum is the leftmost node, the maximum is the rightmost node; both are found by walking one direction until null.

- **Time:** O(H) for search, insert, delete; O(log N) balanced, O(N) degenerate
- **Space:** O(H) recursion or O(1) iteratively

## Code (Optimal)
A minimal BST with iterative `insert`, `search`, and an inorder traversal to demonstrate the sorted property.

### C++
```cpp
#include <vector>
using namespace std;

struct TreeNode {
    int val; TreeNode *left, *right;
    TreeNode(int v) : val(v), left(nullptr), right(nullptr) {}
};

class BST {
public:
    TreeNode* root = nullptr;

    void insert(int key) {
        TreeNode* node = new TreeNode(key);
        if (!root) { root = node; return; }
        TreeNode* cur = root;
        while (true) {
            if (key < cur->val) {
                if (!cur->left) { cur->left = node; return; }
                cur = cur->left;
            } else {
                if (!cur->right) { cur->right = node; return; }
                cur = cur->right;
            }
        }
    }

    bool search(int key) {
        TreeNode* cur = root;
        while (cur && cur->val != key) cur = key < cur->val ? cur->left : cur->right;
        return cur != nullptr;
    }

    void inorder(TreeNode* n, vector<int>& out) {
        if (!n) return;
        inorder(n->left, out); out.push_back(n->val); inorder(n->right, out);
    }
};
```

### Java
```java
import java.util.*;

class TreeNode {
    int val; TreeNode left, right;
    TreeNode(int v) { val = v; }
}

class BST {
    TreeNode root;

    void insert(int key) {
        TreeNode node = new TreeNode(key);
        if (root == null) { root = node; return; }
        TreeNode cur = root;
        while (true) {
            if (key < cur.val) {
                if (cur.left == null) { cur.left = node; return; }
                cur = cur.left;
            } else {
                if (cur.right == null) { cur.right = node; return; }
                cur = cur.right;
            }
        }
    }

    boolean search(int key) {
        TreeNode cur = root;
        while (cur != null && cur.val != key) cur = key < cur.val ? cur.left : cur.right;
        return cur != null;
    }

    void inorder(TreeNode n, List<Integer> out) {
        if (n == null) return;
        inorder(n.left, out); out.add(n.val); inorder(n.right, out);
    }
}
```

### Python
```python
class TreeNode:
    def __init__(self, val):
        self.val = val
        self.left = None
        self.right = None

class BST:
    def __init__(self):
        self.root = None

    def insert(self, key):
        node = TreeNode(key)
        if self.root is None:
            self.root = node
            return
        cur = self.root
        while True:
            if key < cur.val:
                if cur.left is None:
                    cur.left = node
                    return
                cur = cur.left
            else:
                if cur.right is None:
                    cur.right = node
                    return
                cur = cur.right

    def search(self, key):
        cur = self.root
        while cur and cur.val != key:
            cur = cur.left if key < cur.val else cur.right
        return cur is not None

    def inorder(self, n, out):
        if n is None:
            return
        self.inorder(n.left, out)
        out.append(n.val)
        self.inorder(n.right, out)
```

## Key Takeaways
- The BST property is about whole subtrees, which is why validation needs min/max bounds rather than parent-child checks.
- Inorder traversal of a BST is sorted; reach for it whenever a problem mentions "kth", "sorted", or "successor".
- Every basic operation costs O(H); balance is what keeps H logarithmic.
- Check the problem's rule for duplicates before writing `<` versus `<=`.
