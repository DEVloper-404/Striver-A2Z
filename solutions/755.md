# Minimum Cost to Connect Sticks

**Difficulty:** Medium  ·  **Topic:** Heaps [Learning, Medium, Hard Problems] › Hard Problems

## Problem
You have `n` sticks with given lengths. Joining two sticks of lengths `a` and `b` produces a single stick of length `a + b` and costs `a + b`. Keep joining until one stick remains and return the minimum total cost. If there is at most one stick, the cost is 0.

```
Input:  sticks = [2, 4, 3]
Output: 14
```
Join 2 and 3 (cost 5, new stick 5), then join 5 and 4 (cost 9). Total 14. Any other order costs more.

## Approach 1: Try every order (brute force)
Recursively pick any pair, merge them, and recurse on the reduced multiset, keeping the minimum. This explores a huge tree of possibilities and is only useful for verifying small cases.
- **Time:** exponential
- **Space:** O(n) recursion depth

## Approach 2: Sorted list with re-insertion
Sort the sticks. Take the two smallest, add their sum to the answer, and insert the merged stick back into the sorted list (linear insertion). This uses the right greedy idea but pays O(n) per insertion.
- **Time:** O(n^2)
- **Space:** O(1) extra

## Approach 3: Min-heap (optimal)
A stick's length is added to the cost once for every merge it participates in, so lengths merged early get counted many times. To minimise the total, merge the two smallest sticks first, every time. This is exactly the greedy behind Huffman coding.

1. Push all lengths into a min-heap.
2. While more than one stick remains: pop the two smallest, add their sum to `cost`, push the sum back.
3. Return `cost`.

Each of the `n - 1` merges does a constant number of heap operations.
- **Time:** O(n log n)
- **Space:** O(n)

## Code (Optimal)

### C++
```cpp
#include <bits/stdc++.h>
using namespace std;

class Solution {
public:
    int connectSticks(vector<int>& sticks) {
        priority_queue<int, vector<int>, greater<int>> minHeap(sticks.begin(), sticks.end());
        long long cost = 0;
        while (minHeap.size() > 1) {
            int a = minHeap.top(); minHeap.pop();
            int b = minHeap.top(); minHeap.pop();
            cost += a + b;
            minHeap.push(a + b);
        }
        return (int)cost;
    }
};
```

### Java
```java
import java.util.*;

class Solution {
    public int connectSticks(int[] sticks) {
        PriorityQueue<Integer> minHeap = new PriorityQueue<>();
        for (int s : sticks) minHeap.offer(s);

        long cost = 0;
        while (minHeap.size() > 1) {
            int a = minHeap.poll();
            int b = minHeap.poll();
            cost += a + b;
            minHeap.offer(a + b);
        }
        return (int) cost;
    }
}
```

### Python
```python
import heapq
from typing import List


class Solution:
    def connectSticks(self, sticks: List[int]) -> int:
        heap = list(sticks)
        heapq.heapify(heap)
        cost = 0
        while len(heap) > 1:
            a = heapq.heappop(heap)
            b = heapq.heappop(heap)
            cost += a + b
            heapq.heappush(heap, a + b)
        return cost
```

## Key Takeaways
- Greedy "merge the two smallest" is optimal because early merges are re-counted in every later merge; the proof is the same exchange argument used for Huffman trees.
- Use `heapify` on the whole input (O(n)) rather than pushing one by one when the language offers it.
- With a single stick (or none) the loop never runs and the answer is 0.
- Use a 64-bit accumulator in C++/Java; the running sum can exceed 32-bit limits for large inputs even when each stick fits in an `int`.
