# Iterative Inorder Traversal of Binary Tree

**Difficulty:** Easy  ·  **Topic:** Binary Trees [Traversals, Medium and Hard Problems] › Traversals

## Problem
Return the inorder traversal (Left, Root, Right) of a binary tree without recursion. Unlike preorder, you cannot emit a node as soon as you see it, because its whole left subtree has to come out first; the exercise is to manage that delay with an explicit stack.

Input: `root = [1, 2, 3, 4, 5, null, 6]`
```
      1
     / \
    2   3
   / \   \
  4   5   6
```
Output: `[4, 2, 5, 1, 3, 6]`

## Approach 1: Recursive (for reference)
Recurse left, record the node, recurse right. Three lines, but it relies on the call stack and can overflow on a deep skewed tree.
- **Time:** O(n)
- **Space:** O(h) recursion stack

## Approach 2: Explicit stack with a current pointer (optimal)
The recursion "remembers" every ancestor whose left subtree is still being processed. Mimic that with a stack and a `curr` pointer:

1. Starting at `curr = root`, push `curr` and move to `curr.left`, repeating until `curr` is null. This descends the left spine.
2. Pop the top node. Its left subtree is finished, so record its value.
3. Set `curr` to the popped node's right child and go back to step 1.

The loop runs while `curr` is non-null or the stack is non-empty. A node is pushed once when first reached and popped once when its left side is done, so the total work is linear and the stack never holds more than a root-to-leaf path.
- **Time:** O(n)
- **Space:** O(h) for the stack

## Approach 3: Morris inorder (O(1) space)
For the current node with a left child, find the rightmost node of the left subtree. If its right pointer is null, point it at the current node and go left. If it already points to the current node, reset it to null, record the current node, and go right. Nodes with no left child are recorded directly and we go right. Every thread is created and removed once, so it is linear time with no stack.
- **Time:** O(n)
- **Space:** O(1) extra

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <stack>
using namespace std;

// struct TreeNode { int val; TreeNode *left; TreeNode *right; ... } — standard definition

class Solution {
public:
    vector<int> inorderTraversal(TreeNode* root) {
        vector<int> res;
        stack<TreeNode*> st;
        TreeNode* curr = root;
        while (curr != nullptr || !st.empty()) {
            while (curr != nullptr) {    // descend the left spine
                st.push(curr);
                curr = curr->left;
            }
            curr = st.top();
            st.pop();
            res.push_back(curr->val);    // left side done, emit node
            curr = curr->right;          // now the right subtree
        }
        return res;
    }
};
```

class Solution {
    public List<Integer> inorderTraversal(TreeNode root) {

        Deque<TreeNode> st = new ArrayDeque<>();

                curr = curr.left;
            }
            curr = st.pop();
            res.add(curr.val);           // left side done, emit node
            curr = curr.right;           // now the right subtree
        }
        return res;
    }
}

### Python
```python
# class TreeNode: val, left, right — standard definition

class Solution:
    def inorderTraversal(self, root):
        res = []
        stack = []
        curr = root
        while curr is not None or stack:
            while curr is not None:      # descend the left spine
                stack.append(curr)
                curr = curr.left
            curr = stack.pop()
            res.append(curr.val)         # left side done, emit node
            curr = curr.right            # now the right subtree
        return res
```

## Key Takeaways
- The pattern is "push the whole left spine, pop and visit, then step right". The stack holds ancestors whose left subtree is still in progress.
- The outer loop needs both conditions (`curr` non-null OR stack non-empty); dropping either one either stops early or dereferences null.
- After popping a node you go to its right child, not back to the stack, otherwise the right subtree is skipped.
- The same skeleton is reused for BST iterators, k-th smallest, and validating a BST in O(h) space.
