# Best time to buy and sell stock with transaction fees

**Difficulty:** Medium  ·  **Topic:** Dynamic Programming [Patterns and Problems] › DP on Stocks

## Problem
Given `prices[i]` = the stock price on day `i` and an integer `fee`, you may complete as many transactions as you like (buy one share, sell it, repeat), but **each completed transaction costs `fee`**. You can hold at most one share at a time. Return the maximum profit.

```
Input:  prices = [1, 3, 2, 8, 4, 9], fee = 2
Output: 8      (buy at 1 sell at 8 → 8−1−2 = 5, buy at 4 sell at 9 → 9−4−2 = 3)
```

## Approach 1: Recursion with a hold flag (Brute Force)
This is Stock II with one extra term. Let `f(i, canBuy)` = the best profit from day `i` onward.

- If `canBuy`: `max(-prices[i] + f(i+1, false), f(i+1, true))`.
- Else: `max(prices[i] - fee + f(i+1, true), f(i+1, false))`.
- Base case `f(n, ·) = 0`.

Charging the fee on the **sell** (rather than the buy) is a convention — the total is the same either way, as long as you charge it exactly once per completed round trip. Charging it on the sell has the pleasant side effect that an unclosed position never pays a fee.

- **Time:** O(2^n)
- **Space:** O(n)

## Approach 2: Two rolling states (Optimal)
Memoising leaves `2n` states, and since day `i` depends only on day `i+1` the whole table collapses into two scalars:

- `hold` — best balance while owning a share.
- `free` — best balance while owning nothing.

Sweep the prices once:
```
hold = max(hold, free - price)          // keep holding, or buy today with banked profit
free = max(free, hold + price - fee)    // stay out, or sell today and pay the fee
```
Start with `hold = -prices[0]` and `free = 0`, and return `free`.

Why the fee changes the behaviour and not just the arithmetic: without a fee, the optimal strategy takes every single upward tick. With a fee, small ticks are no longer worth closing a position for. The DP handles this automatically — a trade only survives in `free` if `price - buyPrice > fee`. That is exactly why the greedy "sum of positive daily differences" trick from Stock II **breaks** here: it would happily pay the fee on every one-day blip.

Updating `hold` before `free` on the same day is safe: the extra schedule it would allow is buying and selling on the same day, which yields `-fee` and can never beat the value `free` already holds.

**Dry run** on `[1, 3, 2, 8, 4, 9]`, `fee = 2`:

| day | price | hold                | free                    |
|-----|-------|---------------------|-------------------------|
| 0   | 1     | −1                  | 0                       |
| 1   | 3     | max(−1, 0−3) = −1   | max(0, −1+3−2) = 0      |
| 2   | 2     | max(−1, 0−2) = −1   | max(0, −1+2−2) = 0      |
| 3   | 8     | max(−1, 0−8) = −1   | max(0, −1+8−2) = 5      |
| 4   | 4     | max(−1, 5−4) = 1    | max(5, −1+4−2) = 5      |
| 5   | 9     | max(1, 5−9) = 1     | max(5, 1+9−2) = **8**   |

Day 1 is instructive: buying at 1 and selling at 3 nets `3 − 1 − 2 = 0`, so the DP correctly refuses the trade and waits for the bigger move to 8.

- **Time:** O(n)
- **Space:** O(1)

## Approach 3: Greedy with a floating buy price
An equivalent O(1) formulation that some find more intuitive: keep `buy` = the effective price you consider yourself to have paid. Initialise `buy = prices[0]`. For each later price `p`:
- If `p < buy`, update `buy = p` (a cheaper entry is strictly better).
- Else if `p - buy > fee`, bank `p - buy - fee` into the profit and set `buy = p - fee`. Setting `buy` to `p - fee` rather than `p` is the trick: it keeps the position "open" so that a further rise can be captured without paying a second fee, which is exactly how the DP merges consecutive rises into one transaction.

- **Time:** O(n)
- **Space:** O(1)

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int maxProfit(vector<int>& prices, int fee) {
        int n = prices.size();
        if (n < 2) return 0;
        long long hold = -prices[0];   // owning a share
        long long free = 0;            // owning nothing
        for (int i = 1; i < n; i++) {
            hold = max(hold, free - prices[i]);
            free = max(free, hold + prices[i] - fee);
        }
        return (int)free;
    }
};
```

from typing import List


class Solution:
    def maxProfit(self, prices: List[int], fee: int) -> int:
        if len(prices) < 2:
            return 0
        hold = -prices[0]
        free = 0
        for price in prices[1:]:
            hold = max(hold, free - price)
            free = max(free, hold + price - fee)
        return free

## Key Takeaways
- The fee turns "take every upward tick" into "only close a position when the gain clears the fee" — the greedy from Stock II no longer applies, but the two-state DP does, unchanged except for one `- fee`.
- Charge the fee exactly once per round trip; putting it on the sell keeps unclosed positions fee-free and keeps the formula simple.
- Consecutive rises are automatically merged into one transaction, so the DP pays the fee once rather than per day.
- Return the `free` state; and guard `n < 2`, where no transaction is possible and the answer is 0.
