# Find the MST weight

**Difficulty:** Hard  ·  **Topic:** Graphs [Concepts & Problems] › MinimumSpanningTree/Disjoint Set and Problems

## Problem
Given a connected, undirected, weighted graph with `V` vertices and an edge list `edges[i] = [u, v, w]`, return the **total weight of its minimum spanning tree** — the smallest possible sum of weights over any set of `V - 1` edges that connects every vertex.

```
Input:  V = 4
        edges = [[0,1,1],[1,2,2],[2,3,3],[0,3,4],[0,2,5]]
Output: 6
```
Picking `0-1 (1)`, `1-2 (2)` and `2-3 (3)` connects all four vertices for a total of `6`; no cheaper set of three edges does.

## Approach 1: Brute force over edge subsets
Generate every subset of edges of size `V - 1`, check whether it spans and is acyclic, and keep the cheapest. Correct, but `C(E, V-1)` subsets is astronomically large.
- **Time:** O(C(E, V−1) · V)
- **Space:** O(V)

## Approach 2: Kruskal's algorithm with a Disjoint Set (optimal)

**The key observation — sort and be greedy, using components as the guard.** Process edges from cheapest to most expensive. For each edge, ask a single question: *do its two endpoints already sit in the same connected component?*
- **Different components** → take the edge. It merges two pieces of the forest, so it cannot create a cycle, and by the cut property it is a safe choice (it is the cheapest remaining edge crossing the cut between one component and everything else).
- **Same component** → reject it. Adding it would close a cycle, and since we scan in increasing weight order, this edge is the heaviest on that cycle — by the cycle property no MST contains it.

Crucially, that "same component?" test is exactly what a Disjoint Set Union answers in near-constant time. Kruskal's is really just "sorted edges + DSU".

**Why the greedy is globally optimal.** Each accepted edge is the cheapest edge crossing the cut that separates one of the current components from the rest (anything cheaper crossing that cut would have been examined earlier and, if it crossed, would have been accepted). The cut property says such an edge belongs to some MST, so every acceptance keeps us on a path to an optimal tree. After `V - 1` acceptances the forest is a single spanning tree.

**The algorithm.**
1. Sort `edges` by weight ascending — `O(E log E)`.
2. Initialise a DSU over `V` nodes with union by size (or rank) and path compression.
3. Scan the sorted edges. If `find(u) != find(v)`, union them, add `w` to the total, and increment a counter.
4. Stop early once the counter reaches `V - 1`; that is the whole tree.
5. If the scan ends with fewer than `V - 1` accepted edges, the graph is disconnected — there is no spanning tree (return `-1` or the forest weight, per the problem's convention).

**Short dry run** on the example. Sorted: `(0,1,1) (1,2,2) (2,3,3) (0,3,4) (0,2,5)`.
- `(0,1,1)`: leaders `0` and `1` differ → accept, total `1`, components `{0,1} {2} {3}`.
- `(1,2,2)`: leaders differ → accept, total `3`, components `{0,1,2} {3}`.
- `(2,3,3)`: leaders differ → accept, total `6`, one component. Counter hits `V - 1 = 3`, so we stop.
- `(0,3,4)` and `(0,2,5)` would both be rejected as cycle-closing anyway.

**Prim's as an alternative.** Prim's grows a single tree from a start vertex using a min-heap and runs in `O(E log V)` on an adjacency list. Kruskal's is usually the shorter code when the input is already an edge list, which it is here.

**Overflow note.** With `E` up to `10^5` and weights up to `10^6`, the total can exceed `2^31`; accumulate in a 64-bit type if the constraints are large.
- **Time:** O(E log E) — dominated by the sort; the DSU work is O(E · α(V))
- **Space:** O(V) for the DSU arrays

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <algorithm>
#include <numeric>
using namespace std;

class Solution {
    vector<int> parent, sz;
    int find(int x) { return parent[x] == x ? x : parent[x] = find(parent[x]); }
    bool unite(int a, int b) {
        a = find(a); b = find(b);
        if (a == b) return false;
        if (sz[a] < sz[b]) swap(a, b);
        parent[b] = a;
        sz[a] += sz[b];
        return true;
    }
public:
    // edges[i] = {u, v, w}; returns MST weight, or -1 if disconnected
    long long spanningTree(int V, vector<vector<int>> edges) {
        parent.resize(V);
        sz.assign(V, 1);
        iota(parent.begin(), parent.end(), 0);

        sort(edges.begin(), edges.end(),
             [](const vector<int>& a, const vector<int>& b) { return a[2] < b[2]; });

        long long total = 0;
        int taken = 0;
        for (auto& e : edges) {
            if (unite(e[0], e[1])) {
                total += e[2];
                if (++taken == V - 1) break;   // tree complete
            }
        }
        return taken == V - 1 ? total : -1;
    }
};
```

### Java
```java
import java.util.*;

class Solution {
    private int[] parent, size;

    private int find(int x) {
        if (parent[x] != x) parent[x] = find(parent[x]);
        return parent[x];
    }

    private boolean unite(int a, int b) {
        a = find(a); b = find(b);
        if (a == b) return false;
        if (size[a] < size[b]) { int t = a; a = b; b = t; }
        parent[b] = a;
        size[a] += size[b];
        return true;
    }

    public long spanningTree(int V, int[][] edges) {
        parent = new int[V];
        size = new int[V];
        for (int i = 0; i < V; i++) { parent[i] = i; size[i] = 1; }

        Arrays.sort(edges, (a, b) -> Integer.compare(a[2], b[2]));

        long total = 0;
        int taken = 0;
        for (int[] e : edges) {
            if (unite(e[0], e[1])) {
                total += e[2];
                if (++taken == V - 1) break;
            }
        }
        return taken == V - 1 ? total : -1;
    }
}
```

### Python
```python
from typing import List

class Solution:
    # edges[i] = [u, v, w]; returns MST weight, or -1 if disconnected
    def spanningTree(self, V: int, edges: List[List[int]]) -> int:
        parent = list(range(V))
        size = [1] * V

        def find(x: int) -> int:
            while parent[x] != x:
                parent[x] = parent[parent[x]]
                x = parent[x]
            return x

        def unite(a: int, b: int) -> bool:
            a, b = find(a), find(b)
            if a == b:
                return False
            if size[a] < size[b]:
                a, b = b, a
            parent[b] = a
            size[a] += size[b]
            return True

        total = taken = 0
        for u, v, w in sorted(edges, key=lambda e: e[2]):
            if unite(u, v):
                total += w
                taken += 1
                if taken == V - 1:
                    break
        return total if taken == V - 1 else -1
```

## Key Takeaways
- Kruskal's = sort edges ascending + accept an edge only when its endpoints are in different DSU components.
- Rejecting an edge whose endpoints already share a leader is exactly the cycle property: that edge is the heaviest on the cycle it would close.
- Stopping after `V - 1` accepted edges saves scanning the tail; ending with fewer means the graph is disconnected.
- Use path compression with union by size/rank, and accumulate the total in 64-bit when weights and edge counts are large.
