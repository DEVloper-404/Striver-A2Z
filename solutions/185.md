# Children Sum Property in Binary Tree

**Difficulty:** Medium  ·  **Topic:** Binary Trees [Traversals, Medium and Hard Problems] › Hard Problems

## Problem
A binary tree satisfies the children-sum property when every non-leaf node's value equals the sum of its (existing) children's values. Two versions are commonly asked: (a) check whether a tree satisfies the property, and (b) modify the tree so it satisfies the property, where you may only increase node values (never decrease) by any amount.

Input (check): root = [10, 8, 2, 3, 5]
Output: true (8 = 3 + 5, 10 = 8 + 2)

Input (convert): root = [2, 35, 10, 2, 3, 5, 2]
Output: one valid answer is [45, 35, 10, 30, 5, 8, 2]

## Approach 1: Checking the property (post-order DFS)
Recursively verify both subtrees and then check the current node: leaf nodes are always fine; otherwise `node.val` must equal the sum of the non-null children's values. Any failure propagates `false` upward.
- **Time:** O(N)
- **Space:** O(H) recursion

## Approach 2: Converting the tree (two-phase DFS, optimal)
Since we may only increase values, the trick is to push large values downward first so children can grow to match, then fix parents on the way back up:
1. On entering a node, compute `childSum = left.val + right.val` (missing child counts as 0).
2. If `childSum >= node.val`, set `node.val = childSum` (parent already fits or will fit).
   Otherwise, raise each existing child to `node.val` so the children are large enough to eventually sum up to at least the parent.
3. Recurse into both children.
4. On returning, set `node.val` to the new sum of its children (leaf nodes are left untouched).

Step 2 guarantees that after recursion, children's values are at least the parent's original value, so step 4 never decreases anything.
- **Time:** O(N)
- **Space:** O(H) recursion

## Code (Optimal)

### C++
```cpp
// struct TreeNode { int val; TreeNode *left; TreeNode *right; ... } — standard definition
class Solution {
public:
    // (a) check
    bool isChildrenSum(TreeNode* root) {
        if (!root || (!root->left && !root->right)) return true;
        int sum = (root->left ? root->left->val : 0) + (root->right ? root->right->val : 0);
        if (sum != root->val) return false;
        return isChildrenSum(root->left) && isChildrenSum(root->right);
    }

    // (b) convert (only increases allowed)
    void makeChildrenSum(TreeNode* root) {
        if (!root) return;
        int childSum = (root->left ? root->left->val : 0) + (root->right ? root->right->val : 0);
        if (childSum >= root->val) root->val = childSum;
        else {
            if (root->left)  root->left->val  = root->val;
            if (root->right) root->right->val = root->val;
        }
        makeChildrenSum(root->left);
        makeChildrenSum(root->right);
        int total = 0;
        if (root->left)  total += root->left->val;
        if (root->right) total += root->right->val;
        if (root->left || root->right) root->val = total;
    }
};
```

### Python
```python
# class TreeNode: val, left, right — standard definition

class Solution:
    # (a) check
    def isChildrenSum(self, root):
        if root is None or (root.left is None and root.right is None):
            return True
        s = (root.left.val if root.left else 0) + (root.right.val if root.right else 0)
        if s != root.val:
            return False
        return self.isChildrenSum(root.left) and self.isChildrenSum(root.right)

    # (b) convert (only increases allowed)
    def makeChildrenSum(self, root):
        if root is None:
            return
        child_sum = (root.left.val if root.left else 0) + (root.right.val if root.right else 0)
        if child_sum >= root.val:
            root.val = child_sum
        else:
            if root.left:
                root.left.val = root.val
            if root.right:
                root.right.val = root.val
        self.makeChildrenSum(root.left)
        self.makeChildrenSum(root.right)
        if root.left or root.right:
            root.val = (root.left.val if root.left else 0) + (root.right.val if root.right else 0)
```

## Key Takeaways
- Checking is a plain post-order validation; the conversion problem is the one interviewers care about.
- The conversion needs a top-down push (make children big enough) followed by a bottom-up fix (set parent = children sum).
- Leaves never change during the bottom-up phase; only internal nodes are rewritten.
- Without the "push down first" step, a bottom-up fix could produce a parent smaller than its original value, violating the increase-only rule.
