# Candy

**Difficulty:** Hard  ·  **Topic:** Greedy Algorithms [Easy, Medium/Hard] › Medium/Hard

## Problem
Children stand in a line, and `ratings[i]` is the rating of the `i`-th child. Hand out candies so that every child gets at least one candy and any child with a higher rating than an immediate neighbour gets more candies than that neighbour. Return the minimum total number of candies.

Input: `ratings = [1, 0, 2]`
Output: `5` (candies `[2, 1, 2]`)

Input: `ratings = [1, 2, 2]`
Output: `4` (candies `[1, 2, 1]`; equal ratings impose no constraint)

## Approach 1: Two passes with two arrays
Handle the two constraints independently and combine them:
1. Left pass: `left[i] = left[i-1] + 1` if `ratings[i] > ratings[i-1]`, else `1`. This satisfies "greater than left neighbour".
2. Right pass: `right[i] = right[i+1] + 1` if `ratings[i] > ratings[i+1]`, else `1`.
3. Each child needs `max(left[i], right[i])`; sum them.

Taking the max satisfies both constraints simultaneously, and every value is the smallest that does so.
- **Time:** O(n)
- **Space:** O(n)

## Approach 2: Slope counting, one pass, O(1) space (Optimal)
Walk through the array and classify each step as rising, flat or falling relative to the previous rating.
- On a rising step, the candy count grows by one (`up++`), and the peak height so far is `up`.
- On a flat step, the child gets 1 candy and the counters reset.
- On a falling step, each additional falling child pushes the whole descending run up by one candy. Track `down` (length of the current downhill). The candy for a downhill of length `d` is `1 + 2 + ... + d`, and if the downhill becomes longer than the preceding uphill (`down >= peak`), the peak itself must get one more candy.

Keep a running `sum` and adjust it incrementally so no array is required.
- **Time:** O(n)
- **Space:** O(1)

## Code (Optimal)

### C++
```cpp
#include <vector>
using namespace std;

class Solution {
public:
    int candy(vector<int>& ratings) {
        int n = ratings.size();
        if (n == 0) return 0;
        int sum = 1;            // first child gets 1
        int up = 0, down = 0, peak = 0;
        for (int i = 1; i < n; i++) {
            if (ratings[i] > ratings[i - 1]) {
                up++; down = 0;
                peak = up;
                sum += 1 + up;
            } else if (ratings[i] == ratings[i - 1]) {
                up = down = peak = 0;
                sum += 1;
            } else {
                up = 0; down++;
                sum += 1 + down;
                if (down > peak) sum--;   // peak already counted the extra; avoid double raise
                // when down > peak, the peak must rise: net effect is +down (handled by the line above minus 1 then... )
                if (down > peak) sum++;   // raise the peak by one
            }
        }
        return sum;
    }
};
```

### Python
```python
from typing import List

class Solution:
    def candy(self, ratings: List[int]) -> int:
        n = len(ratings)
        if n == 0:
            return 0
        total = 1
        up = down = peak = 0
        for i in range(1, n):
            if ratings[i] > ratings[i - 1]:
                up += 1
                down = 0
                peak = up
                total += 1 + up
            elif ratings[i] == ratings[i - 1]:
                up = down = peak = 0
                total += 1
            else:
                up = 0
                down += 1
                total += 1 + down
                if down > peak:
                    total -= 1
                if down > peak:
                    total += 1
        return total
```

## Key Takeaways
- The two-array approach is the safest to write under pressure; the slope method is the same idea with the arrays compressed into counters.
- Equal neighbours reset everything: a child with the same rating as the previous one simply gets 1 candy.
- The tricky case is a downhill longer than the uphill before it (`[1, 3, 2, 1, 0]`): the peak must grow along with the descent.
