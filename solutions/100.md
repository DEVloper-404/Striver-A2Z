# Check if a tree is a BST or not

**Difficulty:** Medium  ·  **Topic:** Binary Search Trees [Concept and Problems] › Practice Problems

## Problem
Given the root of a binary tree, determine whether it is a valid Binary Search Tree. Validity means: for **every** node, all values in its entire left subtree are strictly smaller and all values in its entire right subtree are strictly larger.

```
Input:  root = [2, 1, 3]
Output: true

Input:  root = [5, 1, 4, null, null, 3, 6]
Output: false   (4's left child 3 is smaller than the root 5, but sits in 5's right subtree)
```

## Approach 1: The tempting wrong answer (local check only)
The most common first attempt is to check, at every node, that `left->val < node->val < right->val` and recurse. This is **not sufficient**, and the second example above is exactly the counter-example: `4 > 3` and `4 < 6`, so node `4` looks fine locally, yet `3` violates the constraint imposed by the ancestor `5`. The BST property is a *global* constraint on whole subtrees, not a parent–child constraint. Any correct solution must propagate information from ancestors down, or from subtrees up.

## Approach 2: Inorder traversal must be strictly increasing
A cleaner characterisation: a binary tree is a BST **iff** its inorder traversal is strictly increasing. Inorder visits the left subtree, the node, then the right subtree, so if the ordering property holds everywhere the emitted sequence must be sorted; conversely if any node were out of place, the two offending values would appear adjacent-in-order and out of order.

So: do an inorder traversal, keep only the previously visited value `prev`, and fail the moment `cur->val <= prev`. No array needed — one variable suffices.

Careful with duplicates: use `<=` (strict increase) for the usual "strictly smaller / strictly larger" definition.

**Dry run** on `[5, 1, 4, null, null, 3, 6]`: inorder is `1, 5, 3, 6`. At `3` we compare against `prev = 5` and `3 <= 5`, so we return false immediately. ✔
- **Time:** O(N)
- **Space:** O(H) for the traversal stack

## Approach 3: Optimal (range propagation, min/max bounds)
The other correct framing pushes ancestor information downward. Every node must lie in an open interval `(low, high)` determined by its ancestors:
- The root may be anything: `(-∞, +∞)`.
- Moving to a left child, the current node becomes a new *upper* bound: `(low, node->val)`.
- Moving to a right child, the current node becomes a new *lower* bound: `(node->val, high)`.

A node is valid iff `low < node->val < high`, and the tree is a BST iff every node passes. This directly encodes "every ancestor's constraint", which is exactly what the naive local check misses.

**Dry run** on the same failing tree:
- `5` in `(-∞, ∞)` ✔ → left child gets `(-∞, 5)`, right child gets `(5, ∞)`.
- `1` in `(-∞, 5)` ✔.
- `4` in `(5, ∞)`? `4 < 5` → **fail**. Return false.

Notice this one caught the violation one level earlier than the inorder scan, at the node whose subtree straddles the bound.

Implementation note: use `long`/`long long` sentinels (or nullable bound types) so that a node holding `INT_MIN` or `INT_MAX` does not spuriously fail against an `INT_MIN`/`INT_MAX` sentinel.
- **Time:** O(N) — every node checked once
- **Space:** O(H) recursion stack

## Code (Optimal)

### C++
```cpp
// struct TreeNode { int val; TreeNode *left, *right; TreeNode(int x) ... } — standard definition
#include <climits>
using namespace std;

class Solution {
    // valid iff low < node->val < high, bounds widened as long long to dodge INT_MIN/INT_MAX
    bool check(TreeNode* node, long long low, long long high) {
        if (node == nullptr) return true;                 // empty subtree is a valid BST
        if (node->val <= low || node->val >= high) return false;
        return check(node->left,  low, node->val) &&
               check(node->right, node->val, high);
    }
public:
    bool isValidBST(TreeNode* root) {
        return check(root, LLONG_MIN, LLONG_MAX);
    }
};
```

### Java
```java
// class TreeNode { int val; TreeNode left, right; TreeNode(int x) ... } — standard definition

class Solution {
    private boolean check(TreeNode node, long low, long high) {
        if (node == null) return true;
        if (node.val <= low || node.val >= high) return false;
        return check(node.left, low, node.val) && check(node.right, node.val, high);
    }

    public boolean isValidBST(TreeNode root) {
        return check(root, Long.MIN_VALUE, Long.MAX_VALUE);
    }
}
```

### Python
```python
# class TreeNode: val, left, right — standard definition

class Solution:
    def isValidBST(self, root):
        def check(node, low, high):
            if node is None:
                return True
            if not (low < node.val < high):
                return False
            # left child inherits an upper bound, right child a lower bound
            return check(node.left, low, node.val) and check(node.right, node.val, high)

        return check(root, float('-inf'), float('inf'))
```

## Key Takeaways
- Checking only `left < node < right` is the classic bug — the BST property constrains entire subtrees, not just immediate children.
- Two correct framings: push bounds down (range check) or read values in order (inorder must be strictly increasing). Both are O(N).
- Use `<=`/`>=` in the comparison so equal values are rejected under the strict definition; switch to non-strict only if the problem allows duplicates.
- Use wide sentinel bounds (`long long`, `Long.MIN_VALUE`, `float('-inf')`) so nodes holding `INT_MIN`/`INT_MAX` are not falsely rejected.
