# Insert a given node in BST

**Difficulty:** Medium  ·  **Topic:** Binary Search Trees [Concept and Problems] › Practice Problems

## Problem
Given the root of a BST and a value `val` that is guaranteed not to already be in the tree, insert `val` and return the root of the updated BST. The result must still satisfy the BST property. Any valid resulting shape is accepted.

```
Input:  root = [4, 2, 7, 1, 3], val = 5
Output: [4, 2, 7, 1, 3, 5]      (5 becomes the left child of 7)

Input:  root = [], val = 9
Output: [9]                     (the new node becomes the root)
```

## Approach 1: Rebuild from a sorted list
Take the inorder traversal (sorted), insert `val` into the right position of the array, then rebuild a BST from that array. Correct, but it touches all N nodes, allocates O(N) memory, and destroys the existing tree structure for no reason.
- **Time:** O(N)
- **Space:** O(N)

## Approach 2: Optimal (walk down and hang the new node off a null pointer)
The crucial insight is that **you never have to restructure anything**. If you follow the search path for `val` — go left when `val < node->val`, right otherwise — you eventually reach a null child pointer. That null spot is exactly where a search for `val` would have terminated, so putting the node there means every future search finds it. And because the node lands at the end of the path that respects all the comparisons along the way, every ancestor's BST constraint is automatically satisfied: each ancestor sent us left or right precisely because `val` belongs on that side.

Concretely:
1. If the tree is empty, the new node *is* the tree — return it.
2. Otherwise keep a pointer `cur` at the root and loop:
   - If `val < cur->val`: if `cur->left` is null, attach a new node there and stop; else `cur = cur->left`.
   - If `val > cur->val`: if `cur->right` is null, attach a new node there and stop; else `cur = cur->right`.
3. Return the original root (it never changes, unless the tree was empty).

**Dry run** for `root = [4, 2, 7, 1, 3]`, `val = 5`:
- At `4`: `5 > 4` → go right. Right child `7` exists, so `cur = 7`.
- At `7`: `5 < 7` → go left. Left child is null → attach `5` as `7->left`. Done.

Resulting tree: `4` with left `2` (children `1`, `3`) and right `7` (left child `5`). Inorder is `1 2 3 4 5 7`, still sorted. ✔

The recursive version is a one-liner in spirit: `insert(node, val)` returns the subtree root after insertion, so `node->left = insert(node->left, val)` re-links automatically when the recursion bottoms out at null and returns a fresh node. The iterative version avoids the O(H) stack, which is why it is the version shown below.

*(If duplicates were allowed, you would pick a convention — say, send equal values right — and the same walk still works.)*
- **Time:** O(H) — O(log N) balanced, O(N) worst case on a skewed tree
- **Space:** O(1) iterative, O(H) recursive

## Code (Optimal)

### C++
```cpp
// struct TreeNode { int val; TreeNode *left, *right; TreeNode(int x) : val(x), left(nullptr), right(nullptr) {} } — standard definition

class Solution {
public:
    TreeNode* insertIntoBST(TreeNode* root, int val) {
        TreeNode* node = new TreeNode(val);
        if (root == nullptr) return node;

        TreeNode* cur = root;
        while (true) {
            if (val < cur->val) {
                if (cur->left == nullptr) { cur->left = node; break; }
                cur = cur->left;
            } else {
                if (cur->right == nullptr) { cur->right = node; break; }
                cur = cur->right;
            }
        }
        return root;
    }
};
```

## Key Takeaways
- Insertion never needs rotation or restructuring in a plain BST: the search path itself proves where the node belongs.
- The new node always becomes a **leaf**, replacing the null pointer where the search for `val` would have failed.
- Handle the empty-tree case separately — that is the only situation where the returned root differs from the input root.
- The cost is the height, so repeatedly inserting sorted values degrades the tree into a linked list and makes insertion O(N); self-balancing trees (AVL, Red-Black) exist to prevent exactly this.
