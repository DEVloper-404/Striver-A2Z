# Minimum multiplications to reach end

**Difficulty:** Hard  ·  **Topic:** Graphs [Concepts & Problems] › Shortest Path Algorithms and Problems

## Problem
You are given an array `arr` of integers, a starting number `start` and a target number `end`. In one step you may pick any `arr[i]` and replace the current number `x` by `(x * arr[i]) % 100000`. Find the minimum number of steps needed to turn `start` into `end`, or return `-1` if it is impossible.

```
Input:  arr = [2, 5, 7], start = 3, end = 30
Output: 2
```
`3 * 2 = 6`, then `6 * 5 = 30`. Two multiplications, and no single multiplication reaches `30`.

## Approach 1: Plain DFS / backtracking
Try every multiplier at every step and recurse. Without a visited set this never terminates (the state space cycles), and even with a depth limit it explores an exponential number of sequences. Not viable.
- **Time:** exponential
- **Space:** O(depth)

## Approach 2: Model it as an unweighted graph and run BFS (optimal)

**The key observation — this is a shortest-path problem in disguise.** Because every value is taken modulo `100000`, the current number is always in `[0, 99999]`. So there are only `100000` distinct *states*. Draw a directed edge from state `x` to state `(x * arr[i]) % 100000` for each `i`. Every edge costs exactly one multiplication, so all edges have **unit weight**, and "minimum multiplications" is literally "shortest path from `start` to `end`" in this graph.

**Why BFS and not Dijkstra.** With uniform edge weights, BFS visits states in non-decreasing order of distance from the source. The first time BFS touches a state, it has reached it by the fewest possible edges — that is the standard BFS optimality property. Dijkstra would also work but adds a needless `log` factor.

**The algorithm.**
1. Keep `dist[0..99999]`, initialised to infinity (or a `visited` array plus a level counter). Set `dist[start % 100000] = 0`.
2. Push `start % 100000` into a queue.
3. Pop a state `x`. If `x == end`, return `dist[x]`.
4. For each `a` in `arr`, compute `nxt = (x * a) % 100000`. If `nxt` has not been reached yet, set `dist[nxt] = dist[x] + 1` and push it.
5. If the queue empties without hitting `end`, return `-1`.

**Why the visited check is essential.** Without it, a state can be re-enqueued endlessly (e.g. multiplying by `1`, or any cycle in the modular graph), and the queue never drains. With it, each of the `10^5` states is expanded at most once and each expansion does `|arr|` work.

**Short dry run** on `arr = [2,5,7], start = 3, end = 30`.
- Level 0: queue `{3}`. Expand `3` → `6`, `15`, `21`, all new, distance `1`.
- Level 1: expand `6` → `12`, `30`, `42`. `30` is the target and gets distance `2`. When it is popped (or checked at push time) we return `2`.

**Careful with overflow.** `x` can be up to `99999` and `arr[i]` up to `100000`, so the product reaches roughly `10^10` — larger than a 32-bit int. Use 64-bit multiplication (`long long` / `long`) before taking the modulus. Also handle `start == end` up front, which needs zero steps.
- **Time:** O(100000 · |arr|) — every modular state is expanded at most once
- **Space:** O(100000) for the distance/visited array and the queue

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <queue>
using namespace std;

class Solution {
public:
    int minimumMultiplications(vector<int>& arr, int start, int end) {
        const int MOD = 100000;
        start %= MOD;
        end %= MOD;
        if (start == end) return 0;

        vector<int> dist(MOD, -1);
        queue<int> q;
        dist[start] = 0;
        q.push(start);

        while (!q.empty()) {
            int x = q.front();
            q.pop();
            for (int a : arr) {
                int nxt = (int)((1LL * x * a) % MOD);
                if (dist[nxt] == -1) {
                    dist[nxt] = dist[x] + 1;
                    if (nxt == end) return dist[nxt];
                    q.push(nxt);
                }
            }
        }
        return -1;
    }
};
```

class Solution {
    public int minimumMultiplications(int[] arr, int start, int end) {
        final int MOD = 100000;
        start %= MOD;
        end %= MOD;

                    if (nxt == end) return dist[nxt];
                    q.add(nxt);
                }

        }

    }
}

### Python
```python
from collections import deque
from typing import List

class Solution:
    def minimumMultiplications(self, arr: List[int], start: int, end: int) -> int:
        MOD = 100000
        start %= MOD
        end %= MOD
        if start == end:
            return 0

        dist = [-1] * MOD
        dist[start] = 0
        q = deque([start])

        while q:
            x = q.popleft()
            for a in arr:
                nxt = (x * a) % MOD
                if dist[nxt] == -1:
                    dist[nxt] = dist[x] + 1
                    if nxt == end:
                        return dist[nxt]
                    q.append(nxt)
        return -1
```

## Key Takeaways
- When a problem's "current value" lives in a bounded range, treat each value as a graph node and each operation as an edge — the search space becomes finite.
- All operations cost the same, so plain BFS gives the minimum count; Dijkstra is unnecessary overhead here.
- The `visited`/`dist` guard is what makes the search terminate at all, since the modular graph is full of cycles.
- Multiply in 64-bit before the modulus, and short-circuit the `start == end` case.
