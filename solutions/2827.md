# Djisktra's Algorithm

**Difficulty:** Hard  ·  **Topic:** Graphs [Concepts & Problems] › Shortest Path Algorithms and Problems

## Problem
Given a weighted graph with `V` vertices and an adjacency list where `adj[u]` holds pairs `{v, w}` (an edge from `u` to `v` of weight `w`, `w >= 0`), and a source vertex `S`, compute the shortest distance from `S` to every vertex. Distances to unreachable vertices are reported as infinity (often `-1` or `1e9`).

```
Input:  V = 5, S = 0,
        edges = [[0,1,4], [0,2,1], [2,1,2], [1,3,1], [2,3,5], [3,4,3]]
Output: [0, 3, 1, 4, 7]
```
Note `dist[1] = 3` via `0 -> 2 -> 1` (1 + 2), not the direct edge of weight 4.

## Approach 1: BFS relaxation without ordering (why it is slow)
Push the source in a plain queue; whenever an edge relaxes a distance, push that vertex again. This does converge to the right answer, but a vertex can be re-expanded many times as better routes trickle in, and in the worst case the work blows up exponentially on adversarial graphs. The fix is to control *the order in which vertices are expanded*.

- **Time:** unbounded in practice (up to exponential)
- **Space:** O(V)

## Approach 2: Dijkstra — always expand the closest unfinalised vertex (Optimal)

**Key observation (the greedy invariant).** Suppose all edge weights are non-negative and let `u` be the unfinalised vertex with the smallest tentative distance `dist[u]`. Then `dist[u]` is already the true shortest distance. Why? Any other route to `u` must leave the finalised set at some vertex `x` and continue along non-negative edges. Since `x` is unfinalised at the point where it is first left, `dist[x] >= dist[u]`, and appending more non-negative weights can only make it larger. So no alternative route can beat `dist[u]`.

That single fact is the whole algorithm: **pick the minimum, declare it final, push its distance to neighbours, repeat.** It also explains why Dijkstra fails with negative edges — the "adding more edges only increases the cost" step collapses.

**Algorithm (with a min-heap / set keyed by distance).**
1. `dist[S] = 0`, everything else `∞`. Put `(0, S)` in a min-priority-queue ordered by distance.
2. Pop the smallest `(d, u)`. If `d > dist[u]`, this is a stale entry left behind by an earlier improvement — skip it.
3. Otherwise relax each edge `u -> v` with weight `w`: if `d + w < dist[v]`, set `dist[v] = d + w` and push `(dist[v], v)`.
4. Repeat until the queue empties. Each vertex is finalised the first time it is popped.

**Set vs priority queue.** A `set<pair<int,int>>` lets you *erase* the old `(oldDist, v)` entry before inserting the improved one, so the container never holds duplicates. A priority queue cannot erase, so it holds stale pairs and you skip them with the `d > dist[u]` check. Both are O((V + E) log V); the set does fewer, more expensive operations, the heap more, cheaper ones. The heap version below is the usual choice.

**Dry run** on the example (source 0):
- `dist = [0, ∞, ∞, ∞, ∞]`, PQ `{(0,0)}`.
- Pop `(0,0)`: relax `0->1` giving `dist[1] = 4`, and `0->2` giving `dist[2] = 1`. PQ `{(1,2), (4,1)}`.
- Pop `(1,2)` — the closest, so `dist[2] = 1` is final. Relax `2->1`: `1 + 2 = 3 < 4`, so `dist[1] = 3`, push `(3,1)`. Relax `2->3`: `dist[3] = 6`. PQ `{(3,1), (4,1) stale, (6,3)}`.
- Pop `(3,1)`: final. Relax `1->3`: `3 + 1 = 4 < 6`, so `dist[3] = 4`, push `(4,3)`.
- Pop `(4,1)`: stale (`4 > dist[1] = 3`) → skipped. Pop `(4,3)`: final; relax `3->4`: `dist[4] = 7`.
- Pop `(6,3)`: stale, skipped. Pop `(7,4)`: final. Result `[0, 3, 1, 4, 7]` ✓

The dry run shows both crucial mechanics: the direct edge `0->1` of weight 4 being beaten by a two-hop route, and stale heap entries being discarded harmlessly.

- **Time:** O((V + E) log V) — each edge can push at most one entry, and heap operations cost log
- **Space:** O(V + E) for the graph, O(V + E) worst case for the heap

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <queue>
#include <climits>
using namespace std;

class Solution {
public:
    // adj[u] = list of {v, w}
    vector<int> dijkstra(int V, vector<vector<pair<int,int>>>& adj, int S) {
        vector<int> dist(V, INT_MAX);
        priority_queue<pair<int,int>, vector<pair<int,int>>, greater<>> pq;  // {dist, node}
        dist[S] = 0;
        pq.push({0, S});

        while (!pq.empty()) {
            auto [d, u] = pq.top(); pq.pop();
            if (d > dist[u]) continue;               // stale entry
            for (auto& [v, w] : adj[u]) {
                if (d + w < dist[v]) {
                    dist[v] = d + w;
                    pq.push({dist[v], v});
                }
            }
        }
        return dist;
    }
};
```

### Java
```java
import java.util.*;

class Solution {
    // adj.get(u) = list of int[]{v, w}
    public int[] dijkstra(int V, List<List<int[]>> adj, int S) {
        int[] dist = new int[V];
        Arrays.fill(dist, Integer.MAX_VALUE);
        dist[S] = 0;

        PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> a[0] - b[0]); // {dist, node}
        pq.add(new int[]{0, S});

        while (!pq.isEmpty()) {
            int[] cur = pq.poll();
            int d = cur[0], u = cur[1];
            if (d > dist[u]) continue;
            for (int[] e : adj.get(u)) {
                int v = e[0], w = e[1];
                if (d + w < dist[v]) {
                    dist[v] = d + w;
                    pq.add(new int[]{dist[v], v});
                }
            }
        }
        return dist;
    }
}
```

### Python
```python
import heapq
from typing import List, Tuple

class Solution:
    # adj[u] = list of (v, w)
    def dijkstra(self, V: int, adj: List[List[Tuple[int, int]]], S: int) -> List[int]:
        INF = float("inf")
        dist = [INF] * V
        dist[S] = 0
        pq = [(0, S)]                       # (distance, node)

        while pq:
            d, u = heapq.heappop(pq)
            if d > dist[u]:                 # stale entry
                continue
            for v, w in adj[u]:
                if d + w < dist[v]:
                    dist[v] = d + w
                    heapq.heappush(pq, (dist[v], v))

        return dist
```

## Key Takeaways
- Dijkstra is greedy: the unfinalised vertex with the smallest tentative distance is already optimal — valid only because weights are **non-negative**.
- Popping a vertex finalises it; the `d > dist[u]` guard cheaply discards stale heap entries instead of deleting them.
- Complexity is O((V + E) log V); with unit weights use plain BFS instead, and with negative edges use Bellman-Ford.
- Store `{distance, node}` in that order so the heap compares distances first.
