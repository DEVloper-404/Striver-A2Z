# Next Greater Element

**Difficulty:** Medium  ·  **Topic:** Stack and Queues [Learning, Pre-In-Post-fix, Monotonic Stack, Implementation] › Monotonic Stack/Queue Problems [VVV. Imp]

## Problem
You are given two arrays `nums1` and `nums2` where `nums1` is a subset of `nums2` and all values are distinct. For every element `x` of `nums1`, locate `x` inside `nums2` and report the first element to its right that is strictly larger. If nothing larger exists to the right, report `-1`. Return the answers in the order of `nums1`.

The core sub-problem is: for each index of an array, find the "next greater element" (NGE) to its right.

```
Input:  nums1 = [4, 1, 2], nums2 = [1, 3, 4, 2]
Output: [-1, 3, -1]
```
4 has nothing larger after it; 1 is followed by 3; 2 is the last element.

## Approach 1: Brute Force
For each `x` in `nums1`, scan `nums2` to find `x`, then keep scanning right until a larger value appears. Two nested scans per query.
- **Time:** O(m · n) where m = |nums1|, n = |nums2|
- **Space:** O(1) extra

## Approach 2: Monotonic Stack + Hash Map (Optimal)
Compute the NGE of every element of `nums2` once, store it in a map, and answer each `nums1` query in O(1).

Walk `nums2` from right to left keeping a stack whose values are strictly decreasing from bottom to top. At index `i`:
1. Pop while the top is ≤ `nums2[i]` — those values can never be the answer for anything further left, because `nums2[i]` is closer and at least as large.
2. If the stack is empty, NGE is `-1`; otherwise it is the top.
3. Push `nums2[i]`.

Every element is pushed and popped at most once, so the whole pass is linear.
- **Time:** O(n + m)
- **Space:** O(n) for the stack and map

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <stack>
#include <unordered_map>
using namespace std;

class Solution {
public:
    vector<int> nextGreaterElement(vector<int>& nums1, vector<int>& nums2) {
        unordered_map<int, int> nge;
        stack<int> st;
        for (int i = (int)nums2.size() - 1; i >= 0; --i) {
            while (!st.empty() && st.top() <= nums2[i]) st.pop();
            nge[nums2[i]] = st.empty() ? -1 : st.top();
            st.push(nums2[i]);
        }
        vector<int> ans;
        ans.reserve(nums1.size());
        for (int x : nums1) ans.push_back(nge[x]);
        return ans;
    }
};
```

### Java
```java
import java.util.*;

class Solution {
    public int[] nextGreaterElement(int[] nums1, int[] nums2) {
        Map<Integer, Integer> nge = new HashMap<>();
        Deque<Integer> st = new ArrayDeque<>();
        for (int i = nums2.length - 1; i >= 0; i--) {
            while (!st.isEmpty() && st.peek() <= nums2[i]) st.pop();
            nge.put(nums2[i], st.isEmpty() ? -1 : st.peek());
            st.push(nums2[i]);
        }
        int[] ans = new int[nums1.length];
        for (int i = 0; i < nums1.length; i++) ans[i] = nge.get(nums1[i]);
        return ans;
    }
}
```

### Python
```python
from typing import List

class Solution:
    def nextGreaterElement(self, nums1: List[int], nums2: List[int]) -> List[int]:
        nge = {}
        st = []
        for x in reversed(nums2):
            while st and st[-1] <= x:
                st.pop()
            nge[x] = st[-1] if st else -1
            st.append(x)
        return [nge[x] for x in nums1]
```

## Key Takeaways
- Right-to-left scan with a decreasing stack is the standard NGE pattern; each element enters and leaves the stack once.
- Pop on `<=` (not `<`) so equal values are not reported as "greater".
- The distinct-values guarantee lets a plain hash map serve as the lookup from value to answer.
