# Matrix chain multiplication

**Difficulty:** Hard  ·  **Topic:** Dynamic Programming [Patterns and Problems] › MCM DP | Partition DP

## Problem
You are given an array `arr` of size `n` that describes a chain of `n - 1` matrices: the i-th matrix (1-indexed) has dimensions `arr[i-1] x arr[i]`. Multiplying an `a x b` matrix with a `b x c` matrix costs `a * b * c` scalar multiplications and produces an `a x c` matrix. Matrix multiplication is associative, so the chain can be bracketed in many ways, each with a different cost. Return the minimum number of scalar multiplications needed to multiply the whole chain.

```
Input:  arr = [10, 20, 30, 40, 50]      (matrices A1:10x20, A2:20x30, A3:30x40, A4:40x50)
Output: 38000
```

## Approach 1: Try every bracketing (Brute Force Recursion)

**The key observation.** We cannot greedily decide anything here — the cheapest first multiplication is not necessarily part of the cheapest overall plan. But whatever the optimal bracketing is, there is exactly one multiplication that happens *last*. That final multiplication splits the chain into a left block and a right block, each already collapsed into a single matrix. So the whole problem is: "where do I place the last cut?"

This is the signature of **partition DP**: instead of picking elements, we pick a *partition point* and recurse on both sides.

**Setting up the state.** Let `f(i, j)` = minimum cost to multiply matrices `A_i .. A_j` into one matrix. Because matrix `A_k` is `arr[k-1] x arr[k]`, the block `A_i..A_j` collapses to a matrix of size `arr[i-1] x arr[j]` — this is true no matter how it was bracketed, which is exactly why the subproblem is self-contained.

We start with `f(1, n-1)` (all `n-1` matrices).

**The recurrence.** Loop `k` from `i` to `j-1`. Cutting at `k` means: first build `A_i..A_k` (cost `f(i,k)`, result `arr[i-1] x arr[k]`), then build `A_{k+1}..A_j` (cost `f(k+1,j)`, result `arr[k] x arr[j]`), then multiply those two, costing `arr[i-1] * arr[k] * arr[j]`.

```
f(i, j) = min over k in [i, j-1] of  f(i, k) + f(k+1, j) + arr[i-1]*arr[k]*arr[j]
```

**Base case.** `i == j` means a single matrix — nothing to multiply, cost `0`.

- **Time:** exponential, roughly O(2^n) — every cut spawns two independent recursions
- **Space:** O(n) recursion stack

## Approach 2: Memoization (Optimal for this article)

The recursion recomputes the same `(i, j)` intervals over and over. There are only O(n^2) distinct intervals, so cache them in a 2-D table `dp[i][j]`, initialised to `-1`. Before computing, check the cache; after computing, store.

**Why memoization is valid.** `f(i, j)` depends only on `i` and `j` — not on how we arrived there — because the shape of the collapsed block (`arr[i-1] x arr[j]`) is fixed by the endpoints. That is the optimal-substructure property partition DP needs.

**Dry run on `arr = [10, 20, 30, 40, 50]`** (so `n = 5`, matrices `A1..A4`, answer is `f(1,4)`).

- `f(1,1) = f(2,2) = f(3,3) = f(4,4) = 0`.
- `f(1,2)` = only `k=1`: `0 + 0 + 10*20*30 = 6000`.
- `f(2,3)` = only `k=2`: `20*30*40 = 24000`.
- `f(3,4)` = only `k=3`: `30*40*50 = 60000`.
- `f(1,3)`: `k=1` → `f(1,1)+f(2,3)+10*20*40 = 0+24000+8000 = 32000`; `k=2` → `f(1,2)+f(3,3)+10*30*40 = 6000+0+12000 = 18000`. Minimum = **18000**.
- `f(2,4)`: `k=2` → `0+60000+20*30*50 = 90000`; `k=3` → `24000+0+20*40*50 = 64000`. Minimum = **64000**.
- `f(1,4)`: `k=1` → `0 + 64000 + 10*20*50 = 74000`; `k=2` → `6000 + 60000 + 10*30*50 = 81000`; `k=3` → `18000 + 0 + 10*40*50 = 38000`. Minimum = **38000**.

So the best bracketing is `((A1 A2) A3) A4`, costing 38000 — and note the greedy "do the cheapest pair first" would have started with `A1*A2` too, but the number only works out because we checked all three cuts.

- **Time:** O(n^3) — O(n^2) states, each scanning up to O(n) cut points
- **Space:** O(n^2) table + O(n) stack

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <algorithm>
#include <climits>
using namespace std;

class Solution {
    int solve(int i, int j, vector<int>& arr, vector<vector<int>>& dp) {
        if (i == j) return 0;                 // single matrix, nothing to do
        if (dp[i][j] != -1) return dp[i][j];

        int best = INT_MAX;
        for (int k = i; k < j; k++) {
            int cost = solve(i, k, arr, dp)
                     + solve(k + 1, j, arr, dp)
                     + arr[i - 1] * arr[k] * arr[j];
            best = min(best, cost);
        }
        return dp[i][j] = best;
    }

public:
    int matrixMultiplication(vector<int>& arr) {
        int n = arr.size();                   // n - 1 matrices
        vector<vector<int>> dp(n, vector<int>(n, -1));
        return solve(1, n - 1, arr, dp);
    }
};
```

### Java
```java
class Solution {
    private int solve(int i, int j, int[] arr, int[][] dp) {
        if (i == j) return 0;
        if (dp[i][j] != -1) return dp[i][j];

        int best = Integer.MAX_VALUE;
        for (int k = i; k < j; k++) {
            int cost = solve(i, k, arr, dp)
                     + solve(k + 1, j, arr, dp)
                     + arr[i - 1] * arr[k] * arr[j];
            best = Math.min(best, cost);
        }
        dp[i][j] = best;
        return best;
    }

    public int matrixMultiplication(int[] arr) {
        int n = arr.length;
        int[][] dp = new int[n][n];
        for (int[] row : dp) java.util.Arrays.fill(row, -1);
        return solve(1, n - 1, arr, dp);
    }
}
```

### Python
```python
from functools import lru_cache
from typing import List

class Solution:
    def matrixMultiplication(self, arr: List[int]) -> int:
        n = len(arr)

        @lru_cache(maxsize=None)
        def solve(i: int, j: int) -> int:
            if i == j:
                return 0
            best = float('inf')
            for k in range(i, j):
                cost = solve(i, k) + solve(k + 1, j) + arr[i - 1] * arr[k] * arr[j]
                best = min(best, cost)
            return best

        ans = solve(1, n - 1)
        solve.cache_clear()
        return ans
```

## Key Takeaways
- Partition DP pattern: don't ask "which element next?", ask "where does the last operation split the range?".
- State `(i, j)` works because the block `A_i..A_j` always collapses to `arr[i-1] x arr[j]`, independent of internal bracketing.
- Start the recursion at `i = 1`, not `i = 0`, since `arr[i-1]` must be a valid row count.
- Edge cases: `n <= 2` (zero or one matrix) returns 0; use `long`/64-bit if dimensions are large enough that `a*b*c` can overflow.
