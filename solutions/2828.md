# Why priority Queue is used in Djisktra's Algorithm

**Difficulty:** Hard  ·  **Topic:** Graphs [Concepts & Problems] › Shortest Path Algorithms and Problems

## Problem
This item explains *why* Dijkstra's algorithm uses a **priority queue (min-heap)** rather than an ordinary FIFO queue, and what breaks — or merely slows down — if you use a plain queue instead. The concrete task remains the same: given a non-negatively weighted graph and a source `S`, find `dist[i]` for every vertex.

```
Graph: 0 --1--> 1 --1--> 2 --1--> 3 --1--> 4
       0 -------------10-------------> 4
Source: 0
Correct answer: [0, 1, 2, 3, 4]      // the long chain beats the single heavy edge
```

## Approach: What the container decides, and why the heap wins

**The relaxation loop is the same either way.** Both versions repeatedly take a vertex out of a container, look at its outgoing edges, and improve neighbours whose distance can be reduced. The container only decides **the order in which vertices are expanded**, and that order determines how much work is repeated.

**1. A plain queue gives a correct but wasteful algorithm.** With a FIFO queue you expand vertices in the order they happened to be discovered, which has nothing to do with their distance. In the example above, the queue pops `0`, pushes `1` (dist 1) and `4` (dist 10). It then pops `1` and works down the chain, eventually discovering `dist[4] = 4`. Since `4 < 10`, vertex `4` must be relaxed and **pushed again**, and everything downstream of `4` must be recomputed. On larger graphs a vertex can be re-expanded many times — once for each improvement that arrives after it was already processed — and the cost degenerates badly (exponential in constructed worst cases). It never produces a wrong answer, it just keeps redoing work.

**2. The priority queue removes the repetition by expanding in distance order.** Popping the *minimum* tentative distance guarantees the popped value is already final. The argument: any alternative route to the popped vertex `u` must exit the finalised region through some unfinalised vertex `x`, and `dist[x] >= dist[u]` because `u` was the minimum; adding further non-negative weights only increases the total. Hence no future discovery can improve `dist[u]`. Each vertex is therefore expanded **once**, and each edge relaxed once — giving the O((V + E) log V) bound.

Put simply: **the heap converts "relax until nothing changes" into "relax once, in the right order."**

**3. Why BFS's plain queue is enough for unit weights.** With every edge equal to 1, discovery order and distance order coincide — the queue is *already* sorted by distance, so a heap adds nothing. The priority queue is exactly the tool that restores this property once weights differ. (The 0-1 BFS variant is the middle ground: with only weights 0 and 1, a deque — push-front for 0, push-back for 1 — preserves sorted order without a heap, at O(V + E).)

**4. Why the heap does not fix negative weights.** The "popped = final" argument depends on "extending a path cannot make it cheaper". A negative edge breaks that, so Dijkstra can finalise a vertex too early no matter which container you use. That situation needs Bellman-Ford (O(V·E)), which is precisely the "relax repeatedly" strategy done a bounded number of times.

**5. Practical detail: stale entries.** A standard heap cannot decrease a key in place, so when `dist[v]` improves we push a *new* pair and leave the old one behind. Skipping entries where the stored distance exceeds the current `dist[v]` costs O(1) and is simpler than maintaining an indexed heap. Using an ordered `set` instead lets you erase the outdated pair, keeping the container smaller at a higher constant cost per operation.

- **Time:** priority queue O((V + E) log V) · plain queue up to exponential re-expansions · plain BFS O(V + E) but only for unit weights
- **Space:** O(V + E) for the graph, O(V + E) for the heap in the worst case

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <queue>
#include <climits>
using namespace std;

class Solution {
public:
    // Dijkstra with a min-heap: every vertex is expanded at most once.
    vector<int> dijkstra(int V, vector<vector<pair<int,int>>>& adj, int S) {
        vector<int> dist(V, INT_MAX);
        priority_queue<pair<int,int>, vector<pair<int,int>>, greater<>> pq; // {dist, node}
        dist[S] = 0;
        pq.push({0, S});

        while (!pq.empty()) {
            auto [d, u] = pq.top(); pq.pop();
            if (d > dist[u]) continue;      // stale pair: a better distance was found later
            for (auto& [v, w] : adj[u]) {
                if (d + w < dist[v]) {
                    dist[v] = d + w;
                    pq.push({dist[v], v});  // no decrease-key: push a fresh pair
                }
            }
        }
        return dist;
    }
};
```

### Java
```java
import java.util.*;

class Solution {
    public int[] dijkstra(int V, List<List<int[]>> adj, int S) {
        int[] dist = new int[V];
        Arrays.fill(dist, Integer.MAX_VALUE);
        dist[S] = 0;

        // ordered by distance -> the popped vertex is always finalised
        PriorityQueue<int[]> pq = new PriorityQueue<>(Comparator.comparingInt(a -> a[0]));
        pq.add(new int[]{0, S});

        while (!pq.isEmpty()) {
            int[] cur = pq.poll();
            int d = cur[0], u = cur[1];
            if (d > dist[u]) continue;
            for (int[] e : adj.get(u)) {
                if (d + e[1] < dist[e[0]]) {
                    dist[e[0]] = d + e[1];
                    pq.add(new int[]{dist[e[0]], e[0]});
                }
            }
        }
        return dist;
    }
}
```

### Python
```python
import heapq
from typing import List, Tuple

class Solution:
    def dijkstra(self, V: int, adj: List[List[Tuple[int, int]]], S: int) -> List[int]:
        INF = float("inf")
        dist = [INF] * V
        dist[S] = 0
        pq = [(0, S)]                       # min-heap keyed by distance

        while pq:
            d, u = heapq.heappop(pq)        # smallest tentative distance => already final
            if d > dist[u]:
                continue                    # stale entry, ignore
            for v, w in adj[u]:
                if d + w < dist[v]:
                    dist[v] = d + w
                    heapq.heappush(pq, (dist[v], v))

        return dist
```

## Key Takeaways
- The priority queue enforces expansion in non-decreasing distance order, which makes each vertex final on its first pop — that is the entire reason it is there.
- A plain queue still yields correct distances but re-expands vertices whenever a shorter route arrives late, destroying the complexity guarantee.
- Distance order equals discovery order only when all weights are equal, which is why BFS needs no heap and 0-1 BFS gets by with a deque.
- No container choice rescues Dijkstra from negative edges — use Bellman-Ford there.
