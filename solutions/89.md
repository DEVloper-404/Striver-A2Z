# Search insert position

**Difficulty:** Easy  ·  **Topic:** Binary Search [1D, 2D Arrays, Search Space] › BS on 1D Arrays

## Problem
Given a sorted array of distinct integers `nums` and a `target`, return the index of `target` if it is present. If it is not, return the index at which it would have to be inserted so that the array stays sorted. Do this in O(log n) time.

Input: `nums = [1, 3, 5, 6], target = 5`
Output: `2`

Input: `nums = [1, 3, 5, 6], target = 2`
Output: `1` (2 would sit between 1 and 3)

Input: `nums = [1, 3, 5, 6], target = 7`
Output: `4`

## Approach 1: Linear Scan
Walk from the left and return the first index `i` with `nums[i] >= target`. If the loop ends, return `n`. Correct, but linear.

- **Time:** O(n)
- **Space:** O(1)

## Approach 2: Lower Bound via Binary Search (Optimal)
The insert position is precisely the lower bound of `target`: the first index whose value is `>= target`.

- If `target` exists, the lower bound lands on it (values are distinct, so there is only one copy).
- If it does not exist, the lower bound is the first larger element, which is exactly where `target` belongs.
- If every value is smaller, the lower bound is `n`, meaning "append at the end".

So run the standard lower-bound search: whenever `nums[mid] >= target`, remember `mid` and move left; otherwise move right.

- **Time:** O(log n)
- **Space:** O(1)

## Code (Optimal)

### C++
```cpp
#include <vector>
using namespace std;

class Solution {
public:
    int searchInsert(vector<int>& nums, int target) {
        int n = nums.size();
        int low = 0, high = n - 1, ans = n;
        while (low <= high) {
            int mid = low + (high - low) / 2;
            if (nums[mid] >= target) {
                ans = mid;
                high = mid - 1;
            } else {
                low = mid + 1;
            }
        }
        return ans;
    }
};
```

### Python
```python
from typing import List

class Solution:
    def searchInsert(self, nums: List[int], target: int) -> int:
        n = len(nums)
        low, high, ans = 0, n - 1, n
        while low <= high:
            mid = (low + high) // 2
            if nums[mid] >= target:
                ans = mid
                high = mid - 1
            else:
                low = mid + 1
        return ans
```

## Key Takeaways
- "Search insert position" is lower bound in disguise; recognising that avoids writing any special case for "found" versus "not found".
- Defaulting the answer to `n` handles a target larger than every element.
- A target smaller than every element gives index 0, because the very first comparison `nums[mid] >= target` keeps pushing `high` left until `ans = 0`.
- An alternative is to run the loop with `low <= high` and return `low` at the end; both are equivalent, but the explicit `ans` variable is easier to reason about.
