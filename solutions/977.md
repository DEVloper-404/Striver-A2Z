# KMP Algorithm or LPS array

**Difficulty:** Hard  ·  **Topic:** Strings › Hard Problems

## Problem
Given a text `haystack` and a pattern `needle`, return the index of the first occurrence of `needle` in `haystack`, or `-1` if it does not occur. The Knuth–Morris–Pratt algorithm does this in O(n + m) time by precomputing an **LPS array** (Longest Proper Prefix which is also a Suffix) for the pattern, so that after a mismatch the text pointer never moves backwards.

```
Input:  haystack = "ababcabcabababd", needle = "ababd"
Output: 10
```

## Approach 1: Brute Force — realign one step at a time
Try each start position `i` in the text and compare the pattern character by character. On a mismatch, throw away all progress, reset to `i + 1`, and start over.

The waste is concrete. Suppose the pattern is `"ababd"` and we have matched `"abab"` before failing on the 5th character. The brute force restarts one position later and re-compares `"bab…"` from scratch — yet we already *know* those characters, because they are part of the pattern we just matched. KMP's entire contribution is turning that knowledge into a shift.

- **Time:** O(n · m)
- **Space:** O(1)

## Approach 2: The LPS array — what it means and why it exists
For the pattern `p`, define `lps[i]` = the length of the longest **proper** prefix of `p[0..i]` that is also a suffix of `p[0..i]`. "Proper" means it cannot be the whole substring, otherwise the answer would trivially be `i + 1` everywhere.

For `p = "ababd"`:

| i | `p[0..i]` | longest proper prefix = suffix | `lps[i]` |
|---|-----------|-------------------------------|----------|
| 0 | `a`       | — (none)                      | 0 |
| 1 | `ab`      | — (`a` ≠ `b`)                 | 0 |
| 2 | `aba`     | `a`                           | 1 |
| 3 | `abab`    | `ab`                          | 2 |
| 4 | `ababd`   | — (nothing repeats)           | 0 |

**Why this is exactly the right information.** Say we have matched `j` characters of the pattern and the next one mismatches. Those `j` matched characters are a chunk of the text we have already read. A future occurrence of the pattern can only start inside that chunk if the pattern's prefix of some length `k` equals the chunk's suffix of length `k` — and `lps[j-1]` gives us the *largest* such `k`. Falling back to `k` therefore skips every hopeless alignment without skipping a real one. Choosing the largest `k` is what guarantees no occurrence is missed.

### Building LPS in O(m)
Use two pointers: `len` = length of the current prefix-suffix match, `i` = the index being filled (starting at 1, since `lps[0] = 0` always).

- If `p[i] == p[len]`, the match extends: `len++`, `lps[i] = len`, `i++`.
- Else if `len > 0`, do **not** move `i`. Instead fall back with `len = lps[len - 1]` and retry the comparison. (This is the same self-referential idea: a shorter prefix-suffix might still extend.)
- Else (`len == 0`), no match is possible here: `lps[i] = 0`, `i++`.

`len` increases at most `m` times in total and each fallback strictly decreases it, so the loop is linear.

- **Time:** O(m)
- **Space:** O(m)

## Approach 3: Optimal — KMP search using LPS
Now scan the text with `i` (text index) and `j` (how many pattern characters currently match):

1. If `text[i] == pat[j]`, both advance.
2. If `j == m`, we have a full match at `i - m`. Report it; to keep finding more, set `j = lps[j - 1]`.
3. On a mismatch with `j > 0`, set `j = lps[j - 1]` — slide the pattern forward while keeping `i` fixed.
4. On a mismatch with `j == 0`, there is nothing to salvage: `i++`.

**`i` never decreases.** That is the guarantee that makes the search linear: each text character is consumed once, and every mismatch either advances `i` or strictly decreases `j` (and `j` only ever grows via `i` advancing), so the total number of steps is at most `2n`.

### Dry run: `text = "ababcabcabababd"`, `pat = "ababd"`, `lps = [0,0,1,2,0]`
- `i=0..3`: `"abab"` matches, `j` reaches 4.
- `i=4`: `text[4]='c'` vs `pat[4]='d'` — mismatch with `j=4`. Fall back to `j = lps[3] = 2`. This says: the `"ab"` we just read is still a valid pattern prefix, so keep it. Note `i` stays at 4.
- `i=4` again: `'c'` vs `pat[2]='a'` — mismatch, `j = lps[1] = 0`.
- `i=4` again: `'c'` vs `pat[0]='a'` — mismatch with `j=0`, so `i++`.
- `i=5,6`: `"ab"` matches, `j=2`. At `i=7`, `'c'` vs `pat[2]='a'` fails → `j = lps[1] = 0`; it still fails at `j=0`, so `i` becomes 8.
- `i=8..11`: `"abab"` matches, `j=4`, `i` reaches 12.
- `i=12`: `text[12]='a'` vs `pat[4]='d'` — mismatch. `j = lps[3] = 2`, keeping the trailing `"ab"` as a live prefix, and `i` stays at 12.
- `i=12`: `'a'` vs `pat[2]='a'` ✓ → `i=13, j=3`. Then `text[13]='b'` vs `pat[3]='b'` ✓ → `i=14, j=4`. Then `text[14]='d'` vs `pat[4]='d'` ✓ → `i=15, j=5`.
- `j == 5 == m` → answer `i - m = 15 - 5 = 10`.

The brute force would have re-examined the `"abab"` prefix several times; KMP read every text character exactly once.

- **Time:** O(n + m)
- **Space:** O(m) for the LPS array

## Code (Optimal)

### C++
```cpp
#include <string>
#include <vector>
using namespace std;

class Solution {
public:
    // lps[i] = longest proper prefix of p[0..i] that is also a suffix of p[0..i]
    vector<int> buildLPS(const string& p) {
        int m = (int)p.size();
        vector<int> lps(m, 0);
        int len = 0, i = 1;
        while (i < m) {
            if (p[i] == p[len]) {
                lps[i++] = ++len;              // match extends
            } else if (len > 0) {
                len = lps[len - 1];            // fall back, keep i fixed
            } else {
                lps[i++] = 0;                  // nothing to salvage
            }
        }
        return lps;
    }

    int strStr(const string& haystack, const string& needle) {
        int n = (int)haystack.size(), m = (int)needle.size();
        if (m == 0) return 0;
        if (m > n) return -1;

        vector<int> lps = buildLPS(needle);
        int i = 0, j = 0;                      // i over text, j over pattern
        while (i < n) {
            if (haystack[i] == needle[j]) {
                i++; j++;
                if (j == m) return i - m;      // full match
            } else if (j > 0) {
                j = lps[j - 1];                // slide pattern, i stays put
            } else {
                i++;
            }
        }
        return -1;
    }
};
```

### Python
```python
from typing import List


class Solution:
    def build_lps(self, p: str) -> List[int]:
        """lps[i] = longest proper prefix of p[:i+1] that is also its suffix."""
        m = len(p)
        lps = [0] * m
        length, i = 0, 1
        while i < m:
            if p[i] == p[length]:
                length += 1
                lps[i] = length            # match extends
                i += 1
            elif length > 0:
                length = lps[length - 1]   # fall back, keep i fixed
            else:
                lps[i] = 0                 # nothing to salvage
                i += 1
        return lps

    def strStr(self, haystack: str, needle: str) -> int:
        n, m = len(haystack), len(needle)
        if m == 0:
            return 0
        if m > n:
            return -1

        lps = self.build_lps(needle)
        i = j = 0                          # i over text, j over pattern
        while i < n:
            if haystack[i] == needle[j]:
                i += 1
                j += 1
                if j == m:
                    return i - m           # full match
            elif j > 0:
                j = lps[j - 1]             # slide pattern, i stays put
            else:
                i += 1
        return -1
```

## Key Takeaways
- `lps[i]` answers "if I fail after matching `i+1` characters, how much of that match is still usable?" — falling back to the *longest* prefix-suffix is what makes the shift safe.
- The text pointer `i` never moves backwards; that single property is the whole O(n + m) guarantee.
- Building LPS uses the array on itself (`len = lps[len - 1]`), which is the same fallback logic applied to the pattern against itself.
- To find *all* occurrences instead of the first, replace `return i - m` with recording `i - m` and continuing from `j = lps[j - 1]`.
