# Insertion Sorting

**Difficulty:** Easy  ·  **Topic:** Learn Important Sorting Techniques › Sorting-I

## Problem
Given an array of `n` integers, sort it in non-decreasing order using insertion sort. The array is sorted in place and returned.

Input: `arr = [14, 9, 15, 12, 6, 8, 13]`
Output: `[6, 8, 9, 12, 13, 14, 15]`

## Approach 1: Insertion Sort
Think of how you sort playing cards in your hand: you keep the cards on the left sorted and insert each new card into its correct spot.

1. Treat `arr[0]` as a sorted region of size one.
2. For each `i` from `1` to `n-1`, take `key = arr[i]`.
3. Walk leftwards from `i-1`, shifting every element greater than `key` one step to the right.
4. Drop `key` into the hole that opens up.

After processing index `i`, the prefix `arr[0..i]` is sorted. Because we shift only strictly greater elements, equal keys keep their original relative order, so the algorithm is stable. On already-sorted input the inner loop never runs, giving a linear best case. It is also the algorithm of choice for very small or nearly sorted arrays, which is why library sorts often switch to it for tiny partitions.

- **Time:** O(n) best case (sorted input), O(n²) average and worst case (reverse sorted input).
- **Space:** O(1).

## Code (Optimal)

### C++
```cpp
#include <vector>
using namespace std;

class Solution {
public:
    vector<int> insertionSort(vector<int>& arr) {
        int n = arr.size();
        for (int i = 1; i < n; i++) {
            int key = arr[i];
            int j = i - 1;
            while (j >= 0 && arr[j] > key) {
                arr[j + 1] = arr[j];
                j--;
            }
            arr[j + 1] = key;
        }
        return arr;
    }
};
```

### Python
```python
class Solution:
    def insertionSort(self, arr: list[int]) -> list[int]:
        for i in range(1, len(arr)):
            key = arr[i]
            j = i - 1
            while j >= 0 and arr[j] > key:
                arr[j + 1] = arr[j]
                j -= 1
            arr[j + 1] = key
        return arr
```

## Key Takeaways
- Invariant: after step `i`, the prefix `arr[0..i]` is sorted; the rest is untouched.
- Shift, don't swap: shifting elements right and writing `key` once is cheaper than repeated swaps.
- Stable, in place, adaptive (fast on nearly sorted data) — the best of the simple O(n²) sorts in practice.
- Pitfall: the `j >= 0` check must come before `arr[j] > key` to avoid an out-of-bounds read.
