# Two Sum In BST | Check if there exists a pair with Sum K

**Difficulty:** Hard  ·  **Topic:** Binary Search Trees [Concept and Problems] › Practice Problems

## Problem
Given the root of a BST and an integer `k`, return `true` if there exist **two different nodes** whose values add up to `k`, and `false` otherwise.

```
Input:  root = [5, 3, 6, 2, 4, null, 7], k = 9
Output: true      (2 + 7 = 9)

Input:  root = [5, 3, 6, 2, 4, null, 7], k = 28
Output: false     (the two largest values are 6 and 7)
```

## Approach 1: Brute Force (search for the complement of every node)
For each node with value `v`, search the tree for `k - v`. If it is found and is a *different* node, return true.

The "different node" check matters: if `k = 2*v`, finding `v` again might just be the same node, so you must confirm a second occurrence (or, with distinct values, reject the self-match).
- **Time:** O(N·H)
- **Space:** O(H)

## Approach 2: Better (hash set over any traversal)
This is the classic Two Sum trick applied to a tree. Traverse in any order; for each value `v`, check whether `k - v` is already in a hash set of previously seen values. If yes, a valid pair exists. Otherwise insert `v` and continue.

Correctness is easy: for any valid pair, one of the two nodes is visited second, and at that moment its partner is already in the set. The self-pairing problem disappears because we check the set *before* inserting the current value.
- **Time:** O(N)
- **Space:** O(N) for the set

## Approach 3: Optimal (two BST iterators — two pointers on a tree)
On a **sorted array** the optimal Two Sum is the two-pointer scan: put `i` at the front, `j` at the back, and compare `a[i] + a[j]` against `k` — if the sum is too small, only moving `i` right can help; if too large, only moving `j` left can help. Each step eliminates one element, so the scan is linear with O(1) space.

A BST's inorder traversal *is* that sorted array — we just cannot index into it. The fix is to build two **stack-based iterators** that generate the sequence lazily from both ends:

- A **forward** iterator does the normal inorder (push the left spine; `next()` pops and then pushes the popped node's right spine). It yields values in ascending order — that is the left pointer.
- A **reverse** iterator mirrors it (push the right spine; `next()` pops and then pushes the popped node's left spine). It yields values in descending order — that is the right pointer.

Then run the two-pointer loop on `left = forward.next()` and `right = reverse.next()`:
1. If `left >= right`, the pointers have met or crossed — every pair has been considered, return false.
2. If `left + right == k`, return true.
3. If `left + right < k`, we need a bigger sum → advance the forward iterator.
4. If `left + right > k`, we need a smaller sum → advance the reverse iterator.

The `left >= right` guard is what prevents pairing a node with itself, which is exactly the pitfall from Approach 1.

**Dry run** on `[5, 3, 6, 2, 4, null, 7]` with `k = 9`. Sorted values are `2, 3, 4, 5, 6, 7`.
- forward → `2`, reverse → `7`. Sum `9` = k → **true**, on the very first comparison. ✔

**Dry run** with `k = 8`:
- `2 + 7 = 9 > 8` → advance reverse → `6`.
- `2 + 6 = 8` → true (nodes 2 and 6). ✔

**Dry run** with `k = 28`:
- `2 + 7 = 9 < 28` → advance forward → 3, 4, 5, 6 in turn, sums 10, 11, 12, 13, all `< 28`.
- After forward yields `6` and reverse still holds `7`, the next forward step gives `7`, so `left >= right` → **false**. ✔

Each iterator pushes and pops each node at most once, so the loop is O(N) overall, and the two stacks together hold at most O(H) nodes. That is a genuine space win over the hash set for tall-but-balanced trees: O(H) = O(log N) versus O(N).
- **Time:** O(N)
- **Space:** O(H)

## Code (Optimal)

### C++
```cpp
// struct TreeNode { int val; TreeNode *left, *right; TreeNode(int x) ... } — standard definition
#include <stack>
using namespace std;

class BSTIterator {
    stack<TreeNode*> st;
    bool reverse;                       // false = ascending inorder, true = descending
    void pushAll(TreeNode* node) {
        while (node) {
            st.push(node);
            node = reverse ? node->right : node->left;
        }
    }
public:
    BSTIterator(TreeNode* root, bool rev) : reverse(rev) { pushAll(root); }
    bool hasNext() const { return !st.empty(); }
    int next() {
        TreeNode* node = st.top(); st.pop();
        pushAll(reverse ? node->left : node->right);
        return node->val;
    }
};

class Solution {
public:
    bool findTarget(TreeNode* root, int k) {
        if (root == nullptr) return false;
        BSTIterator lo(root, false), hi(root, true);

        int left = lo.next(), right = hi.next();
        while (left < right) {
            long long sum = (long long)left + right;
            if (sum == k) return true;
            if (sum < k) left  = lo.next();   // need a larger value on the left
            else         right = hi.next();   // need a smaller value on the right
        }
        return false;
    }
};
```

### Java
```java
// class TreeNode { int val; TreeNode left, right; TreeNode(int x) ... } — standard definition
import java.util.*;

class BSTIterator {
    private final Deque<TreeNode> st = new ArrayDeque<>();
    private final boolean reverse;

    BSTIterator(TreeNode root, boolean reverse) {
        this.reverse = reverse;
        pushAll(root);
    }

    private void pushAll(TreeNode node) {
        while (node != null) {
            st.push(node);
            node = reverse ? node.right : node.left;
        }
    }

    boolean hasNext() { return !st.isEmpty(); }

    int next() {
        TreeNode node = st.pop();
        pushAll(reverse ? node.left : node.right);
        return node.val;
    }
}

class Solution {
    public boolean findTarget(TreeNode root, int k) {
        if (root == null) return false;
        BSTIterator lo = new BSTIterator(root, false);
        BSTIterator hi = new BSTIterator(root, true);

        int left = lo.next(), right = hi.next();
        while (left < right) {
            long sum = (long) left + right;
            if (sum == k) return true;
            if (sum < k) left = lo.next();
            else         right = hi.next();
        }
        return false;
    }
}
```

### Python
```python
# class TreeNode: val, left, right — standard definition

class BSTIterator:
    def __init__(self, root, reverse):
        self.st = []
        self.reverse = reverse
        self._push_all(root)

    def _push_all(self, node):
        while node:
            self.st.append(node)
            node = node.right if self.reverse else node.left

    def has_next(self):
        return len(self.st) > 0

    def next(self):
        node = self.st.pop()
        self._push_all(node.left if self.reverse else node.right)
        return node.val


class Solution:
    def findTarget(self, root, k):
        if root is None:
            return False
        lo = BSTIterator(root, False)   # ascending
        hi = BSTIterator(root, True)    # descending

        left, right = lo.next(), hi.next()
        while left < right:             # left < right also rules out using one node twice
            total = left + right
            if total == k:
                return True
            if total < k:
                left = lo.next()
            else:
                right = hi.next()
        return False
```

## Key Takeaways
- A BST is a sorted sequence in disguise, so the sorted-array two-pointer technique applies directly — you just need iterators instead of indices.
- One forward inorder iterator and one reverse inorder iterator give you the two ends of the sorted order lazily, in O(H) space.
- The `left < right` loop condition is doing double duty: it terminates the scan and forbids pairing a node with itself.
- The hash-set solution is simpler and also O(N) time, but costs O(N) space; prefer it when clarity matters and the iterator version when space does.
