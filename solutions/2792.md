# Morris Inorder Traversal of a Binary Tree

**Difficulty:** Hard  ·  **Topic:** Binary Trees [Traversals, Medium and Hard Problems] › Hard Problems

## Problem
Return the inorder traversal (left, root, right) of a binary tree using O(1) auxiliary space, without recursion or an explicit stack. The Morris method does this by creating temporary links from a subtree's rightmost node back to its ancestor and cleaning them up afterwards.

Input: root = [1, null, 2, 3]
Output: [1, 3, 2]

Input: root = [4, 2, 6, 1, 3, 5, 7]
Output: [1, 2, 3, 4, 5, 6, 7]

## Approach 1: Recursion or explicit stack
Standard inorder: recurse left, visit, recurse right; or iterate with a stack that pushes the entire left spine, pops, records, and moves right. Linear time, but O(H) space.
- **Time:** O(N)
- **Space:** O(H)

## Approach 2: Optimal (Morris traversal)
Maintain a `cur` pointer starting at the root:
1. If `cur.left` is null, there is nothing before `cur` in this subtree: record `cur` and move right.
2. Otherwise find `pred`, the rightmost node in `cur`'s left subtree (stopping if we hit a thread that already points to `cur`).
   - If `pred.right` is null: set `pred.right = cur` (the thread) and go left. Do **not** record yet.
   - If `pred.right == cur`: the left subtree is fully visited. Remove the thread, record `cur`, and go right.

The thread guarantees that after finishing the left subtree we land back on `cur` without any saved state. Each edge is traversed a bounded number of times, so the work is linear.
- **Time:** O(N)
- **Space:** O(1)

## Code (Optimal)

### C++
```cpp
// struct TreeNode { int val; TreeNode *left; TreeNode *right; ... } — standard definition
#include <vector>
using namespace std;

class Solution {
public:
    vector<int> inorderTraversal(TreeNode* root) {
        vector<int> out;
        TreeNode* cur = root;
        while (cur) {
            if (!cur->left) {
                out.push_back(cur->val);
                cur = cur->right;
            } else {
                TreeNode* pred = cur->left;
                while (pred->right && pred->right != cur) pred = pred->right;
                if (!pred->right) {
                    pred->right = cur;      // create thread
                    cur = cur->left;
                } else {
                    pred->right = nullptr;  // remove thread
                    out.push_back(cur->val);
                    cur = cur->right;
                }
            }
        }
        return out;
    }
};
```

    public List<Integer> inorderTraversal(TreeNode root) {
        List<Integer> out = new ArrayList<>();
        TreeNode cur = root;

            if (cur.left == null) {
                out.add(cur.val);
                cur = cur.right;

                TreeNode pred = cur.left;
                while (pred.right != null && pred.right != cur) pred = pred.right;

                    pred.right = cur;       // create thread
                    cur = cur.left;
                } else {
                    pred.right = null;      // remove thread
                    out.add(cur.val);
                    cur = cur.right;
                }
            }
        }
        return out;
    }
}

                out.append(cur.val)

                    pred = pred.right

## Key Takeaways
- The inorder predecessor's right pointer is always free (it is the rightmost node of the left subtree), which is what makes threading possible.
- Record a node when its thread is removed (second visit) for inorder; record on the first visit for preorder.
- The predecessor loop must stop at `pred.right == cur`, otherwise it follows the thread forever.
- Restoring every thread means the caller's tree is unchanged when the function returns.
