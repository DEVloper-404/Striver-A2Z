# Longest subarray with given sum K(positives)

**Difficulty:** Medium  ·  **Topic:** Solve Problems on Arrays [Easy -> Medium -> Hard] › Easy

## Problem
Given an array of `n` non-negative integers and a target `k`, return the length of the longest contiguous subarray whose elements sum to exactly `k`. If no such subarray exists, return `0`.

Input: `arr = [1, 2, 3, 1, 1, 1, 1, 4, 2, 3], k = 3`
Output: `3` (the subarray `[1, 1, 1]`)

## Approach 1: Try Every Subarray
For every start index `i`, extend an end index `j` and keep a running sum. Whenever the sum equals `k`, record `j - i + 1` as a candidate. Because all values are non-negative, the running sum never decreases, so you can break out of the inner loop as soon as it exceeds `k`.

- **Time:** O(n²)
- **Space:** O(1)

## Approach 2: Prefix Sum with Hash Map
Let `pref[j]` be the sum of `arr[0..j]`. A subarray `(i, j]` sums to `k` exactly when `pref[j] - pref[i] = k`, i.e. `pref[i] = pref[j] - k`. Walk the array, keep a hash map from each prefix sum to the **first** index where it occurred, and for each `j` look up `pref[j] - k`. Storing only the first occurrence maximises the length. This approach also works when the array contains negatives (it is the general solution for the next problem).

- **Time:** O(n) average (hash map)
- **Space:** O(n)

## Approach 3: Sliding Window (Optimal for non-negatives)
When every element is `>= 0`, growing a window can only increase its sum and shrinking it from the left can only decrease it. That monotonic behaviour lets us use two pointers:

1. Keep a window `[left, right]` with sum `sum`.
2. Move `right` forward one step, adding `arr[right]`.
3. While `sum > k` and `left <= right`, subtract `arr[left]` and advance `left`.
4. If `sum == k`, update the answer with `right - left + 1`.

Every element enters and leaves the window at most once, so the total work is linear with no extra memory. With negative numbers this breaks because shrinking the window might raise the sum; that case needs the prefix-sum map.

- **Time:** O(n) — amortised over both pointers.
- **Space:** O(1)

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int longestSubarray(vector<int>& arr, long long k) {
        int n = arr.size();
        int left = 0, best = 0;
        long long sum = 0;
        for (int right = 0; right < n; right++) {
            sum += arr[right];
            while (sum > k && left <= right) {
                sum -= arr[left];
                left++;
            }
            if (sum == k) best = max(best, right - left + 1);
        }
        return best;
    }
};
```

class Solution:
    def longestSubarray(self, arr: list[int], k: int) -> int:
        left = 0
        total = 0
        best = 0
        for right in range(len(arr)):
            total += arr[right]
            while total > k and left <= right:
                total -= arr[left]
                left += 1
            if total == k:
                best = max(best, right - left + 1)
        return best

## Key Takeaways
- Sliding window works only because all elements are non-negative: the window sum is monotone in both directions.
- Shrink from the left while the sum is too big, then check for equality — the order matters.
- With zeros in the array, a window can stay at sum `k` while growing, which is why the check happens after every step.
- For arrays with negatives, switch to the prefix-sum hash map (see "Longest subarray with sum K").
