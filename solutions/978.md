# Longest happy prefix

**Difficulty:** Hard  ·  **Topic:** Strings › Hard Problems

## Problem
A **happy prefix** of a string `s` is a non-empty prefix that is also a suffix of `s`, but is not the entire string (a *proper* prefix). Given `s`, return its longest happy prefix, or the empty string `""` if none exists.

```
Input:  s = "ababab"
Output: "abab"     ("abab" is both a prefix and a suffix; "ababab" itself doesn't count)
```

```
Input:  s = "abcd"
Output: ""         (no proper prefix equals a suffix)
```

## Approach 1: Brute Force — try every length
For each candidate length `k` from `n - 1` down to `1`, compare `s[0..k-1]` with `s[n-k..n-1]` and return the first `k` that matches.

Correct, and worth writing once to fix the definition in your head. But each comparison costs up to O(n), and there are up to `n - 1` candidates, so the total is O(n²). On the pathological input `"aaaa…a"` you do the full quadratic work while the answer is simply the first `n - 1` characters.

- **Time:** O(n²)
- **Space:** O(1)

## Approach 2: Better — string hashing
Precompute a polynomial prefix hash of `s`. Then `hash(0, k-1)` and `hash(n-k, n-1)` are each O(1), so scanning `k` from `n-1` down to `1` costs O(n) overall.

This is fast and short, but it is *probabilistic*: two different strings can share a hash. To be safe you would verify the winning candidate with a real character comparison, which costs another O(n). It works, yet the next approach gets the same bound deterministically and with less machinery.

- **Time:** O(n)
- **Space:** O(n)

## Approach 3: Optimal — this problem *is* the LPS array

### The key observation
Read the definition of a happy prefix again: "longest proper prefix that is also a suffix". That is verbatim the definition of `lps[n-1]` in the KMP preprocessing array. So the entire problem collapses to: build the LPS array of `s` and return `s.substr(0, lps[n-1])`.

Recall `lps[i]` = the length of the longest proper prefix of `s[0..i]` that is also a suffix of `s[0..i]`. Taking `i = n - 1` makes the substring the whole string, so `lps[n-1]` is exactly the length we want. If it is 0, no happy prefix exists and we return `""`.

### How the LPS array is built in O(n)
Two pointers: `len` = the length of the prefix-suffix match currently being extended, and `i` = the position being filled. `lps[0] = 0` always, since a single character has no proper prefix.

For each `i` from 1:
- **`s[i] == s[len]`** — the existing match of length `len` extends by one character. Set `len++`, `lps[i] = len`, advance `i`.
- **Mismatch with `len > 0`** — do **not** advance `i`. The match of length `len` cannot continue, but a *shorter* prefix-suffix of the already-matched region might. The longest such shorter candidate has length `lps[len - 1]`, so set `len = lps[len - 1]` and retry the same `i`. This self-referential fallback is the clever part: it reuses answers already computed for earlier positions instead of rescanning.
- **Mismatch with `len == 0`** — nothing to fall back to, so `lps[i] = 0` and advance `i`.

**Why it is linear:** `len` grows by at most 1 per increment of `i`, so it increases at most `n` times overall; each fallback strictly decreases `len`, so there can be at most `n` fallbacks in total. Both loops together are O(n).

### Dry run on `s = "ababab"` (n = 6)
| i | `s[i]` | `len` before | comparison | action | `lps[i]` |
|---|--------|--------------|------------|--------|----------|
| 1 | `b` | 0 | `s[1]='b'` vs `s[0]='a'` ✗, `len=0` | write 0, `i++` | 0 |
| 2 | `a` | 0 | `s[2]='a'` vs `s[0]='a'` ✓ | `len=1` | 1 |
| 3 | `b` | 1 | `s[3]='b'` vs `s[1]='b'` ✓ | `len=2` | 2 |
| 4 | `a` | 2 | `s[4]='a'` vs `s[2]='a'` ✓ | `len=3` | 3 |
| 5 | `b` | 3 | `s[5]='b'` vs `s[3]='b'` ✓ | `len=4` | 4 |

`lps = [0,0,1,2,3,4]`, so `lps[5] = 4` and the answer is `s.substr(0, 4) = "abab"`. Checking by hand: `"abab"` is indeed the first four and last four characters of `"ababab"`. ✓

For `"abcd"` every comparison fails at `len = 0`, giving `lps = [0,0,0,0]` and the answer `""`.

A case where the fallback fires: `s = "aabaaab"`. At `i = 5` we have `len = 2` (from `"aa"`), and `s[5]='a'` vs `s[2]='b'` mismatches, so `len` drops to `lps[1] = 1`, then `s[5]='a'` vs `s[1]='a'` matches, giving `lps[5] = 2`. Without the fallback we would have lost the still-valid `"a"` overlap.

- **Time:** O(n)
- **Space:** O(n) for the LPS array

## Code (Optimal)

### C++
```cpp
#include <string>
#include <vector>
using namespace std;

class Solution {
public:
    string longestPrefix(const string& s) {
        int n = (int)s.size();
        if (n < 2) return "";

        vector<int> lps(n, 0);   // lps[i]: longest proper prefix of s[0..i] that is a suffix
        int len = 0, i = 1;
        while (i < n) {
            if (s[i] == s[len]) {
                lps[i++] = ++len;          // extend the current match
            } else if (len > 0) {
                len = lps[len - 1];        // fall back to a shorter prefix-suffix
            } else {
                lps[i++] = 0;              // no overlap possible here
            }
        }
        return s.substr(0, lps[n - 1]);
    }
};
```

```java
class Solution {
    public String longestPrefix(String s) {
        int n = s.length();
        if (n < 2) return "";

        int[] lps = new int[n];   // lps[i]: longest proper prefix of s[0..i] that is a suffix
        int len = 0, i = 1;
        while (i < n) {
            if (s.charAt(i) == s.charAt(len)) {
                lps[i++] = ++len;          // extend the current match
            } else if (len > 0) {
                len = lps[len - 1];        // fall back to a shorter prefix-suffix
            } else {
                lps[i++] = 0;              // no overlap possible here
            }
        }
        return s.substring(0, lps[n - 1]);
    }
}
```

### Python
```python
class Solution:
    def longestPrefix(self, s: str) -> str:
        n = len(s)
        if n < 2:
            return ""

        lps = [0] * n          # lps[i]: longest proper prefix of s[:i+1] that is a suffix
        length, i = 0, 1
        while i < n:
            if s[i] == s[length]:
                length += 1
                lps[i] = length         # extend the current match
                i += 1
            elif length > 0:
                length = lps[length - 1]   # fall back to a shorter prefix-suffix
            else:
                lps[i] = 0                 # no overlap possible here
                i += 1

        return s[:lps[n - 1]]
```

## Key Takeaways
- Recognising that "longest proper prefix that is also a suffix" *is* the LPS definition turns a Hard-tagged problem into a single array build plus one substring.
- The fallback `len = lps[len - 1]` is the heart of KMP preprocessing — it reuses already-computed overlaps instead of rescanning, and is why the build is O(n) rather than O(n²).
- Never advance `i` on a mismatch when `len > 0`; that off-by-one is the most common bug in LPS code.
- Edge cases: `n < 2` and `lps[n-1] == 0` both yield `""`. Overlapping prefix and suffix are allowed (`"aaa"` → `"aa"`), which is why hashing/brute force must compare, not merely count.
