# Palindrome partitioning II

**Difficulty:** Hard  ·  **Topic:** Dynamic Programming [Patterns and Problems] › MCM DP | Partition DP

## Problem
Given a string `s`, partition it so that every resulting piece is a palindrome. Return the **minimum number of cuts** needed. A string of length `n` split into `k` palindromic pieces uses `k - 1` cuts, and the answer is `0` when `s` is already a palindrome.

```
Input:  s = "aab"
Output: 1
```
Cutting once after `"aa"` gives `["aa", "b"]`, both palindromes. No zero-cut split exists because `"aab"` itself is not a palindrome.

## Approach 1: Front partition recursion (Brute Force)

Unlike MCM, this is a **front partition**: we stand at the left end of the remaining suffix and decide where the *first* piece ends. Whatever that choice is, the rest of the string is a fresh, independent instance of the same problem.

Let `f(i)` = minimum number of **pieces** the suffix `s[i..n-1]` can be split into (counting pieces is easier than counting cuts; we subtract 1 at the very end).

```
f(n) = 0
f(i) = min over j in [i, n-1] such that s[i..j] is a palindrome of ( 1 + f(j+1) )
```

Why pieces and not cuts? If we tried to count cuts directly, the last piece would need a special case (it costs no trailing cut). Counting pieces makes every branch uniform: pay 1 for the piece you just cut off, then recurse. Answer = `f(0) - 1`.

Without memoization every index branches up to `n` ways, giving exponential blow-up.

- **Time:** O(2^n · n) including palindrome checks
- **Space:** O(n) recursion stack

## Approach 2: Memoization / tabulation on `i` (Better)

`f(i)` depends only on `i`, so cache it in a 1-D array of size `n + 1`. Now there are `n` states, each doing an O(n) loop, but each palindrome check inside costs O(n) — total O(n^3).

- **Time:** O(n^3)
- **Space:** O(n)

## Approach 3: Precompute palindromes, then 1-D DP (Optimal)

The O(n) palindrome check is pure waste, because the same substrings are re-tested constantly. Precompute a table `isPal[i][j]` in O(n^2) using the recurrence:

```
isPal[i][j] = (s[i] == s[j]) AND (j - i < 2 OR isPal[i+1][j-1])
```

Fill it by iterating `i` from `n-1` down to `0` and `j` from `i` up to `n-1`, so `isPal[i+1][j-1]` is always already computed. The `j - i < 2` clause covers single characters and adjacent pairs, which have no inner substring.

Then the DP loop becomes O(1) per candidate cut:

1. Set `dp[n] = 0`.
2. For `i` from `n-1` down to `0`: set `dp[i] = INF`; for each `j` in `[i, n-1]` with `isPal[i][j]` true, take `dp[i] = min(dp[i], 1 + dp[j+1])`.
3. Return `dp[0] - 1`.

`dp[i]` is never infinite in practice, because `j = i` always works (a single character is a palindrome), so a valid split always exists.

**Dry run on `s = "aab"`.**

Palindrome table: `isPal[0][0]=T` (`"a"`), `isPal[1][1]=T` (`"a"`), `isPal[2][2]=T` (`"b"`), `isPal[0][1]=T` (`"aa"`, chars equal and gap < 2), `isPal[1][2]=F` (`'a' != 'b'`), `isPal[0][2]=F` (`'a' != 'b'`).

DP, right to left, with `dp[3] = 0`:
- `dp[2]`: only `j=2` is a palindrome → `1 + dp[3] = 1`. So `dp[2] = 1`.
- `dp[1]`: `j=1` (`"a"`) → `1 + dp[2] = 2`; `j=2` (`"ab"`) rejected. So `dp[1] = 2`.
- `dp[0]`: `j=0` (`"a"`) → `1 + dp[1] = 3`; `j=1` (`"aa"`) → `1 + dp[2] = 2`; `j=2` (`"aab"`) rejected. So `dp[0] = 2`.

Minimum pieces = 2, so minimum cuts = `2 - 1 = 1`. The winning `j = 1` corresponds to the piece `"aa"` followed by the optimal split of `"b"`.

- **Time:** O(n^2)
- **Space:** O(n^2) for the palindrome table, O(n) for the DP array

## Code (Optimal)

### C++
```cpp
#include <string>
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int minCut(string s) {
        int n = s.size();
        if (n <= 1) return 0;

        // isPal[i][j] = true iff s[i..j] is a palindrome
        vector<vector<bool>> isPal(n, vector<bool>(n, false));
        for (int i = n - 1; i >= 0; i--) {
            for (int j = i; j < n; j++) {
                if (s[i] == s[j] && (j - i < 2 || isPal[i + 1][j - 1]))
                    isPal[i][j] = true;
            }
        }

        // dp[i] = minimum number of palindromic pieces covering s[i..n-1]
        vector<int> dp(n + 1, 0);
        for (int i = n - 1; i >= 0; i--) {
            int best = n;                       // at most n pieces
            for (int j = i; j < n; j++) {
                if (isPal[i][j]) best = min(best, 1 + dp[j + 1]);
            }
            dp[i] = best;
        }
        return dp[0] - 1;                       // pieces -> cuts
    }
};
```

### Java
```java
class Solution {
    public int minCut(String s) {
        int n = s.length();
        if (n <= 1) return 0;

        boolean[][] isPal = new boolean[n][n];
        for (int i = n - 1; i >= 0; i--) {
            for (int j = i; j < n; j++) {
                if (s.charAt(i) == s.charAt(j)
                        && (j - i < 2 || isPal[i + 1][j - 1])) {
                    isPal[i][j] = true;
                }
            }
        }

        int[] dp = new int[n + 1];              // dp[n] = 0
        for (int i = n - 1; i >= 0; i--) {
            int best = n;
            for (int j = i; j < n; j++) {
                if (isPal[i][j]) best = Math.min(best, 1 + dp[j + 1]);
            }
            dp[i] = best;
        }
        return dp[0] - 1;
    }
}
```

### Python
```python
class Solution:
    def minCut(self, s: str) -> int:
        n = len(s)
        if n <= 1:
            return 0

        is_pal = [[False] * n for _ in range(n)]
        for i in range(n - 1, -1, -1):
            for j in range(i, n):
                if s[i] == s[j] and (j - i < 2 or is_pal[i + 1][j - 1]):
                    is_pal[i][j] = True

        dp = [0] * (n + 1)                      # dp[n] = 0
        for i in range(n - 1, -1, -1):
            best = n
            for j in range(i, n):
                if is_pal[i][j]:
                    best = min(best, 1 + dp[j + 1])
            dp[i] = best

        return dp[0] - 1
```

## Key Takeaways
- Front partition DP: fix where the **first** piece ends, then recurse on the remaining suffix — a 1-D state `i` is enough, unlike MCM's 2-D interval.
- Count pieces during the DP and subtract 1 at the end; counting cuts directly forces an ugly special case for the last piece.
- Precomputing `isPal[i][j]` drops the complexity from O(n^3) to O(n^2) — the palindrome check is the real bottleneck, not the partition loop.
- Edge cases: empty or single-character string → 0 cuts; an already-palindromic string yields `dp[0] = 1` and therefore 0 cuts.
