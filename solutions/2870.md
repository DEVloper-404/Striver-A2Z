# Graph Representation | C++

**Difficulty:** Easy  ·  **Topic:** Graphs [Concepts & Problems] › Learning

## Problem
This item covers how to actually store a graph in C++: reading the standard input format, building an adjacency matrix or an adjacency list with STL containers, handling directed vs undirected and weighted vs unweighted edges, and knowing which representation to pick under given constraints.

Standard input format: first line `n m` (nodes numbered `1..n`, and `m` edges), then `m` lines of `u v`.

```
Input:
4 4
1 2
1 3
2 4
3 4

Adjacency list built:
1 -> 2 3
2 -> 1 4
3 -> 1 4
4 -> 2 3
```

## Approach: choosing and building the representation in C++

**Adjacency matrix.** A 2-D array where `adj[u][v]` records whether an edge exists (or its weight). In C++ this is `vector<vector<int>>` sized `(n+1) x (n+1)` so that 1-indexed node numbers work naturally.

```cpp
vector<vector<int>> adj(n + 1, vector<int>(n + 1, 0));
for (int i = 0; i < m; i++) {
    int u, v; cin >> u >> v;
    adj[u][v] = 1;
    adj[v][u] = 1;              // undirected: mark both directions
}
```
Edge lookup `adj[u][v]` is O(1). The killer is memory: `n = 10^5` needs 10^10 integers. As a rough rule, a matrix is only viable for `n` up to a few thousand.

**Adjacency list.** A vector of vectors where `adj[u]` holds the neighbours of `u`. This is the representation you should reach for by default.

```cpp
vector<vector<int>> adj(n + 1);
for (int i = 0; i < m; i++) {
    int u, v; cin >> u >> v;
    adj[u].push_back(v);
    adj[v].push_back(u);        // remove this line for a directed graph
}
```
Why it wins: memory is O(N + 2M), and iterating over `adj[u]` costs `degree(u)` rather than `n`. A BFS or DFS over the whole graph therefore runs in O(N + M) instead of O(N²).

**Directed graphs.** Push only `adj[u].push_back(v)`. Everything else is identical. If you also need reverse edges (for example to compute indegrees or to run Kosaraju's algorithm) build a second list `radj` in the same loop.

**Weighted graphs.** Store pairs. `vector<vector<pair<int,int>>> adj(n+1)` where each entry is `{neighbour, weight}`:

```cpp
vector<vector<pair<int,int>>> adj(n + 1);
int u, v, w; cin >> u >> v >> w;
adj[u].push_back({v, w});
adj[v].push_back({u, w});       // undirected
```
Dijkstra and Prim consume exactly this shape.

**Iterating neighbours.** The range-for loop is the clean idiom, and structured bindings make weighted lists readable:

```cpp
for (int v : adj[u]) { /* unweighted */ }
for (auto [v, w] : adj[u]) { /* weighted, C++17 */ }
```

**Practical notes.**
- Sizing containers as `n + 1` and leaving index 0 unused is the least error-prone convention for 1-indexed input. Use `n` if the problem is 0-indexed.
- Add `ios::sync_with_stdio(false); cin.tie(nullptr);` — with `m` up to 10^5 or more, unbuffered `cin` alone can cost you the time limit.
- `vector<vector<int>>` is preferred over raw arrays or `list<int>`: contiguous inner storage means the traversal is cache-friendly.
- If the input can contain self-loops (`u == v`) or repeated edges, the adjacency list stores them faithfully; decide per problem whether to filter them out.

- **Time:** O(N + M) to read and build a list; O(N² + M) to allocate and fill a matrix
- **Space:** O(N + 2M) for an undirected adjacency list; O(N²) for a matrix

## Code (Optimal)

### C++
```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m;
    cin >> n >> m;                        // nodes 1..n, m edges

    vector<vector<int>> adj(n + 1);       // adjacency list
    for (int i = 0; i < m; i++) {
        int u, v;
        cin >> u >> v;
        adj[u].push_back(v);
        adj[v].push_back(u);              // delete for a directed graph
    }

    for (int u = 1; u <= n; u++) {
        cout << u << " ->";
        for (int v : adj[u]) cout << ' ' << v;
        cout << '\n';
    }
    return 0;
}
```

### Java
```java
// The same adjacency list, written with Java collections.
import java.util.*;

public class Main {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        int n = sc.nextInt(), m = sc.nextInt();

        List<List<Integer>> adj = new ArrayList<>();
        for (int i = 0; i <= n; i++) adj.add(new ArrayList<>());

        for (int i = 0; i < m; i++) {
            int u = sc.nextInt(), v = sc.nextInt();
            adj.get(u).add(v);
            adj.get(v).add(u);
        }

        for (int u = 1; u <= n; u++) System.out.println(u + " -> " + adj.get(u));
        sc.close();
    }
}
```

### Python
```python
# The same adjacency list, written with Python lists.
import sys

def main():
    data = sys.stdin.read().split()
    n, m = int(data[0]), int(data[1])
    idx = 2

    adj = [[] for _ in range(n + 1)]
    for _ in range(m):
        u, v = int(data[idx]), int(data[idx + 1])
        idx += 2
        adj[u].append(v)
        adj[v].append(u)

    for u in range(1, n + 1):
        print(u, "->", " ".join(map(str, adj[u])))

if __name__ == "__main__":
    main()
```

## Key Takeaways
- Default to `vector<vector<int>> adj(n + 1)`: O(N + 2M) memory and neighbour iteration proportional to degree.
- Use an adjacency matrix only for small dense graphs where O(1) edge existence checks genuinely matter — O(N²) memory rules it out beyond a few thousand nodes.
- Undirected means two `push_back` calls per edge; directed means one. Weighted means storing `pair<int,int>` instead of `int`.
- Turn on fast I/O with `ios::sync_with_stdio(false)` — graph inputs are large by nature.
