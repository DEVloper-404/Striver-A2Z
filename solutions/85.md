# First and last occurrence

**Difficulty:** Easy  ·  **Topic:** Binary Search [1D, 2D Arrays, Search Space] › BS on 1D Arrays

## Problem
Given a non-decreasing array `nums` and a `target`, return the index of the first occurrence and the index of the last occurrence of `target` as a pair. If `target` is not present, return `[-1, -1]`. The solution must run in O(log n).

Input: `nums = [5, 7, 7, 8, 8, 10], target = 8`
Output: `[3, 4]`

Input: `nums = [5, 7, 7, 8, 8, 10], target = 6`
Output: `[-1, -1]`

## Approach 1: Linear Scan
Walk the array once. The first time you see `target`, record its index as `first`; every time you see it, update `last`. Return `[first, last]`, or `[-1, -1]` if never seen.

- **Time:** O(n)
- **Space:** O(1)

## Approach 2: Lower Bound + Upper Bound
- `first = lowerBound(target)` (first index with value `>= target`).
- If `first == n` or `nums[first] != target`, the target is absent: return `[-1, -1]`.
- `last = upperBound(target) - 1` (one before the first index with value `> target`).

This reuses two generic helpers and is very hard to get wrong.

- **Time:** O(log n)
- **Space:** O(1)

## Approach 3: Two Targeted Binary Searches (Optimal)
Write one binary search that hunts for the first occurrence and one for the last:

- **First occurrence:** when `nums[mid] == target`, store `mid` and keep searching to the left (`high = mid - 1`) in case an earlier copy exists. When `nums[mid] < target` go right, otherwise go left.
- **Last occurrence:** when `nums[mid] == target`, store `mid` and keep searching to the right (`low = mid + 1`). Other cases move exactly as in ordinary binary search.

If the first search returns `-1`, skip the second one.

- **Time:** O(log n)
- **Space:** O(1)

## Code (Optimal)

### C++
```cpp
#include <vector>
using namespace std;

class Solution {
    int firstOcc(vector<int>& nums, int target) {
        int low = 0, high = (int)nums.size() - 1, ans = -1;
        while (low <= high) {
            int mid = low + (high - low) / 2;
            if (nums[mid] == target) { ans = mid; high = mid - 1; }
            else if (nums[mid] < target) low = mid + 1;
            else high = mid - 1;
        }
        return ans;
    }
    int lastOcc(vector<int>& nums, int target) {
        int low = 0, high = (int)nums.size() - 1, ans = -1;
        while (low <= high) {
            int mid = low + (high - low) / 2;
            if (nums[mid] == target) { ans = mid; low = mid + 1; }
            else if (nums[mid] < target) low = mid + 1;
            else high = mid - 1;
        }
        return ans;
    }
public:
    vector<int> searchRange(vector<int>& nums, int target) {
        int first = firstOcc(nums, target);
        if (first == -1) return {-1, -1};
        return {first, lastOcc(nums, target)};
    }
};
```

### Python
```python
from typing import List

class Solution:
    def searchRange(self, nums: List[int], target: int) -> List[int]:
        def first_occ() -> int:
            low, high, ans = 0, len(nums) - 1, -1
            while low <= high:
                mid = (low + high) // 2
                if nums[mid] == target:
                    ans = mid
                    high = mid - 1
                elif nums[mid] < target:
                    low = mid + 1
                else:
                    high = mid - 1
            return ans

        def last_occ() -> int:
            low, high, ans = 0, len(nums) - 1, -1
            while low <= high:
                mid = (low + high) // 2
                if nums[mid] == target:
                    ans = mid
                    low = mid + 1
                elif nums[mid] < target:
                    low = mid + 1
                else:
                    high = mid - 1
            return ans

        first = first_occ()
        if first == -1:
            return [-1, -1]
        return [first, last_occ()]
```

## Key Takeaways
- Finding a match is not the end: to get the first/last copy, record the hit and keep shrinking the range in the direction you care about.
- Check that the element actually exists before computing the last index; otherwise the lower/upper-bound variant can return a bogus pair.
- Both halves cost O(log n), so the total is still logarithmic.
- The same "record and continue" idea powers count-of-occurrences, floor/ceil, and many search-space problems.
