# Course Schedule I

**Difficulty:** Hard  ·  **Topic:** Graphs [Concepts & Problems] › Topo Sort and Problems

## Problem
There are `numCourses` courses labelled `0` to `numCourses - 1`. You are given a list `prerequisites` where each pair `[a, b]` means *you must take course `b` before course `a`*. Return `true` if it is possible to finish every course, `false` otherwise.

```
Input:  numCourses = 4, prerequisites = [[1,0], [2,1], [3,2]]
Output: true          // take 0, 1, 2, 3 in that order

Input:  numCourses = 2, prerequisites = [[1,0], [0,1]]
Output: false         // each course requires the other
```

## Approach 1: Try every permutation (brute force)
Generate all `numCourses!` orderings and check whether some ordering satisfies all prerequisite pairs. Correct but hopeless: 15 courses already means 10^12 permutations. It does, however, make the underlying question explicit — *does a valid ordering exist at all?*

- **Time:** O(V! · E)
- **Space:** O(V)

## Approach 2: Model as a graph and detect a cycle with Kahn's algorithm (Optimal)

**Modelling step.** Draw an edge `b -> a` for every pair `[a, b]` ("finish `b`, then `a` becomes available"). The direction matters: the edge points from prerequisite to dependent, so a valid study plan is exactly a **topological ordering** of this directed graph.

**Key observation.** A topological ordering exists if and only if the graph has no directed cycle. If courses form a loop — `0` needs `1`, `1` needs `0` — no starting point exists and the plan is impossible. So the question "can all courses be finished?" is literally "is this graph acyclic?".

**Algorithm (Kahn's / BFS topological sort).**
1. Build the adjacency list `graph[b].push_back(a)` and the in-degree array, where `indeg[a]` counts how many prerequisites course `a` still has.
2. Push every course with `indeg == 0` into a queue — these need nothing and can be taken immediately.
3. Repeatedly pop a course `u`, count it as taken, and for each dependent `v` decrement `indeg[v]`; when `indeg[v]` hits 0 all of `v`'s prerequisites are done, so push `v`.
4. Answer `taken == numCourses`.

**Why the count decides it.** Each course is enqueued at most once, and only after all its prerequisites are consumed. If some course is never enqueued, its in-degree never fell to 0, meaning it forever waits on a prerequisite that itself waits — a cycle upstream of it. So `taken < numCourses` ⟺ a cycle exists ⟺ impossible.

**Dry run** on `numCourses = 4`, `[[1,0],[2,1],[3,2]]`. Edges `0->1, 1->2, 2->3`; in-degrees `0:0, 1:1, 2:1, 3:1`.
- Queue `[0]`. Pop 0 → taken = 1, `indeg[1]` = 0 → push 1.
- Pop 1 → taken = 2, `indeg[2]` = 0 → push 2. Pop 2 → taken = 3, push 3. Pop 3 → taken = 4.
- `4 == 4` → `true`.

Now `numCourses = 2`, `[[1,0],[0,1]]`. Edges `0->1` and `1->0`; both in-degrees are 1, so the queue starts **empty**, `taken = 0 < 2` → `false`.

- **Time:** O(V + E) where `V = numCourses`, `E = prerequisites.length`
- **Space:** O(V + E) for the adjacency list, in-degree array and queue

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <queue>
using namespace std;

class Solution {
public:
    bool canFinish(int numCourses, vector<vector<int>>& prerequisites) {
        vector<vector<int>> graph(numCourses);
        vector<int> indeg(numCourses, 0);
        for (auto& p : prerequisites) {
            int course = p[0], need = p[1];
            graph[need].push_back(course);   // need -> course
            indeg[course]++;
        }

        queue<int> q;
        for (int i = 0; i < numCourses; i++)
            if (indeg[i] == 0) q.push(i);

        int taken = 0;
        while (!q.empty()) {
            int u = q.front(); q.pop();
            taken++;
            for (int v : graph[u]) {
                if (--indeg[v] == 0) q.push(v);
            }
        }
        return taken == numCourses;
    }
};
```

### Java
```java
import java.util.*;

class Solution {
    public boolean canFinish(int numCourses, int[][] prerequisites) {
        List<List<Integer>> graph = new ArrayList<>();
        for (int i = 0; i < numCourses; i++) graph.add(new ArrayList<>());
        int[] indeg = new int[numCourses];
        for (int[] p : prerequisites) {
            graph.get(p[1]).add(p[0]);
            indeg[p[0]]++;
        }

        Queue<Integer> q = new ArrayDeque<>();
        for (int i = 0; i < numCourses; i++)
            if (indeg[i] == 0) q.add(i);

        int taken = 0;
        while (!q.isEmpty()) {
            int u = q.poll();
            taken++;
            for (int v : graph.get(u)) {
                if (--indeg[v] == 0) q.add(v);
            }
        }
        return taken == numCourses;
    }
}
```

### Python
```python
from collections import deque
from typing import List

class Solution:
    def canFinish(self, numCourses: int, prerequisites: List[List[int]]) -> bool:
        graph = [[] for _ in range(numCourses)]
        indeg = [0] * numCourses
        for course, need in prerequisites:
            graph[need].append(course)
            indeg[course] += 1

        q = deque(i for i in range(numCourses) if indeg[i] == 0)
        taken = 0
        while q:
            u = q.popleft()
            taken += 1
            for v in graph[u]:
                indeg[v] -= 1
                if indeg[v] == 0:
                    q.append(v)

        return taken == numCourses
```

## Key Takeaways
- "Can all tasks be completed?" with pairwise prerequisites is always a **cycle-detection in a directed graph** question.
- Get the edge direction right: `[a, b]` means `b -> a`, prerequisite pointing to dependent.
- Kahn's count `taken == numCourses` is the acyclicity test; no separate cycle check is needed.
- Watch the edge cases: zero prerequisites (always `true`) and self-dependency `[a, a]` (always `false`, since `indeg[a]` never drops to 0).
