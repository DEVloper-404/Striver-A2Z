# Count subsets with sum K

**Difficulty:** Hard  ·  **Topic:** Dynamic Programming [Patterns and Problems] › DP on Subsequences

## Problem
Given an array of non-negative integers and a target `K`, count how many subsets (subsequences, order irrelevant) have elements summing to exactly `K`. Two subsets are different if they use different *positions*, even when the values coincide. Return the count modulo 1e9+7.

```
Input:  arr = [1, 2, 2, 3], K = 3
Output: 3
Explanation: {1,2} using the first 2, {1,2} using the second 2, and {3}.
```

## Approach 1: Brute Force (recursion over pick / don't pick)

**The observation.** Stand at index `i` with a remaining target `t`. There are exactly two things you can do with `arr[i]`: take it (target drops to `t - arr[i]`) or leave it (target stays `t`). Both branches are independent, so the number of ways from `(i, t)` is the *sum* of the ways from the two children.

```
f(i, t) = f(i-1, t) + f(i-1, t - arr[i])      // second term only if t >= arr[i]
```

**Base case, and the zero trap.** At `i = 0` there is one element left. The naive base "return 1 if t == 0 or t == arr[0]" is wrong when `arr[0] == 0 && t == 0`, because then *both* the empty pick and the pick of that zero are valid — the answer is 2, not 1. The clean way to write it:

```
if (i == 0):
    if (t == 0 && arr[0] == 0) return 2
    if (t == 0 || t == arr[0]) return 1
    return 0
```

- **Time:** O(2^n)
- **Space:** O(n)

## Approach 2: Memoization
The recursion only ever asks about pairs `(i, t)` with `0 ≤ i < n` and `0 ≤ t ≤ K`, so there are just `n·(K+1)` distinct states while the tree has 2^n nodes — massive overlap. Cache the answers in a table initialised to `-1` and the exponential collapses to polynomial.

- **Time:** O(n · K)
- **Space:** O(n · K) table + O(n) stack

## Approach 3: Optimal (bottom-up tabulation, 1-D)

Convert the recursion into a table filled in the same direction the recursion resolves: index `0` upward, all targets.

`dp[i][t] = number of subsets of arr[0..i] summing to t`

- **Base row (`i = 0`):** `dp[0][0] = 1` (empty subset) and then `dp[0][arr[0]] += 1` if `arr[0] ≤ K`. Using `+=` on a fresh zero row automatically produces the value 2 for `dp[0][0]` when `arr[0] == 0`, so the zero case is handled without a special branch.
- **Transition:** `dp[i][t] = dp[i-1][t] + (t >= arr[i] ? dp[i-1][t-arr[i]] : 0)`, taken mod 1e9+7.
- **Answer:** `dp[n-1][K]`.

Row `i` reads only row `i-1`, so two rolling arrays of size `K+1` suffice.

**Dry run on arr = [1, 2, 2, 3], K = 3.** Rows are indexed by target 0..3.

| after element | t=0 | t=1 | t=2 | t=3 |
|---|---|---|---|---|
| 1 | 1 | 1 | 0 | 0 |
| 2 | 1 | 1 | 1 | 1 |
| 2 | 1 | 1 | 2 | 2 |
| 3 | 1 | 1 | 2 | 3 |

`dp[3][3] = 3`, matching the three subsets listed above. Notice how the second `2` bumps `t=2` from 1 to 2 — positions matter, duplicates count separately.

- **Time:** O(n · K)
- **Space:** O(K)

## Code (Optimal)

### C++
```cpp
class Solution {
public:
    int findWays(vector<int>& arr, int K) {
        const int MOD = 1000000007;
        int n = arr.size();

        vector<int> prev(K + 1, 0), cur(K + 1, 0);
        prev[0] = 1;                      // empty subset
        if (arr[0] <= K) prev[arr[0]] = (prev[arr[0]] + 1) % MOD;

        for (int i = 1; i < n; i++) {
            for (int t = 0; t <= K; t++) {
                int notTake = prev[t];
                int take = (t >= arr[i]) ? prev[t - arr[i]] : 0;
                cur[t] = (notTake + take) % MOD;
            }
            prev = cur;
        }
        return prev[K];
    }
};
```

```java
class Solution {
    public int findWays(int[] arr, int K) {
        final int MOD = 1000000007;
        int n = arr.length;

        int[] prev = new int[K + 1];
        int[] cur = new int[K + 1];
        prev[0] = 1;
        if (arr[0] <= K) prev[arr[0]] = (prev[arr[0]] + 1) % MOD;

        for (int i = 1; i < n; i++) {
            for (int t = 0; t <= K; t++) {
                int notTake = prev[t];
                int take = (t >= arr[i]) ? prev[t - arr[i]] : 0;
                cur[t] = (notTake + take) % MOD;
            }
            int[] tmp = prev; prev = cur; cur = tmp;
        }
        return prev[K];
    }
}
```

### Python
```python
class Solution:
    def findWays(self, arr, K):
        MOD = 1000000007
        n = len(arr)

        prev = [0] * (K + 1)
        prev[0] = 1
        if arr[0] <= K:
            prev[arr[0]] = (prev[arr[0]] + 1) % MOD

        for i in range(1, n):
            cur = [0] * (K + 1)
            for t in range(K + 1):
                not_take = prev[t]
                take = prev[t - arr[i]] if t >= arr[i] else 0
                cur[t] = (not_take + take) % MOD
            prev = cur

        return prev[K]
```

## Key Takeaways
- Counting problems replace the `max`/`min` of an optimisation DP with a `+` — the recursion shape is identical to subset-sum.
- Zeros are the classic trap: each zero doubles the count of every subset, and the `+=` base row is what encodes that.
- Subsets are counted by index, so equal values at different positions are different subsets.
- One rolling row of size `K+1` is enough; a single row iterated from `t = K` down to `0` also works because each cell only looks left.
