# Assign Cookies

**Difficulty:** Easy  ·  **Topic:** Greedy Algorithms [Easy, Medium/Hard] › Easy Problems

## Problem
You have `n` children and `m` cookies. Child `i` is content only if the cookie they receive has size at least `g[i]` (their greed factor), and each child may receive at most one cookie and each cookie may go to at most one child. Maximise the number of content children.

```
Input:  g = [1, 2, 3], s = [1, 1]
Output: 1
```
Only one cookie of size 1 can satisfy the child with greed 1; the other cookie is too small for anyone else.

## Approach 1: Try every assignment (brute force)
Enumerate all ways of matching children to cookies — for each permutation or each subset assignment, count how many children are satisfied — and keep the best. This is guaranteed correct but the search space is factorial in `min(n, m)`, so it is unusable beyond tiny inputs. It is worth stating only to make clear what "optimal" means: a maximum-cardinality matching between children and cookies.

- **Time:** O(m! ) in the worst case
- **Space:** O(n + m)

## Approach 2: Sort both arrays and match with two pointers (Optimal)
**Key observation.** Consider the least greedy child. If any cookie can satisfy them, the *smallest* such cookie should be used. Why? Suppose an optimal solution gives that child a bigger cookie `B` while a smaller sufficient cookie `A` sits unused or goes to someone else. Swapping the two cookies keeps this child content (`A` was already big enough) and cannot hurt the other recipient, since `B >= A` satisfies anything `A` satisfied. So there is always an optimal solution that pairs the least greedy child with the smallest cookie that fits — the greedy choice never loses anything. Repeating the argument on the remaining children and cookies gives an optimal solution overall (an exchange argument).

**Algorithm.**
1. Sort `g` (greed factors) ascending and `s` (cookie sizes) ascending.
2. Keep two pointers, `i` over children and `j` over cookies, both at 0, and a counter.
3. While both pointers are in range:
   - if `s[j] >= g[i]`, this cookie satisfies this child: increment the counter and advance **both** pointers;
   - otherwise the cookie is too small for the least greedy remaining child, so it is too small for *everyone* remaining (the children are sorted ascending) — discard it by advancing `j` only.
4. The counter is the answer.

Each cookie is examined once and either used or thrown away, so a single sweep suffices.

**Dry run on `g = [1, 2, 3]`, `s = [1, 1]`** (already sorted):
- `i=0, j=0`: `s[0]=1 >= g[0]=1` → satisfy child 0, count = 1, `i=1, j=1`.
- `i=1, j=1`: `s[1]=1 < g[1]=2` → cookie is useless for every remaining child, `j=2`.
- `j` is out of range, loop ends. Answer **1**.

A second example, `g = [1, 2]`, `s = [1, 2, 3]`: child 0 takes the size-1 cookie, child 1 takes the size-2 cookie, the size-3 cookie is spare → answer 2. Note how *not* giving child 0 the size-3 cookie is precisely what leaves room for child 1.

- **Time:** O(n log n + m log m) for the two sorts; the scan itself is O(n + m).
- **Space:** O(1) auxiliary (or O(log n) for the sort's stack).

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int findContentChildren(vector<int>& g, vector<int>& s) {
        sort(g.begin(), g.end());
        sort(s.begin(), s.end());
        int i = 0, j = 0, satisfied = 0;
        while (i < (int)g.size() && j < (int)s.size()) {
            if (s[j] >= g[i]) {        // smallest cookie that fits the least greedy child
                satisfied++;
                i++;
                j++;
            } else {
                j++;                   // too small for everyone left: discard it
            }
        }
        return satisfied;
    }
};
```

```python
from typing import List

class Solution:
    def findContentChildren(self, g: List[int], s: List[int]) -> int:
        g.sort()
        s.sort()
        i = j = satisfied = 0
        while i < len(g) and j < len(s):
            if s[j] >= g[i]:          # smallest sufficient cookie
                satisfied += 1
                i += 1
                j += 1
            else:
                j += 1                # too small for every remaining child
        return satisfied
```

## Key Takeaways
- The greedy rule is "cheapest resource to the cheapest demand": give the least greedy child the smallest cookie that works, proved optimal by an exchange argument.
- Sorting both arrays is what makes the "too small for this child ⇒ too small for all remaining children" shortcut valid.
- Advance both pointers on a match, only the cookie pointer on a miss; never advance the child pointer alone, or you would give up on a child a later cookie could satisfy.
- Edge cases fall out naturally: empty arrays return 0, and unused leftover cookies simply never get visited.
