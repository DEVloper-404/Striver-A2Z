# Best Time to Buy and Sell Stock with Cooldown

**Difficulty:** Medium  ·  **Topic:** Dynamic Programming [Patterns and Problems] › DP on Stocks

## Problem
Given `prices[i]` = the stock price on day `i`, you may complete as many transactions as you like (buy one, sell one, repeat), but with one restriction: **after you sell, you must skip one day** before you are allowed to buy again. You can hold at most one share at a time. Return the maximum profit.

```
Input:  prices = [1, 2, 3, 0, 2]
Output: 3      (buy at 1, sell at 3 → +2, cooldown, buy at 0, sell at 2 → +1)
```

## Approach 1: Recursion with a "can buy" flag and a skip (Brute Force)
Start from the ordinary unlimited-transaction recursion `f(i, canBuy)` and change exactly one line: when you sell on day `i`, you may not act on day `i+1`, so you jump to day `i+2`.

- If `canBuy`: `max(-prices[i] + f(i+1, false), f(i+1, true))`.
- Else: `max(prices[i] + f(i+2, true), f(i+1, false))` — note the `i+2`, which *is* the cooldown.
- Base case: `f(i, ·) = 0` for `i >= n` (so the `i+2` jump must tolerate `i+2 == n+1`).

That is the entire difference from Stock II, and it is why this problem is best understood as "the same machine with one extra edge".

- **Time:** O(2^n)
- **Space:** O(n)

## Approach 2: Memoization / Tabulation
Only `n × 2` states exist, so cache them. Tabulating from `i = n-1` down to `0` works, but the `i+2` lookup makes the array bookkeeping slightly fiddly (you need rows `i+1` and `i+2` alive at once).

- **Time:** O(n)
- **Space:** O(n)

## Approach 3: Three-state machine (Optimal)
A cleaner formulation replaces the `i+2` jump with an explicit third state, so every transition looks only one day ahead. On each day you are in exactly one of:

- **hold** — you own a share.
- **sold** — you sold *today*, so tomorrow is a forced rest day.
- **rest** — you own nothing and you are free to buy today.

The transitions read directly off those definitions:
```
hold = max(hold, rest - price)   // keep the share, or buy today (only legal from 'rest')
sold = hold + price              // the only way to be in 'sold' is to have held and sold today
rest = max(rest, sold)           // stay idle, or arrive from yesterday's 'sold' (cooldown served)
```
The cooldown is enforced structurally: buying reads `rest`, and yesterday's `sold` can only become `rest` after one full day passes. There is no path from `sold` straight into `hold`.

All three must be computed from **yesterday's** values, so snapshot them before updating. Initialise `hold = -prices[0]`, `sold = -infinity` (you cannot have sold before day 0), `rest = 0`. The answer is `max(sold, rest)` on the last day — never `hold`, since ending with an unsold share wastes the money spent on it.

**Dry run** on `[1, 2, 3, 0, 2]`:

| day | price | hold | sold | rest |
|-----|-------|------|------|------|
| 0   | 1     | −1   | −∞   | 0    |
| 1   | 2     | −1   | 1    | 0    |
| 2   | 3     | −1   | 2    | 1    |
| 3   | 0     | 1    | −1   | 2    |
| 4   | 2     | 1    | **3**| 2    |

Look at day 3: `hold` becomes `1` because `rest = 1` (the profit of 2 banked on day 2, made available only after the cooldown day) minus a price of 0. Selling on day 4 gives `1 + 2 = 3`.

- **Time:** O(n)
- **Space:** O(1)

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <algorithm>
#include <climits>
using namespace std;

class Solution {
public:
    int maxProfit(vector<int>& prices) {
        int n = prices.size();
        if (n < 2) return 0;

        int hold = -prices[0];      // owning a share
        int sold = INT_MIN / 2;     // sold today -> tomorrow is a cooldown
        int rest = 0;               // free to buy

        for (int i = 1; i < n; i++) {
            int pHold = hold, pSold = sold, pRest = rest;
            hold = max(pHold, pRest - prices[i]);
            sold = pHold + prices[i];
            rest = max(pRest, pSold);
        }
        return max(sold, rest);
    }
};
```

### Python
```python
from typing import List


class Solution:
    def maxProfit(self, prices: List[int]) -> int:
        if len(prices) < 2:
            return 0
        hold = -prices[0]
        sold = float('-inf')
        rest = 0
        for price in prices[1:]:
            hold, sold, rest = max(hold, rest - price), hold + price, max(rest, sold)
        return int(max(sold, rest))
```

## Key Takeaways
- A cooldown is either an `i+2` jump in the recursion or an extra state in the machine; the three-state version is easier to get right because every edge advances exactly one day.
- Buying may only read the `rest` state — that single restriction is the whole cooldown rule.
- Update all states from a snapshot of yesterday's values; overwriting `hold` before computing `sold` silently allows buying and selling on the same day chain.
- The answer is `max(sold, rest)`; including `hold` would count a share you never sold.
