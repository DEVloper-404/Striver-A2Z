# N meetings in one room

**Difficulty:** Medium  ·  **Topic:** Greedy Algorithms [Easy, Medium/Hard] › Medium/Hard

## Problem
You are given `n` meetings, each with a start time `start[i]` and end time `end[i]`. Only one meeting can happen in the room at a time, and a new meeting can begin only strictly after the previous one has finished (end time of one must be less than start time of the next). Return the maximum number of meetings that can be scheduled in the room.

Input: `start = [1, 3, 0, 5, 8, 5]`, `end = [2, 4, 6, 7, 9, 9]`
Output: `4` (meetings at (1,2), (3,4), (5,7), (8,9))

## Approach 1: Brute Force (try all subsets)
Enumerate every subset of meetings, check that the chosen meetings are pairwise non-conflicting, and keep the largest valid subset. This is exponential and only useful to convince yourself what "valid" means.
- **Time:** O(2^n · n)
- **Space:** O(n)

## Approach 2: Greedy by earliest finish time (Optimal)
Key observation: among all meetings that can still be held, picking the one that **finishes earliest** leaves the most room for the remaining meetings. Any optimal schedule can be transformed into one that starts with the earliest-finishing meeting without losing a meeting (exchange argument), so the greedy choice is safe.

1. Pair each meeting as `(start, end)` and sort by `end` ascending.
2. Keep `lastEnd` = end time of the last selected meeting (initially `-1` or `0`).
3. Walk through the sorted list; if `start > lastEnd`, take the meeting and update `lastEnd = end`.
4. Count how many meetings were taken.

- **Time:** O(n log n) for the sort
- **Space:** O(n) for the paired array

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int maxMeetings(vector<int>& start, vector<int>& end) {
        int n = start.size();
        vector<pair<int,int>> meets(n);
        for (int i = 0; i < n; i++) meets[i] = {end[i], start[i]};
        sort(meets.begin(), meets.end());   // sort by end time

        int count = 0;
        int lastEnd = -1;
        for (auto& m : meets) {
            int e = m.first, s = m.second;
            if (s > lastEnd) {
                count++;
                lastEnd = e;
            }
        }
        return count;
    }
};
```

### Java
```java
import java.util.*;

class Solution {
    public int maxMeetings(int[] start, int[] end) {
        int n = start.length;
        int[][] meets = new int[n][2];
        for (int i = 0; i < n; i++) {
            meets[i][0] = start[i];
            meets[i][1] = end[i];
        }
        Arrays.sort(meets, (a, b) -> Integer.compare(a[1], b[1]));

        int count = 0, lastEnd = -1;
        for (int[] m : meets) {
            if (m[0] > lastEnd) {
                count++;
                lastEnd = m[1];
            }
        }
        return count;
    }
}
```

### Python
```python
from typing import List

class Solution:
    def maxMeetings(self, start: List[int], end: List[int]) -> int:
        meets = sorted(zip(start, end), key=lambda m: m[1])
        count = 0
        last_end = -1
        for s, e in meets:
            if s > last_end:
                count += 1
                last_end = e
        return count
```

## Key Takeaways
- Interval scheduling: sort by **end time**, not start time; earliest finish is the provably safe greedy choice.
- The comparison is strict (`start > lastEnd`) because a meeting cannot begin at the same instant the previous one ends in this problem; check the exact rule of the variant you are solving.
- If the problem asks for the *indices* of chosen meetings, keep the original index in the tuple and sort ties by index.
