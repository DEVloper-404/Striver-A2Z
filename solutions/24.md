# Maximum Product Subarray in an Array

**Difficulty:** Hard  ·  **Topic:** Solve Problems on Arrays [Easy -> Medium -> Hard] › Hard

## Problem
Given an integer array `nums`, find the contiguous non-empty subarray whose product is the largest, and return that product. The array may contain zeros and negative numbers.

Input: `nums = [2, 3, -2, 4]`
Output: `6` (subarray `[2, 3]`)

Input: `nums = [-2, 0, -1]`
Output: `0`

## Approach 1: Brute Force
For each start `i`, extend the end `j` while multiplying, and track the maximum product seen.
- **Time:** O(n²)
- **Space:** O(1)

## Approach 2: Track both max and min running products
A negative number flips signs, so the smallest (most negative) product ending at `i-1` can become the largest at `i`. Keep two values ending at the current index: `curMax` and `curMin`. At each element `x`, the new candidates are `x`, `curMax * x`, and `curMin * x`; take the max and min of those three. The answer is the max over all `curMax`.
- **Time:** O(n)
- **Space:** O(1)

## Approach 3: Prefix and suffix products (Optimal, simplest to reason about)
Key observation: if the array has no zeros, the best subarray is either the whole array (when the count of negatives is even) or the whole array with a prefix or suffix removed up to the first / last negative. Either way, the answer is the largest prefix product or the largest suffix product. Zeros split the array into independent segments, and resetting the running product to 1 whenever it hits 0 handles that automatically.

1. Walk `i` from 0 to n-1 maintaining `pre *= nums[i]` and `suf *= nums[n-1-i]`.
2. Before multiplying, if `pre == 0` reset it to 1; same for `suf`.
3. Answer is the maximum of every `pre` and `suf` encountered.

Since a zero element itself gives a product of 0, a segment-only-negative case like `[-2, 0, -1]` correctly returns 0.

- **Time:** O(n)
- **Space:** O(1)

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <algorithm>
#include <climits>
using namespace std;

class Solution {
public:
    int maxProduct(vector<int>& nums) {
        int n = nums.size();
        long long pre = 1, suf = 1;
        long long best = LLONG_MIN;
        for (int i = 0; i < n; ++i) {
            if (pre == 0) pre = 1;
            if (suf == 0) suf = 1;
            pre *= nums[i];
            suf *= nums[n - 1 - i];
            best = max(best, max(pre, suf));
        }
        return (int)best;
    }
};
```

### Python
```python
from typing import List

class Solution:
    def maxProduct(self, nums: List[int]) -> int:
        n = len(nums)
        pre = suf = 1
        best = float("-inf")
        for i in range(n):
            if pre == 0:
                pre = 1
            if suf == 0:
                suf = 1
            pre *= nums[i]
            suf *= nums[n - 1 - i]
            best = max(best, pre, suf)
        return best
```

## Key Takeaways
- Unlike max-sum, a negative running product is worth remembering because one more negative can turn it into the maximum; that is why both the min/max-tracking and prefix/suffix approaches work.
- Zeros act as hard barriers; resetting the running product to 1 restarts the segment.
- LeetCode guarantees the product of any prefix/suffix fits in 32 bits, but using 64-bit locally is a cheap safety net.
