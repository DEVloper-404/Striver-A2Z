# Combination Sum II

**Difficulty:** Medium  ·  **Topic:** Recursion [PatternWise] › Subsequences Pattern

## Problem
Given an array `candidates` that may contain **duplicate** numbers and a target `target`, return all **unique** combinations that sum to `target`. Each element of the array may be used **at most once** (an element that appears twice in the array may appear at most twice in a combination). Combinations are multisets — order does not matter, and the same multiset must not be printed twice.

```
Input:  candidates = [10, 1, 2, 7, 6, 1, 5], target = 8
Output: [[1, 1, 6], [1, 2, 5], [1, 7], [2, 6]]
```

## Approach 1: Generate everything, then de-duplicate with a set
Run the plain pick/not-pick subsequence recursion where "pick" moves to `index + 1` (each element used once). Sort every found combination and insert it into a `set`, so `[1, 7]` produced from the first `1` and `[7, 1]`-equivalent produced from the second `1` collapse into one entry.

This is correct but wasteful: the recursion still walks every duplicate branch, and each successful leaf costs an extra `O(k log k)` sort plus a set insertion. With many repeated values the duplicate work dominates.

- **Time:** O(2^n · k log k)
- **Space:** O(2^n · k) for the set, O(n) recursion.

## Approach 2: Sort + skip duplicates at the same recursion level (Optimal)
The key observation is *where* duplicates are born. Sort the array first so equal values sit next to each other:
`[1, 1, 2, 5, 6, 7, 10]`.

Now think of the recursion as: "I am filling position `p` of my combination, and I may choose any index `j >= start`." If indices 1 and 2 both hold the value `1`, then choosing index 1 for position `p` and choosing index 2 for position `p` lead to **identical** subtrees — same value consumed, same suffix of the array still available. That is precisely one duplicate combination. Choosing them in *different* positions (one at position `p`, the other deeper down) is fine and produces `[1, 1, 6]`, which we do want.

So the rule is: **at a given recursion level, use each distinct value only once**. Concretely, inside the loop skip index `j` when `j > start && candidates[j] == candidates[j-1]`. The `j > start` guard is essential — it allows the *first* occurrence at this level (which may equal the value the parent just picked, giving `[1, 1, ...]`), and blocks only repeats within the same loop.

**Algorithm.**
1. Sort `candidates`.
2. `solve(start, remaining)`: if `remaining == 0`, record a copy of `current`.
3. Loop `j` from `start` to `n-1`:
   - if `j > start` and `candidates[j] == candidates[j-1]`, `continue`;
   - if `candidates[j] > remaining`, `break` (sorted, so nothing later fits either);
   - push `candidates[j]`, recurse on `(j + 1, remaining - candidates[j])`, pop.

**Dry run on the sorted array with target 8.** At the top level `start = 0`:
- `j = 0` picks `1` → inside, `start = 1`, so `j = 1` (the second `1`) is *allowed* → `[1, 1]`, remaining 6 → picks `6` → `[1, 1, 6]`. Back up, `[1, 2, 5]` and `[1, 7]` are found the same way.
- `j = 1` at the top level is a second `1` with `j > start`, so it is skipped — this is exactly what would have re-emitted `[1, 2, 5]` and `[1, 7]`.
- `j = 2` picks `2` → `[2, 6]`. Later values 5, 6, 7, 10 start branches that cannot reach 8 with the remaining suffix.

Every answer appears exactly once, with no set and no post-processing.

- **Time:** O(2^n · k) worst case (all elements distinct and small), `k` = average combination length for copying.
- **Space:** O(n) recursion depth plus the working combination.

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    vector<vector<int>> combinationSum2(vector<int>& candidates, int target) {
        sort(candidates.begin(), candidates.end());
        vector<vector<int>> res;
        vector<int> cur;
        solve(0, target, candidates, cur, res);
        return res;
    }

private:
    void solve(int start, int remaining, vector<int>& cand,
               vector<int>& cur, vector<vector<int>>& res) {
        if (remaining == 0) {
            res.push_back(cur);
            return;
        }
        for (int j = start; j < (int)cand.size(); j++) {
            if (j > start && cand[j] == cand[j - 1]) continue;  // same value, same level
            if (cand[j] > remaining) break;                     // sorted: rest is worse
            cur.push_back(cand[j]);
            solve(j + 1, remaining - cand[j], cand, cur, res);  // each index used once
            cur.pop_back();
        }
    }
};
```

### Java
```java
import java.util.*;

class Solution {
    public List<List<Integer>> combinationSum2(int[] candidates, int target) {
        Arrays.sort(candidates);
        List<List<Integer>> res = new ArrayList<>();
        solve(0, target, candidates, new ArrayList<>(), res);
        return res;
    }

    private void solve(int start, int remaining, int[] cand,
                       List<Integer> cur, List<List<Integer>> res) {
        if (remaining == 0) {
            res.add(new ArrayList<>(cur));
            return;
        }
        for (int j = start; j < cand.length; j++) {
            if (j > start && cand[j] == cand[j - 1]) continue;
            if (cand[j] > remaining) break;
            cur.add(cand[j]);
            solve(j + 1, remaining - cand[j], cand, cur, res);
            cur.remove(cur.size() - 1);
        }
    }
}
```

### Python
```python
from typing import List

class Solution:
    def combinationSum2(self, candidates: List[int], target: int) -> List[List[int]]:
        candidates.sort()
        res, cur = [], []
        n = len(candidates)

        def solve(start: int, remaining: int) -> None:
            if remaining == 0:
                res.append(cur[:])
                return
            for j in range(start, n):
                if j > start and candidates[j] == candidates[j - 1]:
                    continue
                if candidates[j] > remaining:
                    break
                cur.append(candidates[j])
                solve(j + 1, remaining - candidates[j])
                cur.pop()

        solve(0, target)
        return res
```

## Key Takeaways
- Duplicates in the *answer* come from picking the same **value** at the same **position** of the combination — sorting plus `j > start && a[j] == a[j-1]` removes exactly those branches.
- The `j > start` part is not optional: dropping it would also forbid legitimate repeats like `[1, 1, 6]`.
- `solve(j + 1, ...)` (not `j`) is what makes this "each element once", the one-line difference from Combination Sum I.
- Sorting also enables the `break` prune, and since all numbers are positive, `remaining < 0` never needs a separate check.
