# Floor and Ceil in a BST

**Difficulty:** Easy  ·  **Topic:** Binary Search Trees [Concept and Problems] › Practice Problems

## Problem
Given the root of a Binary Search Tree and an integer `key`, find two values:
- **Floor** — the largest value in the tree that is `<= key`.
- **Ceil** — the smallest value in the tree that is `>= key`.

If no such value exists, report `-1` for that quantity.

```
Input:  tree = [10, 5, 13, 3, 7, 11, 15], key = 8
Output: floor = 7, ceil = 10

Input:  tree = [10, 5, 13, 3, 7, 11, 15], key = 13
Output: floor = 13, ceil = 13   (an exact match is both floor and ceil)
```

## Approach 1: Brute Force (collect the inorder traversal)
Do an inorder traversal to get a sorted array of all values. Then walk the array (or binary search it) for the last element `<= key` and the first element `>= key`.

This is correct but wasteful: it materialises every node even though the answer depends on a single root-to-leaf path.
- **Time:** O(N) to traverse, plus O(log N) to binary search
- **Space:** O(N) for the array

## Approach 2: Optimal (single downward walk using the BST ordering)
The key observation is that a BST lets you *discard half the tree at every step*, and while you discard, you can remember the best candidate you have seen.

Think about floor. Standing at a node with value `v`:
- If `v == key`, we found an exact match. `key` itself is the floor — nothing can beat it.
- If `v > key`, then `v` is too big to be the floor, and so is *every node in its right subtree* (they are all `> v > key`). So `v` cannot be an answer and neither can anything to its right; move left.
- If `v < key`, then `v` **is** a valid floor candidate — record it. But maybe there is a larger value that is still `<= key`, and any such value must live in the right subtree (everything left of `v` is smaller than `v`). So save `v` as the current best and move right.

Ceil is the mirror image: when `v >= key`, record `v` and move left looking for something smaller that still clears `key`; when `v < key`, move right.

Because each step goes down one level, the walk visits at most `H` nodes where `H` is the height.

**Dry run** for `key = 8` on `[10, 5, 13, 3, 7, 11, 15]`, computing floor:
1. At `10`: `10 > 8`, so 10 is not a candidate → go left.
2. At `5`: `5 < 8`, record `floor = 5` → go right (hoping for something bigger but still ≤ 8).
3. At `7`: `7 < 8`, record `floor = 7` → go right.
4. Right child is null → stop. Answer `7`. ✔

Computing ceil for the same key:
1. At `10`: `10 >= 8`, record `ceil = 10` → go left.
2. At `5`: `5 < 8` → go right.
3. At `7`: `7 < 8` → go right → null. Answer `10`. ✔

Note both loops are iterative, so no recursion stack is needed at all.
- **Time:** O(H) — O(log N) for a balanced BST, O(N) for a skewed one
- **Space:** O(1)

## Code (Optimal)

### C++
```cpp
// struct TreeNode { int val; TreeNode *left, *right; TreeNode(int x) ... } — standard definition
#include <utility>
using namespace std;

class Solution {
public:
    int floorInBST(TreeNode* root, int key) {
        int best = -1;
        TreeNode* cur = root;
        while (cur) {
            if (cur->val == key) return cur->val;
            if (cur->val < key) {          // valid candidate, try for a bigger one
                best = cur->val;
                cur = cur->right;
            } else {                        // too big, everything right of it is worse
                cur = cur->left;
            }
        }
        return best;
    }

    int ceilInBST(TreeNode* root, int key) {
        int best = -1;
        TreeNode* cur = root;
        while (cur) {
            if (cur->val == key) return cur->val;
            if (cur->val > key) {          // valid candidate, try for a smaller one
                best = cur->val;
                cur = cur->left;
            } else {                        // too small, everything left of it is worse
                cur = cur->right;
            }
        }
        return best;
    }

    pair<int,int> floorCeilOfBST(TreeNode* root, int key) {
        return {floorInBST(root, key), ceilInBST(root, key)};
    }
};
```

### Python

```python
# class TreeNode: val, left, right — standard definition

class Solution:
    def floorInBST(self, root, key):
        best, cur = -1, root
        while cur:
            if cur.val == key:
                return cur.val
            if cur.val < key:
                best = cur.val          # candidate; look right for a bigger one
                cur = cur.right
            else:
                cur = cur.left
        return best

    def ceilInBST(self, root, key):
        best, cur = -1, root
        while cur:
            if cur.val == key:
                return cur.val
            if cur.val > key:
                best = cur.val          # candidate; look left for a smaller one
                cur = cur.left
            else:
                cur = cur.right
        return best

    def floorCeilOfBST(self, root, key):
        return self.floorInBST(root, key), self.ceilInBST(root, key)
```

## Key Takeaways
- The BST property turns "search the whole tree" into "walk one root-to-leaf path": at every node you learn which half is hopeless.
- The trick is *remember-then-descend* — when a node is a valid answer, store it and keep going in the direction that could improve it.
- Floor and ceil are exact mirrors; only the comparison and the descent direction flip.
- Edge cases: `key` smaller than the minimum gives floor `-1`; `key` larger than the maximum gives ceil `-1`; an exact hit is simultaneously the floor and the ceil.
