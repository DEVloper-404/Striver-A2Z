# Partition Array for Maximum Sum

**Difficulty:** Medium  ·  **Topic:** Dynamic Programming [Patterns and Problems] › MCM DP | Partition DP

## Problem
Given an integer array `arr` and an integer `k`, split `arr` into contiguous subarrays each of length **at most** `k`. After splitting, every element of a subarray is replaced by the maximum value in that subarray. Return the largest possible sum of the resulting array.

```
Input:  arr = [1, 15, 7, 9, 2, 5, 10], k = 3
Output: 84
```
The split `[1,15,7] [9] [2,5,10]` becomes `[15,15,15, 9, 10,10,10]`, summing to `45 + 9 + 30 = 84`.

## Approach 1: Try every split (Brute Force Recursion)

**Why greedy fails.** A tempting rule is "always grab `k` elements" or "always extend while the max stays the same", but neither is safe. In the example, greedily taking `[1,15,7]` happens to be right, yet the very next group is a *single* element `9` — a greedy length-3 grab there would swallow `2` and `5` at a lower max and lose points. The correct group length depends on what comes after, so we must search.

**Front partition formulation.** Stand at index `i` and decide only how long the **first** group is. Everything after `i + len` is an independent subproblem of the same shape.

Let `f(i)` = the maximum achievable sum using only `arr[i..n-1]`.

```
f(n) = 0
f(i) = max over len in [1, min(k, n-i)] of
           ( max(arr[i .. i+len-1]) * len + f(i + len) )
```

The term `max(...) * len` is the contribution of the group we just formed: every one of its `len` slots holds the group's maximum.

- **Time:** O(k^n) without caching
- **Space:** O(n) recursion stack

## Approach 2: 1-D DP with a rolling maximum (Optimal)

`f(i)` depends only on `i`, so a 1-D array of size `n + 1` suffices — this is the standard front-partition shape, the same as Palindrome Partitioning II.

**One more efficiency detail.** Recomputing `max(arr[i..i+len-1])` from scratch for each `len` would cost O(k) per candidate, making the inner work O(k^2). Instead, grow the group one element at a time and keep a running `curMax`: as `len` goes `1, 2, 3, ...`, do `curMax = max(curMax, arr[i+len-1])`. Each candidate is then O(1).

**The algorithm.**
1. Allocate `dp[0..n]`, set `dp[n] = 0`.
2. For `i` from `n-1` down to `0`:
   - `curMax = -infinity`, `best = -infinity`.
   - For `len = 1` while `len <= k` and `i + len <= n`:
     - `curMax = max(curMax, arr[i + len - 1])`
     - `best = max(best, curMax * len + dp[i + len])`
   - `dp[i] = best`
3. Return `dp[0]`.

We iterate `i` downward because `dp[i]` reads `dp[i + len]`, which lies to the right.

**Dry run on `arr = [1,15,7,9,2,5,10]`, `k = 3`** (`n = 7`, `dp[7] = 0`):

- `dp[6]`: only `len=1` → `10·1 + 0 = 10`. → **10**
- `dp[5]`: `len=1` → `5 + dp[6] = 15`; `len=2` → `max(5,10)=10`, `10·2 + dp[7] = 20`. → **20**
- `dp[4]`: `len=1` → `2 + 20 = 22`; `len=2` → `5·2 + dp[6] = 20`; `len=3` → `10·3 + dp[7] = 30`. → **30**
- `dp[3]`: `len=1` → `9 + 30 = 39`; `len=2` → `9·2 + dp[5] = 38`; `len=3` → `9·3 + dp[6] = 37`. → **39**
- `dp[2]`: `len=1` → `7 + 39 = 46`; `len=2` → `9·2 + dp[4] = 48`; `len=3` → `9·3 + dp[5] = 47`. → **48**
- `dp[1]`: `len=1` → `15 + 48 = 63`; `len=2` → `15·2 + dp[3] = 69`; `len=3` → `15·3 + dp[4] = 75`. → **75**
- `dp[0]`: `len=1` → `1 + 75 = 76`; `len=2` → `15·2 + dp[2] = 78`; `len=3` → `15·3 + dp[3] = 84`. → **84**

Answer `dp[0] = 84`. Following the winners backwards: `dp[0]` chose `len=3` (`[1,15,7]`), then `dp[3]` chose `len=1` (`[9]`), then `dp[4]` chose `len=3` (`[2,5,10]`) — exactly the split shown above, including the single-element group that greedy would have missed.

- **Time:** O(n · k)
- **Space:** O(n)

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <algorithm>
#include <climits>
using namespace std;

class Solution {
public:
    int maxSumAfterPartitioning(vector<int>& arr, int k) {
        int n = arr.size();
        vector<int> dp(n + 1, 0);               // dp[n] = 0

        for (int i = n - 1; i >= 0; i--) {
            int curMax = INT_MIN, best = INT_MIN;
            for (int len = 1; len <= k && i + len <= n; len++) {
                curMax = max(curMax, arr[i + len - 1]);
                best = max(best, curMax * len + dp[i + len]);
            }
            dp[i] = best;
        }
        return dp[0];
    }
};
```

### Python
```python
from typing import List

class Solution:
    def maxSumAfterPartitioning(self, arr: List[int], k: int) -> int:
        n = len(arr)
        dp = [0] * (n + 1)                      # dp[n] = 0

        for i in range(n - 1, -1, -1):
            cur_max = float('-inf')
            best = float('-inf')
            length = 1
            while length <= k and i + length <= n:
                cur_max = max(cur_max, arr[i + length - 1])
                best = max(best, cur_max * length + dp[i + length])
                length += 1
            dp[i] = best

        return dp[0]
```

## Key Takeaways
- Front partition DP: choose the length of the first group, then solve the remaining suffix — one index is the entire state.
- Maintain the group maximum incrementally as the group grows; recomputing it per candidate turns O(n·k) into O(n·k^2) for nothing.
- The bound is `len <= min(k, n - i)`; forgetting the `n - i` guard reads past the end of the array.
- Greedy on group length or group maximum is provably wrong here — the example's lone `[9]` group is the counterexample.
