# Best time to buy and sell stock IV

**Difficulty:** Medium  ·  **Topic:** Dynamic Programming [Patterns and Problems] › DP on Stocks

## Problem
Given an integer `k` and an array `prices` where `prices[i]` is the stock price on day `i`, return the maximum profit achievable with **at most `k` transactions**. You may hold at most one share at a time, so each buy must be followed by a sell before the next buy.

```
Input:  k = 2, prices = [3, 2, 6, 5, 0, 3]
Output: 7      (buy at 2 sell at 6 → +4, buy at 0 sell at 3 → +3)
```

## Approach 1: Recursion over (day, canBuy, remaining) (Brute Force)
This is the general form of the whole stock family. Let `f(i, canBuy, cap)` = best profit from day `i` onward with `cap` transactions left.

- `f(n, ·, ·) = 0` and `f(·, ·, 0) = 0`.
- If `canBuy`: `max(-prices[i] + f(i+1, false, cap), f(i+1, true, cap))` — buy today or wait.
- Else: `max(prices[i] + f(i+1, true, cap-1), f(i+1, false, cap))` — sell today (which consumes one transaction) or keep holding.

Every legal schedule of at most `k` trades is reachable, so the recursion is correct; it is just exponential.

- **Time:** O(2^n)
- **Space:** O(n)

## Approach 2: Memoization / Tabulation
The state space is only `n × 2 × (k+1)`, so cache it. Bottom-up, iterate `i` from `n-1` down to `0`, `cap` from `1` to `k`, and fill both `canBuy` values using row `i+1`. Since each day depends only on the next day, two 2D slices of size `2 × (k+1)` are enough — that is the space-optimised version.

- **Time:** O(n · k)
- **Space:** O(n · k), reducible to O(k)

## Approach 3: `k` pairs of rolling variables (Optimal)
Generalise the four-variable trick from Stock III. Keep two arrays of length `k+1`:

- `buy[t]` — best balance after *entering* the `t`-th trade.
- `sell[t]` — best balance after *closing* the `t`-th trade.

For each price, sweep `t` from `1` to `k`:
```
buy[t]  = max(buy[t],  sell[t-1] - price)   // fund trade t with the profit of the first t-1 trades
sell[t] = max(sell[t], buy[t]    + price)   // close trade t
```
`sell[0] = 0` anchors the chain (before any trade you have zero cash). Initialise every `buy[t]` to `-infinity` and every `sell[t]` to `0`, since "at most `k`" permits using fewer. The answer is `sell[k]`, which is monotonically ≥ `sell[t]` for every smaller `t`.

Updating in place within one price is safe for the same reason as in Stock III: the only extra schedules it admits are same-day buy/sell pairs worth `0`.

**Practical shortcut:** a completed transaction needs at least two days, so if `k >= n/2` the cap is not binding and the problem degenerates into Stock II — just sum every positive daily difference in O(n). This matters because LeetCode allows `k` up to 100 with `n` up to 1000, and it also avoids allocating a huge array when `k` is enormous.

**Dry run** for `k = 2`, `prices = [3, 2, 6, 5, 0, 3]`:

| price | buy[1] | sell[1] | buy[2] | sell[2] |
|-------|--------|---------|--------|---------|
| 3     | −3     | 0       | −3     | 0       |
| 2     | −2     | 0       | −2     | 0       |
| 6     | −2     | 4       | −2     | 4       |
| 5     | −2     | 4       | −1     | 4       |
| 0     | 0      | 4       | 4      | 4       |
| 3     | 0      | 4       | 4      | **7**   |

At price `0`, `buy[2]` jumps to `4`: the first trade already banked 4 and the second share cost nothing, so the running balance is 4. Selling at 3 then gives 7.

- **Time:** O(n · k)
- **Space:** O(k)

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <algorithm>
#include <climits>
using namespace std;

class Solution {
public:
    int maxProfit(int k, vector<int>& prices) {
        int n = prices.size();
        if (n < 2 || k == 0) return 0;

        // If k is large enough, the cap never binds: take every upward move.
        if (k >= n / 2) {
            int profit = 0;
            for (int i = 1; i < n; i++)
                profit += max(0, prices[i] - prices[i - 1]);
            return profit;
        }

        vector<int> buy(k + 1, INT_MIN), sell(k + 1, 0);
        for (int price : prices) {
            for (int t = 1; t <= k; t++) {
                buy[t]  = max(buy[t], sell[t - 1] - price);
                sell[t] = max(sell[t], buy[t] + price);
            }
        }
        return sell[k];
    }
};
```

### Java
```java
class Solution {
    public int maxProfit(int k, int[] prices) {
        int n = prices.length;
        if (n < 2 || k == 0) return 0;

        if (k >= n / 2) {
            int profit = 0;
            for (int i = 1; i < n; i++) {
                profit += Math.max(0, prices[i] - prices[i - 1]);
            }
            return profit;
        }

        int[] buy = new int[k + 1];
        int[] sell = new int[k + 1];
        java.util.Arrays.fill(buy, Integer.MIN_VALUE / 2);

        for (int price : prices) {
            for (int t = 1; t <= k; t++) {
                buy[t] = Math.max(buy[t], sell[t - 1] - price);
                sell[t] = Math.max(sell[t], buy[t] + price);
            }
        }
        return sell[k];
    }
}
```

### Python
```python
from typing import List


class Solution:
    def maxProfit(self, k: int, prices: List[int]) -> int:
        n = len(prices)
        if n < 2 or k == 0:
            return 0

        if k >= n // 2:
            return sum(max(0, prices[i] - prices[i - 1]) for i in range(1, n))

        buy = [float('-inf')] * (k + 1)
        sell = [0] * (k + 1)
        for price in prices:
            for t in range(1, k + 1):
                buy[t] = max(buy[t], sell[t - 1] - price)
                sell[t] = max(sell[t], buy[t] + price)
        return sell[k]
```

## Key Takeaways
- `buy[t] = max(buy[t], sell[t-1] - price)` is the whole idea: each trade is bankrolled by the accumulated profit of all previous trades.
- Decrement the transaction counter on the sell, and let `sell[t]` start at `0` so "at most k" gracefully covers using fewer trades.
- When `k >= n/2` the constraint is vacuous — special-case it to keep memory and time in check for huge `k`.
- Use `INT_MIN / 2` (not `INT_MIN`) in Java/C++ if you ever add to it before it is overwritten, to avoid signed overflow.
