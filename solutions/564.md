# Longest subarray with sum K

**Difficulty:** Medium  ·  **Topic:** Solve Problems on Arrays [Easy -> Medium -> Hard] › Easy

## Problem
Given an array of `n` integers that may include negative values and zeros, and a target `k`, return the length of the longest contiguous subarray whose sum is exactly `k`. Return `0` if none exists.

Input: `arr = [-1, 1, 1], k = 1`
Output: `3` (the whole array sums to 1)

Input: `arr = [2, 3, 5, 1, 9], k = 10`
Output: `3` (`[2, 3, 5]`)

## Approach 1: Check Every Subarray
Fix a start index, extend an end index while maintaining the running sum, and record the length whenever it hits `k`. Unlike the all-positive version, you cannot break early when the sum exceeds `k` because a later negative could bring it back down.

- **Time:** O(n²)
- **Space:** O(1)

## Approach 2: Prefix Sums + Hash Map (Optimal)
Define `pref[j]` as the sum of `arr[0..j]`. A subarray ending at `j` and starting at `i+1` sums to `k` iff `pref[j] - pref[i] == k`, i.e. `pref[i] == pref[j] - k`.

Walk the array once, maintaining the current prefix sum and a hash map `firstIdx` from prefix value to the earliest index where that prefix occurred:

1. Add `arr[j]` to `sum`.
2. If `sum == k`, the subarray `[0..j]` works; candidate length `j + 1`.
3. If `sum - k` is in the map, the subarray from `firstIdx[sum - k] + 1` to `j` works; candidate length `j - firstIdx[sum - k]`.
4. Insert `sum -> j` into the map **only if `sum` is not already present**. Keeping the earliest index is what makes the found subarray as long as possible — this matters when zeros or cancelling negatives produce repeated prefix sums.

Why does the sliding window fail here? With negatives the window sum is not monotone: shrinking from the left can *increase* the sum, so there is no safe rule for when to move `left`. The prefix map avoids that problem by remembering every prefix seen.

- **Time:** O(n) average with an unordered map (O(n log n) with an ordered map).
- **Space:** O(n)

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <unordered_map>
#include <algorithm>
using namespace std;

class Solution {
public:
    int longestSubarray(vector<int>& arr, long long k) {
        unordered_map<long long, int> firstIdx;
        long long sum = 0;
        int best = 0;
        for (int j = 0; j < (int)arr.size(); j++) {
            sum += arr[j];
            if (sum == k) best = max(best, j + 1);
            auto it = firstIdx.find(sum - k);
            if (it != firstIdx.end()) best = max(best, j - it->second);
            if (!firstIdx.count(sum)) firstIdx[sum] = j;
        }
        return best;
    }
};
```

### Java
```java
import java.util.HashMap;
import java.util.Map;

class Solution {
    public int longestSubarray(int[] arr, long k) {
        Map<Long, Integer> firstIdx = new HashMap<>();
        long sum = 0;
        int best = 0;
        for (int j = 0; j < arr.length; j++) {
            sum += arr[j];
            if (sum == k) best = Math.max(best, j + 1);
            Integer prev = firstIdx.get(sum - k);
            if (prev != null) best = Math.max(best, j - prev);
            firstIdx.putIfAbsent(sum, j);
        }
        return best;
    }
}
```

### Python
```python
class Solution:
    def longestSubarray(self, arr: list[int], k: int) -> int:
        first_idx: dict[int, int] = {}
        total = 0
        best = 0
        for j, x in enumerate(arr):
            total += x
            if total == k:
                best = max(best, j + 1)
            if total - k in first_idx:
                best = max(best, j - first_idx[total - k])
            if total not in first_idx:
                first_idx[total] = j
        return best
```

## Key Takeaways
- Subarray-sum questions on arbitrary integers reduce to "have I seen prefix `sum - k` before?" — a hash map answers that in O(1).
- Store only the **first** index of each prefix sum; overwriting it would shorten the subarrays you find.
- Handle `sum == k` explicitly (or seed the map with `0 -> -1`) so subarrays starting at index 0 are counted.
- The sliding-window trick from the positives-only version is invalid here because negatives break the monotonic sum.
