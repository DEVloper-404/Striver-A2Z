# Palindrome Number

**Difficulty:** Easy  ·  **Topic:** Learn the basics › Know Basic Maths

## Problem
Given an integer `x`, return `true` if it reads the same forwards and backwards, otherwise `false`. Negative numbers are never palindromes because of the leading minus sign.

Input: `x = 121`
Output: `true`

Input: `x = -121`
Output: `false`

Input: `x = 10`
Output: `false`

## Approach 1: Convert to a string
Turn the number into a string and compare it with its reverse (or use two pointers from both ends). Easy to write, but it allocates a string, and interviewers usually ask you to do it "without converting to a string".

- **Time:** O(log₁₀ x)
- **Space:** O(log₁₀ x)

## Approach 2: Reverse the whole number
Reverse the digits with the usual `rev = rev * 10 + x % 10` loop and compare with the original. Use a 64-bit accumulator so the reverse of a large 32-bit input cannot overflow.

- **Time:** O(log₁₀ x)
- **Space:** O(1)

## Approach 3: Reverse only half the digits
Reverse digits from the right until the reversed part is at least as large as what remains on the left. At that point:

- even digit count: `x == rev`
- odd digit count: `x == rev / 10` (drop the middle digit)

This halves the work and never overflows because `rev` only ever holds half the digits. Numbers ending in 0 (other than 0 itself) must be rejected upfront, otherwise `10` would reverse to `1` and the half-comparison would misfire.

- **Time:** O(log₁₀ x)
- **Space:** O(1)

## Code (Optimal)

### C++
```cpp
class Solution {
public:
    bool isPalindrome(int x) {
        if (x < 0 || (x % 10 == 0 && x != 0)) return false;
        int rev = 0;
        while (x > rev) {
            rev = rev * 10 + x % 10;
            x /= 10;
        }
        return x == rev || x == rev / 10;
    }
};
```

### Python
```python
class Solution:
    def isPalindrome(self, x: int) -> bool:
        if x < 0 or (x % 10 == 0 and x != 0):
            return False
        rev = 0
        while x > rev:
            rev = rev * 10 + x % 10
            x //= 10
        return x == rev or x == rev // 10
```

## Key Takeaways
- Negative numbers and non-zero numbers ending in 0 are immediate `false`.
- Reversing only half the digits avoids overflow entirely and is the version to present in an interview.
- For an odd digit count the middle digit ends up in `rev`; compare against `rev / 10` to discard it.
