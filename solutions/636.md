# Longest Increasing Subsequence

**Difficulty:** Medium  ·  **Topic:** Dynamic Programming [Patterns and Problems] › DP on LIS

## Problem
Given an integer array `nums`, return the length of the longest **strictly increasing subsequence**. A subsequence keeps the original relative order but may skip any number of elements; it does not have to be contiguous.

```
Input:  nums = [10, 9, 2, 5, 3, 7, 101, 18]
Output: 4      (one such subsequence is [2, 3, 7, 18]; [2, 3, 7, 101] also has length 4)
```

## Approach 1: Take / not-take recursion (Brute Force)
Walk the array with an index `i` and remember the index `prev` of the last element we accepted (`-1` if none yet). At each step:

- **Skip** `nums[i]`: recurse on `(i+1, prev)`.
- **Take** `nums[i]`, allowed only when `prev == -1 || nums[i] > nums[prev]`: recurse on `(i+1, i)` and add 1.

The answer is `f(0, -1)`. Memoising on `(i, prev+1)` makes this O(n²) time and O(n²) space, which is correct but wasteful.

- **Time:** O(2^n) raw, O(n²) memoised
- **Space:** O(n²)

## Approach 2: Classic O(n²) DP on "ending at i"
The cleaner state drops the `prev` dimension by *anchoring* the subsequence at its last element.

Let `dp[i]` = the length of the longest increasing subsequence that **ends exactly at index `i`**. Then `nums[i]` is the final element, and the element before it must be some `nums[j]` with `j < i` and `nums[j] < nums[i]`. Therefore:

```
dp[i] = 1 + max{ dp[j] : j < i and nums[j] < nums[i] }      (or 1 if no such j)
```

Every increasing subsequence has a unique last element, so scanning `max(dp)` over all `i` covers all of them — that is why the anchoring is safe.

**Dry run** on `[10, 9, 2, 5, 3, 7, 101, 18]`:

| i | nums[i] | valid j (nums[j] < nums[i]) | dp[i] |
|---|---------|-----------------------------|-------|
| 0 | 10      | —                           | 1     |
| 1 | 9       | —                           | 1     |
| 2 | 2       | —                           | 1     |
| 3 | 5       | 2                           | 2     |
| 4 | 3       | 2                           | 2     |
| 5 | 7       | 2, 3, 4                     | 3     |
| 6 | 101     | all                         | 4     |
| 7 | 18      | 2, 3, 4, 5                  | 4     |

`max(dp) = 4`.

- **Time:** O(n²)
- **Space:** O(n)

## Approach 3: Patience / binary search (Optimal)
Keep an array `tails` where `tails[len-1]` = the **smallest possible tail value** of any increasing subsequence of length `len` found so far. Two facts make this work:

1. `tails` is always strictly increasing. (A length-`k+1` subsequence contains a length-`k` prefix whose tail is smaller, so the best tail for `k` is smaller than the best tail for `k+1`.) Being sorted is what lets us binary search it.
2. Keeping the *smallest* tail is never harmful: a smaller tail can be extended by strictly more future elements, so it dominates any larger tail of the same length.

For each `x` in `nums`, binary search for the first entry in `tails` that is `>= x`:
- If none exists, `x` extends the longest chain — append it, growing the answer by 1.
- Otherwise overwrite that entry with `x`, improving (lowering) the best tail for that length.

The final answer is `tails.size()`. Note that `tails` is **not** necessarily an actual subsequence of the input — only its length is meaningful. (For a strictly increasing LIS use `lower_bound` / `bisect_left`; for a non-decreasing variant use `upper_bound` / `bisect_right`.)

**Dry run** on the same array:

| x   | action                       | tails            |
|-----|------------------------------|------------------|
| 10  | append                       | [10]             |
| 9   | replace 10                   | [9]              |
| 2   | replace 9                    | [2]              |
| 5   | append                       | [2, 5]           |
| 3   | replace 5                    | [2, 3]           |
| 7   | append                       | [2, 3, 7]        |
| 101 | append                       | [2, 3, 7, 101]   |
| 18  | replace 101                  | [2, 3, 7, 18]    |

Length `4`.

- **Time:** O(n log n)
- **Space:** O(n)

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int lengthOfLIS(vector<int>& nums) {
        vector<int> tails;                       // tails[k] = smallest tail of an LIS of length k+1
        for (int x : nums) {
            auto it = lower_bound(tails.begin(), tails.end(), x);
            if (it == tails.end()) tails.push_back(x);   // x extends the longest chain
            else *it = x;                                // x gives a better (smaller) tail
        }
        return (int)tails.size();
    }
};
```

### Java
```java
import java.util.Arrays;

class Solution {
    public int lengthOfLIS(int[] nums) {
        int[] tails = new int[nums.length];
        int size = 0;
        for (int x : nums) {
            int pos = Arrays.binarySearch(tails, 0, size, x);
            if (pos < 0) pos = -(pos + 1);       // insertion point = first element >= x
            tails[pos] = x;
            if (pos == size) size++;
        }
        return size;
    }
}
```

### Python
```python
from bisect import bisect_left
from typing import List


class Solution:
    def lengthOfLIS(self, nums: List[int]) -> int:
        tails = []
        for x in nums:
            pos = bisect_left(tails, x)          # first index with tails[pos] >= x
            if pos == len(tails):
                tails.append(x)
            else:
                tails[pos] = x
        return len(tails)
```

## Key Takeaways
- Anchoring the state at "subsequence ending at index i" removes the `prev` dimension and gives the standard O(n²) LIS recurrence.
- The `tails` array stays sorted by construction, which is precisely what makes binary search legal — this is the reason the O(n log n) method works.
- `tails` gives the correct *length* but is not itself a valid subsequence; to print the actual LIS you need parent pointers (see the "Print LIS" problem).
- `lower_bound`/`bisect_left` gives strictly increasing; switch to `upper_bound`/`bisect_right` for the non-decreasing version.
