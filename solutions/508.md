# Shortest path in undirected graph with unit weights

**Difficulty:** Hard  ·  **Topic:** Graphs [Concepts & Problems] › Shortest Path Algorithms and Problems

## Problem
You are given an undirected graph with `N` vertices (`0..N-1`) and `M` edges, where **every edge has weight 1**, plus a source vertex `src`. Return an array `dist` where `dist[i]` is the minimum number of edges on a path from `src` to `i`, and `-1` for vertices unreachable from `src`.

```
Input:  N = 9, src = 0,
        edges = [[0,1],[0,3],[3,4],[4,5],[5,6],[1,2],[2,6],[6,7],[7,8],[6,8]]
Output: [0, 1, 2, 1, 2, 3, 3, 4, 4]
```
For example vertex 6 is reached in 3 steps via `0 -> 1 -> 2 -> 6` (and also `0 -> 3 -> 4 -> 5 -> 6` costs 4, which is worse).

## Approach 1: Dijkstra with a priority queue
Dijkstra works on any non-negative weights, so it certainly works here. But it pays an extra `log` factor for the heap, and on unit weights that price buys nothing.

- **Time:** O((N + M) log N)
- **Space:** O(N)

## Approach 2: Plain BFS (Optimal)

**Key observation.** When all edges cost 1, the *length* of a path is just its number of edges — so "shortest path" and "fewest hops" are the same thing, and BFS explores the graph in exactly that order. BFS visits all vertices at distance 0, then all at distance 1, then all at distance 2, and so on: it expands in concentric rings around the source.

This gives the crucial guarantee: **the first time BFS reaches a vertex, it does so along a shortest path.** No later route can be shorter, because every later route is discovered from a ring at distance ≥ the current one. That is why a plain `visited` check suffices and no distance relaxation/re-insertion is ever needed — the sorted-by-distance behaviour that Dijkstra buys with a heap comes free from the FIFO queue when all weights are equal.

**Algorithm.**
1. Build the adjacency list; because the graph is undirected, each edge `[u, v]` is added to both `adj[u]` and `adj[v]`.
2. Initialise `dist[i] = -1` (meaning unvisited/unreachable) for all `i`, set `dist[src] = 0`, and push `src` into a queue.
3. While the queue is non-empty: pop `u`; for each neighbour `v` with `dist[v] == -1`, set `dist[v] = dist[u] + 1` and push `v`.
4. Return `dist`. Vertices still at `-1` are in different connected components.

Setting `dist[v]` at push time (not pop time) is what keeps each vertex out of the queue more than once.

**Dry run** on the example, source 0:
- `dist[0] = 0`, queue `[0]`.
- Pop 0: neighbours 1 and 3 get distance 1. Queue `[1, 3]`.
- Pop 1: neighbour 2 gets 2 (0 already set). Pop 3: neighbour 4 gets 2. Queue `[2, 4]`.
- Pop 2: neighbour 6 gets 3. Pop 4: neighbour 5 gets 3. Queue `[6, 5]`.
- Pop 6: neighbours 7 and 8 get 4; neighbour 5 already has 3, left alone — this is the moment where a longer alternative route to 5 is correctly rejected. Pop 5: nothing new.
- Pop 7, pop 8: neighbours already assigned. Result `[0,1,2,1,2,3,3,4,4]` ✓

- **Time:** O(N + M) — each vertex dequeued once, each edge examined twice (once from each endpoint)
- **Space:** O(N + M) for the adjacency list, O(N) for `dist` and the queue

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <queue>
using namespace std;

class Solution {
public:
    vector<int> shortestPath(vector<vector<int>>& edges, int N, int M, int src) {
        vector<vector<int>> adj(N);
        for (auto& e : edges) {
            adj[e[0]].push_back(e[1]);
            adj[e[1]].push_back(e[0]);      // undirected
        }

        vector<int> dist(N, -1);
        dist[src] = 0;
        queue<int> q;
        q.push(src);

        while (!q.empty()) {
            int u = q.front(); q.pop();
            for (int v : adj[u]) {
                if (dist[v] == -1) {        // first visit == shortest
                    dist[v] = dist[u] + 1;
                    q.push(v);
                }
            }
        }
        return dist;
    }
};
```

### Java
```java
import java.util.*;

class Solution {
    public int[] shortestPath(int[][] edges, int N, int M, int src) {
        List<List<Integer>> adj = new ArrayList<>();
        for (int i = 0; i < N; i++) adj.add(new ArrayList<>());
        for (int[] e : edges) {
            adj.get(e[0]).add(e[1]);
            adj.get(e[1]).add(e[0]);
        }

        int[] dist = new int[N];
        Arrays.fill(dist, -1);
        dist[src] = 0;
        Queue<Integer> q = new ArrayDeque<>();
        q.add(src);

        while (!q.isEmpty()) {
            int u = q.poll();
            for (int v : adj.get(u)) {
                if (dist[v] == -1) {
                    dist[v] = dist[u] + 1;
                    q.add(v);
                }
            }
        }
        return dist;
    }
}
```

### Python
```python
from collections import deque
from typing import List

class Solution:
    def shortestPath(self, edges: List[List[int]], N: int, M: int, src: int) -> List[int]:
        adj = [[] for _ in range(N)]
        for u, v in edges:
            adj[u].append(v)
            adj[v].append(u)

        dist = [-1] * N
        dist[src] = 0
        q = deque([src])
        while q:
            u = q.popleft()
            for v in adj[u]:
                if dist[v] == -1:
                    dist[v] = dist[u] + 1
                    q.append(v)
        return dist
```

## Key Takeaways
- Unit weights make BFS optimal: the FIFO queue already visits vertices in non-decreasing distance order, so no priority queue is needed.
- The first visit to a vertex is final — record the distance when you *enqueue*, not when you dequeue, to avoid duplicates.
- Use `dist[i] == -1` as both "unvisited" and "unreachable"; the two coincide at the end.
- Same technique powers grid problems (each cell is a vertex, each legal move a unit edge) and "minimum number of moves" puzzles.
