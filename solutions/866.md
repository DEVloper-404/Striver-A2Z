# Combination Sum III

**Difficulty:** Medium  ·  **Topic:** Recursion [PatternWise] › Subsequences Pattern

## Problem
Find all combinations of exactly `k` distinct digits from `1..9` that add up to `n`. Each digit may be used at most once, every combination must be unique, and the order of numbers inside a combination does not matter.

```
Input:  k = 3, n = 9
Output: [[1, 2, 6], [1, 3, 5], [2, 3, 4]]
```
`[1, 2, 6]` and `[6, 2, 1]` are the same combination, so only one is listed.

## Approach 1: Enumerate all subsets of 1..9 and filter
There are only 9 digits, so there are just `2^9 = 512` subsets. Walk the standard pick/not-pick recursion over digits 1 through 9; at the leaf, keep the subset if its size is `k` and its sum is `n`. Because we always move forward through the digits, each subset is built in increasing order and appears exactly once — uniqueness is free.

This is fast enough for the fixed 1..9 universe, but it does all its checking at the very end, exploring thousands of dead branches that could have been cut immediately.

- **Time:** O(2^9 · k) — constant, but with a big constant.
- **Space:** O(9) recursion depth.

## Approach 2: Backtracking with size and sum pruning (Optimal)
The search is the same shape, but we test the two constraints *while descending* instead of at the leaf. Two facts make the pruning sharp:

1. **Digits are positive**, so once `remaining` (what still has to be paid) drops below the digit we are about to take, no deeper choice can fix it — and since we iterate digits in increasing order, every later digit is worse too. That justifies a `break`, not just a `continue`.
2. **The count is fixed at `k`.** If `current.size() == k` and `remaining != 0`, the branch is already dead; if `remaining == 0` and the size is `k`, we have an answer.

Define `solve(digit, remaining)` where `digit` is the smallest number still allowed:

1. If `current.size() == k`: record a copy when `remaining == 0`; return either way.
2. For `d` from `digit` to `9`:
   - if `d > remaining`, `break`;
   - push `d`, recurse on `(d + 1, remaining - d)`, pop.

Passing `d + 1` enforces both "each digit at most once" and "strictly increasing order", which is what guarantees no duplicate combination is ever emitted.

**Dry run for `k = 3, n = 9`.** Starting at digit 1 with remaining 9:
- `1` → remaining 8, next digit ≥ 2. `2` → remaining 6, size 2, next digit ≥ 3; the loop needs a single digit equal to 6, so `3, 4, 5` are pushed and rejected at size 3, and `6` gives `[1, 2, 6]`. Then `7, 8, 9` are all `> 6` at the third level, so they break out.
- `1, 3` → remaining 5 → `[1, 3, 5]`. `1, 4` → remaining 4 but the next digit must be ≥ 5 > 4, break.
- `2` → remaining 7 → `2, 3` → remaining 4 → `[2, 3, 4]`. `2, 4` needs 3 from a digit ≥ 5, break.
- `3` → remaining 6, best possible continuation is `4 + 5 = 9 > 6` at each step, so those branches die quickly. `4` and above cannot reach 9 with three increasing digits at all.

- **Time:** O(C(9, k) · k) in the worst case — bounded by a small constant since the digit set is fixed.
- **Space:** O(k) for the recursion stack and the working combination.

## Code (Optimal)

### C++
```cpp
#include <vector>
using namespace std;

class Solution {
public:
    vector<vector<int>> combinationSum3(int k, int n) {
        vector<vector<int>> res;
        vector<int> cur;
        solve(1, n, k, cur, res);
        return res;
    }

private:
    void solve(int digit, int remaining, int k,
               vector<int>& cur, vector<vector<int>>& res) {
        if ((int)cur.size() == k) {
            if (remaining == 0) res.push_back(cur);
            return;
        }
        for (int d = digit; d <= 9; d++) {
            if (d > remaining) break;          // increasing digits: rest is worse
            cur.push_back(d);
            solve(d + 1, remaining - d, k, cur, res);
            cur.pop_back();
        }
    }
};
```

### Java
```java
import java.util.*;

class Solution {
    public List<List<Integer>> combinationSum3(int k, int n) {
        List<List<Integer>> res = new ArrayList<>();
        solve(1, n, k, new ArrayList<>(), res);
        return res;
    }

    private void solve(int digit, int remaining, int k,
                       List<Integer> cur, List<List<Integer>> res) {
        if (cur.size() == k) {
            if (remaining == 0) res.add(new ArrayList<>(cur));
            return;
        }
        for (int d = digit; d <= 9; d++) {
            if (d > remaining) break;
            cur.add(d);
            solve(d + 1, remaining - d, k, cur, res);
            cur.remove(cur.size() - 1);
        }
    }
}
```

### Python
```python
from typing import List

class Solution:
    def combinationSum3(self, k: int, n: int) -> List[List[int]]:
        res, cur = [], []

        def solve(digit: int, remaining: int) -> None:
            if len(cur) == k:
                if remaining == 0:
                    res.append(cur[:])
                return
            for d in range(digit, 10):
                if d > remaining:
                    break
                cur.append(d)
                solve(d + 1, remaining - d)
                cur.pop()

        solve(1, n)
        return res
```

## Key Takeaways
- Forcing strictly increasing digits (`solve(d + 1, ...)`) makes every combination unique by construction — no set, no sorting of results.
- Two independent prunes apply here: the fixed size `k` and the positive-digit `break` on `d > remaining`.
- Impossible inputs fall out automatically: the smallest reachable sum is `1+2+...+k` and the largest is `9+8+...`, so anything outside that range simply returns an empty list.
- The same skeleton solves Combination Sum I/II; only the "which index next" rule and the duplicate handling change.
