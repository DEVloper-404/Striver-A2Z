# Best time to buy and sell stock III

**Difficulty:** Medium  ·  **Topic:** Dynamic Programming [Patterns and Problems] › DP on Stocks

## Problem
Given `prices[i]` = the price of a stock on day `i`, find the maximum profit you can make with **at most two transactions**. You must sell before buying again (no holding two shares at once). Doing zero or one transaction is allowed.

```
Input:  prices = [3, 3, 5, 0, 0, 3, 1, 4]
Output: 6      (buy at 0 sell at 3 → +3, then buy at 1 sell at 4 → +3)
```

## Approach 1: Recursion with three pieces of state (Brute Force)
Extend the two-state stock machine with a counter for how many transactions remain. Let `f(i, canBuy, cap)` = best profit from day `i` onward, where `cap` is the number of transactions still allowed.

- If `cap == 0` or `i == n`: return `0`.
- If `canBuy`: `max(-prices[i] + f(i+1, false, cap), f(i+1, true, cap))`.
- Else: `max(prices[i] + f(i+1, true, cap-1), f(i+1, false, cap))` — decrement the cap on the **sell**, so a transaction counts once it is completed.

Correct, but branching twice per day is exponential.

- **Time:** O(2^n)
- **Space:** O(n)

## Approach 2: Tabulated DP over (day, canBuy, cap)
There are only `n × 2 × 3` states, so memoise or tabulate. A common alternative encoding drops the boolean and instead uses four "phases" `0..3` (buy-1, sell-1, buy-2, sell-2), which is the same machine with the states flattened.

Because day `i` reads only day `i+1`, the table collapses to a small constant number of rows.

- **Time:** O(n · 2 · 3) = O(n)
- **Space:** O(n) for the table, O(1) after compression

## Approach 3: Four rolling variables (Optimal)
This is the cleanest way to write the same DP. Track the best balance after each of the four milestones:

- `buy1` — best balance after buying the first share.
- `sell1` — best balance after selling the first share.
- `buy2` — best balance after buying the second share (funded by `sell1`).
- `sell2` — best balance after selling the second share.

Each day, update in that order:
```
buy1  = max(buy1,  -price)          // first purchase comes out of a zero balance
sell1 = max(sell1, buy1  + price)   // close the first trade
buy2  = max(buy2,  sell1 - price)   // second purchase is funded by the first trade's profit
sell2 = max(sell2, buy2  + price)   // close the second trade
```
Why is it safe to use the freshly updated value of `buy1` when computing `sell1` on the same day? Because that would mean buying and selling on the same day, which contributes exactly `0` profit — never better than what `sell1` already holds. The same argument covers the other pairs, so the in-place cascade is harmless and saves temporaries.

Since "at most two" includes doing fewer, `sell1` and `sell2` both start at `0`, and `sell2` is the answer (it is always ≥ `sell1` because a second trade of zero profit is always available).

**Dry run** on `[3, 3, 5, 0, 0, 3, 1, 4]`:

| price | buy1 | sell1 | buy2 | sell2 |
|-------|------|-------|------|-------|
| 3     | −3   | 0     | −3   | 0     |
| 3     | −3   | 0     | −3   | 0     |
| 5     | −3   | 2     | −3   | 2     |
| 0     | 0    | 2     | 2    | 2     |
| 0     | 0    | 2     | 2    | 2     |
| 3     | 0    | 3     | 2    | 5     |
| 1     | 0    | 3     | 2    | 5     |
| 4     | 0    | 4     | 2    | **6** |

Note the row for price `0`: `buy2` becomes `2`, meaning "I already banked 2 profit and bought again for free." That banked profit is exactly what makes the two-transaction chaining work.

- **Time:** O(n)
- **Space:** O(1)

## Approach 4: Split the array at every day
Another intuitive O(n) method: for each index `i`, compute `left[i]` = best single-transaction profit within `prices[0..i]` (prefix scan with a running minimum) and `right[i]` = best single-transaction profit within `prices[i..n-1]` (suffix scan with a running maximum). The answer is `max over i of left[i] + right[i]`, because the two transactions must be separated by some day. This uses O(n) extra space but is easy to reason about and to verify.

- **Time:** O(n)
- **Space:** O(n)

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <algorithm>
#include <climits>
using namespace std;

class Solution {
public:
    int maxProfit(vector<int>& prices) {
        int buy1 = INT_MIN, sell1 = 0;
        int buy2 = INT_MIN, sell2 = 0;
        for (int price : prices) {
            buy1  = max(buy1,  -price);
            sell1 = max(sell1, buy1 + price);
            buy2  = max(buy2,  sell1 - price);
            sell2 = max(sell2, buy2 + price);
        }
        return sell2;
    }
};
```

    def maxProfit(self, prices: List[int]) -> int:

        sell1 = sell2 = 0

            buy1 = max(buy1, -price)

## Key Takeaways
- The transaction cap is just one more dimension on the standard hold/free stock DP; decrement it on the sell so a trade is counted once completed.
- The four-variable form is the compressed table — `buy2 = max(buy2, sell1 - price)` is the line that chains the second trade onto the first trade's profit.
- Updating the four variables in place within one day is safe: any "same-day" artifact it allows earns 0 profit.
- "At most two" means the answer can be 0 (strictly decreasing prices) or come from a single trade; initialising both sell values to 0 handles that automatically.
