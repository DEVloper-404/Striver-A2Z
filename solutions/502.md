# Topological sort or Kahn's algorithm

**Difficulty:** Hard  ·  **Topic:** Graphs [Concepts & Problems] › Topo Sort and Problems

## Problem
Given a Directed Acyclic Graph with `V` vertices and adjacency list `adj`, output a topological ordering — a sequence containing every vertex once, in which the tail of every edge appears before its head. Kahn's algorithm builds this ordering with BFS instead of recursion.

```
Input:  V = 6, edges = [[5,0], [5,2], [4,0], [4,1], [2,3], [3,1]]
Output: 4 5 2 3 1 0        // any ordering respecting all edges is accepted
```

## Approach 1: DFS finish order (for contrast)
Run DFS, push each vertex onto a stack after its whole subtree is explored, and reverse. It works and is O(V + E), but it is recursive (stack-overflow risk on deep graphs) and does not naturally tell you *whether* the graph was acyclic.

## Approach 2: Kahn's algorithm — repeatedly remove in-degree-0 vertices (Optimal)

**Key observation.** A vertex with **in-degree 0** has no prerequisite: nothing must come before it, so it can safely be placed next in the ordering. Once you place it, you can conceptually delete it and its outgoing edges from the graph; that lowers the in-degree of each of its successors, possibly creating new in-degree-0 vertices. Repeating this peels the DAG apart layer by layer, and the order in which vertices are peeled is a topological order.

**Algorithm.**
1. Compute `indeg[v]` for every vertex by scanning all adjacency lists once: every edge `u -> v` adds 1 to `indeg[v]`.
2. Push all vertices with `indeg == 0` into a queue. These are the sources.
3. While the queue is non-empty:
   - pop `u`, append it to the answer;
   - for each neighbour `v` of `u`, do `indeg[v]--` (we "removed" edge `u -> v`); if `indeg[v]` becomes 0, push `v`.
4. If the answer contains all `V` vertices, it is a valid topological order.

**Why it is correct.** A vertex is only enqueued when its in-degree hits 0, which happens only after *all* of its predecessors have already been popped and appended. So for every edge `u -> v`, `u` is written before `v` — exactly the definition. Every vertex is enqueued exactly once (in-degree drops to 0 once and never rises), so the output is a permutation of the vertices.

**Cycle detection comes free.** Every vertex on a cycle has a predecessor inside that cycle, so its in-degree never reaches 0 and it is never enqueued. Therefore if the produced list has fewer than `V` entries, the graph contains a cycle and no topological order exists. This is why Kahn's is the tool of choice for "Course Schedule"-style problems.

**Dry run** on the example. Edges: `5->0, 5->2, 4->0, 4->1, 2->3, 3->1`.
- In-degrees: `0:2 (from 5,4)`, `1:2 (from 4,3)`, `2:1 (from 5)`, `3:1 (from 2)`, `4:0`, `5:0`.
- Queue starts `[4, 5]`. Pop 4 → output `4`; decrement 0 → 1, decrement 1 → 1. Nothing hits 0.
- Pop 5 → output `4 5`; 0 → 0 (push 0), 2 → 0 (push 2). Queue `[0, 2]`.
- Pop 0 → output `4 5 0`; no outgoing edges. Pop 2 → output `4 5 0 2`; 3 → 0 (push 3).
- Pop 3 → output `4 5 0 2 3`; 1 → 0 (push 1). Pop 1 → output `4 5 0 2 3 1`. Six vertices → valid.

- **Time:** O(V + E) — one pass to build in-degrees, then each vertex dequeued once and each edge relaxed once
- **Space:** O(V) for the in-degree array and queue

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <queue>
using namespace std;

class Solution {
public:
    vector<int> topoSort(int V, vector<vector<int>>& adj) {
        vector<int> indeg(V, 0);
        for (int u = 0; u < V; u++)
            for (int v : adj[u]) indeg[v]++;

        queue<int> q;
        for (int i = 0; i < V; i++)
            if (indeg[i] == 0) q.push(i);

        vector<int> order;
        order.reserve(V);
        while (!q.empty()) {
            int u = q.front(); q.pop();
            order.push_back(u);
            for (int v : adj[u]) {
                if (--indeg[v] == 0) q.push(v);
            }
        }
        // order.size() < V  =>  the graph has a cycle
        return order;
    }
};
```

### Java
```java
import java.util.*;

class Solution {
    public int[] topoSort(int V, List<List<Integer>> adj) {
        int[] indeg = new int[V];
        for (int u = 0; u < V; u++)
            for (int v : adj.get(u)) indeg[v]++;

        Queue<Integer> q = new ArrayDeque<>();
        for (int i = 0; i < V; i++)
            if (indeg[i] == 0) q.add(i);

        int[] order = new int[V];
        int idx = 0;
        while (!q.isEmpty()) {
            int u = q.poll();
            order[idx++] = u;
            for (int v : adj.get(u)) {
                if (--indeg[v] == 0) q.add(v);
            }
        }
        if (idx < V) return new int[0];   // cycle: no topological order
        return order;
    }
}
```

### Python
```python
from collections import deque
from typing import List

class Solution:
    def topoSort(self, V: int, adj: List[List[int]]) -> List[int]:
        indeg = [0] * V
        for u in range(V):
            for v in adj[u]:
                indeg[v] += 1

        q = deque(i for i in range(V) if indeg[i] == 0)
        order: List[int] = []
        while q:
            u = q.popleft()
            order.append(u)
            for v in adj[u]:
                indeg[v] -= 1
                if indeg[v] == 0:
                    q.append(v)

        return order if len(order) == V else []   # empty => cycle
```

## Key Takeaways
- Kahn's algorithm = BFS over in-degrees: repeatedly output a vertex with no remaining prerequisites.
- A vertex enters the queue only once — the instant its last incoming edge is removed.
- `len(order) < V` means a cycle, which makes this the standard cycle-detection method for directed graphs.
- Iterative, so no recursion-depth limit; swap the queue for a min-heap if you need the lexicographically smallest topological order.
