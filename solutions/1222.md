# Introduction to Graph

**Difficulty:** Easy  ·  **Topic:** Graphs [Concepts & Problems] › Learning

## Problem
This item introduces graphs: what they are, the vocabulary you will meet in every graph problem, the two standard ways to store them, and how to read the input format that judges use. There is no single computation to perform — the goal is to be fluent in the terminology and to be able to build a graph in memory before attempting traversal problems.

A graph is a set of **nodes** (also called vertices) connected by **edges**. Unlike a tree, a graph may contain cycles, may be disconnected, and has no designated root.

Typical input format: the first line gives `n` (number of nodes) and `m` (number of edges), followed by `m` lines each holding one edge `u v`.

```
Input:
5 4
1 2
1 3
2 4
3 5

Meaning: 5 nodes; node 1 is connected to 2 and 3, node 2 to 4, node 3 to 5.
```

## Approach: the vocabulary and the two representations

**Directed vs undirected.** In an **undirected** graph an edge `u—v` can be traversed both ways, so it appears in the adjacency list of both `u` and `v`. In a **directed** graph an edge `u→v` only goes one way and is stored only under `u`. Almost every bug beginners hit in graph problems is forgetting to add the reverse edge for an undirected graph.

**Degree.** In an undirected graph, the degree of a node is the number of edges touching it. Summing degrees over all nodes counts every edge twice, so **total degree = 2 × E**. In a directed graph you instead speak of *indegree* (edges coming in) and *outdegree* (edges going out).

**Path.** A sequence of nodes where consecutive nodes are connected by an edge and no node repeats. A **cycle** is a path that returns to its starting node.

**Connected components.** A graph need not be one piece. A connected component is a maximal set of nodes that can all reach each other. This is why traversal code almost always looks like:

```cpp
for (int i = 1; i <= n; i++)
    if (!visited[i]) dfs(i);      // one call per component
```
Forgetting this outer loop is the second classic bug — you only explore the component containing your starting node.

**Weighted graphs.** Edges may carry a cost. The input then has three numbers per line (`u v w`) and the adjacency list stores pairs `(neighbour, weight)`.

**Representation 1 — adjacency matrix.** A 2-D array `adj[n+1][n+1]` where `adj[u][v] = 1` (or the weight) if an edge exists. Checking "is there an edge between u and v?" is O(1), which is its one real advantage.

```cpp
vector<vector<int>> adj(n + 1, vector<int>(n + 1, 0));
adj[u][v] = 1;
adj[v][u] = 1;      // undirected only
```
Memory is O(N²) regardless of how few edges there are, so with `n = 10^5` this is 10^10 cells — completely unusable. Use it only for small, dense graphs.

**Representation 2 — adjacency list.** For each node, store a list of its neighbours. Memory is O(N + 2E) for undirected graphs, which is what real constraints demand, and iterating a node's neighbours is proportional to its degree rather than to `n`.

```cpp
vector<vector<int>> adj(n + 1);
adj[u].push_back(v);
adj[v].push_back(u);   // undirected only
```
This is the default choice in virtually every competitive/interview problem.

**1-indexed vs 0-indexed.** Judges usually number nodes `1..n`. Sizing the containers as `n + 1` and ignoring index 0 is the simplest way to avoid off-by-one errors; if the problem numbers nodes `0..n-1`, size them `n`.

- **Time:** O(N + M) to build an adjacency list; O(N²) to allocate a matrix
- **Space:** O(N + 2M) for an adjacency list (undirected); O(N²) for a matrix

## Code (Optimal)

### C++
```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n, m;
    cin >> n >> m;                       // n nodes (1..n), m edges

    vector<vector<int>> adj(n + 1);      // adjacency list
    for (int i = 0; i < m; i++) {
        int u, v;
        cin >> u >> v;
        adj[u].push_back(v);
        adj[v].push_back(u);             // drop this line for a directed graph
    }

    for (int u = 1; u <= n; u++) {
        cout << u << " ->";
        for (int v : adj[u]) cout << ' ' << v;
        cout << '\n';
    }
    return 0;
}
```

### Java
```java
import java.util.*;

public class Main {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        int n = sc.nextInt(), m = sc.nextInt();

        List<List<Integer>> adj = new ArrayList<>();
        for (int i = 0; i <= n; i++) adj.add(new ArrayList<>());

        for (int i = 0; i < m; i++) {
            int u = sc.nextInt(), v = sc.nextInt();
            adj.get(u).add(v);
            adj.get(v).add(u);           // omit for a directed graph
        }

        for (int u = 1; u <= n; u++) {
            System.out.println(u + " -> " + adj.get(u));
        }
        sc.close();
    }
}
```

### Python
```python
import sys

def main():
    data = sys.stdin.read().split()
    idx = 0
    n, m = int(data[idx]), int(data[idx + 1])
    idx += 2

    adj = [[] for _ in range(n + 1)]     # nodes 1..n
    for _ in range(m):
        u, v = int(data[idx]), int(data[idx + 1])
        idx += 2
        adj[u].append(v)
        adj[v].append(u)                 # omit for a directed graph

    for u in range(1, n + 1):
        print(u, "->", adj[u])

if __name__ == "__main__":
    main()
```

## Key Takeaways
- Adjacency list is the default: O(N + 2E) memory and neighbour iteration proportional to degree; the matrix is only for small dense graphs needing O(1) edge lookups.
- For an **undirected** graph you must push the edge into both lists — forgetting the reverse edge is the most common beginner bug.
- Graphs can be disconnected, so traversals need an outer loop over all nodes that starts a new search from every unvisited one.
- Size containers as `n + 1` when nodes are numbered `1..n`; store `(neighbour, weight)` pairs when edges are weighted.
