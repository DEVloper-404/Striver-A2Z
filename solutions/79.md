# Split array - largest sum

**Difficulty:** Hard  ·  **Topic:** Binary Search [1D, 2D Arrays, Search Space] › BS on Answers

## Problem
Given an integer array `nums` and an integer `k`, split `nums` into `k` non-empty contiguous subarrays so that the largest subarray sum is as small as possible. Return that minimised largest sum.

Input: nums = [7, 2, 5, 10, 8], k = 2
Output: 18  (split as [7, 2, 5] and [10, 8] → sums 14 and 18)

## Approach 1: Recursive Partitioning (Brute Force / DP)
Define `f(i, k)` = the minimum largest sum when splitting `nums[i..]` into `k` parts. Try every possible end for the first part, take the max of its sum and `f(next, k - 1)`, and keep the minimum. With memoisation this is O(n^2 * k), which is fine for small inputs but far from optimal.
- **Time:** O(n^2 * k) with memoisation
- **Space:** O(n * k)

## Approach 2: Binary Search on the Largest Sum
Any answer lies between `max(nums)` (the largest single element must fit somewhere) and `sum(nums)` (everything in one part). For a candidate limit `L`, greedily count how many subarrays are needed if no subarray may exceed `L`: start a new one whenever adding the next element would overflow. If the count is `<= k`, `L` is achievable (extra parts can be created by splitting further, which never raises the max). The count is non-increasing in `L`, so binary search for the smallest feasible `L`.
- **Time:** O(n * log(sum - max))
- **Space:** O(1)

## Code (Optimal)

### C++
```cpp
class Solution {
public:
    int partsNeeded(const vector<int>& nums, int limit) {
        int parts = 1;
        long long cur = 0;
        for (int x : nums) {
            if (cur + x > limit) { parts++; cur = 0; }
            cur += x;
        }
        return parts;
    }

    int splitArray(vector<int>& nums, int k) {
        int lo = *max_element(nums.begin(), nums.end());
        int hi = accumulate(nums.begin(), nums.end(), 0);
        int ans = hi;
        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2;
            if (partsNeeded(nums, mid) <= k) {
                ans = mid;
                hi = mid - 1;
            } else {
                lo = mid + 1;
            }
        }
        return ans;
    }
};
```

### Java

```java
class Solution {
    private int partsNeeded(int[] nums, int limit) {
        int parts = 1;
        long cur = 0;
        for (int x : nums) {
            if (cur + x > limit) { parts++; cur = 0; }
            cur += x;
        }
        return parts;
    }

    public int splitArray(int[] nums, int k) {
        int lo = 0, hi = 0;
        for (int x : nums) { lo = Math.max(lo, x); hi += x; }
        int ans = hi;
        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2;
            if (partsNeeded(nums, mid) <= k) {
                ans = mid;
                hi = mid - 1;
            } else {
                lo = mid + 1;
            }
        }
        return ans;
    }
}
```

### Python
```python
from typing import List

class Solution:
    def splitArray(self, nums: List[int], k: int) -> int:
        def parts_needed(limit: int) -> int:
            parts, cur = 1, 0
            for x in nums:
                if cur + x > limit:
                    parts += 1
                    cur = 0
                cur += x
            return parts

        lo, hi = max(nums), sum(nums)
        ans = hi
        while lo <= hi:
            mid = (lo + hi) // 2
            if parts_needed(mid) <= k:
                ans = mid
                hi = mid - 1
            else:
                lo = mid + 1
        return ans
```

## Key Takeaways
- Same code as Book Allocation with `k` students; only the story changes.
- The greedy check with `<= k` is correct because splitting a subarray further never increases the maximum.
- Since `k <= n` is guaranteed on LeetCode, no `-1` case is needed here.
