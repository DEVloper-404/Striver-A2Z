# DFS

**Difficulty:** Medium  ·  **Topic:** Graphs [Concepts & Problems] › Learning

## Problem
Depth-first search visits a graph by committing to one path and following it as far as it goes before backing up and trying the next option. Given a graph with `V` vertices (`0..V-1`) as an adjacency list, return the order in which DFS starting at vertex 0 visits the nodes.

```
Input:  V = 5, adj = [[1,2,3], [0], [0,4], [0], [2]]
Output: [0, 1, 2, 4, 3]
```
Starting at 0 we dive into 1 (dead end), come back, dive into 2 → 4 (dead end), come back, then 3.

## Approach 1: The idea and why it terminates
Think of exploring a maze while holding a piece of chalk. At every junction you mark the floor, then walk down the first unmarked corridor. When you hit a dead end — or a junction where every corridor is already chalked — you walk back to the previous junction and try its next corridor. You stop when you back all the way out of the entrance.

Two things make this correct:
1. **The visited array guarantees termination.** A graph may have cycles, so naive "follow edges" would loop forever. Since we only recurse into unvisited nodes and mark each node at most once, at most `V` recursive frames are ever opened.
2. **It reaches everything reachable.** Suppose some node `u` reachable from the source were never visited. Take a path `src → ... → x → u`; since `src` is visited, walk along the path to the first unvisited node — its predecessor `x` is visited, and when we processed `x` we looped over *all* of its neighbours, including `u`, and would have recursed into it. Contradiction.

The recursion stack is doing the bookkeeping of "where do I return to". That is exactly a stack, which is why the iterative version simply replaces the call stack with an explicit one.
- **Time:** O(V + E) — every vertex is entered once and every adjacency entry is read once.
- **Space:** O(V) for `visited` plus O(V) recursion depth in the worst case (a path graph).

## Approach 2: Recursive DFS, step by step
```
dfs(node):
    visited[node] = true
    append node to the answer            # pre-order position
    for nb in adj[node]:
        if not visited[nb]:
            dfs(nb)
    # anything written here runs on the way back up (post-order position)
```

Dry run on `adj = [[1,2,3], [0], [0,4], [0], [2]]` starting at 0:

| step | call | action |
|---|---|---|
| 1 | `dfs(0)` | mark 0, order `[0]`, neighbours 1,2,3 |
| 2 | `dfs(1)` | mark 1, order `[0,1]`, only neighbour 0 is visited → return |
| 3 | `dfs(2)` | mark 2, order `[0,1,2]`, neighbour 0 visited, neighbour 4 free |
| 4 | `dfs(4)` | mark 4, order `[0,1,2,4]`, neighbour 2 visited → return |
| 5 | back in `dfs(0)` | neighbour 3 free |
| 6 | `dfs(3)` | mark 3, order `[0,1,2,4,3]` → return |

The order depends on the order of neighbours in the adjacency list — DFS order is not unique.

The **post-order position** (after the loop) is what makes DFS more than a traversal: writing to a list there gives a reverse topological order for a DAG, and tracking a "currently in the recursion stack" flag there gives directed cycle detection.

For a possibly disconnected graph, wrap the call: `for i in 0..V-1: if not visited[i]: dfs(i)` — that also counts connected components.
- **Time:** O(V + E)
- **Space:** O(V)

## Approach 3: Iterative DFS
When `V` reaches 10^5 and the graph can be a long chain, recursion depth becomes a real risk (stack overflow in C++/Java, `RecursionError` in Python). Replace the call stack with a manual one:

1. Push the source, mark visited.
2. Pop a node, append it to the order.
3. Push each unvisited neighbour and mark it visited.

Note this produces a valid DFS order but not necessarily the *same* order as the recursive version, because the last neighbour pushed is popped first. Pushing neighbours in reverse gives the recursive order back.
- **Time:** O(V + E)
- **Space:** O(V)

## Code (Optimal)

### C++
```cpp
#include <vector>
using namespace std;

class Solution {
public:
    vector<int> dfsOfGraph(int V, vector<vector<int>>& adj) {
        vector<int> order;
        vector<int> visited(V, 0);
        dfs(0, adj, visited, order);
        return order;
    }

private:
    void dfs(int node, vector<vector<int>>& adj, vector<int>& visited, vector<int>& order) {
        visited[node] = 1;
        order.push_back(node);
        for (int nb : adj[node]) {
            if (!visited[nb]) dfs(nb, adj, visited, order);
        }
    }
};
```

### Java
```java
import java.util.*;

class Solution {
    public List<Integer> dfsOfGraph(int V, List<List<Integer>> adj) {
        List<Integer> order = new ArrayList<>();
        boolean[] visited = new boolean[V];
        dfs(0, adj, visited, order);
        return order;
    }

    private void dfs(int node, List<List<Integer>> adj, boolean[] visited, List<Integer> order) {
        visited[node] = true;
        order.add(node);
        for (int nb : adj.get(node)) {
            if (!visited[nb]) dfs(nb, adj, visited, order);
        }
    }
}
```

### Python
```python
from typing import List

class Solution:
    def dfsOfGraph(self, V: int, adj: List[List[int]]) -> List[int]:
        order = []
        visited = [False] * V
        stack = [0]
        visited[0] = True
        while stack:
            node = stack.pop()
            order.append(node)
            # reversed() so neighbours are explored in list order,
            # matching the recursive version
            for nb in reversed(adj[node]):
                if not visited[nb]:
                    visited[nb] = True
                    stack.append(nb)
        return order
```

## Key Takeaways
- DFS = stack semantics; mark visited on entry so cycles cannot loop forever.
- The code position *after* the neighbour loop (post-order) is where topological sort and cycle detection hook in.
- DFS order is not unique — it depends on adjacency-list ordering — and it does **not** give shortest paths.
- Prefer the iterative form when the graph can be ~10^5 nodes deep.
