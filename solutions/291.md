# Maximum sum of non adjacent elements

**Difficulty:** Medium  ·  **Topic:** Dynamic Programming [Patterns and Problems] › 1D DP

## Problem
Given an array `nums` of non-negative integers, pick a subset of elements with **no two adjacent** indices so that their sum is as large as possible. Return that maximum sum. (This is exactly LeetCode's *House Robber* — houses in a row, and you cannot rob two neighbours.)

```
Input:  nums = [2, 1, 4, 9]
Output: 11
        Pick indices 0 and 3 → 2 + 9 = 11 (indices 1 and 3 give 10)
```

## Approach 1: Recursion — pick or skip (brute force)

**Key observation.** Walk the array from the last index backwards and ask a single yes/no question at each element: *do I take it?* The two choices are constrained differently, and that constraint is the whole problem:

- **Take `nums[i]`** — then index `i-1` is forbidden, so the rest of the answer comes from the prefix ending at `i-2`: `nums[i] + f(i-2)`.
- **Skip `nums[i]`** — no constraint is created, so the answer is `f(i-1)`.

Take the better of the two:
```
f(i) = max( nums[i] + f(i-2), f(i-1) )
f(0) = nums[0]
f(i) = 0 for i < 0
```

Why is this correct? The "no two adjacent" rule is *local* — it only ever relates `i` to `i-1`. Once we decide about `i`, the remaining subproblem is a clean, smaller instance of the same problem on a prefix, with no leftover state to carry. That is what makes a one-parameter DP sufficient.

**Why greedy fails:** "repeatedly take the largest remaining element and delete its neighbours" looks plausible but breaks on `[4, 5, 4, 0, 4, 5, 4]` — it grabs both 5s (total 10) while taking the four 4s at indices 0, 2, 4, 6 gives 16. Only comparing both branches at every position is safe.

Written as plain recursion each call spawns two more, so the tree is `O(2^n)`.
- **Time:** O(2^n)
- **Space:** O(n) recursion stack

## Approach 2: Memoization
The state is the single index `i`, so there are `n` states, each doing O(1) work. Cache `f(i)` in `dp[i]` (sentinel `-1`) and return the cached value on a repeat visit.
- **Time:** O(n)
- **Space:** O(n) table + O(n) stack

## Approach 3: Tabulation
Fill forward. `dp[0] = nums[0]`; for `i = 1 … n-1`:
```
take = nums[i] + (i > 1 ? dp[i-2] : 0)
skip = dp[i-1]
dp[i] = max(take, skip)
```
The answer is `dp[n-1]`. Note `dp[i]` means "best sum using only the first `i+1` elements", so it is non-decreasing in `i` for non-negative inputs.
- **Time:** O(n)
- **Space:** O(n)

## Approach 4: Two rolling variables (Optimal)

`dp[i]` depends only on `dp[i-1]` and `dp[i-2]`, so replace the array with two variables: `prev1 = dp[i-1]` and `prev2 = dp[i-2]`.

**Algorithm.**
1. `prev2 = 0`, `prev1 = nums[0]`.
2. For `i = 1 … n-1`:
   - `take = nums[i] + prev2`
   - `skip = prev1`
   - `cur = max(take, skip)`
   - slide: `prev2 = prev1`, `prev1 = cur`
3. Return `prev1`.

Initialising `prev2 = 0` before the loop is exactly the `i-2 < 0 → 0` base case, so no special-casing is needed inside the loop.

**Dry run on `[2, 1, 4, 9]`.** Start `prev2 = 0`, `prev1 = 2`.

| i | nums[i] | take = nums[i]+prev2 | skip = prev1 | cur | (prev2, prev1) |
|---|---|---|---|---|---|
| 1 | 1 | 1 + 0 = 1 | 2 | **2** | (2, 2) |
| 2 | 4 | 4 + 2 = 6 | 2 | **6** | (2, 6) |
| 3 | 9 | 9 + 2 = 11 | 6 | **11** | (6, 11) |

Return `11` — the subset `{2, 9}`. ✔ Notice at `i = 3` the algorithm compared "rob house 3 plus the best up to house 1" against "don't rob house 3 and keep the best up to house 2", exactly the pick/skip split.
- **Time:** O(n)
- **Space:** O(1)

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int maxNonAdjacentSum(vector<int>& nums) {
        int n = nums.size();
        if (n == 0) return 0;
        int prev2 = 0;            // best using elements up to i-2
        int prev1 = nums[0];      // best using elements up to i-1
        for (int i = 1; i < n; i++) {
            int take = nums[i] + prev2;
            int skip = prev1;
            int cur  = max(take, skip);
            prev2 = prev1;
            prev1 = cur;
        }
        return prev1;
    }

    // LeetCode 198 signature
    int rob(vector<int>& nums) { return maxNonAdjacentSum(nums); }
};
```

### Python
```python
from typing import List


class Solution:
    def maxNonAdjacentSum(self, nums: List[int]) -> int:
        if not nums:
            return 0
        prev2 = 0                 # best using elements up to i-2
        prev1 = nums[0]           # best using elements up to i-1
        for i in range(1, len(nums)):
            take = nums[i] + prev2
            skip = prev1
            prev2, prev1 = prev1, max(take, skip)
        return prev1

    # LeetCode 198 signature
    def rob(self, nums: List[int]) -> int:
        return self.maxNonAdjacentSum(nums)
```

## Key Takeaways
- The pick/skip template: at each index compare `value + f(i-2)` (take, blocking the neighbour) against `f(i-1)` (skip). This is the base pattern for every "no two adjacent" variant.
- The adjacency constraint is local, so a one-dimensional state (the index) is enough — no need to remember what was picked earlier.
- `prev2 = 0` before the loop encodes the `i < 0 → 0` base case cleanly.
- With negative numbers allowed, clamp the "take" branch (or the answer) at 0 if the empty subset is permitted.
- The circular version (first and last are neighbours) reuses this exactly twice: once on `nums[0..n-2]`, once on `nums[1..n-1]`, taking the max — see *House Robber II*.
