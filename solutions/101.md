# Construct a BST from a preorder traversal

**Difficulty:** Medium  ·  **Topic:** Binary Search Trees [Concept and Problems] › Practice Problems

## Problem
Given an array that is the preorder traversal (node → left → right) of a BST with distinct values, rebuild the tree and return its root.

```
Input:  preorder = [8, 5, 1, 7, 10, 12]
Output: [8, 5, 10, 1, 7, null, 12]

Input:  preorder = [1, 3]
Output: [1, null, 3]
```

Unlike a general binary tree, a BST needs only *one* traversal to be reconstructed — the ordering property supplies the missing information that a second traversal would normally provide.

## Approach 1: Repeated BST insertion
Create an empty tree, then insert `preorder[0]`, `preorder[1]`, … one by one using standard BST insertion. Because preorder always emits a node before any of its descendants, each element is inserted after all of its ancestors, so it lands in exactly the right place.

Simple and obviously correct, but each insertion costs O(H), and if the input is already sorted the tree degenerates into a chain.
- **Time:** O(N·H) — O(N log N) average, O(N²) worst case
- **Space:** O(H) for the insertion walk

## Approach 2: Better (sort to get inorder, then use the preorder+inorder construction)
Sorting the preorder array gives the inorder traversal of the same BST (distinct values). Now you have both traversals and can apply the classic O(N) preorder+inorder reconstruction with a hash map of inorder positions.

Correct, but it needs a sort, an extra array, and a hash map for information the BST property already encodes.
- **Time:** O(N log N) dominated by the sort
- **Space:** O(N)

## Approach 3: Optimal (single pass with an upper bound)
Here is the observation that makes this linear. Walk the preorder array left to right with a global index `i`. Build a recursive function `build(bound)` that consumes elements belonging to the subtree whose values must all be **less than `bound`**:

1. If `i` has run past the end, or `preorder[i] > bound`, this subtree is empty — return null without consuming anything.
2. Otherwise `preorder[i]` is the root of this subtree. Consume it (`i++`).
3. Its **left** subtree contains exactly the following elements that are smaller than the root, so recurse with `bound = root->val`.
4. Its **right** subtree contains the elements that are larger than the root but still smaller than the *inherited* bound, so recurse with `bound` unchanged.

Why is the single upper bound enough? In preorder, the elements of a subtree form one contiguous block that starts at the root. Everything after the root that is smaller than it belongs to the left subtree; the first element that exceeds the root ends the left subtree. And the right subtree ends where the element exceeds the ancestor bound we inherited. A lower bound is never needed because we scan strictly left to right — anything already consumed can never be revisited.

**Dry run** on `[8, 5, 1, 7, 10, 12]` with initial `bound = +∞`:
- `build(∞)`: takes `8`. Root = 8.
  - Left = `build(8)`: takes `5`. 
    - Left = `build(5)`: takes `1`. Its `build(1)` sees `7 > 1` → null. Its `build(5)` sees `7 > 5` → null. So node `1` is a leaf. Returns 1.
    - Right = `build(8)`: `7 < 8` → takes `7`. Both its calls immediately see `10`, which exceeds bounds 7 and 8 → leaf. Returns 7.
    - So node `5` has children `1` and `7`.
  - Right = `build(∞)`: `10 < ∞` → takes `10`.
    - Left = `build(10)`: `12 > 10` → null.
    - Right = `build(∞)`: takes `12` → leaf.
  - Root `8` has left `5` and right `10`. ✔

Each array element is consumed exactly once and each null check is O(1), so the whole construction is a single linear sweep.
- **Time:** O(N)
- **Space:** O(H) recursion stack (an explicit stack version can make it iterative)

## Code (Optimal)

### C++
```cpp
// struct TreeNode { int val; TreeNode *left, *right; TreeNode(int x) : val(x), left(nullptr), right(nullptr) {} } — standard definition
#include <vector>
#include <climits>
using namespace std;

class Solution {
    int i = 0;

    TreeNode* build(vector<int>& pre, long long bound) {
        // Nothing left, or the next value belongs to an ancestor's right subtree.
        if (i == (int)pre.size() || pre[i] > bound) return nullptr;

        TreeNode* root = new TreeNode(pre[i++]);
        root->left  = build(pre, root->val);   // left subtree: values < root
        root->right = build(pre, bound);       // right subtree: root < values < bound
        return root;
    }
public:
    TreeNode* bstFromPreorder(vector<int>& preorder) {
        i = 0;
        return build(preorder, LLONG_MAX);
    }
};
```

### Java
```java
// class TreeNode { int val; TreeNode left, right; TreeNode(int x) { val = x; } } — standard definition

class Solution {
    private int i = 0;

    private TreeNode build(int[] pre, long bound) {
        if (i == pre.length || pre[i] > bound) return null;

        TreeNode root = new TreeNode(pre[i++]);
        root.left  = build(pre, root.val);
        root.right = build(pre, bound);
        return root;
    }

    public TreeNode bstFromPreorder(int[] preorder) {
        i = 0;
        return build(preorder, Long.MAX_VALUE);
    }
}
```

### Python
```python
# class TreeNode: val, left, right — standard definition

class Solution:
    def bstFromPreorder(self, preorder):
        self.i = 0

        def build(bound):
            if self.i == len(preorder) or preorder[self.i] > bound:
                return None
            root = TreeNode(preorder[self.i])
            self.i += 1
            root.left = build(root.val)   # everything smaller than root comes next
            root.right = build(bound)     # then values between root and the inherited bound
            return root

        return build(float('inf'))
```

## Key Takeaways
- A BST is fully determined by its preorder alone — the ordering property replaces the second traversal you would need for a general binary tree.
- The one-bound trick works because preorder lays out each subtree as a contiguous block beginning with its root; the first value exceeding the bound marks where that block ends.
- A shared index (`i`) advanced by the recursion is what keeps this a single O(N) sweep instead of repeated scanning.
- Use a bound type wider than `int` (or `+∞`) so that a node holding `INT_MAX` is not mistakenly rejected.
