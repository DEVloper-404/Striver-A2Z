# Linear Search

**Difficulty:** Easy  ·  **Topic:** Solve Problems on Arrays [Easy -> Medium -> Hard] › Easy

## Problem
Given an array of `n` integers and a target value `num`, return the index of the first occurrence of `num` in the array. If `num` is not present, return `-1`.

Input: `arr = [1, 2, 3, 4, 5], num = 3`
Output: `2`

Input: `arr = [5, 4, 3, 2], num = 1`
Output: `-1`

## Approach 1: Linear Scan
The array carries no ordering guarantee, so there is nothing to exploit: check each element from left to right and stop at the first match. Returning immediately on a hit means the average case can be much faster than `n` steps when the target is near the front; the worst case (target absent or at the end) inspects every element.

If the array were sorted, binary search would bring this down to O(log n), but for unsorted data a full scan is the best possible, since any element skipped could have been the target.

- **Time:** O(n) worst case, O(1) best case.
- **Space:** O(1)

## Code (Optimal)

### C++
```cpp
#include <vector>
using namespace std;

class Solution {
public:
    int linearSearch(vector<int>& arr, int num) {
        for (int i = 0; i < (int)arr.size(); i++) {
            if (arr[i] == num) return i;
        }
        return -1;
    }
};
```

### Java
```java
class Solution {
    public int linearSearch(int[] arr, int num) {
        for (int i = 0; i < arr.length; i++) {
            if (arr[i] == num) return i;
        }
        return -1;
    }
}
```

### Python
```python
class Solution:
    def linearSearch(self, arr: list[int], num: int) -> int:
        for i, x in enumerate(arr):
            if x == num:
                return i
        return -1
```

## Key Takeaways
- Unsorted data forces a full scan; O(n) is a lower bound because every unread element could be the answer.
- Return on the first match so the function reports the earliest index.
- Edge cases: empty array returns `-1`; duplicates return the smallest matching index.
