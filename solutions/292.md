# Ninja's training

**Difficulty:** Medium  ·  **Topic:** Dynamic Programming [Patterns and Problems] › 2D/3D DP and DP on Grids

## Problem
A ninja trains for `n` days. Each day he can do exactly one of three activities — running (0), fighting (1), or learning (2) — and `points[day][activity]` is the merit he earns. The rule: he may **not** repeat the same activity on two consecutive days. Return the maximum total merit over the `n` days.

```
Input:  points = [[10, 40, 70],
                  [20, 50, 80],
                  [30, 60, 90]]
Output: 210
        Day 0 → activity 2 (70), day 1 → activity 1 (50), day 2 → activity 2 (90)
```

## Approach 1: Recursion (brute force)

**Why one index is not enough.** Unlike the 1D problems, knowing "which day am I on" is not sufficient — the legal choices today depend on what was done yesterday. So the state needs a second parameter.

Define `f(day, last)` = maximum merit obtainable from day `0` through day `day`, where `last` is the activity that is **forbidden** on `day` (because it was chosen on `day+1`). Use `last = 3` as a sentinel meaning "nothing is forbidden", which is what we pass for the final day.

```
f(day, last) = max over task in {0,1,2}, task != last  of
                   points[day][task] + f(day-1, task)
f(0, last)   = max over task != last of points[0][task]
```

Reading it top-down: on the last day we try each allowed activity, add its points, and recursively solve the previous days with that activity now banned.

Why is this correct? The constraint is again *local* — it only relates consecutive days — so once we fix today's activity, everything about the past is summarised by a single number (that activity). No further history matters.

The recursion branches into 3 (really 2, after excluding `last`) at every level, so it costs about `O(2^n)`.
- **Time:** O(2^n)
- **Space:** O(n) recursion stack

## Approach 2: Memoization
The state space is small: `n` days × 4 values of `last` = `4n` states, each doing O(3) work. Cache in `dp[day][last]` with sentinel `-1`.
- **Time:** O(n · 4 · 3) = O(n)
- **Space:** O(4n) table + O(n) recursion stack

## Approach 3: Tabulation (bottom-up)

Keep the same meaning as the recursion — `dp[day][last]` = best merit over days `0..day` when activity `last` is banned on `day` — and fill days in increasing order, so row `day` is built from the already-final row `day-1`.

**Base row (day 0).** For each `last` in `0..3`, `dp[0][last] = max(points[0][task])` over `task != last`. Concretely, for `last = 0` it is `max(p[0][1], p[0][2])`, and for the sentinel `last = 3` it is the max of all three.

**Transition.** For `day = 1 … n-1` and each `last` in `0..3`:
```
dp[day][last] = max over task != last of ( points[day][task] + dp[day-1][task] )
```

**Answer:** `dp[n-1][3]` — the last day with nothing banned.

- **Time:** O(n · 4 · 3) = O(n)
- **Space:** O(4n)

## Approach 4: Rolling row (Optimal)

Row `day` reads only row `day-1`, so a single array of 4 numbers replaces the table.

**Algorithm.**
1. Build `prev[0..3]` from `points[0]` as described above.
2. For each subsequent day, build a fresh `cur[0..3]` using `prev`, then set `prev = cur`.
3. Return `prev[3]`.

**Dry run on the example.**

Day 0 row: `points[0] = [10, 40, 70]`.
`prev[0] = max(40,70) = 70`, `prev[1] = max(10,70) = 70`, `prev[2] = max(10,40) = 40`, `prev[3] = 70`.

Day 1, `points[1] = [20, 50, 80]`:
- `cur[0]` = max over task ∈ {1,2}: `50 + prev[1]=70` → 120; `80 + prev[2]=40` → 120 ⇒ **120**
- `cur[1]` = max over {0,2}: `20 + 70` = 90; `80 + 40` = 120 ⇒ **120**
- `cur[2]` = max over {0,1}: `20 + 70` = 90; `50 + 70` = 120 ⇒ **120**
- `cur[3]` = max over all three: 120, 120, 120 ⇒ **120**

Day 2, `points[2] = [30, 60, 90]`, with `prev = [120,120,120,120]`:
- `cur[3]` = max(`30 + prev[0]`, `60 + prev[1]`, `90 + prev[2]`) = max(150, 180, 210) = **210**

Answer `210`. ✔ Tracing back: day 2 chose activity 2 (90), which required day 1's best with activity 2 banned = 120 from `80 + prev[2]`… i.e. day 1 chose activity 1 (50) with day 0's `prev[1] = 70` (activity 2). Sequence 2 → 1 → 2, total `70 + 50 + 90 = 210`. ✔
- **Time:** O(n · 12) = O(n)
- **Space:** O(1) — four numbers

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int ninjaTraining(int n, vector<vector<int>>& points) {
        // prev[last] = best merit through the current day when 'last' is banned
        vector<int> prev(4, 0);
        prev[0] = max(points[0][1], points[0][2]);
        prev[1] = max(points[0][0], points[0][2]);
        prev[2] = max(points[0][0], points[0][1]);
        prev[3] = max(points[0][0], max(points[0][1], points[0][2]));

        for (int day = 1; day < n; day++) {
            vector<int> cur(4, 0);
            for (int last = 0; last < 4; last++) {
                for (int task = 0; task < 3; task++) {
                    if (task == last) continue;
                    cur[last] = max(cur[last], points[day][task] + prev[task]);
                }
            }
            prev = cur;
        }
        return prev[3];
    }
};
```

```python
from typing import List


class Solution:
    def ninjaTraining(self, n: int, points: List[List[int]]) -> int:
        # prev[last] = best merit through the current day when 'last' is banned
        prev = [0] * 4
        prev[0] = max(points[0][1], points[0][2])
        prev[1] = max(points[0][0], points[0][2])
        prev[2] = max(points[0][0], points[0][1])
        prev[3] = max(points[0])

        for day in range(1, n):
            cur = [0] * 4
            for last in range(4):
                for task in range(3):
                    if task == last:
                        continue
                    cur[last] = max(cur[last], points[day][task] + prev[task])
            prev = cur

        return prev[3]
```

## Key Takeaways
- When today's legal choices depend on yesterday's choice, add that choice to the state: `(day, lastActivity)` instead of just `(day)`.
- A sentinel value (`last = 3`) for "no restriction" keeps the base case and the final answer uniform — no special-case branch needed.
- The state space is `O(n × 4)` with `O(3)` work each, so the whole DP is linear despite looking two-dimensional.
- Each day reads only the previous day, so the table collapses to one array of four integers.
- The same "remember the previous choice" pattern generalises to `k` activities, giving `O(n · k²)` (or `O(n · k)` with a prefix/suffix-max trick to avoid rescanning the previous row).
