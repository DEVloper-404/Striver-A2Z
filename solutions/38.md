# Largest Element

**Difficulty:** Easy  ·  **Topic:** Solve Problems on Arrays [Easy -> Medium -> Hard] › Easy

## Problem
Given an array of `n` integers, return the largest value in it. The array is non-empty.

Input: `arr = [2, 5, 1, 3, 0]`
Output: `5`

## Approach 1: Sort and Pick the Last
Sort the array in ascending order; the largest element ends up at index `n-1`. This works but does far more work than needed and destroys the input order.

- **Time:** O(n log n)
- **Space:** O(1) beyond the sort's own overhead.

## Approach 2: Single Scan (Optimal)
Keep a running maximum. Initialise it with `arr[0]`, walk the rest of the array once, and whenever the current element is bigger, replace the running maximum. At the end the variable holds the answer.

Starting from `arr[0]` rather than a sentinel like `0` or `INT_MIN` avoids bugs with all-negative arrays and keeps the code type-independent.

- **Time:** O(n)
- **Space:** O(1)

## Code (Optimal)

### C++
```cpp
#include <vector>
using namespace std;

class Solution {
public:
    int largestElement(vector<int>& arr) {
        int best = arr[0];
        for (int i = 1; i < (int)arr.size(); i++) {
            if (arr[i] > best) best = arr[i];
        }
        return best;
    }
};
```

### Java
```java
class Solution {
    public int largestElement(int[] arr) {
        int best = arr[0];
        for (int i = 1; i < arr.length; i++) {
            if (arr[i] > best) best = arr[i];
        }
        return best;
    }
}
```

### Python
```python
class Solution:
    def largestElement(self, arr: list[int]) -> int:
        best = arr[0]
        for x in arr[1:]:
            if x > best:
                best = x
        return best
```

## Key Takeaways
- One linear pass with a running maximum is optimal; you must look at every element at least once.
- Seed the maximum with the first element instead of `0` so negative-only arrays work.
- Sorting is a valid but wasteful O(n log n) alternative.
