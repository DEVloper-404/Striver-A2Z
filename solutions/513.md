# Most stones removed with same row or column

**Difficulty:** Medium  ·  **Topic:** Graphs [Concepts & Problems] › MinimumSpanningTree/Disjoint Set and Problems

## Problem
On a 2D plane, `stones[i] = [row_i, col_i]` gives the coordinates of a stone (at most one stone per cell). A stone may be removed if it shares its **row or its column** with another stone that is still on the plane. Return the maximum number of stones that can be removed.

```
Input:  stones = [[0,0],[0,1],[1,0],[1,2],[2,1],[2,2]]
Output: 5
```
All six stones are linked into one group, so you can strip it down to a single survivor.

## Approach 1: Simulate removals greedily
Repeatedly scan for any stone sharing a row or column with another and remove it, until no stone qualifies. This actually reaches the optimum for this problem, but each scan is `O(n)` and there are up to `n` removals with `O(n²)` pair checks, and it gives no insight into *why* the answer is what it is.
- **Time:** O(n³) in a naive implementation
- **Space:** O(n)

## Approach 2: Connected components via DSU (optimal)

**Key observation — group the stones.** Say two stones are "linked" if they share a row or a column, and take the transitive closure of that relation. That partitions the stones into connected components. Removals can only happen inside a component (a stone never interacts with a stone in another component).

**Key observation — every component collapses to exactly one stone.** Consider a component of size `k`.
- *You can always get down to 1.* A connected component has a spanning tree. Remove stones in reverse order of a DFS traversal — i.e. always remove a current leaf of the traversal, which by construction still shares a row or column with its parent, which is still present. Repeating this leaves only the DFS root. So `k - 1` removals are achievable.
- *You can never get below 1.* The last stone in a component has nothing left to pair with, so it can never be removed.

Therefore the answer is `n - (number of components)`. The problem reduces entirely to counting components.

**The trick for building components efficiently.** Comparing all `O(n²)` pairs works for `n ≤ 1000`, but there is a much cleaner formulation: instead of connecting stone-to-stone, connect each stone to **its row** and **its column**. Treat rows and columns as nodes in the same DSU:
- node `r` represents "row r";
- node `c + OFFSET` represents "column c", where `OFFSET` (here `100001`, above the maximum coordinate) keeps row and column ids from colliding.

For each stone `(r, c)`, `union(r, c + OFFSET)`. Two stones in the same row now automatically land in the same DSU set through the shared row node; likewise for columns; and transitivity is handled by the DSU itself. This makes component construction `O(n · α)` instead of `O(n²)`.

**Counting components correctly.** Do not count all DSU roots — that would include rows and columns that hold no stone. Instead collect the set of distinct leaders of the row/column ids that actually appear in `stones`, and count those. The answer is `n - |that set|`.

**Short dry run** on the example, writing column `c` as `c + OFFSET` with `OFFSET = 100001`.
- `(0,0)`: union row `0` with col `100001`.
- `(0,1)`: union row `0` with col `100002` → rows `0`, cols `100001`, `100002` are one set.
- `(1,0)`: union row `1` with col `100001` → row `1` joins the same set.
- `(1,2)`: union row `1` with col `100003` → col `100003` joins.
- `(2,1)`: union row `2` with col `100002` → row `2` joins.
- `(2,2)`: union row `2` with col `100003` → already the same set, no change.
Every stone's row-node has the same leader, so there is exactly `1` component. Answer `6 - 1 = 5`. ✓

**Edge case worth noting.** A stone that shares neither row nor column with any other forms its own component of size 1 and contributes `0` removals — the formula handles it automatically.
- **Time:** O(n · α(N)) ≈ O(n), where `N` is the coordinate range
- **Space:** O(N) for the DSU arrays (or O(n) with a hash-map DSU)

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <algorithm>
#include <unordered_set>
#include <numeric>
using namespace std;

class Solution {
    vector<int> parent, sz;
    int find(int x) { return parent[x] == x ? x : parent[x] = find(parent[x]); }
    void unite(int a, int b) {
        a = find(a); b = find(b);
        if (a == b) return;
        if (sz[a] < sz[b]) swap(a, b);
        parent[b] = a;
        sz[a] += sz[b];
    }
public:
    int removeStones(vector<vector<int>>& stones) {
        const int OFFSET = 100001;         // separates column ids from row ids
        int N = 2 * OFFSET;
        parent.resize(N);
        sz.assign(N, 1);
        iota(parent.begin(), parent.end(), 0);

        for (auto& s : stones) unite(s[0], s[1] + OFFSET);

        unordered_set<int> leaders;
        for (auto& s : stones) leaders.insert(find(s[0]));

        return (int)stones.size() - (int)leaders.size();
    }
};
```

### Java
```java
import java.util.*;

class Solution {
    private int[] parent, size;

    private int find(int x) {
        if (parent[x] != x) parent[x] = find(parent[x]);
        return parent[x];
    }

    private void unite(int a, int b) {
        a = find(a); b = find(b);
        if (a == b) return;
        if (size[a] < size[b]) { int t = a; a = b; b = t; }
        parent[b] = a;
        size[a] += size[b];
    }

    public int removeStones(int[][] stones) {
        final int OFFSET = 100001;
        int N = 2 * OFFSET;
        parent = new int[N];
        size = new int[N];
        for (int i = 0; i < N; i++) { parent[i] = i; size[i] = 1; }

        for (int[] s : stones) unite(s[0], s[1] + OFFSET);

        Set<Integer> leaders = new HashSet<>();
        for (int[] s : stones) leaders.add(find(s[0]));

        return stones.length - leaders.size();
    }
}
```

### Python
```python
from typing import List

class Solution:
    def removeStones(self, stones: List[List[int]]) -> int:
        parent = {}

        def find(x):
            parent.setdefault(x, x)
            while parent[x] != x:
                parent[x] = parent[parent[x]]
                x = parent[x]
            return x

        def unite(a, b):
            ra, rb = find(a), find(b)
            if ra != rb:
                parent[rb] = ra

        # row r -> key ('r', r);  column c -> key ('c', c)
        for r, c in stones:
            unite(('r', r), ('c', c))

        leaders = {find(('r', r)) for r, _c in stones}
        return len(stones) - len(leaders)
```

## Key Takeaways
- The whole problem reduces to `answer = total stones − number of connected components`, because each component can always be shrunk to exactly one stone and never below.
- Union the **row index with the column index** rather than stone with stone — that turns an `O(n²)` pairwise build into a near-linear one.
- Offset column ids (or use tagged keys, as in the Python version) so a row and a column with the same number are not conflated.
- Count leaders only over rows/columns that actually contain a stone, otherwise empty lines inflate the component count.
