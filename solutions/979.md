# Rabin Karp Algorithm

**Difficulty:** Hard  ·  **Topic:** Strings › Hard Problems

## Problem
Given a text `text` of length `n` and a pattern `pat` of length `m`, find every starting index in `text` where `pat` occurs. Rabin–Karp solves this by comparing **hashes** of length-`m` windows instead of comparing characters, using a rolling hash that updates in O(1) as the window slides.

```
Input:  text = "abracadabra", pat = "abra"
Output: [0, 7]
```

## Approach 1: Brute Force — slide and compare
Line the pattern up at index 0, compare character by character; on the first mismatch shift right by one and try again. Simple and always correct.

The cost is the problem: for each of the `n - m + 1` alignments you may compare up to `m` characters. On adversarial input like `text = "aaaa…a"`, `pat = "aaa…ab"` every alignment matches `m - 1` characters before failing, giving the full `O(n·m)`.

The wasted work is *re-reading the same characters* at every shift. Rabin–Karp attacks exactly that.

- **Time:** O(n · m)
- **Space:** O(1)

## Approach 2: Optimal — rolling hash with verification

### The core observation
Comparing two length-`m` strings costs `m` operations, but comparing two *numbers* costs one. So map every length-`m` window to a number with a polynomial hash:

```
H(s[i..i+m-1]) = s[i]·B^(m-1) + s[i+1]·B^(m-2) + … + s[i+m-1]·B^0   (mod M)
```

If we had to recompute this from scratch for each window we would be back to O(n·m). The trick is that **consecutive windows overlap in `m - 1` characters**, so one can be derived from the other:

```
next = ( (cur − text[i]·B^(m−1)) · B + text[i+m] ) mod M
```

Read that as three steps: subtract the outgoing character's contribution (it sits in the highest place value, hence the `B^(m-1)` factor), shift everything one place left by multiplying by `B`, then add the incoming character in the ones place. Each shift is O(1), so all `n - m + 1` window hashes cost O(n) total.

### Why the verification step is not optional
Hashing is many-to-one: different strings can produce the same value modulo `M`. A bare hash comparison would therefore report false matches. So whenever `windowHash == patternHash`, do **one** direct character-by-character comparison to confirm. This keeps the algorithm deterministically correct while the hash filters out virtually all alignments for free.

With a good base and a large prime modulus, a spurious collision happens with probability roughly `m/M` per alignment, so the expected number of wasted verifications across the whole scan is tiny. That is why the *expected* running time is O(n + m) even though the worst case (an adversary who forces a collision at every position, or a pattern that genuinely occurs everywhere) is O(n·m).

### Implementation details that bite
- Compute `B^(m-1) mod M` once before the loop; never call `pow` inside it.
- After subtracting `text[i]·B^(m-1)`, the value can go negative in C++/Java — add `M` before continuing.
- Keep `B` and `M` small enough that `B · M` fits in a signed 64-bit integer; `B = 256`, `M = 1e9+7` is safe.

### Dry run: `text = "abracadabra"`, `pat = "abra"` (m = 4)
1. Hash `"abra"` → some value `P`. Hash the first window `text[0..3] = "abra"` → the same value. Hashes agree, verify characters, confirm a match at **index 0**.
2. Roll to `"brac"`: drop `'a'`, add `'c'`. Its hash differs from `P`, skip in O(1).
3. Windows `"raca"`, `"acad"`, `"cada"`, `"adab"`, `"dabr"` all roll in O(1) and all differ from `P`.
4. Window at index 7 is `"abra"` — hash matches, verification confirms a match at **index 7**.
5. The window can no longer fit; stop.

Total character comparisons: only the two genuine matches, 8 characters, instead of the ~30 the brute force would perform.

- **Time:** O(n + m) expected; O(n · m) worst case
- **Space:** O(1) beyond the output list

## Code (Optimal)

### C++
```cpp
#include <string>
#include <vector>
using namespace std;

class Solution {
public:
    // Returns every starting index where pat occurs in text.
    vector<int> rabinKarp(const string& text, const string& pat) {
        const long long MOD = 1000000007LL;
        const long long BASE = 256;

        int n = (int)text.size(), m = (int)pat.size();
        vector<int> result;
        if (m == 0 || m > n) return result;

        // highest place value: BASE^(m-1) mod MOD
        long long power = 1;
        for (int i = 0; i < m - 1; i++) power = (power * BASE) % MOD;

        long long patHash = 0, winHash = 0;
        for (int i = 0; i < m; i++) {
            patHash = (patHash * BASE + (unsigned char)pat[i]) % MOD;
            winHash = (winHash * BASE + (unsigned char)text[i]) % MOD;
        }

        for (int i = 0; i + m <= n; i++) {
            // hash match is only a hint -> verify to rule out collisions
            if (winHash == patHash && text.compare(i, m, pat) == 0)
                result.push_back(i);

            if (i + m < n) {   // roll the window one step right
                long long out = (unsigned char)text[i] * power % MOD;
                winHash = (winHash - out % MOD + MOD) % MOD;
                winHash = (winHash * BASE + (unsigned char)text[i + m]) % MOD;
            }
        }
        return result;
    }
};
```

### Java
```java
import java.util.*;

class Solution {
    // Returns every starting index where pat occurs in text.
    public List<Integer> rabinKarp(String text, String pat) {
        final long MOD = 1_000_000_007L;
        final long BASE = 256;

        int n = text.length(), m = pat.length();
        List<Integer> result = new ArrayList<>();
        if (m == 0 || m > n) return result;

        // highest place value: BASE^(m-1) mod MOD
        long power = 1;
        for (int i = 0; i < m - 1; i++) power = (power * BASE) % MOD;

        long patHash = 0, winHash = 0;
        for (int i = 0; i < m; i++) {
            patHash = (patHash * BASE + pat.charAt(i)) % MOD;
            winHash = (winHash * BASE + text.charAt(i)) % MOD;
        }

        for (int i = 0; i + m <= n; i++) {
            // hash match is only a hint -> verify to rule out collisions
            if (winHash == patHash && text.startsWith(pat, i))
                result.add(i);

            if (i + m < n) {   // roll the window one step right
                long out = (text.charAt(i) * power) % MOD;
                winHash = (winHash - out + MOD) % MOD;
                winHash = (winHash * BASE + text.charAt(i + m)) % MOD;
            }
        }
        return result;
    }
}
```

### Python
```python
from typing import List


class Solution:
    def rabin_karp(self, text: str, pat: str) -> List[int]:
        """Returns every starting index where pat occurs in text."""
        MOD = 1_000_000_007
        BASE = 256

        n, m = len(text), len(pat)
        result: List[int] = []
        if m == 0 or m > n:
            return result

        power = pow(BASE, m - 1, MOD)      # highest place value

        pat_hash = 0
        win_hash = 0
        for i in range(m):
            pat_hash = (pat_hash * BASE + ord(pat[i])) % MOD
            win_hash = (win_hash * BASE + ord(text[i])) % MOD

        for i in range(n - m + 1):
            # hash match is only a hint -> verify to rule out collisions
            if win_hash == pat_hash and text[i:i + m] == pat:
                result.append(i)

            if i + m < n:                  # roll the window one step right
                win_hash = (win_hash - ord(text[i]) * power) % MOD
                win_hash = (win_hash * BASE + ord(text[i + m])) % MOD

        return result
```

## Key Takeaways
- The whole speedup comes from one identity: adjacent windows share `m - 1` characters, so the next hash is `(cur − out·B^(m−1))·B + in`.
- Always verify a hash match with a real comparison — that is what turns a probabilistic filter into a correct algorithm.
- Precompute `B^(m-1)` once, and normalise negative values after subtraction in C++/Java.
- Expected O(n + m), worst case O(n·m); when you need a guaranteed linear bound with no hashing at all, use KMP instead.
