# Bridges in graph

**Difficulty:** Hard  ·  **Topic:** Graphs [Concepts & Problems] › Other Algorithms

## Problem
Given a connected undirected graph with `n` nodes and a list of `connections`, find all **bridges** (also called critical connections): edges whose removal increases the number of connected components. Return them in any order.

```
Input:  n = 4, connections = [[0,1],[1,2],[2,0],[1,3]]
Output: [[1,3]]
```
Edges `0-1`, `1-2`, `2-0` sit on a cycle, so removing any one of them leaves the other two to keep those nodes connected. Removing `1-3` isolates node `3`, so it is the only bridge.

## Approach 1: Remove each edge and test connectivity
For each of the `E` edges, delete it, run a DFS/BFS from any node, and check whether all `n` nodes are still reachable. If not, that edge is a bridge. Correct and easy to reason about, but it re-traverses the graph once per edge.
- **Time:** O(E · (V + E))
- **Space:** O(V + E)

## Approach 2: Tarjan's algorithm with discovery and low times (optimal)

**The key observation.** Run one DFS. It classifies every edge as either a **tree edge** (used to visit a new node) or a **back edge** (pointing to an already-visited ancestor). A tree edge `u → v` is a bridge exactly when **the subtree rooted at `v` has no back edge climbing above `v`** — because such a back edge would be an alternative route around the edge `u–v`, and without one, cutting `u–v` severs `v`'s subtree from the rest.

**Turning that into numbers.** Maintain two arrays, filled during the DFS:
- `disc[u]` — the timestamp when `u` was first visited (its discovery time). Fixed once assigned.
- `low[u]` — the smallest discovery time reachable from `u`'s subtree using tree edges plus **at most one** back edge.

`low[u]` is computed as the minimum of: `disc[u]`; `low[v]` for every child `v` in the DFS tree; and `disc[w]` for every back edge `u → w` to an already-visited node that is not the parent.

**The bridge condition.** For a tree edge `u → v`:

```
low[v] > disc[u]   ⟺   u–v is a bridge
```

Read it literally: the highest point `v`'s subtree can climb to is still *below* `u`. Nothing in that subtree can reach `u` or anything above it without using the edge `u–v` itself, so that edge is the only link. If instead `low[v] <= disc[u]`, some descendant has a back edge to `u` or an ancestor of `u`, giving a bypass — not a bridge.

**The parent-edge trap.** In an undirected graph, every edge appears in both adjacency lists, so from `v` you will always see `u` again. You must skip the edge back to the parent, or `low[v]` would wrongly pick up `disc[u]` and no edge would ever look like a bridge. Skipping by *parent node* is fine when there are no parallel edges; if the input can contain duplicate edges between the same pair, skip by *edge id* instead — with a genuine parallel edge, neither copy is a bridge, and the edge-id version gets that right automatically.

**The algorithm.**
1. Build an adjacency list. Initialise `disc` and `low` to `-1` and a global `timer = 0`.
2. DFS from node `0` (loop over all nodes if the graph might be disconnected). On entering `u`: `disc[u] = low[u] = timer++`.
3. For each neighbour `v`:
   - if `v` is the parent, skip;
   - if `v` is unvisited: recurse, then `low[u] = min(low[u], low[v])`, and if `low[v] > disc[u]` record `{u, v}` as a bridge;
   - else (`v` already visited, a back edge): `low[u] = min(low[u], disc[v])`. Note it is `disc[v]`, **not** `low[v]` — using `low[v]` here can propagate values across a cross-branch and give wrong answers.

**Short dry run** on the example, starting at `0` with parent `-1`.
- `disc[0] = low[0] = 0`. Go to `1`: `disc[1] = low[1] = 1`. Go to `2`: `disc[2] = low[2] = 2`.
- From `2`, neighbour `0` is visited and is not the parent → back edge, so `low[2] = min(2, disc[0]) = 0`.
- Return to `1`: `low[1] = min(1, low[2]) = 0`. Check `low[2] (0) > disc[1] (1)`? No → `1-2` is not a bridge.
- From `1`, go to `3`: `disc[3] = low[3] = 3`; node `3`'s only neighbour is its parent, so `low[3]` stays `3`. Back in `1`: check `low[3] (3) > disc[1] (1)`? Yes → **`1-3` is a bridge**.
- Return to `0`: `low[0] = min(0, low[1]) = 0`. Check `low[1] (0) > disc[0] (0)`? No → `0-1` is not a bridge.
Result `[[1,3]]`. ✓

**Related.** The same `disc`/`low` machinery, with the condition changed to `low[v] >= disc[u]` (plus a special case for the DFS root having two or more children), finds **articulation points** — cut vertices instead of cut edges.
- **Time:** O(V + E) — a single DFS
- **Space:** O(V + E) for the adjacency list, plus O(V) for `disc`, `low` and the recursion stack

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
    vector<vector<int>> adj;
    vector<int> disc, low;
    vector<vector<int>> bridges;
    int timer = 0;

    void dfs(int u, int parent) {
        disc[u] = low[u] = timer++;
        for (int v : adj[u]) {
            if (v == parent) continue;              // do not walk back up
            if (disc[v] == -1) {                    // tree edge
                dfs(v, u);
                low[u] = min(low[u], low[v]);
                if (low[v] > disc[u]) bridges.push_back({u, v});
            } else {                                // back edge
                low[u] = min(low[u], disc[v]);      // disc, not low
            }
        }
    }
public:
    vector<vector<int>> criticalConnections(int n, vector<vector<int>>& connections) {
        adj.assign(n, {});
        for (auto& c : connections) {
            adj[c[0]].push_back(c[1]);
            adj[c[1]].push_back(c[0]);
        }
        disc.assign(n, -1);
        low.assign(n, -1);
        for (int i = 0; i < n; i++)
            if (disc[i] == -1) dfs(i, -1);
        return bridges;
    }
};
```

### Java
```java
import java.util.*;

class Solution {
    private List<Integer>[] adj;
    private int[] disc, low;
    private List<List<Integer>> bridges;
    private int timer = 0;

    private void dfs(int u, int parent) {
        disc[u] = low[u] = timer++;
        for (int v : adj[u]) {
            if (v == parent) continue;
            if (disc[v] == -1) {
                dfs(v, u);
                low[u] = Math.min(low[u], low[v]);
                if (low[v] > disc[u]) bridges.add(Arrays.asList(u, v));
            } else {
                low[u] = Math.min(low[u], disc[v]);
            }
        }
    }

    public List<List<Integer>> criticalConnections(int n, List<List<Integer>> connections) {
        adj = new List[n];
        for (int i = 0; i < n; i++) adj[i] = new ArrayList<>();
        for (List<Integer> c : connections) {
            adj[c.get(0)].add(c.get(1));
            adj[c.get(1)].add(c.get(0));
        }
        disc = new int[n];
        low = new int[n];
        Arrays.fill(disc, -1);
        Arrays.fill(low, -1);
        bridges = new ArrayList<>();
        for (int i = 0; i < n; i++)
            if (disc[i] == -1) dfs(i, -1);
        return bridges;
    }
}
```

### Python
```python
import sys
from typing import List

class Solution:
    def criticalConnections(self, n: int, connections: List[List[int]]) -> List[List[int]]:
        sys.setrecursionlimit(300000)
        adj = [[] for _ in range(n)]
        for u, v in connections:
            adj[u].append(v)
            adj[v].append(u)

        disc = [-1] * n
        low = [0] * n
        bridges: List[List[int]] = []
        timer = 0

        def dfs(u: int, parent: int) -> None:
            nonlocal timer
            disc[u] = low[u] = timer
            timer += 1
            for v in adj[u]:
                if v == parent:
                    continue
                if disc[v] == -1:                 # tree edge
                    dfs(v, u)
                    low[u] = min(low[u], low[v])
                    if low[v] > disc[u]:
                        bridges.append([u, v])
                else:                             # back edge
                    low[u] = min(low[u], disc[v])

        for i in range(n):
            if disc[i] == -1:
                dfs(i, -1)
        return bridges
```

## Key Takeaways
- A tree edge `u–v` is a bridge iff `low[v] > disc[u]` — nothing in `v`'s subtree can reach `u` or above without that edge.
- Update `low[u]` with `low[child]` for tree edges but with `disc[neighbour]` for back edges; mixing them up breaks the algorithm.
- Skip the parent edge, and skip by **edge id** rather than parent node if parallel edges are possible (parallel edges are never bridges).
- One DFS gives all bridges in `O(V + E)`; the same `disc`/`low` values with `low[v] >= disc[u]` yield articulation points.
