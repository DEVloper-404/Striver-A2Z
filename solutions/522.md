# Floyd warshall algorithm

**Difficulty:** Hard  ·  **Topic:** Graphs [Concepts & Problems] › Shortest Path Algorithms and Problems

## Problem
Given a directed weighted graph as an adjacency **matrix** `mat`, where `mat[i][j]` is the weight of the edge `i → j` and `-1` means "no edge", replace the matrix in place with all-pairs shortest distances: `mat[i][j]` becomes the cost of the cheapest path from `i` to `j` (still `-1` if no path exists). Weights may be negative, but the graph is assumed to have no negative cycle; detecting one is a bonus we get for free.

```
Input:  mat = [[ 0,  2, -1, -1],
               [ 1,  0,  3, -1],
               [-1, -1,  0, -1],
               [ 3,  5,  4,  0]]
Output: [[0, 2, 5, -1],
         [1, 0, 3, -1],
         [-1, -1, 0, -1],
         [3, 5, 4, 0]]
```
`0 → 2` has no direct edge, but `0 → 1 → 2` costs `2 + 3 = 5`.

## Approach 1: Run a single-source algorithm from every vertex
Call Dijkstra `V` times: `O(V · E log V)`. That works only for non-negative weights. With negative edges you would need Bellman–Ford from each source: `O(V² · E)`, which for a dense graph (`E ≈ V²`) is `O(V⁴)` — worse than what follows, and far more code.
- **Time:** O(V · E log V) with Dijkstra, O(V² · E) with Bellman–Ford
- **Space:** O(V²) for the output matrix

## Approach 2: Floyd–Warshall — DP over allowed intermediate vertices (optimal)

**The key observation.** Instead of thinking "which path", think "which vertices am I allowed to pass through". Define

```
D_k[i][j] = cheapest cost from i to j using only vertices {0, 1, ..., k-1} as intermediates
```

`D_0[i][j]` is just the direct edge (or infinity). Now go from `D_k` to `D_{k+1}` by asking a single yes/no question about vertex `k`: **does the best path use `k` or not?**
- If it does not, the cost is `D_k[i][j]`.
- If it does, the path splits at `k` into `i → k` and `k → j`, and both halves use only vertices below `k` as intermediates (a shortest path never revisits `k`), so the cost is `D_k[i][k] + D_k[k][j]`.

Taking the minimum of the two gives the recurrence

```
D_{k+1}[i][j] = min( D_k[i][j],  D_k[i][k] + D_k[k][j] )
```

After processing all `k` from `0` to `V-1`, every vertex is permitted as an intermediate, so the matrix holds true shortest distances.

**Why the in-place triple loop is safe.** We overwrite one matrix rather than keeping `V` copies. During iteration `k`, the row `k` and column `k` entries never change, because `D[i][k] = min(D[i][k], D[i][k] + D[k][k])` and `D[k][k]` is `0` — so the values we read on the right-hand side are still the `D_k` values we need. That is the reason **`k` must be the outermost loop**; swapping the loop order breaks this invariant and produces wrong answers.

**Short dry run** on the example. With `k = 1` (allowing vertex `1` as an intermediate), the pair `(0, 2)` is updated: `D[0][2] = min(INF, D[0][1] + D[1][2]) = min(INF, 2 + 3) = 5`. Vertex `2` has no outgoing edges other than to itself, so nothing else improves, and vertex `3` is unreachable from everyone else, so its column stays `-1` outside its own row.

**Negative-cycle detection.** If after the algorithm some `D[i][i] < 0`, then vertex `i` sits on a cycle of negative total weight — you can loop around it and keep getting cheaper, so shortest paths are undefined for the component containing it.

**Sentinel handling.** Convert `-1` to a large `INF` before the loops and back to `-1` afterwards, and skip relaxation whenever either half is `INF` (or use an `INF` big enough that `INF + INF` does not overflow, e.g. `10^8` in 32-bit).
- **Time:** O(V³)
- **Space:** O(1) extra — the update is in place on the input matrix

## Code (Optimal)

### C++
```cpp
#include <vector>
using namespace std;

class Solution {
public:
    void shortestDistance(vector<vector<int>>& mat) {
        int n = mat.size();
        const int INF = 100000000;

        for (int i = 0; i < n; i++)
            for (int j = 0; j < n; j++)
                if (mat[i][j] == -1) mat[i][j] = INF;

        for (int k = 0; k < n; k++)               // k MUST be outermost
            for (int i = 0; i < n; i++) {
                if (mat[i][k] == INF) continue;   // prune: no i -> k path
                for (int j = 0; j < n; j++) {
                    if (mat[k][j] == INF) continue;
                    if (mat[i][k] + mat[k][j] < mat[i][j])
                        mat[i][j] = mat[i][k] + mat[k][j];
                }
            }

        // negative cycle check: mat[i][i] < 0 for some i
        for (int i = 0; i < n; i++)
            for (int j = 0; j < n; j++)
                if (mat[i][j] == INF) mat[i][j] = -1;
    }
};
```

### Python
```python
from typing import List

class Solution:
    def shortestDistance(self, mat: List[List[int]]) -> None:
        n = len(mat)
        INF = 10 ** 8

        for i in range(n):
            for j in range(n):
                if mat[i][j] == -1:
                    mat[i][j] = INF

        for k in range(n):                 # k must be the outermost loop
            row_k = mat[k]
            for i in range(n):
                ik = mat[i][k]
                if ik == INF:
                    continue
                row_i = mat[i]
                for j in range(n):
                    cand = ik + row_k[j]
                    if cand < row_i[j]:
                        row_i[j] = cand

        # a negative cycle exists iff mat[i][i] < 0 for some i
        for i in range(n):
            for j in range(n):
                if mat[i][j] == INF:
                    mat[i][j] = -1
```

## Key Takeaways
- Floyd–Warshall is DP over the *set of permitted intermediate vertices*, not over paths — that framing makes the three-line recurrence obvious.
- The `k` loop must be outermost; any other nesting order silently produces wrong distances.
- `O(V³)` beats "Bellman–Ford from every source" on dense graphs and handles negative weights, unlike repeated Dijkstra.
- A negative diagonal entry (`dist[i][i] < 0`) after the run is the negative-cycle signal you get for free.
