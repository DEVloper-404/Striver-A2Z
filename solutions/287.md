# Climbing stairs

**Difficulty:** Medium  ·  **Topic:** Dynamic Programming [Patterns and Problems] › 1D DP

## Problem
You are at the bottom of a staircase with `n` steps. From any step you may climb either **1** step or **2** steps at a time. Count the number of distinct ways to reach the top (step `n`). Two ways are different if the sequence of jump sizes differs.

```
Input:  n = 4
Output: 5
        1+1+1+1, 1+1+2, 1+2+1, 2+1+1, 2+2
```

## Approach 1: Plain recursion (brute force)
Think **backwards from the top**. The very last move that lands you on step `n` was either a 1-step from `n-1` or a 2-step from `n-2`. Those two possibilities are disjoint (they differ in the last move) and together they cover every way, so

```
ways(n) = ways(n-1) + ways(n-2)
```

Base cases: `ways(0) = 1` — there is exactly one way to "already be" at the ground, the empty sequence — and `ways(1) = 1`. Writing this directly as recursion works, but the call tree branches twice at every level and recomputes the same subproblems, giving roughly `2^n` calls.
- **Time:** O(2^n)
- **Space:** O(n) recursion stack

## Approach 2: Memoization
The state is a single number: the step index. There are only `n+1` distinct states, so cache them. Keep `dp[i] = -1` initially; on entering `solve(i)`, return `dp[i]` if it is already filled, otherwise compute `solve(i-1) + solve(i-2)` and store it. Every state is now evaluated once.
- **Time:** O(n)
- **Space:** O(n) table + O(n) stack

## Approach 3: Tabulation
Turn the recursion around and fill the table from small to large. Set `dp[0] = 1`, `dp[1] = 1`, then for `i` from `2` to `n` compute `dp[i] = dp[i-1] + dp[i-2]`. When `dp[i]` is computed, both dependencies are already in the table, so the order is valid. The answer is `dp[n]`. This removes the recursion stack entirely.
- **Time:** O(n)
- **Space:** O(n)

## Approach 4: Two rolling variables (Optimal)

**The observation that unlocks it:** `dp[i]` reads only `dp[i-1]` and `dp[i-2]`. Nothing older is ever touched again, so the whole array is unnecessary — two variables suffice.

Keep `prev1 = dp[i-1]` and `prev2 = dp[i-2]`. In each iteration compute `cur = prev1 + prev2`, then slide the window: `prev2 = prev1`, `prev1 = cur`.

**Algorithm.**
1. If `n <= 1`, return `1` (zero or one step each has exactly one way).
2. Initialise `prev2 = 1` (ways to reach step 0), `prev1 = 1` (ways to reach step 1).
3. Loop `i = 2 … n`: `cur = prev1 + prev2`; `prev2 = prev1`; `prev1 = cur`.
4. Return `prev1`, which now holds `dp[n]`.

**Dry run for n = 4.** Start `prev2 = 1, prev1 = 1`.
- `i = 2`: `cur = 1 + 1 = 2` → `(prev2, prev1) = (1, 2)` — two ways to reach step 2 (`1+1`, `2`). ✔
- `i = 3`: `cur = 2 + 1 = 3` → `(2, 3)` — three ways to step 3. ✔
- `i = 4`: `cur = 3 + 2 = 5` → `(3, 5)`.

Return `5`. ✔ Notice the sequence `1, 1, 2, 3, 5` — this is exactly the Fibonacci numbers shifted by one, which is a useful sanity check to remember.
- **Time:** O(n)
- **Space:** O(1)

## Code (Optimal)

### C++
```cpp
class Solution {
public:
    int climbStairs(int n) {
        if (n <= 1) return 1;
        int prev2 = 1;   // ways to stand on step 0
        int prev1 = 1;   // ways to stand on step 1
        for (int i = 2; i <= n; i++) {
            int cur = prev1 + prev2;
            prev2 = prev1;
            prev1 = cur;
        }
        return prev1;
    }
};
```

### Python
```python
class Solution:
    def climbStairs(self, n: int) -> int:
        if n <= 1:
            return 1
        prev2, prev1 = 1, 1      # ways to reach step 0 and step 1
        for _ in range(2, n + 1):
            prev2, prev1 = prev1, prev1 + prev2
        return prev1
```

## Key Takeaways
- Count paths by conditioning on the **last move**: the ways split cleanly into "arrived by a 1-step" and "arrived by a 2-step".
- The recurrence is Fibonacci; `climbStairs(n) = Fib(n+1)` with `Fib(1)=Fib(2)=1`.
- `ways(0) = 1` (the empty path), not `0` — getting this base case wrong shifts every answer.
- Since each state looks back only two positions, the O(n) table collapses to O(1) with two rolling variables.
- If jumps of size `1..k` were allowed, the same reasoning gives a sum over the last `k` states — that is the "Frog jump with K distances" generalisation.
