# Accounts merge

**Difficulty:** Hard  ·  **Topic:** Graphs [Concepts & Problems] › MinimumSpanningTree/Disjoint Set and Problems

## Problem
You are given `accounts`, where `accounts[i][0]` is a person's name and the rest of the list are their email addresses. Two accounts belong to the same person if they share **at least one email**; the same name alone is not enough (two different people can be named "John"). Merge all accounts of the same person and return, for each merged person, a list whose first element is the name followed by their emails **sorted alphabetically**.

```
Input:  accounts = [["John","j1@m.com","john@m.com"],
                    ["John","johnny@m.com","j1@m.com"],
                    ["Mary","mary@m.com"],
                    ["John","johnsmith@m.com"]]
Output: [["John","j1@m.com","john@m.com","johnny@m.com"],
         ["Mary","mary@m.com"],
         ["John","johnsmith@m.com"]]
```
The first two John accounts share `j1@m.com`, so they merge. The last John shares no email with them, so he stays separate.

## Approach 1: Pairwise comparison with repeated passes
Compare every pair of accounts for a shared email and merge when found, repeating until a full pass changes nothing. Merging is transitive (A shares with B, B shares with C ⇒ all three are one person), so a single pass is not enough and you may need many. Cost is roughly `O(passes · n² · k)` with `k` emails per account — far too slow.
- **Time:** O(n² · k) per pass, several passes
- **Space:** O(n · k)

## Approach 2: Disjoint Set over account indices (optimal)

**The key observation.** "Shares an email" is exactly a graph edge between two accounts, and "same person" is the transitive closure of that relation — i.e. a connected component. DSU is built for exactly this, and it handles transitivity automatically without repeated passes.

**The trick: let each email name its first owner.** Rather than comparing accounts pairwise, keep a hash map `emailToIndex: email → account index`. Walk every account `i` and every email `e` in it:
- If `e` is unseen, record `emailToIndex[e] = i`.
- If `e` was already claimed by account `j`, then accounts `i` and `j` share an email → `union(i, j)`.

Each email is examined once, so this builds all the edges in one linear sweep. Transitive merges (account 0 ↔ 1 via one email, 1 ↔ 2 via another) are absorbed by the DSU's `find`.

**Why unioning indices, not emails, is convenient.** The DSU is over `n` accounts, a small dense integer range, so a plain array DSU works. Each component's leader index also tells us the correct name (all accounts in a component share the person, so any member's name is right).

**Collecting the answer.**
1. After all unions, create a bucket per leader: for each email `e` in `emailToIndex`, append `e` to `bucket[find(emailToIndex[e])]`.
   Using the map's keys rather than re-walking the accounts automatically de-duplicates emails that appeared several times.
2. For each non-empty bucket, sort its emails lexicographically and prepend `accounts[leader][0]` as the name.

**Short dry run** on the example.
- Account 0 claims `j1@m.com → 0` and `john@m.com → 0`.
- Account 1: `johnny@m.com` is new → claims it. `j1@m.com` is already owned by 0 → `union(1, 0)`. Now `{0, 1}` is one component.
- Account 2 claims `mary@m.com → 2`; no collisions.
- Account 3 claims `johnsmith@m.com → 3`; no collisions.
Buckets by leader: leader of `{0,1}` gets `{j1@m.com, john@m.com, johnny@m.com}` (sorted), account `2` gets `{mary@m.com}`, account `3` gets `{johnsmith@m.com}`. Prepend names → the expected output.

**Two easy traps.** (1) Never merge on matching *names* — the whole point of the problem is that names repeat. (2) Emails inside a single account can repeat and the same email can appear in several accounts; keying the final collection off the map's key set removes duplicates for free.
- **Time:** O(N log N) where `N` is the total number of emails — dominated by sorting each bucket; the DSU work is O(N · α(n))
- **Space:** O(N) for the map, the buckets and the DSU

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <string>
#include <unordered_map>
#include <algorithm>
#include <numeric>
using namespace std;

class Solution {
    vector<int> parent, sz;
    int find(int x) { return parent[x] == x ? x : parent[x] = find(parent[x]); }
    void unite(int a, int b) {
        a = find(a); b = find(b);
        if (a == b) return;
        if (sz[a] < sz[b]) swap(a, b);
        parent[b] = a;
        sz[a] += sz[b];
    }
public:
    vector<vector<string>> accountsMerge(vector<vector<string>>& accounts) {
        int n = accounts.size();
        parent.resize(n);
        sz.assign(n, 1);
        iota(parent.begin(), parent.end(), 0);

        unordered_map<string, int> emailToIndex;
        for (int i = 0; i < n; i++) {
            for (int j = 1; j < (int)accounts[i].size(); j++) {
                const string& e = accounts[i][j];
                auto it = emailToIndex.find(e);
                if (it == emailToIndex.end()) emailToIndex[e] = i;
                else unite(i, it->second);
            }
        }

        vector<vector<string>> buckets(n);
        for (auto& [email, idx] : emailToIndex)
            buckets[find(idx)].push_back(email);

        vector<vector<string>> res;
        for (int i = 0; i < n; i++) {
            if (buckets[i].empty()) continue;
            sort(buckets[i].begin(), buckets[i].end());
            vector<string> row;
            row.push_back(accounts[i][0]);
            for (auto& e : buckets[i]) row.push_back(e);
            res.push_back(move(row));
        }
        return res;
    }
};
```

### Java
```java
import java.util.*;

class Solution {
    private int[] parent, size;

    private int find(int x) {
        if (parent[x] != x) parent[x] = find(parent[x]);
        return parent[x];
    }

    private void unite(int a, int b) {
        a = find(a); b = find(b);
        if (a == b) return;
        if (size[a] < size[b]) { int t = a; a = b; b = t; }
        parent[b] = a;
        size[a] += size[b];
    }

    public List<List<String>> accountsMerge(List<List<String>> accounts) {
        int n = accounts.size();
        parent = new int[n];
        size = new int[n];
        for (int i = 0; i < n; i++) { parent[i] = i; size[i] = 1; }

        Map<String, Integer> emailToIndex = new HashMap<>();
        for (int i = 0; i < n; i++) {
            List<String> acc = accounts.get(i);
            for (int j = 1; j < acc.size(); j++) {
                String e = acc.get(j);
                Integer owner = emailToIndex.get(e);
                if (owner == null) emailToIndex.put(e, i);
                else unite(i, owner);
            }
        }

        Map<Integer, List<String>> buckets = new HashMap<>();
        for (Map.Entry<String, Integer> en : emailToIndex.entrySet())
            buckets.computeIfAbsent(find(en.getValue()), k -> new ArrayList<>())
                   .add(en.getKey());

        List<List<String>> res = new ArrayList<>();
        for (Map.Entry<Integer, List<String>> en : buckets.entrySet()) {
            List<String> emails = en.getValue();
            Collections.sort(emails);
            List<String> row = new ArrayList<>();
            row.add(accounts.get(en.getKey()).get(0));
            row.addAll(emails);
            res.add(row);
        }
        return res;
    }
}
```

### Python
```python
from collections import defaultdict
from typing import List

class Solution:
    def accountsMerge(self, accounts: List[List[str]]) -> List[List[str]]:
        n = len(accounts)
        parent = list(range(n))
        size = [1] * n

        def find(x: int) -> int:
            while parent[x] != x:
                parent[x] = parent[parent[x]]
                x = parent[x]
            return x

        def unite(a: int, b: int) -> None:
            a, b = find(a), find(b)
            if a == b:
                return
            if size[a] < size[b]:
                a, b = b, a
            parent[b] = a
            size[a] += size[b]

        email_to_index = {}
        for i, acc in enumerate(accounts):
            for email in acc[1:]:
                if email in email_to_index:
                    unite(i, email_to_index[email])
                else:
                    email_to_index[email] = i

        buckets = defaultdict(list)
        for email, idx in email_to_index.items():
            buckets[find(idx)].append(email)

        return [[accounts[leader][0]] + sorted(emails)
                for leader, emails in buckets.items()]
```

## Key Takeaways
- "Shares at least one X" plus transitivity is a connected-components problem — reach for DSU rather than repeated pairwise passes.
- Map each email to the **first account index that claimed it**; a second claim is an edge to union. One linear sweep builds the whole graph.
- Merge on emails only, never on names — duplicate names are the point of the problem.
- Build the output from the email→index map's keys so duplicate emails collapse automatically, then sort each bucket and prepend the leader's name.
