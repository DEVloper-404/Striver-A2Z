# Book Allocation Problem

**Difficulty:** Hard  ·  **Topic:** Binary Search [1D, 2D Arrays, Search Space] › BS on Answers

## Problem
There are `n` books with `pages[i]` pages each, arranged in a row, and `m` students. Every book must go to exactly one student, each student gets a contiguous block of books, and every student gets at least one book. Assign books so that the maximum pages any student reads is minimised; return that minimum. If `m > n`, return `-1`.

Input: pages = [12, 34, 67, 90], m = 2
Output: 113  (split as [12, 34, 67] and [90] → max is 113)

## Approach 1: Try Every Maximum Load
The answer is at least `max(pages)` (one student must read the largest book) and at most `sum(pages)` (one student reads everything). For each candidate limit `L` in that range, greedily walk the books, starting a new student whenever adding the next book would exceed `L`. If the number of students used is `<= m`, `L` works; the first such `L` is the answer.
- **Time:** O((sum - max) * n)
- **Space:** O(1)

## Approach 2: Binary Search on the Maximum Load
Raising the limit `L` can only reduce the number of students needed, so "students needed" is non-increasing in `L`. Binary search `L` over `[max(pages), sum(pages)]`, using the greedy count. If `students(mid) <= m`, `mid` is feasible: record and go left; otherwise go right.

Why `<= m` rather than `== m`? If a limit works with fewer students, we can always split a block further to use exactly `m` without raising the maximum.
- **Time:** O(n * log(sum - max))
- **Space:** O(1)

## Code (Optimal)

### C++
```cpp
class Solution {
public:
    int studentsNeeded(const vector<int>& pages, int limit) {
        int students = 1;
        long long load = 0;
        for (int p : pages) {
            if (load + p > limit) { students++; load = 0; }
            load += p;
        }
        return students;
    }

    int findPages(vector<int>& pages, int m) {
        int n = pages.size();
        if (m > n) return -1;
        int lo = *max_element(pages.begin(), pages.end());
        int hi = accumulate(pages.begin(), pages.end(), 0);
        int ans = hi;
        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2;
            if (studentsNeeded(pages, mid) <= m) {
                ans = mid;
                hi = mid - 1;
            } else {
                lo = mid + 1;
            }
        }
        return ans;
    }
};
```

class Solution {
    private int studentsNeeded(int[] pages, int limit) {
        int students = 1;
        long load = 0;
        for (int p : pages) {
            if (load + p > limit) { students++; load = 0; }
            load += p;
        }
        return students;
    }

    public int findPages(int[] pages, int m) {
        int n = pages.length;
        if (m > n) return -1;
        int lo = 0, hi = 0;
        for (int p : pages) { lo = Math.max(lo, p); hi += p; }
        int ans = hi;
        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2;
            if (studentsNeeded(pages, mid) <= m) {
                ans = mid;
                hi = mid - 1;
            } else {
                lo = mid + 1;
            }
        }
        return ans;
    }
}

### Python
```python
from typing import List

class Solution:
    def findPages(self, pages: List[int], m: int) -> int:
        n = len(pages)
        if m > n:
            return -1

        def students_needed(limit: int) -> int:
            students, load = 1, 0
            for p in pages:
                if load + p > limit:
                    students += 1
                    load = 0
                load += p
            return students

        lo, hi = max(pages), sum(pages)
        ans = hi
        while lo <= hi:
            mid = (lo + hi) // 2
            if students_needed(mid) <= m:
                ans = mid
                hi = mid - 1
            else:
                lo = mid + 1
        return ans
```

## Key Takeaways
- "Minimise the maximum contiguous chunk" pattern; identical to Split Array Largest Sum and Painter's Partition.
- Lower bound must be `max(pages)`, otherwise the greedy count is meaningless for the biggest book.
- Handle `m > n` up front; the binary search assumes every student can get a book.
