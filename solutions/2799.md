# Print Longest Common Subsequence | (DP - 26)

**Difficulty:** Hard  ·  **Topic:** Dynamic Programming [Patterns and Problems] › DP on Strings

## Problem
Given two strings `s1` and `s2`, return one longest common subsequence itself — not just its length. If several LCSs have the same maximum length, any one of them is acceptable.

```
Input:  s1 = "abcde", s2 = "bdgek"
Output: "bde"
Explanation: "bde" appears in order in both strings and has length 3, the maximum.
```

## Approach 1: Compute the length table first

Printing the answer requires knowing *which* choice the DP made at each step, so we cannot use the O(m) space-optimised LCS — we need the whole 2-D table.

Build `dp[i][j]` = LCS length of the first `i` characters of `s1` and the first `j` of `s2`:

```
dp[i][j] = 1 + dp[i-1][j-1]                     if s1[i-1] == s2[j-1]
dp[i][j] = max(dp[i-1][j], dp[i][j-1])          otherwise
```

with row 0 and column 0 all zeros (an empty string shares nothing).

- **Time:** O(n · m)
- **Space:** O(n · m)

## Approach 2: Optimal — backtrack through the table

**The key idea.** The table records not only the length but also the *reason* for it. Walk backwards from the bottom-right corner `(n, m)` and undo the decision that produced each cell:

1. If `s1[i-1] == s2[j-1]`, that character was matched — it belongs in the LCS. Append it and move diagonally to `(i-1, j-1)`.
2. Otherwise the cell took the max of its top and left neighbours. Move towards whichever neighbour is larger: if `dp[i-1][j] > dp[i][j-1]` go up to `(i-1, j)`, else go left to `(i, j-1)`. Ties can go either way — that is exactly the freedom that lets multiple LCSs exist.
3. Stop when `i == 0` or `j == 0`.

The characters come out in reverse order (we walk from the end), so reverse the collected string at the finish. The walk takes at most `n + m` steps because every move decreases `i + j` by at least one.

**Why the walk is correct.** Case 1 is safe because when the last characters agree, some LCS of the prefixes ends with that pair, so committing to it does not shorten the result. Case 2 is safe because when they differ, `dp[i][j]` literally equals one of its two neighbours, and stepping into that neighbour keeps us on a path whose cells all carry the true optimum for their prefixes.

**Dry run on s1 = "abcde", s2 = "bdgek".** The completed table (rows = prefixes of `s1`, columns = prefixes of `s2`):

|     | "" | b | d | g | e | k |
|-----|----|---|---|---|---|---|
| ""  | 0 | 0 | 0 | 0 | 0 | 0 |
| a   | 0 | 0 | 0 | 0 | 0 | 0 |
| b   | 0 | 1 | 1 | 1 | 1 | 1 |
| c   | 0 | 1 | 1 | 1 | 1 | 1 |
| d   | 0 | 1 | 2 | 2 | 2 | 2 |
| e   | 0 | 1 | 2 | 2 | 3 | 3 |

Backtracking from `(5, 5)`:
- `(5,5)`: `s1[4]='e'` vs `s2[4]='k'` — differ. `dp[4][5]=2`, `dp[5][4]=3`, so go left to `(5,4)`.
- `(5,4)`: `'e'` vs `'e'` — match. Emit `e`, go to `(4,3)`.
- `(4,3)`: `'d'` vs `'g'` — differ. `dp[3][3]=1`, `dp[4][2]=2`, go left to `(4,2)`.
- `(4,2)`: `'d'` vs `'d'` — match. Emit `d`, go to `(3,1)`.
- `(3,1)`: `'c'` vs `'b'` — differ. `dp[2][1]=1`, `dp[3][0]=0`, go up to `(2,1)`.
- `(2,1)`: `'b'` vs `'b'` — match. Emit `b`, go to `(1,0)`.
- `j == 0` → stop.

Collected `"edb"`, reversed → `"bde"`.

- **Time:** O(n · m) to build + O(n + m) to backtrack
- **Space:** O(n · m) — the full table is required

## Code (Optimal)

### C++
```cpp
class Solution {
public:
    string printLCS(string s1, string s2) {
        int n = s1.size(), m = s2.size();
        vector<vector<int>> dp(n + 1, vector<int>(m + 1, 0));

        for (int i = 1; i <= n; i++)
            for (int j = 1; j <= m; j++)
                dp[i][j] = (s1[i - 1] == s2[j - 1])
                         ? 1 + dp[i - 1][j - 1]
                         : max(dp[i - 1][j], dp[i][j - 1]);

        string res;
        int i = n, j = m;
        while (i > 0 && j > 0) {
            if (s1[i - 1] == s2[j - 1]) {
                res.push_back(s1[i - 1]);      // matched char belongs to the LCS
                i--; j--;
            } else if (dp[i - 1][j] > dp[i][j - 1]) {
                i--;
            } else {
                j--;
            }
        }
        reverse(res.begin(), res.end());
        return res;
    }
};
```

### Java
```java
class Solution {
    public String printLCS(String s1, String s2) {
        int n = s1.length(), m = s2.length();
        int[][] dp = new int[n + 1][m + 1];

        for (int i = 1; i <= n; i++)
            for (int j = 1; j <= m; j++)
                dp[i][j] = (s1.charAt(i - 1) == s2.charAt(j - 1))
                         ? 1 + dp[i - 1][j - 1]
                         : Math.max(dp[i - 1][j], dp[i][j - 1]);

        StringBuilder sb = new StringBuilder();
        int i = n, j = m;
        while (i > 0 && j > 0) {
            if (s1.charAt(i - 1) == s2.charAt(j - 1)) {
                sb.append(s1.charAt(i - 1));
                i--; j--;
            } else if (dp[i - 1][j] > dp[i][j - 1]) {
                i--;
            } else {
                j--;
            }
        }
        return sb.reverse().toString();
    }
}
```

### Python
```python
class Solution:
    def printLCS(self, s1, s2):
        n, m = len(s1), len(s2)
        dp = [[0] * (m + 1) for _ in range(n + 1)]

        for i in range(1, n + 1):
            for j in range(1, m + 1):
                if s1[i - 1] == s2[j - 1]:
                    dp[i][j] = 1 + dp[i - 1][j - 1]
                else:
                    dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])

        res = []
        i, j = n, m
        while i > 0 and j > 0:
            if s1[i - 1] == s2[j - 1]:
                res.append(s1[i - 1])
                i -= 1
                j -= 1
            elif dp[i - 1][j] > dp[i][j - 1]:
                i -= 1
            else:
                j -= 1

        return ''.join(reversed(res))
```

## Key Takeaways
- Printing the answer forces you to keep the full O(n·m) table — the rolling-row trick only survives when you need the length alone.
- Backtracking replays the recurrence backwards: diagonal on a match, otherwise step toward the larger neighbour.
- Characters are produced in reverse, so remember the final reverse; forgetting it is the most common bug here.
- The same backtracking template prints the shortest common supersequence and reconstructs edit-distance operations.
