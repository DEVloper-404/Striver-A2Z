# Requirements needed to construct a unique BT

**Difficulty:** Medium  ·  **Topic:** Binary Trees [Traversals, Medium and Hard Problems] › Hard Problems

## Problem
This is a theory item. Given some combination of preorder, inorder, and postorder traversals of a binary tree, when is the tree uniquely determined? The question comes up as a prerequisite to the construction problems (preorder+inorder, postorder+inorder), and as a common interview trick question ("can you build a tree from preorder and postorder?").

Input: preorder = [1, 2], postorder = [2, 1]
Output: not unique — 2 could be either the left or the right child of 1

Input: preorder = [1, 2], inorder = [2, 1]
Output: unique — 2 must be the left child of 1

## Approach: Why inorder is the key ingredient
**What each traversal tells you.**
- Preorder (`root, left, right`) and postorder (`left, right, root`) both identify the root instantly (first / last element), but say nothing about *which side* the remaining nodes fall on.
- Inorder (`left, root, right`) does the opposite: once you know the root, everything before it in the inorder sequence is the left subtree and everything after is the right subtree.

**Combinations that work.**
1. Preorder + Inorder: take `preorder[0]` as the root, locate it in inorder to split into left/right groups, recurse. Unique.
2. Postorder + Inorder: same idea with `postorder[last]` as the root. Unique.

**Combination that does not work.**
Preorder + Postorder alone cannot distinguish a node with only a left child from a node with only a right child. Any tree where some node has exactly one child yields at least two valid answers. Uniqueness is restored only if the tree is *full* (every node has 0 or 2 children), because then the second preorder element is definitely the left child, and finding it in postorder splits the subtrees.

**A single traversal is never enough.** With only one sequence, you cannot tell where the left subtree ends, so several shapes fit.

**Special cases that do work with a single sequence.**
- A BST from its preorder (or postorder) alone: the BST ordering property replaces the inorder information, since the sorted order *is* the inorder.
- A complete binary tree from level order alone: the shape is fixed by completeness.
- Any traversal that explicitly includes null markers (as used in serialization) is enough on its own.

Small illustration of the ambiguity:
```
preorder = [1, 2], postorder = [2, 1]

   1            1
  /      or      \
 2                2
```
Both trees produce exactly those two sequences.

- **Time:** O(N) or O(N log N) for the construction algorithms that follow (see the next problems)
- **Space:** O(N) for the hash map from value to inorder index

## Code (Optimal)
There is no single algorithm to implement here; the code shows the helper that checks whether a preorder/postorder pair can be built uniquely, i.e., whether every node has 0 or 2 children, by attempting a reconstruction and detecting the one-child case.

### C++
```cpp
#include <vector>
#include <unordered_map>
using namespace std;

class Solution {
    // returns false if the (pre, post) pair admits more than one tree
    bool build(vector<int>& pre, vector<int>& post, unordered_map<int,int>& postIdx,
               int ps, int pe, int qs, int qe) {
        if (ps > pe) return true;          // empty subtree, nothing ambiguous
        if (ps == pe) return true;         // single node
        int leftRoot = pre[ps + 1];
        int leftEnd = postIdx[leftRoot];   // left subtree ends here in postorder
        int leftSize = leftEnd - qs + 1;
        if (leftSize == pe - ps) return false; // only one child -> ambiguous
        return build(pre, post, postIdx, ps + 1, ps + leftSize, qs, leftEnd) &&
               build(pre, post, postIdx, ps + leftSize + 1, pe, leftEnd + 1, qe - 1);
    }
public:
    bool isUniqueFromPrePost(vector<int>& pre, vector<int>& post) {
        unordered_map<int,int> postIdx;
        for (int i = 0; i < (int)post.size(); ++i) postIdx[post[i]] = i;
        return build(pre, post, postIdx, 0, pre.size() - 1, 0, post.size() - 1);
    }
};
```

### Java
```java
import java.util.*;

class Solution {
    private Map<Integer, Integer> postIdx = new HashMap<>();

    private boolean build(int[] pre, int[] post, int ps, int pe, int qs, int qe) {
        if (ps >= pe) return true;
        int leftRoot = pre[ps + 1];
        int leftEnd = postIdx.get(leftRoot);
        int leftSize = leftEnd - qs + 1;
        if (leftSize == pe - ps) return false;   // node has exactly one child
        return build(pre, post, ps + 1, ps + leftSize, qs, leftEnd)
            && build(pre, post, ps + leftSize + 1, pe, leftEnd + 1, qe - 1);
    }

    public boolean isUniqueFromPrePost(int[] pre, int[] post) {
        for (int i = 0; i < post.length; i++) postIdx.put(post[i], i);
        return build(pre, post, 0, pre.length - 1, 0, post.length - 1);
    }
}
```

### Python
```python
class Solution:
    def isUniqueFromPrePost(self, pre, post):
        post_idx = {v: i for i, v in enumerate(post)}

        def build(ps, pe, qs, qe):
            if ps >= pe:
                return True
            left_root = pre[ps + 1]
            left_end = post_idx[left_root]
            left_size = left_end - qs + 1
            if left_size == pe - ps:      # exactly one child: ambiguous
                return False
            return build(ps + 1, ps + left_size, qs, left_end) and \
                   build(ps + left_size + 1, pe, left_end + 1, qe - 1)

        return build(0, len(pre) - 1, 0, len(post) - 1)
```

## Key Takeaways
- Preorder or postorder gives the root; inorder gives the left/right split. You need both kinds of information.
- Preorder + postorder is ambiguous whenever some node has a single child; it becomes unique only for full binary trees.
- Extra structure (BST property, completeness, or explicit null markers) can substitute for inorder.
- Duplicate values break all of these methods, since locating the root in inorder becomes ambiguous.
