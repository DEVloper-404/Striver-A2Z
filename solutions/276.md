# Different Ways to Evaluate a Boolean Expression

**Difficulty:** Medium  ·  **Topic:** Dynamic Programming [Patterns and Problems] › MCM DP | Partition DP

## Problem
You are given a boolean expression as a string. Characters at even positions are operands, either `'T'` (true) or `'F'` (false); characters at odd positions are operators, one of `'&'` (AND), `'|'` (OR), `'^'` (XOR). Count the number of ways to fully parenthesize the expression so that it evaluates to **true**. Return the count modulo `1000000007`.

```
Input:  exp = "T|T&F"
Output: 1
```
The two possible bracketings are `T | (T & F) = T | F = T` (counts) and `(T | T) & F = T & F = F` (does not), so the answer is 1.

## Approach 1: Enumerate all bracketings (Brute Force)

Every bracketing corresponds to choosing which operator is applied **last**. Recursively pick a last operator, recursively bracket the left and right halves, evaluate, and count the ones that come out true. Without caching, the number of bracketings of `m` operands is the Catalan number `C(m-1)`, which explodes past `m ≈ 20`.

- **Time:** O(Catalan(n)) — exponential
- **Space:** O(n) recursion stack

## Approach 2: Partition DP carrying "true count" AND "false count" (Optimal)

**Observation 1 — partition on the last operator.** Same shape as MCM: for a sub-expression covering indices `i..j` (both operand positions), the operator applied last sits at some odd index `k` strictly between them. That operator combines the value of `exp[i..k-1]` with the value of `exp[k+1..j]`, and those two halves are independent.

**Observation 2 — counting true is not enough.** If we only tracked "ways to make this half true", we could not handle `&` correctly: `A & B` is true only when both are true, but `A & B` is *false* in three different ways, and an enclosing `|` or `^` needs those false counts. So the state must carry a flag: `f(i, j, isTrue)` = number of ways to bracket `exp[i..j]` so it evaluates to `isTrue`.

**Observation 3 — combine by multiplication.** For a fixed cut `k`, the left half can be made true in `lT` ways and false in `lF` ways; similarly `rT`, `rF` on the right. Every left bracketing pairs with every right bracketing, so counts multiply. Then we just read off the truth table:

| operator | ways to be TRUE | ways to be FALSE |
|---|---|---|
| `&` | `lT*rT` | `lT*rF + lF*rT + lF*rF` |
| `\|` | `lT*rT + lT*rF + lF*rT` | `lF*rF` |
| `^` | `lT*rF + lF*rT` | `lT*rT + lF*rF` |

Sum these over all valid `k` (stepping by 2, since operators live at odd offsets from `i`).

**Base case.** `i == j` is a single operand: it contributes 1 way if it matches the requested truth value, otherwise 0.

**Memoization.** States are `(i, j, isTrue)` — O(n^2) intervals times 2 — and each scans O(n) cut points.

**Dry run on `exp = "T|T&F"`** (indices: `0='T'`, `1='|'`, `2='T'`, `3='&'`, `4='F'`).

Single operands:
- `f(0,0,T)=1, f(0,0,F)=0`
- `f(2,2,T)=1, f(2,2,F)=0`
- `f(4,4,T)=0, f(4,4,F)=1`

`f(0,2)` — only cut `k=1`, operator `|`, with `lT=1,lF=0,rT=1,rF=0`:
- true: `1·1 + 1·0 + 0·1 = 1`; false: `0·0 = 0`

`f(2,4)` — only cut `k=3`, operator `&`, with `lT=1,lF=0` (from `f(2,2)`) and `rT=0,rF=1` (from `f(4,4)`):
- true: `1·0 = 0`; false: `1·1 + 0·0 + 0·1 = 1`

`f(0,4)` — two cuts:
- `k=1`, operator `|`: left `f(0,0)` gives `lT=1,lF=0`; right `f(2,4)` gives `rT=0,rF=1`. True ways `= 1·0 + 1·1 + 0·0 = 1`.
- `k=3`, operator `&`: left `f(0,2)` gives `lT=1,lF=0`; right `f(4,4)` gives `rT=0,rF=1`. True ways `= 1·0 = 0`.

Total `f(0,4,T) = 1 + 0 = 1`, matching the hand count. The single winning bracketing is the `k=1` one, `T | (T & F)`.

- **Time:** O(n^3) — O(n^2) intervals × 2 flags × O(n) cuts
- **Space:** O(n^2) memo table + O(n) stack

## Code (Optimal)

### C++
```cpp
#include <string>
#include <vector>
#include <array>
using namespace std;

class Solution {
    static const long long MOD = 1000000007LL;

    long long solve(int i, int j, int isTrue, const string& exp,
                    vector<vector<array<long long, 2>>>& dp) {
        if (i > j) return 0;
        if (i == j) {
            if (isTrue) return exp[i] == 'T' ? 1 : 0;
            return exp[i] == 'F' ? 1 : 0;
        }
        if (dp[i][j][isTrue] != -1) return dp[i][j][isTrue];

        long long ways = 0;
        for (int k = i + 1; k <= j - 1; k += 2) {      // operators at odd offsets
            long long lT = solve(i, k - 1, 1, exp, dp);
            long long lF = solve(i, k - 1, 0, exp, dp);
            long long rT = solve(k + 1, j, 1, exp, dp);
            long long rF = solve(k + 1, j, 0, exp, dp);

            char op = exp[k];
            if (op == '&') {
                if (isTrue) ways += lT * rT;
                else        ways += lT * rF + lF * rT + lF * rF;
            } else if (op == '|') {
                if (isTrue) ways += lT * rT + lT * rF + lF * rT;
                else        ways += lF * rF;
            } else { // '^'
                if (isTrue) ways += lT * rF + lF * rT;
                else        ways += lT * rT + lF * rF;
            }
            ways %= MOD;
        }
        return dp[i][j][isTrue] = ways;
    }

public:
    int evaluateExp(string& exp) {
        int n = exp.size();
        vector<vector<array<long long, 2>>> dp(
            n, vector<array<long long, 2>>(n, {-1, -1}));
        return (int)solve(0, n - 1, 1, exp, dp);
    }
};
```

### Java
```java
class Solution {
    private static final long MOD = 1000000007L;

    private long solve(int i, int j, int isTrue, String exp, long[][][] dp) {
        if (i > j) return 0;
        if (i == j) {
            if (isTrue == 1) return exp.charAt(i) == 'T' ? 1 : 0;
            return exp.charAt(i) == 'F' ? 1 : 0;
        }
        if (dp[i][j][isTrue] != -1) return dp[i][j][isTrue];

        long ways = 0;
        for (int k = i + 1; k <= j - 1; k += 2) {
            long lT = solve(i, k - 1, 1, exp, dp);
            long lF = solve(i, k - 1, 0, exp, dp);
            long rT = solve(k + 1, j, 1, exp, dp);
            long rF = solve(k + 1, j, 0, exp, dp);

            char op = exp.charAt(k);
            if (op == '&') {
                if (isTrue == 1) ways += lT * rT;
                else             ways += lT * rF + lF * rT + lF * rF;
            } else if (op == '|') {
                if (isTrue == 1) ways += lT * rT + lT * rF + lF * rT;
                else             ways += lF * rF;
            } else {
                if (isTrue == 1) ways += lT * rF + lF * rT;
                else             ways += lT * rT + lF * rF;
            }
            ways %= MOD;
        }
        dp[i][j][isTrue] = ways;
        return ways;
    }

    public int evaluateExp(String exp) {
        int n = exp.length();
        long[][][] dp = new long[n][n][2];
        for (long[][] plane : dp)
            for (long[] row : plane)
                java.util.Arrays.fill(row, -1L);
        return (int) solve(0, n - 1, 1, exp, dp);
    }
}
```

### Python
```python
from functools import lru_cache

class Solution:
    def evaluateExp(self, exp: str) -> int:
        MOD = 1_000_000_007
        n = len(exp)

        @lru_cache(maxsize=None)
        def solve(i: int, j: int, is_true: bool) -> int:
            if i > j:
                return 0
            if i == j:
                return int(exp[i] == ('T' if is_true else 'F'))

            ways = 0
            for k in range(i + 1, j, 2):            # operators at odd offsets
                lT = solve(i, k - 1, True)
                lF = solve(i, k - 1, False)
                rT = solve(k + 1, j, True)
                rF = solve(k + 1, j, False)
                op = exp[k]

                if op == '&':
                    ways += lT * rT if is_true else lT * rF + lF * rT + lF * rF
                elif op == '|':
                    ways += (lT * rT + lT * rF + lF * rT) if is_true else lF * rF
                else:                                # '^'
                    ways += (lT * rF + lF * rT) if is_true else lT * rT + lF * rF
                ways %= MOD

            return ways

        ans = solve(0, n - 1, True)
        solve.cache_clear()
        return ans
```

## Key Takeaways
- Partition on the last operator, exactly like MCM — but the state needs a third dimension because an enclosing operator may need the *false* count of a half.
- Independent halves means the counts **multiply**, then the operator's truth table decides which products to add.
- Operators are only at odd offsets from `i`, so the cut loop steps by 2; forgetting this both slows things down and produces garbage cuts.
- Take the modulus inside the loop and use 64-bit accumulators — the products of two counts near `10^9` overflow 32 bits instantly.
