# Single element in a Sorted Array

**Difficulty:** Medium  ·  **Topic:** Binary Search [1D, 2D Arrays, Search Space] › BS on 1D Arrays

## Problem
You are given a sorted array `nums` in which every element appears exactly twice, except for one element that appears once. Return that single element. The solution must run in O(log n) time and O(1) space.

Input: `nums = [1, 1, 2, 3, 3, 4, 4, 8, 8]`
Output: `2`

Input: `nums = [3, 3, 7, 7, 10, 11, 11]`
Output: `10`

## Approach 1: Linear Scan / XOR
Walk the array in steps of two and return the first element that differs from its neighbour, or XOR every element together (pairs cancel, leaving the single one). Both are O(n).

- **Time:** O(n)
- **Space:** O(1)

## Approach 2: Binary Search on Pair Alignment (Optimal)
Before the single element, pairs start at even indices: `(0,1), (2,3), ...`. After it, every pair is shifted by one and starts at an odd index. So for any index `i`:

- If `i` is on the left of the single element, `nums[i]` equals its partner at `i ^ 1` (the even index pairs with the next odd, the odd index pairs with the previous even).
- If `i` is on the right (or is the single element), `nums[i] != nums[i ^ 1]`.

This is a monotone predicate, so binary search on it:

1. Handle the trivial cases: single element at index 0 or `n - 1` if it differs from its only neighbour.
2. Search over `low = 1 .. high = n - 2`. If `nums[mid]` differs from both neighbours, it is the answer.
3. Otherwise decide which side `mid` is on. If `mid` is even and `nums[mid] == nums[mid + 1]`, or `mid` is odd and `nums[mid] == nums[mid - 1]`, then pairs are still aligned and the single element is to the right: `low = mid + 1`. Else it is to the left: `high = mid - 1`.

- **Time:** O(log n)
- **Space:** O(1)

## Code (Optimal)

### C++
```cpp
#include <vector>
using namespace std;

class Solution {
public:
    int singleNonDuplicate(vector<int>& nums) {
        int n = nums.size();
        if (n == 1) return nums[0];
        if (nums[0] != nums[1]) return nums[0];
        if (nums[n - 1] != nums[n - 2]) return nums[n - 1];

        int low = 1, high = n - 2;
        while (low <= high) {
            int mid = low + (high - low) / 2;
            if (nums[mid] != nums[mid - 1] && nums[mid] != nums[mid + 1]) return nums[mid];

            bool leftSideAligned = (mid % 2 == 0) ? (nums[mid] == nums[mid + 1])
                                                  : (nums[mid] == nums[mid - 1]);
            if (leftSideAligned) low = mid + 1;   // single is to the right
            else high = mid - 1;                  // single is to the left
        }
        return -1; // unreachable for valid input
    }
};
```

### Python
```python
from typing import List

class Solution:
    def singleNonDuplicate(self, nums: List[int]) -> int:
        n = len(nums)
        if n == 1:
            return nums[0]
        if nums[0] != nums[1]:
            return nums[0]
        if nums[n - 1] != nums[n - 2]:
            return nums[n - 1]

        low, high = 1, n - 2
        while low <= high:
            mid = (low + high) // 2
            if nums[mid] != nums[mid - 1] and nums[mid] != nums[mid + 1]:
                return nums[mid]

            if mid % 2 == 0:
                left_side_aligned = nums[mid] == nums[mid + 1]
            else:
                left_side_aligned = nums[mid] == nums[mid - 1]

            if left_side_aligned:
                low = mid + 1   # single element is to the right
            else:
                high = mid - 1  # single element is to the left
        return -1  # unreachable for valid input
```

## Key Takeaways
- The trick is index parity: pairs sit on (even, odd) indices before the lone element and on (odd, even) after it, which gives a monotone condition to binary search on.
- Shrinking the search range to `1 .. n-2` after checking the ends removes all out-of-bounds checks inside the loop.
- A compact alternative: search only even indices with `mid ^ 1` as the partner; the first even `i` where `nums[i] != nums[i ^ 1]` is the answer.
- XOR of all elements is a neat O(n) fallback but does not meet the logarithmic requirement.
