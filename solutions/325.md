# Unbounded knapsack

**Difficulty:** Hard  ·  **Topic:** Dynamic Programming [Patterns and Problems] › DP on Subsequences

## Problem
You are given `n` items, item `i` having weight `wt[i]` and value `val[i]`, and a bag of capacity `W`. Unlike the 0/1 version, each item can be picked **any number of times**. Maximise the total value that fits in the bag.

```
Input:  wt = [2, 4, 6], val = [5, 11, 13], W = 10
Output: 27
Explanation: take item 0 once (w 2, v 5) and item 1 twice (w 8, v 22) -> weight 10, value 27.
```

## Approach 1: Recursion (not take / take-and-stay)

**The key observation.** In 0/1 knapsack, taking an item moves you past it. Here, taking an item leaves it available. So the only change to the classic recursion is *which index the "take" branch recurses on*.

At index `i` with capacity `c`:
- **Not take:** `f(i-1, c)` — item `i` is discarded forever.
- **Take:** `val[i] + f(i, c - wt[i])` — you pay the weight, collect the value, and remain at index `i` so the same item can be taken again. Only allowed when `wt[i] <= c`.

```
f(i, c) = max( f(i-1, c), val[i] + f(i, c - wt[i]) )
```

**Base case.** At `i = 0` only item 0 remains and we can take as many copies as fit: `f(0, c) = (c / wt[0]) * val[0]` using integer division. This closed form is important — a "take one at a time" base case would still be correct but the closed form keeps the recursion clean and terminating.

Termination is guaranteed because the "take" branch strictly decreases the capacity (weights are positive).

- **Time:** exponential
- **Space:** O(W) recursion depth

## Approach 2: Memoization
Only `(i, c)` matters, and there are `n · (W+1)` such pairs, so a 2-D cache initialised to `-1` turns the exponential tree into one pass over the state space.

- **Time:** O(n · W)
- **Space:** O(n · W) table + O(W) stack

## Approach 3: Optimal (tabulation, one rolling row)

`dp[i][c] = best value achievable from items 0..i with capacity c`

- **Base row:** `dp[0][c] = (c / wt[0]) * val[0]`.
- **Transition:** `dp[i][c] = max(dp[i-1][c], val[i] + dp[i][c - wt[i]])`. The take term reads the **same** row at a smaller capacity — the current row is already correct there because we fill capacities in increasing order.
- **Answer:** `dp[n-1][W]`.

**Collapsing to 1-D.** Because "take" reads the current row and "not take" reads the previous row at the *same* capacity, a single array works: for each item, sweep `c` from `wt[i]` up to `W` doing `dp[c] = max(dp[c], val[i] + dp[c - wt[i]])`. Before the item's sweep, `dp[c]` holds the previous row's value (= not take); during the sweep `dp[c - wt[i]]` may already include the current item (= take again). This upward sweep is exactly the difference from 0/1 knapsack, where the sweep must run downward so each item is used at most once.

**Dry run on wt = [2,4,6], val = [5,11,13], W = 10.** Start `dp = [0]*11`.
- Item 0 (w 2, v 5), sweep up: `dp = [0,0,5,5,10,10,15,15,20,20,25]` — as many 2s as fit.
- Item 1 (w 4, v 11): `dp[4] = max(10, 11 + dp[0]) = 11`; `dp[6] = max(15, 11 + dp[2]) = 16`; `dp[8] = max(20, 11 + dp[4]) = 22`; `dp[10] = max(25, 11 + dp[6]) = 27`. Odd capacities pick up the leftover 5. Row is now `[0,0,5,5,11,11,16,16,22,22,27]`.
- Item 2 (w 6, v 13): `dp[6] = max(16, 13 + dp[0]) = 16`; `dp[10] = max(27, 13 + dp[4]) = max(27, 24) = 27`.

Answer `dp[10] = 27`, which is one item 0 plus two of item 1.

- **Time:** O(n · W)
- **Space:** O(W)

## Code (Optimal)

### C++
```cpp
class Solution {
public:
    int unboundedKnapsack(int n, int W, vector<int>& val, vector<int>& wt) {
        vector<int> dp(W + 1, 0);

        for (int i = 0; i < n; i++)
            for (int c = wt[i]; c <= W; c++)          // upward -> item reusable
                dp[c] = max(dp[c], val[i] + dp[c - wt[i]]);

        return dp[W];
    }
};
```

### Java
```java
class Solution {
    public int unboundedKnapsack(int n, int W, int[] val, int[] wt) {
        int[] dp = new int[W + 1];

        for (int i = 0; i < n; i++)
            for (int c = wt[i]; c <= W; c++)
                dp[c] = Math.max(dp[c], val[i] + dp[c - wt[i]]);

        return dp[W];
    }
}
```

### Python
```python
class Solution:
    def unboundedKnapsack(self, n, W, val, wt):
        dp = [0] * (W + 1)

        for i in range(n):
            for c in range(wt[i], W + 1):
                cand = val[i] + dp[c - wt[i]]
                if cand > dp[c]:
                    dp[c] = cand

        return dp[W]
```

## Key Takeaways
- The single structural difference from 0/1 knapsack: the "take" branch recurses on `i`, not `i-1`.
- In 1-D that becomes the capacity sweep direction — **upward** for unbounded, **downward** for 0/1. Getting this backwards silently solves the wrong problem.
- The base row `(c / wt[0]) * val[0]` uses integer division to pack as many copies of item 0 as fit.
- Coin Change (min coins), Coin Change 2 (count combinations) and Rod Cutting are all this same recurrence with a different objective.
