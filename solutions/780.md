# Number of Longest Increasing Subsequences

**Difficulty:** Medium  ·  **Topic:** Dynamic Programming [Patterns and Problems] › DP on LIS

## Problem
Given an integer array `nums`, return **how many** strictly increasing subsequences of *maximum* length there are. Two subsequences are considered different if they use different index sets, even when the values are identical.

```
Input:  nums = [1, 3, 5, 4, 7]
Output: 2      (the LIS length is 4: [1,3,5,7] and [1,3,4,7])

Input:  nums = [2, 2, 2, 2, 2]
Output: 5      (the LIS length is 1, and each of the five elements is one)
```

## Approach 1: Enumerate all increasing subsequences (Brute Force)
Generate every subsequence, keep the increasing ones, find the maximum length, and count how many reach it. Exponential and only useful as a mental reference for correctness.

- **Time:** O(2^n · n)
- **Space:** O(n)

## Approach 2: LIS DP carrying a count alongside the length (Optimal)
Take the standard O(n²) LIS and give every state a second field.

- `dp[i]` = length of the longest increasing subsequence **ending at index `i`**.
- `cnt[i]` = how many such maximum-length subsequences end at index `i`.

Both start at `1` — every element on its own is an increasing subsequence of length 1, and there is exactly one way to have it.

For each `i`, scan every `j < i` with `nums[j] < nums[i]`. The candidate length through `j` is `dp[j] + 1`, and there are exactly two cases:

1. **`dp[j] + 1 > dp[i]`** — we found a *strictly better* chain. Everything counted so far for `i` is now obsolete, so **overwrite**: `dp[i] = dp[j] + 1` and `cnt[i] = cnt[j]`. Note it is `= cnt[j]`, not `+= cnt[j]`, and not `= 1`: every one of the `cnt[j]` best chains ending at `j` extends to a distinct best chain ending at `i`.
2. **`dp[j] + 1 == dp[i]`** — we found *another* way to achieve the same best length, through a different predecessor. **Accumulate**: `cnt[i] += cnt[j]`. The chains coming through different `j` values are distinct because their second-to-last index differs, so no double counting occurs.

If `dp[j] + 1 < dp[i]`, ignore `j` entirely.

Finally, let `maxLen = max(dp)`. The answer is `Σ cnt[i]` over all `i` with `dp[i] == maxLen`. Summing over all such endpoints is valid because each longest subsequence has exactly one last index, so it is counted in exactly one bucket.

**Dry run** on `[1, 3, 5, 4, 7]`:

| i | nums[i] | work                                                               | dp[i] | cnt[i] |
|---|---------|--------------------------------------------------------------------|-------|--------|
| 0 | 1       | —                                                                  | 1     | 1      |
| 1 | 3       | j=0: 1+1 > 1 → overwrite                                           | 2     | 1      |
| 2 | 5       | j=0 → 2 (overwrite); j=1: 2+1 = 3 > 2 → overwrite, cnt = cnt[1] = 1 | 3     | 1      |
| 3 | 4       | j=0 → 2; j=1: 3 > 2 → overwrite, cnt = 1; j=2: 5 ≮ 4, skipped       | 3     | 1      |
| 4 | 7       | j=2: 3+1 = 4 > 3 → overwrite, cnt = cnt[2] = 1; j=3: 3+1 = 4 **ties** → cnt += cnt[3] = 1 | 4 | **2** |

`maxLen = 4`, reached only at index 4, so the answer is `cnt[4] = 2`.

The second example, `[2,2,2,2,2]`, never satisfies `nums[j] < nums[i]`, so every `dp[i] = 1` and `cnt[i] = 1`; `maxLen = 1` and the sum over all five indices gives `5` — which is why the final answer must be a **sum**, not a single `cnt` value.

- **Time:** O(n²)
- **Space:** O(n)

## Approach 3: Segment tree / BIT for O(n log n)
For large `n`, the inner loop is really the query "over all values strictly less than `nums[i]`, what is the maximum `dp`, and what is the total `cnt` at that maximum?" A segment tree over coordinate-compressed values, where each node stores the pair `(bestLength, countAtThatLength)` and merging takes the better length or adds the counts on a tie, answers that in O(log n). The DP logic is identical; only the lookup changes.

- **Time:** O(n log n)
- **Space:** O(n)

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int findNumberOfLIS(vector<int>& nums) {
        int n = nums.size();
        if (n == 0) return 0;

        vector<int> dp(n, 1), cnt(n, 1);
        int maxLen = 1;

        for (int i = 0; i < n; i++) {
            for (int j = 0; j < i; j++) {
                if (nums[j] < nums[i]) {
                    if (dp[j] + 1 > dp[i]) {      // strictly better chain: reset the count
                        dp[i] = dp[j] + 1;
                        cnt[i] = cnt[j];
                    } else if (dp[j] + 1 == dp[i]) {  // another way to the same length
                        cnt[i] += cnt[j];
                    }
                }
            }
            maxLen = max(maxLen, dp[i]);
        }

        int total = 0;
        for (int i = 0; i < n; i++)
            if (dp[i] == maxLen) total += cnt[i];
        return total;
    }
};
```

### Python
```python
from typing import List


class Solution:
    def findNumberOfLIS(self, nums: List[int]) -> int:
        n = len(nums)
        if n == 0:
            return 0

        dp = [1] * n
        cnt = [1] * n

        for i in range(n):
            for j in range(i):
                if nums[j] < nums[i]:
                    if dp[j] + 1 > dp[i]:
                        dp[i] = dp[j] + 1
                        cnt[i] = cnt[j]
                    elif dp[j] + 1 == dp[i]:
                        cnt[i] += cnt[j]

        max_len = max(dp)
        return sum(c for length, c in zip(dp, cnt) if length == max_len)
```

## Key Takeaways
- Counting DPs carry two fields: the optimal value and the number of ways to achieve it. On a strict improvement you **replace** the count; on a tie you **add** to it.
- `cnt[i] = cnt[j]` (not `1`) on the improvement branch — every optimal chain ending at `j` yields a distinct optimal chain ending at `i`.
- The final answer sums `cnt[i]` over *all* indices achieving `maxLen`, because a longest subsequence can end at many different positions.
- Test with all-equal input like `[2,2,2,2,2]`: it catches both the "sum, don't take one value" bug and any accidental use of `<=` instead of `<`.
