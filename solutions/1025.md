# Maximum Xor with an element from an array

**Difficulty:** Hard  ·  **Topic:** Tries › Problems

## Problem
Given an array `nums` and a list of queries where `queries[i] = [x_i, m_i]`, answer each query with the maximum value of `nums[j] ^ x_i` taken over all `j` such that `nums[j] <= m_i`. If no element of `nums` is `<= m_i`, the answer for that query is `-1`. Return the answers in the original query order.

```
Input:  nums = [0, 1, 2, 3, 4], queries = [[3,1], [1,3], [5,6]]
Output: [3, 3, 7]
```
For `[3,1]` only `{0,1}` are allowed and `3^0 = 3` wins; for `[1,3]` the pool is `{0,1,2,3}` and `1^2 = 3` wins; for `[5,6]` everything is allowed and `5^2 = 7` wins.

## Approach 1: Scan the array per query (Brute Force)

For every query, loop over `nums`, skip elements above `m_i`, and track the best XOR. Correct but `O(n)` per query.

- **Time:** O(q · n)
- **Space:** O(1)

## Approach 2: Offline processing with a growing binary trie (Optimal)

**The obstacle.** The plain "max XOR with an element" trie answers a query in `O(B)`, but here each query has an extra ceiling `m_i`. A trie holding *all* of `nums` would happily return a partner larger than `m_i`, and there is no cheap way to filter during the descent.

**Observation 1 — the constraint is monotone.** The allowed pool for a query is `{ v in nums : v <= m }`. If `m` grows, the pool only *grows*; nothing is ever removed. So if we handle the queries in increasing order of `m`, the trie only ever needs **insertions** — never deletions.

**Observation 2 — queries may be reordered, as long as we remember where they came from.** Nothing in the problem couples one query to another, so we are free to answer them **offline**: sort them by `m`, answer in that order, and write each result back into the slot given by its original index.

**The algorithm.**
1. Sort `nums` ascending.
2. Build a list of query indices sorted by `m_i` ascending.
3. Keep a pointer `ptr = 0` into the sorted `nums`, an empty binary trie, and an answers array pre-filled with `-1`.
4. Process queries in the sorted order. For query `(x, m)`:
   - While `ptr < n` and `nums[ptr] <= m`, insert `nums[ptr]` into the trie and advance `ptr`.
   - If `ptr == 0` the trie is still empty (every element exceeds `m`) → leave the answer as `-1`.
   - Otherwise run the standard greedy descent: at bit `i`, with `b = (x >> i) & 1`, prefer child `1 - b` (which makes the XOR bit `1`) and fall back to child `b`.
5. Return the answers array.

Because `ptr` only moves forward across the whole run, the total insertion work is `O(n · B)`, not `O(q · n · B)`. This "sort the queries so the data structure only grows" trick is the general offline pattern; it applies whenever the constraint is a monotone threshold.

**Dry run on `nums = [0,1,2,3,4]`, `queries = [[3,1],[1,3],[5,6]]`.**

`nums` is already sorted. Sorting query indices by `m` gives the order `0 (m=1), 1 (m=3), 2 (m=6)` — here it happens to match the input order.

- **Query index 0: `x = 3, m = 1`.** Insert while `nums[ptr] <= 1`: that adds `0` and `1`, so `ptr = 2` and the trie holds `{0, 1}`. Greedy for `x = 3` (`011` in 3 bits): at bit 1, `x` has `1` and we want a stored `0` — both `0` and `1` have bit 1 = 0, so we take it (XOR bit 1). At bit 0, `x` has `1` and we want `0` — `0` qualifies, take it (XOR bit 1). Result `11 = 3`. Answer slot 0 = **3**.
- **Query index 1: `x = 1, m = 3`.** Insert while `nums[ptr] <= 3`: adds `2` and `3`, `ptr = 4`, trie holds `{0,1,2,3}`. Greedy for `x = 1` (`01`): at bit 1, `x` has `0`, want `1` — `2` and `3` have it, take it (XOR bit 1). At bit 0, among `{2,3}`, `x` has `1` and we want `0` — `2` qualifies, take it (XOR bit 1). Result `11 = 3`, from the pair `1 ^ 2`. Answer slot 1 = **3**.
- **Query index 2: `x = 5, m = 6`.** Insert while `nums[ptr] <= 6`: adds `4`, `ptr = 5`, trie holds `{0,1,2,3,4}`. Greedy for `x = 5` (`101`): bit 2 — `x` has `1`, want `0`, available from `{0,1,2,3}` → XOR bit 1, survivors `{0,1,2,3}`. Bit 1 — `x` has `0`, want `1`, available from `{2,3}` → XOR bit 1, survivors `{2,3}`. Bit 0 — `x` has `1`, want `0`, and `2` qualifies → XOR bit 1. Result `111 = 7`, from `5 ^ 2`. Answer slot 2 = **7**.

Final answers `[3, 3, 7]`. Note `ptr` advanced `0 → 2 → 4 → 5` and never went back — each element was inserted exactly once across all three queries.

- **Time:** O(n log n + q log q + (n + q) · B)
- **Space:** O(n · B) trie nodes plus O(q) for the ordering

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <algorithm>
#include <numeric>
using namespace std;

class Solution {
    struct Node { Node* links[2] = {nullptr, nullptr}; };

    static const int B = 30;                    // values fit in bits 30..0

    void insert(Node* root, int num) {
        Node* cur = root;
        for (int i = B; i >= 0; i--) {
            int bit = (num >> i) & 1;
            if (cur->links[bit] == nullptr) cur->links[bit] = new Node();
            cur = cur->links[bit];
        }
    }

    int queryMax(Node* root, int num) {
        Node* cur = root;
        int best = 0;
        for (int i = B; i >= 0; i--) {
            int bit = (num >> i) & 1;
            int want = 1 - bit;                 // opposite bit -> XOR bit is 1
            if (cur->links[want] != nullptr) {
                best |= (1 << i);
                cur = cur->links[want];
            } else {
                cur = cur->links[bit];
            }
        }
        return best;
    }

public:
    vector<int> maximizeXor(vector<int>& nums, vector<vector<int>>& queries) {
        sort(nums.begin(), nums.end());

        int q = queries.size();
        vector<int> order(q);
        iota(order.begin(), order.end(), 0);
        sort(order.begin(), order.end(), [&](int a, int b) {
            return queries[a][1] < queries[b][1];       // by the ceiling m
        });

        Node* root = new Node();
        vector<int> ans(q, -1);
        int ptr = 0, n = nums.size();

        for (int qi : order) {
            int x = queries[qi][0], m = queries[qi][1];
            while (ptr < n && nums[ptr] <= m) insert(root, nums[ptr++]);
            if (ptr == 0) continue;                     // trie empty -> stays -1
            ans[qi] = queryMax(root, x);
        }
        return ans;
    }
};
```

    public int[] maximizeXor(int[] nums, int[][] queries) {

        int q = queries.length;
        Integer[] order = new Integer[q];
        for (int i = 0; i < q; i++) order[i] = i;

        }
        return ans;
    }
}

### Python
```python
from typing import List

class Solution:
    def maximizeXor(self, nums: List[int], queries: List[List[int]]) -> List[int]:
        B = 30                                       # values fit in bits 30..0
        nums = sorted(nums)
        n = len(nums)

        root = [None, None]                          # a node is [child0, child1]

        def insert(num: int) -> None:
            cur = root
            for i in range(B, -1, -1):
                bit = (num >> i) & 1
                if cur[bit] is None:
                    cur[bit] = [None, None]
                cur = cur[bit]

        def query_max(num: int) -> int:
            cur = root
            best = 0
            for i in range(B, -1, -1):
                bit = (num >> i) & 1
                want = 1 - bit                       # opposite bit -> XOR bit 1
                if cur[want] is not None:
                    best |= (1 << i)
                    cur = cur[want]
                else:
                    cur = cur[bit]
            return best

        order = sorted(range(len(queries)), key=lambda i: queries[i][1])
        ans = [-1] * len(queries)
        ptr = 0

        for qi in order:
            x, m = queries[qi]
            while ptr < n and nums[ptr] <= m:
                insert(nums[ptr])
                ptr += 1
            if ptr == 0:                             # trie empty -> answer stays -1
                continue
            ans[qi] = query_max(x)

        return ans
```

## Key Takeaways
- Offline processing: sort queries by their threshold so the structure only ever grows — no deletions, and each element is inserted exactly once overall.
- Always carry the original query index and write results back into that slot; sorting the queries otherwise scrambles the output.
- The `-1` case is detected by "nothing has been inserted yet" (`ptr == 0`), which is cheaper and clearer than probing the trie.
- Sort `nums` first — the two-pointer insertion is only valid on sorted data. This pattern generalises to any query with a monotone `<= m` filter.
