# Coin Change 2 (DP - 22)

**Difficulty:** Hard  ·  **Topic:** Dynamic Programming [Patterns and Problems] › DP on Subsequences

## Problem
Given an array of distinct coin denominations and a target `amount`, count how many distinct **combinations** of coins add up exactly to the amount. You have an infinite supply of each denomination, and two combinations are the same if they use the same multiset of coins — order does not matter.

```
Input:  coins = [1, 2, 5], amount = 5
Output: 4
Explanation: 5 = 5, 5 = 2+2+1, 5 = 2+1+1+1, 5 = 1+1+1+1+1.

Input:  coins = [2], amount = 3
Output: 0
```

## Approach 1: Recursion (pick / stay)

**The observation.** This is the unbounded-knapsack shape with counting instead of maximising. At index `i` with amount `t` remaining:
- **Not take:** move to `i-1` with `t` unchanged, permanently retiring coin `i`.
- **Take:** subtract `coins[i]` from `t` but **stay at index `i`**, since the coin can be used again.

```
f(i, t) = f(i-1, t) + f(i, t - coins[i])      // second term only if t >= coins[i]
```

**Base case.** At `i = 0` only `coins[0]` remains, so there is exactly one way if `t % coins[0] == 0` and zero ways otherwise.

**Why this counts combinations, not permutations.** The recursion visits coins in a fixed order: it finishes deciding how many copies of `coins[i]` to use before it ever moves to `i-1`. So `1+2` and `2+1` are never generated as two separate paths — the coin order is baked into the recursion structure. That is the whole difference between this problem and "count ordered ways", and it is easy to break accidentally (see the takeaways).

- **Time:** exponential
- **Space:** O(amount) stack depth

## Approach 2: Memoization
There are only `n · (amount+1)` distinct `(i, t)` states, so cache them in a 2-D table of `-1`s.

- **Time:** O(n · amount)
- **Space:** O(n · amount) + O(amount) stack

## Approach 3: Optimal (tabulation with a single rolling row)

`dp[i][t] = number of combinations using coins[0..i] that sum to t`

- **Base row:** `dp[0][t] = 1` when `t % coins[0] == 0`, else 0.
- **Transition:** `dp[i][t] = dp[i-1][t] + dp[i][t - coins[i]]` — the second term reads the **current** row, which is the "coin can be reused" part.
- **Answer:** `dp[n-1][amount]`.

Collapsing to one dimension: keep a single array `dp` of size `amount+1` with `dp[0] = 1`, and for each coin sweep `t` from `coin` upward doing `dp[t] += dp[t - coin]`.

The loop **order is the entire algorithm**. The coin loop is on the outside; the amount loop is on the inside. That means when we process coin `c`, every value in `dp` already reflects combinations built only from earlier coins plus copies of `c`. A combination therefore gets counted once, in the order the coins were processed. Swapping the loops (amount outside, coins inside) would count `1+2` and `2+1` separately and answer a different question.

Sweeping `t` upward (not downward) is what allows multiple copies of the same coin — `dp[t - coin]` may already include coin `c`.

**Dry run on coins = [1, 2, 5], amount = 5.** Start `dp = [1, 0, 0, 0, 0, 0]`.
- Coin 1: `dp[t] += dp[t-1]` for t = 1..5 → `[1, 1, 1, 1, 1, 1]` (one all-ones combination per amount).
- Coin 2: t=2 → `dp[2] = 1 + dp[0] = 2`; t=3 → `1 + dp[1] = 2`; t=4 → `1 + dp[2] = 3`; t=5 → `1 + dp[3] = 3`. Now `[1, 1, 2, 2, 3, 3]`.
- Coin 5: t=5 → `dp[5] = 3 + dp[0] = 4`.

`dp[5] = 4`, matching the four combinations listed above.

- **Time:** O(n · amount)
- **Space:** O(amount)

## Code (Optimal)

### C++
```cpp
class Solution {
public:
    int change(int amount, vector<int>& coins) {
        vector<unsigned long long> dp(amount + 1, 0);
        dp[0] = 1;                                  // one way to make 0: take nothing

        for (int coin : coins)                      // coin loop OUTSIDE -> combinations
            for (int t = coin; t <= amount; t++)    // upward -> unlimited copies
                dp[t] += dp[t - coin];

        return (int)dp[amount];
    }
};
```

### Python
```python
class Solution:
    def change(self, amount, coins):
        dp = [0] * (amount + 1)
        dp[0] = 1

        for coin in coins:
            for t in range(coin, amount + 1):
                dp[t] += dp[t - coin]

        return dp[amount]
```

## Key Takeaways
- Coin loop outside, amount loop inside counts **combinations**; reversing the loops counts **permutations** — same array, different problem.
- Sweeping the amount upward permits reuse of a coin (unbounded knapsack); sweeping downward would make each coin usable at most once (0/1 knapsack).
- `dp[0] = 1` is the base: the empty selection is one valid way to reach amount 0.
- Counts grow fast; use a 64-bit accumulator (or mod) even when the final answer is guaranteed to fit in an int.
