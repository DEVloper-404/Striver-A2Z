# Kth element of 2 sorted arrays

**Difficulty:** Medium  ·  **Topic:** Binary Search [1D, 2D Arrays, Search Space] › BS on Answers

## Problem
Given two sorted arrays `a` (size `m`) and `b` (size `n`) and an integer `k` (1-indexed, `1 <= k <= m + n`), return the k-th smallest element of their combined sorted order without actually merging them.

Input: a = [2, 3, 6, 7, 9], b = [1, 4, 8, 10], k = 5
Output: 6  (merged: [1, 2, 3, 4, 6, 7, 8, 9, 10] → 5th is 6)

## Approach 1: Merge and Index
Merge the two arrays with two pointers into a new array and return the element at index `k - 1`.
- **Time:** O(m + n)
- **Space:** O(m + n)

## Approach 2: Merge with a Counter
Run the two-pointer merge but only count how many elements have been emitted; return the k-th one without storing anything.
- **Time:** O(k)
- **Space:** O(1)

## Approach 3: Binary Search on the Partition
The k-th element is the largest element of the left half when the "left half" is exactly the `k` smallest elements. Pick `i` elements from `a` and `j = k - i` from `b`. The cut is valid when `l1 <= r2` and `l2 <= r1` (with `l1 = a[i-1]`, `r1 = a[i]`, `l2 = b[j-1]`, `r2 = b[j]`, using ±infinity at boundaries). Then the answer is `max(l1, l2)`.

Binary search `i` on the smaller array. The bounds are tighter than in the median problem: `i` must be at least `max(0, k - n)` (so `j <= n`) and at most `min(k, m)` (so `j >= 0`).
- If `l1 > r2`, we took too many from `a`: `hi = i - 1`.
- If `l2 > r1`, too few: `lo = i + 1`.
- **Time:** O(log(min(m, n)))
- **Space:** O(1)

## Code (Optimal)

### C++
```cpp
class Solution {
public:
    int kthElement(vector<int>& a, vector<int>& b, int k) {
        if (a.size() > b.size()) return kthElement(b, a, k);
        int m = a.size(), n = b.size();
        int lo = max(0, k - n), hi = min(k, m);
        const int INF = INT_MAX;
        while (lo <= hi) {
            int i = lo + (hi - lo) / 2;
            int j = k - i;
            int l1 = (i > 0) ? a[i - 1] : -INF;
            int r1 = (i < m) ? a[i] : INF;
            int l2 = (j > 0) ? b[j - 1] : -INF;
            int r2 = (j < n) ? b[j] : INF;
            if (l1 <= r2 && l2 <= r1) return max(l1, l2);
            if (l1 > r2) hi = i - 1;
            else lo = i + 1;
        }
        return -1; // unreachable for valid input
    }
};
```

class Solution {
    public int kthElement(int[] a, int[] b, int k) {
        if (a.length > b.length) return kthElement(b, a, k);
        int m = a.length, n = b.length;
        int lo = Math.max(0, k - n), hi = Math.min(k, m);
        while (lo <= hi) {
            int i = lo + (hi - lo) / 2;
            int j = k - i;
            int l1 = (i > 0) ? a[i - 1] : Integer.MIN_VALUE;
            int r1 = (i < m) ? a[i] : Integer.MAX_VALUE;
            int l2 = (j > 0) ? b[j - 1] : Integer.MIN_VALUE;
            int r2 = (j < n) ? b[j] : Integer.MAX_VALUE;
            if (l1 <= r2 && l2 <= r1) return Math.max(l1, l2);
            if (l1 > r2) hi = i - 1;
            else lo = i + 1;
        }
        return -1;
    }
}

### Python
```python
from typing import List

class Solution:
    def kthElement(self, a: List[int], b: List[int], k: int) -> int:
        if len(a) > len(b):
            a, b = b, a
        m, n = len(a), len(b)
        lo, hi = max(0, k - n), min(k, m)
        INF = float("inf")
        while lo <= hi:
            i = (lo + hi) // 2
            j = k - i
            l1 = a[i - 1] if i > 0 else -INF
            r1 = a[i] if i < m else INF
            l2 = b[j - 1] if j > 0 else -INF
            r2 = b[j] if j < n else INF
            if l1 <= r2 and l2 <= r1:
                return max(l1, l2)
            if l1 > r2:
                hi = i - 1
            else:
                lo = i + 1
        return -1
```

## Key Takeaways
- Same partition trick as Median of Two Sorted Arrays, with the left half fixed at exactly `k` elements.
- The search range `[max(0, k - n), min(k, m)]` is what keeps `j` valid; forgetting it causes index errors.
- Answer is `max(l1, l2)`, the biggest element in the left half.
- The O(k) merge-with-counter is a good fallback and easy to reason about.
