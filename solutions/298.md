# Minimum Falling Path Sum

**Difficulty:** Medium  ·  **Topic:** Dynamic Programming [Patterns and Problems] › 2D/3D DP and DP on Grids

## Problem
Given an `n × n` matrix, a *falling path* starts at **any** cell of the first row and moves down one row at a time. From cell `(i, j)` it may drop to `(i+1, j-1)`, `(i+1, j)` or `(i+1, j+1)` — straight down or diagonally by one — as long as it stays inside the matrix. Return the **minimum sum** of a falling path.

```
Input:  matrix = [[2, 1, 3],
                  [6, 5, 4],
                  [7, 8, 9]]
Output: 13
        Path 1 → 5 → 7 : (0,1) → (1,1) → (2,0), sum = 1 + 5 + 7 = 13
```

## Approach 1: Recursion over all starting columns (brute force)

**What makes this different from a fixed-start grid problem.** There is no single source and no single destination — the path may begin at any column of row 0 and end at any column of row `n-1`. The clean way to handle that is to define the state so the *freedom lives at the base case*, and then take a minimum over all endpoints at the top level.

Let `f(i, j)` = minimum sum of a falling path that starts somewhere in row 0 and **ends at cell `(i, j)`**. Split on where the last step came from — the cell above-left, directly above, or above-right:

```
f(0, j) = matrix[0][j]                                   // path of length 1
f(i, j) = matrix[i][j] + min( f(i-1, j-1),
                              f(i-1, j),
                              f(i-1, j+1) )              // out-of-range terms = +INF
answer  = min over j of f(n-1, j)
```

Why is a plain `min` of the three correct? The cost of the step into `(i, j)` is `matrix[i][j]` regardless of which of the three cells we came from, so the cheapest path ending at `(i, j)` through a given predecessor is exactly "cheapest path ending at that predecessor" plus a constant. Optimal substructure holds; no information beyond the predecessor's cell needs to be carried.

Use `+INF` (not `0`) for out-of-range predecessors — using `0` would invent free paths that fall off the side of the matrix. In practice use a big constant like `1e9` so adding `matrix[i][j]` cannot overflow.

Each call branches into 3 and the depth is `n`, so raw recursion costs about `O(3^n)` per starting column.
- **Time:** O(n · 3^n)
- **Space:** O(n) recursion stack

## Approach 2: Memoization
The state is the pair `(i, j)`, so there are `n²` states and each does O(3) work. Cache in `dp[i][j]` with a sentinel (`INT_MAX` or a `visited` flag — careful, `-1` is a legal answer if the matrix contains negatives, which it may).
- **Time:** O(n²)
- **Space:** O(n²) table + O(n) stack

## Approach 3: Tabulation
Fill row 0 with the matrix's first row, then compute each subsequent row from the one above:

```
dp[0][j] = matrix[0][j]
dp[i][j] = matrix[i][j] + min(dp[i-1][j-1], dp[i-1][j], dp[i-1][j+1])   // skip out-of-range
answer   = min(dp[n-1][*])
```

**Dry run on the example.**

| row | dp values | how |
|---|---|---|
| 0 | `[2, 1, 3]` | copy of row 0 |
| 1 | `[7, 6, 5]` | `6+min(2,1)=7` · `5+min(2,1,3)=6` · `4+min(1,3)=5` |
| 2 | `[13, 13, 14]` | `7+min(7,6)=13` · `8+min(7,6,5)=13` · `9+min(6,5)=14` |

Minimum of the last row = **13**. ✔ Tracing back, `dp[2][0] = 13` came from `dp[1][1] = 6`, which came from `dp[0][1] = 1` — the path `1 → 5 → 7`.
- **Time:** O(n²)
- **Space:** O(n²)

## Approach 4: Two rolling rows (Optimal)

Row `i` reads only row `i-1`, so keep a single array `prev` of length `n` and build a fresh `cur` each row. (Unlike Unique Paths you cannot safely update in place, because `dp[i][j]` needs `dp[i-1][j+1]` — a cell to the *right* in the previous row — which an in-place left-to-right sweep would have already overwritten.)

**Algorithm.**
1. `prev = matrix[0]`.
2. For `i = 1 … n-1`: for each `j`, take `best = prev[j]`; if `j > 0` also consider `prev[j-1]`; if `j < n-1` also consider `prev[j+1]`; set `cur[j] = matrix[i][j] + best`. Then `prev = cur`.
3. Return `min(prev)`.
- **Time:** O(n²)
- **Space:** O(n)

## Approach 5: The close cousin — Minimum Path Sum in a grid
The same machinery solves the fixed-endpoint variant (LeetCode 64): start at `(0,0)`, end at `(m-1, n-1)`, and move only **right or down**. Only the transition and the base case change — two predecessors instead of three, one start instead of `n`, one end instead of `n`:

```
dp[0][0] = grid[0][0]
dp[i][j] = grid[i][j] + min( dp[i-1][j] (if i>0), dp[i][j-1] (if j>0) )
answer   = dp[m-1][n-1]
```
Recognising that both problems are "minimum cost to reach this cell, split on the last move" is the transferable idea; the direction set and the endpoint rules are just parameters.
- **Time:** O(m·n)
- **Space:** O(n) with a rolling row

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <algorithm>
#include <climits>
using namespace std;

class Solution {
public:
    int minFallingPathSum(vector<vector<int>>& matrix) {
        int n = matrix.size();
        vector<int> prev = matrix[0];
        for (int i = 1; i < n; i++) {
            vector<int> cur(n);
            for (int j = 0; j < n; j++) {
                int best = prev[j];                       // straight down
                if (j > 0)     best = min(best, prev[j - 1]);   // from up-left
                if (j < n - 1) best = min(best, prev[j + 1]);   // from up-right
                cur[j] = matrix[i][j] + best;
            }
            prev = cur;
        }
        return *min_element(prev.begin(), prev.end());
    }
};
```

### Java
```java
import java.util.Arrays;

class Solution {
    public int minFallingPathSum(int[][] matrix) {
        int n = matrix.length;
        int[] prev = Arrays.copyOf(matrix[0], n);
        for (int i = 1; i < n; i++) {
            int[] cur = new int[n];
            for (int j = 0; j < n; j++) {
                int best = prev[j];                            // straight down
                if (j > 0)     best = Math.min(best, prev[j - 1]);  // from up-left
                if (j < n - 1) best = Math.min(best, prev[j + 1]);  // from up-right
                cur[j] = matrix[i][j] + best;
            }
            prev = cur;
        }
        int ans = Integer.MAX_VALUE;
        for (int v : prev) ans = Math.min(ans, v);
        return ans;
    }
}
```

```python
from typing import List


class Solution:
    def minFallingPathSum(self, matrix: List[List[int]]) -> int:
        n = len(matrix)
        prev = list(matrix[0])
        for i in range(1, n):
            cur = [0] * n
            for j in range(n):
                best = prev[j]                          # straight down
                if j > 0:
                    best = min(best, prev[j - 1])       # from up-left
                if j < n - 1:
                    best = min(best, prev[j + 1])       # from up-right
                cur[j] = matrix[i][j] + best
            prev = cur
        return min(prev)
```

## Key Takeaways
- With a free starting point, put the freedom in the base row (`dp[0][j] = matrix[0][j]`); with a free ending point, take a `min` over the final row.
- The recurrence is always "cell cost + best predecessor", where the predecessor set is determined by the allowed moves — three cells here, two for right/down grid paths.
- Out-of-range predecessors must be `+INF`, never `0`, or the DP will manufacture paths that leave the matrix.
- Do **not** update a single row in place here: the recurrence reads `prev[j+1]`, which in-place updating would have already clobbered. Keep two rows.
- Same skeleton, different parameters, solves Minimum Path Sum in a grid and Triangle — recognise the family rather than memorising each.
