# Java Collections

**Difficulty:** Easy  ·  **Topic:** Learn the basics › Learn STL/Java-Collections or similar thing in your language

## Problem
This is a theory item. It covers the Java Collections Framework — the standard set of interfaces (`List`, `Set`, `Map`, `Queue`, `Deque`) and their concrete implementations (`ArrayList`, `HashMap`, `TreeMap`, `PriorityQueue`, `ArrayDeque`, ...) — plus the `Collections` and `Arrays` utility classes. The goal is to know which class to pick for a problem and what each operation costs.

Input: none. Output: a working map from "I need X" to "use class Y", with the common method names and complexities.

## Approach
Java splits collections into interfaces (what you can do) and implementations (how it is stored). Program against the interface and choose the implementation by cost.

**1. `List` — ordered, indexed, duplicates allowed**

- `ArrayList<E>`: backed by a resizable array. `get(i)`/`set(i, x)` O(1), `add(x)` amortised O(1), `add(i, x)`/`remove(i)` O(n).
- `LinkedList<E>`: doubly linked. O(1) add/remove at the ends, O(n) indexed access. Rarely the right choice; `ArrayDeque` beats it for queues.

```java
List<Integer> list = new ArrayList<>();
list.add(5); list.add(3); list.add(8);
list.add(1, 99);            // insert at index 1 -> [5, 99, 3, 8]
list.remove(Integer.valueOf(99)); // remove by value (boxed), not index
Collections.sort(list);     // [3, 5, 8]
Collections.reverse(list);
int mx = Collections.max(list);
```

Note the trap: `list.remove(1)` removes the element at index 1, while `list.remove(Integer.valueOf(1))` removes the value 1.

**2. `Set` — no duplicates**

- `HashSet<E>`: hash table, O(1) average `add`/`contains`/`remove`, no order.
- `LinkedHashSet<E>`: same, but remembers insertion order.
- `TreeSet<E>`: red-black tree, O(log n) operations, sorted; gives `first()`, `last()`, `floor(x)`, `ceiling(x)`, `higher(x)`, `lower(x)`, `headSet`, `tailSet`.

**3. `Map` — key to value**

- `HashMap<K,V>`: O(1) average. Core methods: `put`, `get`, `getOrDefault`, `containsKey`, `remove`, `merge`, `entrySet()`.
- `TreeMap<K,V>`: sorted by key, O(log n), with `firstKey`, `lastKey`, `floorKey`, `ceilingKey`.
- `LinkedHashMap<K,V>`: insertion order; with access-order mode it is the standard building block for an LRU cache.

```java
Map<String, Integer> freq = new HashMap<>();
for (String w : words) freq.merge(w, 1, Integer::sum);   // count words
for (Map.Entry<String, Integer> e : freq.entrySet())
    System.out.println(e.getKey() + " -> " + e.getValue());
int c = freq.getOrDefault("missing", 0);                  // safe lookup
```

**4. `Queue` / `Deque` / `PriorityQueue`**

- `ArrayDeque<E>`: use it for both stacks (`push`/`pop`/`peek`) and queues (`offer`/`poll`/`peek`). All O(1). Prefer it over the legacy `Stack` class.
- `PriorityQueue<E>`: binary heap, min-heap by default. `offer`/`poll` O(log n), `peek` O(1). Pass a comparator for a max-heap: `new PriorityQueue<>(Collections.reverseOrder())` or `(a, b) -> b - a` (careful with overflow; use `Integer.compare`).

**5. Utility classes**

- `Arrays.sort(int[])` (dual-pivot quicksort, O(n log n)), `Arrays.sort(T[], comparator)`, `Arrays.fill`, `Arrays.asList`, `Arrays.binarySearch`, `Arrays.toString`.
- `Collections.sort`, `reverse`, `max`, `min`, `swap`, `frequency`, `unmodifiableList`.
- Sorting arrays of arrays: `Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]))`.

**6. Iteration and boxing**

Enhanced for loops work on every collection. Primitive arrays (`int[]`) are not collections; `List<Integer>` boxes each value, which costs memory and time — use `int[]` in hot loops when the size is fixed.

- **Time:** `ArrayList` index O(1); `HashMap`/`HashSet` O(1) average; `TreeMap`/`TreeSet`/`PriorityQueue` O(log n); sorting O(n log n).
- **Space:** O(n) for n stored elements (plus boxing overhead for wrapper types).

## Code (Optimal)

A single program that touches every collection you are likely to need in interviews.

### C++
```cpp
// C++ counterparts of the Java classes discussed above.
#include <bits/stdc++.h>
using namespace std;

int main() {
    vector<int> list = {5, 3, 8};                 // ArrayList
    sort(list.begin(), list.end());               // Collections.sort

    unordered_map<string, int> freq;              // HashMap
    for (string w : {"a", "b", "a"}) freq[w]++;

    set<int> sorted = {5, 1, 3};                  // TreeSet
    auto ceil3 = sorted.lower_bound(3);           // ceiling(3) -> 3

    priority_queue<int, vector<int>, greater<int>> minHeap; // PriorityQueue
    for (int x : list) minHeap.push(x);

    deque<int> dq;                                // ArrayDeque
    dq.push_back(1); dq.push_front(0); dq.pop_back();

    cout << list[0] << ' ' << freq["a"] << ' ' << *ceil3 << ' '
         << minHeap.top() << ' ' << dq.front() << '\n';       // 3 2 3 3 0
    return 0;
}
```

### Java
```java
import java.util.*;

public class Main {
    public static void main(String[] args) {
        // List
        List<Integer> list = new ArrayList<>(List.of(5, 3, 8));
        Collections.sort(list);                                 // [3, 5, 8]

        // Map with counting
        Map<String, Integer> freq = new HashMap<>();
        for (String w : new String[]{"a", "b", "a"}) freq.merge(w, 1, Integer::sum);

        // Sorted set with navigation
        TreeSet<Integer> sorted = new TreeSet<>(List.of(5, 1, 3));
        int ceil3 = sorted.ceiling(3);                          // 3

        // Heaps
        PriorityQueue<Integer> minHeap = new PriorityQueue<>(list);
        PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Collections.reverseOrder());
        maxHeap.addAll(list);

        // Stack and queue via ArrayDeque
        Deque<Integer> stack = new ArrayDeque<>();
        stack.push(1); stack.push(2); stack.pop();              // top is 1
        Queue<Integer> queue = new ArrayDeque<>();
        queue.offer(0); queue.offer(1);                         // front is 0

        // Sorting a 2-D array by first column
        int[][] intervals = {{3, 4}, {1, 2}};
        Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));

        System.out.println(list.get(0) + " " + freq.get("a") + " " + ceil3 + " "
                + minHeap.peek() + " " + maxHeap.peek() + " " + stack.peek() + " "
                + queue.peek() + " " + intervals[0][0]);        // 3 2 3 3 8 1 0 1
    }
}
```

### Python
```python
import heapq
from collections import Counter, deque
from bisect import bisect_left

def main():
    lst = sorted([5, 3, 8])                # list + sort

    freq = Counter(["a", "b", "a"])        # dict-based counting

    srt = sorted({5, 1, 3})                # sorted unique values
    ceil3 = srt[bisect_left(srt, 3)]       # ceiling(3) -> 3

    min_heap = list(lst); heapq.heapify(min_heap)
    max_heap = [-x for x in lst]; heapq.heapify(max_heap)

    stack = [1, 2]; stack.pop()            # list as stack
    queue = deque([0, 1])                  # deque as queue

    intervals = sorted([[3, 4], [1, 2]], key=lambda p: p[0])

    print(lst[0], freq["a"], ceil3, min_heap[0], -max_heap[0],
          stack[-1], queue[0], intervals[0][0])   # 3 2 3 3 8 1 0 1

if __name__ == "__main__":
    main()
```

## Key Takeaways
- Pick by cost: `ArrayList` for indexed access, `HashMap`/`HashSet` for O(1) lookup, `TreeMap`/`TreeSet` when you need order or floor/ceiling queries, `PriorityQueue` for repeated min/max.
- Use `ArrayDeque` for stacks and queues; avoid the legacy `Stack` and `Vector` classes.
- `list.remove(int)` and `list.remove(Object)` do different things; `map.merge` and `getOrDefault` replace most manual null checks.
- Comparators should use `Integer.compare(a, b)` rather than `a - b` to avoid overflow.
