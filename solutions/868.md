# Subsets II

**Difficulty:** Medium  ·  **Topic:** Recursion [PatternWise] › Subsequences Pattern

## Problem
Given an integer array `nums` that may contain duplicates, return **all possible subsets (the power set) without any duplicate subsets**. Subsets are multisets — `[1, 2]` and `[2, 1]` are the same subset and must appear only once. The answer may be returned in any order.

```
Input:  nums = [1, 2, 2]
Output: [[], [1], [1, 2], [1, 2, 2], [2], [2, 2]]
```
Note that `[1, 2]` is a single entry even though it can be built from either copy of the `2`.

## Approach 1: Generate all 2^n subsets, then de-duplicate
Run the plain pick/not-pick recursion. At each leaf, sort the collected subset and insert it into a set of vectors; finally copy the set into the answer. Sorting makes `[2, 1]`-style orderings comparable, and the set collapses identical multisets.

Correct, and easy to write under pressure, but it pays for every duplicate twice: once to generate the branch and once to sort and hash the result. With `n = 15` and many repeats, most of the `32768` leaves are thrown away.

- **Time:** O(2^n · n log n)
- **Space:** O(2^n · n) for the set.

## Approach 2: Sort + skip repeats at the same level (Optimal)
Sort `nums` so equal values are adjacent: `[1, 2, 2]`.

Now build subsets with a loop-based recursion rather than a binary one. `solve(start)` means "the current prefix is a valid subset; extend it with any index `j >= start`". Crucially, **record `current` as an answer the moment you enter `solve`, before extending it** — every prefix is itself a subset, so no separate base case is needed and the empty subset is captured on the very first call.

The duplicate rule is the same observation as in Combination Sum II: inside one loop, index `j` and index `j-1` holding the same value produce identical subtrees — same value appended, same suffix available afterwards — so the second one is pure repetition. Skip it with `if (j > start && nums[j] == nums[j-1]) continue;`. The `j > start` guard permits the first occurrence at this level, which is what lets `[2]` grow into `[2, 2]`.

**Algorithm.**
1. Sort `nums`.
2. `solve(start)`: push a copy of `current` into the answer.
3. For `j` from `start` to `n-1`: skip if `j > start && nums[j] == nums[j-1]`; otherwise push `nums[j]`, call `solve(j + 1)`, pop.

**Dry run on `[1, 2, 2]`.**
- `solve(0)` records `[]`.
  - `j = 0` takes `1` → `solve(1)` records `[1]`.
    - `j = 1` takes `2` → `solve(2)` records `[1, 2]`.
      - `j = 2`, but `j > start`? here `start = 2`, so `j == start` and the second `2` is allowed → records `[1, 2, 2]`.
    - `j = 2` back at `start = 1`: `nums[2] == nums[1]` and `j > start`, so it is **skipped** — this is exactly the branch that would have re-emitted `[1, 2]`.
  - `j = 1` takes `2` → records `[2]`, then `[2, 2]`.
  - `j = 2` at `start = 0`: duplicate of index 1 at the same level → skipped, which would have re-emitted `[2]`.

Six subsets, each exactly once, no set required.

- **Time:** O(2^n · n) — bounded by the number of subsets times the cost of copying each.
- **Space:** O(n) recursion depth plus the working subset.

## Code (Optimal)

### C++
```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    vector<vector<int>> subsetsWithDup(vector<int>& nums) {
        sort(nums.begin(), nums.end());
        vector<vector<int>> res;
        vector<int> cur;
        solve(0, nums, cur, res);
        return res;
    }

private:
    void solve(int start, vector<int>& nums,
               vector<int>& cur, vector<vector<int>>& res) {
        res.push_back(cur);                 // every prefix is itself a subset
        for (int j = start; j < (int)nums.size(); j++) {
            if (j > start && nums[j] == nums[j - 1]) continue;   // same value, same level
            cur.push_back(nums[j]);
            solve(j + 1, nums, cur, res);
            cur.pop_back();
        }
    }
};
```

### Java
```java
import java.util.*;

class Solution {
    public List<List<Integer>> subsetsWithDup(int[] nums) {
        Arrays.sort(nums);
        List<List<Integer>> res = new ArrayList<>();
        solve(0, nums, new ArrayList<>(), res);
        return res;
    }

    private void solve(int start, int[] nums,
                       List<Integer> cur, List<List<Integer>> res) {
        res.add(new ArrayList<>(cur));
        for (int j = start; j < nums.length; j++) {
            if (j > start && nums[j] == nums[j - 1]) continue;
            cur.add(nums[j]);
            solve(j + 1, nums, cur, res);
            cur.remove(cur.size() - 1);
        }
    }
}
```

### Python
```python
from typing import List

class Solution:
    def subsetsWithDup(self, nums: List[int]) -> List[List[int]]:
        nums.sort()
        res, cur = [], []
        n = len(nums)

        def solve(start: int) -> None:
            res.append(cur[:])
            for j in range(start, n):
                if j > start and nums[j] == nums[j - 1]:
                    continue
                cur.append(nums[j])
                solve(j + 1)
                cur.pop()

        solve(0)
        return res
```

## Key Takeaways
- Sorting is what makes duplicate detection a local `nums[j] == nums[j-1]` check instead of a global set lookup.
- Recording `current` on entry (not at a leaf) is the trick that emits every subset, including the empty one, with no base case.
- `j > start` distinguishes "a repeated value at the same position" (bad) from "a repeated value deeper in the same subset" (good, e.g. `[2, 2]`).
- The same level-skip idiom reappears in Combination Sum II, Permutations II, and Palindrome Partitioning with duplicates — learn it once, reuse it everywhere.
