# Largest BST in Binary Tree

**Difficulty:** Hard  ·  **Topic:** Binary Search Trees [Concept and Problems] › Practice Problems

## Problem
Given the root of a **binary tree** (not necessarily a BST), find the number of nodes in the largest subtree that *is* a valid BST. A "subtree" here means a node together with all of its descendants — you may not pick and choose which descendants to include.

```
Input:  root = [10, 5, 15, 1, 8, null, 7]
Output: 3      (the subtree rooted at 5 → {1, 5, 8} is a BST of size 3;
                the whole tree is not, because 7 sits in 10's right subtree)

Input:  root = [4, 2, 7, 1, 3]
Output: 5      (the entire tree is already a BST)
```

## Approach 1: Brute Force (validate every subtree independently)
For every node, run a full "is this subtree a BST?" check and, if it passes, count its nodes. Track the maximum.

This works but re-examines the same nodes over and over — validating the subtree at each of N nodes costs O(size of that subtree), which is O(N²) in total (O(N·H) if you fuse the validation and the counting).
- **Time:** O(N²) worst case
- **Space:** O(H)

## Approach 2: Optimal (single bottom-up pass returning a summary triple)
The redundancy in the brute force comes from asking the same question repeatedly. Fix it by making one **post-order** pass in which every subtree reports a small summary to its parent, so the parent can decide in O(1).

What does a parent actually need to know about each child's subtree? Exactly three things:
- `minVal` — the smallest value in it,
- `maxVal` — the largest value in it,
- `size` — the number of nodes in the **largest BST inside it**, and (crucially) we agree that this size counts the *whole* child subtree only when that whole subtree is a BST.

Now at a node with value `v`, having received `L = (Lmin, Lmax, Lsize)` and `R = (Rmin, Rmax, Rsize)`:

**The subtree rooted at `v` is a BST if and only if** the left subtree is a BST, the right subtree is a BST, and `Lmax < v < Rmin`. That last condition is the whole point: it is not enough for the children to be BSTs individually — every value on the left must be below `v` and every value on the right above it, and the extremes are what decide that.

- If the condition holds, this subtree is a BST of size `Lsize + Rsize + 1`. Report `(min(Lmin, v), max(Rmax, v), Lsize + Rsize + 1)`.
- If it fails, this subtree is *not* a BST. Report a range that can never satisfy an ancestor's check — `(-∞, +∞)` — so no ancestor is fooled into thinking it is valid. The size we report is `max(Lsize, Rsize)`, the best BST found anywhere below.

Empty subtrees report `(+∞, -∞, 0)`, chosen so that `Lmax < v < Rmin` is trivially satisfied when a child is missing (a leaf compares `-∞ < v < +∞`).

Keep a running global maximum of the sizes reported by valid BSTs — or simply return the size field, since it already carries "largest BST below me" forward.

**Dry run** on `[10, 5, 15, 1, 8, null, 7]`:
- Node `1` (leaf): children report `(∞, -∞, 0)`. Check `-∞ < 1 < ∞` ✔ → reports `(1, 1, 1)`.
- Node `8` (leaf): reports `(8, 8, 1)`.
- Node `5`: `Lmax = 1 < 5 < 8 = Rmin` ✔ → BST of size `1+1+1 = 3`. Reports `(1, 8, 3)`.
- Node `7` (leaf): reports `(7, 7, 1)`.
- Node `15`: left child is empty `(∞, -∞, 0)`, right is `(7, 7, 1)`. Check `-∞ < 15 < 7`? **No**, `15 > 7` → not a BST. Reports `(-∞, ∞, max(0, 1) = 1)`.
- Node `10`: right child reported an invalid marker, so the check `Lmax(8) < 10 < Rmin(-∞)` fails → not a BST. Reports size `max(3, 1) = 3`.
- Answer: **3**. ✔

Every node is visited once and does O(1) work, so this is linear.

**Related variant.** The "maximum sum BST in a binary tree" question is the same algorithm with a fourth field in the summary: the sum of the subtree. When the BST check passes, the candidate sum is `Lsum + Rsum + v`, and you track the maximum over all valid subtrees (starting the answer at 0 if empty subtrees are allowed, so negative-sum BSTs do not win).
- **Time:** O(N) — one post-order traversal
- **Space:** O(H) recursion stack

## Code (Optimal)

### C++
```cpp
// struct TreeNode { int val; TreeNode *left, *right; TreeNode(int x) ... } — standard definition
#include <algorithm>
#include <climits>
using namespace std;

class Solution {
    struct Info {
        long long minVal;   // smallest value in this subtree
        long long maxVal;   // largest value in this subtree
        int size;           // size of the largest BST inside this subtree
    };

    Info solve(TreeNode* node) {
        // Empty subtree: bounds chosen so a leaf's check always passes.
        if (node == nullptr) return { LLONG_MAX, LLONG_MIN, 0 };

        Info L = solve(node->left);
        Info R = solve(node->right);

        if (L.maxVal < node->val && node->val < R.minVal) {
            // Whole subtree is a BST.
            return { min<long long>(L.minVal, node->val),
                     max<long long>(R.maxVal, node->val),
                     L.size + R.size + 1 };
        }
        // Not a BST: poison the bounds so no ancestor can pass its check.
        return { LLONG_MIN, LLONG_MAX, max(L.size, R.size) };
    }
public:
    int largestBSTSubtree(TreeNode* root) {
        return solve(root).size;
    }
};
```

### Java
```java
// class TreeNode { int val; TreeNode left, right; TreeNode(int x) ... } — standard definition

class Solution {
    private static class Info {
        long minVal, maxVal;
        int size;
        Info(long mn, long mx, int s) { minVal = mn; maxVal = mx; size = s; }
    }

    private Info solve(TreeNode node) {
        if (node == null) return new Info(Long.MAX_VALUE, Long.MIN_VALUE, 0);

        Info L = solve(node.left);
        Info R = solve(node.right);

        if (L.maxVal < node.val && node.val < R.minVal) {
            return new Info(Math.min(L.minVal, node.val),
                            Math.max(R.maxVal, node.val),
                            L.size + R.size + 1);
        }
        return new Info(Long.MIN_VALUE, Long.MAX_VALUE, Math.max(L.size, R.size));
    }

    public int largestBSTSubtree(TreeNode root) {
        return solve(root).size;
    }
}
```

### Python
```python
# class TreeNode: val, left, right — standard definition

class Solution:
    def largestBSTSubtree(self, root):
        NEG, POS = float('-inf'), float('inf')

        def solve(node):
            # returns (min value, max value, size of largest BST inside)
            if node is None:
                return (POS, NEG, 0)      # so a leaf's check NEG < v < POS passes

            lmin, lmax, lsize = solve(node.left)
            rmin, rmax, rsize = solve(node.right)

            if lmax < node.val < rmin:    # this whole subtree is a BST
                return (min(lmin, node.val), max(rmax, node.val), lsize + rsize + 1)

            # broken: report impossible bounds so no ancestor can be valid
            return (NEG, POS, max(lsize, rsize))

        return solve(root)[2]
```

## Key Takeaways
- Think bottom-up: each subtree returns a tiny summary (min, max, size) so its parent decides in O(1) instead of re-scanning.
- The validity test at a node is `leftMax < node.val < rightMin` — child-level validity alone is not enough.
- Returning `(-∞, +∞)` for a broken subtree is the neat trick that makes every ancestor automatically fail its own check without an extra boolean flag.
- The empty-subtree sentinels are deliberately "inverted" (`min = +∞`, `max = -∞`) so leaves and one-child nodes need no special casing.
