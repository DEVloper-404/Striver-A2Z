# Minimum insertions to make string palindrome | DP-29

**Difficulty:** Hard  ·  **Topic:** Dynamic Programming [Patterns and Problems] › DP on Strings

## Problem
Given a string `s`, you may insert any character at any position, any number of times. Return the minimum number of insertions needed to turn `s` into a palindrome.

```
Input:  s = "abcaa"
Output: 2
Explanation: insert 'c' and 'b' to get "aacbcaa" -> 2 insertions.

Input:  s = "aba"
Output: 0
Explanation: already a palindrome.
```

## Approach 1: Brute Force
Try inserting characters in every possible position and recurse until the string is a palindrome, minimising the count. The branching factor is (length × alphabet size), so this explodes immediately. It does, however, confirm the answer is finite: appending `reverse(s)` to `s` always works, so the answer is at most `n`.

- **Time:** exponential
- **Space:** O(n) depth

## Approach 2: Optimal (keep the longest palindromic subsequence, pad the rest)

**The key observation.** Insertions never delete anything, so all `n` original characters survive in the final palindrome, in their original order. Think about which characters we *do not* have to pair up with an insertion.

Suppose the final palindrome has length `n + k` where `k` is the number of insertions. Look at the subset of original characters that already sit symmetrically inside it. That subset is a palindromic subsequence of `s`. Every original character *not* in that subset needs a partner inserted to mirror it — one insertion each. Hence

```
k >= n - (length of the largest palindromic subsequence of s)
```

And this bound is achievable: take a longest palindromic subsequence `p` of `s`, and for each of the `n - |p|` leftover characters insert its mirror on the opposite side. The result is a palindrome using exactly `n - |p|` insertions. Therefore

```
answer = n - LPS(s)
```

**Sanity checks.** If `s` is already a palindrome, `LPS(s) = n` and the answer is 0. If all characters are distinct, `LPS(s) = 1` and the answer is `n - 1`, which is right — you can only keep one character as the centre.

**Computing LPS.** A palindromic subsequence of `s` is exactly a common subsequence of `s` and `reverse(s)` (reading the same characters backwards through the reversed string spells the same palindrome). So `LPS(s) = LCS(s, reverse(s))`, computed with the standard table:

```
dp[i][j] = 1 + dp[i-1][j-1]                     if s[i-1] == r[j-1]
dp[i][j] = max(dp[i-1][j], dp[i][j-1])          otherwise
```

**Dry run on s = "abcaa"** (`n = 5`, `r = "aacba"`). The LCS table works out to `dp[5][5] = 3`, realised by the subsequence `"aca"` (positions 0, 2, 3 of `s` — a genuine palindrome). So the answer is `5 - 3 = 2`: the leftover characters are `b` and one `a`, and mirroring each costs one insertion, giving for example `"aacbcaa"`.

- **Time:** O(n²)
- **Space:** O(n) with two rolling rows

## Code (Optimal)

### C++
```cpp
class Solution {
public:
    int minInsertions(string s) {
        int n = s.size();
        string r(s.rbegin(), s.rend());

        // lps = LCS(s, reverse(s))
        vector<int> prev(n + 1, 0), cur(n + 1, 0);
        for (int i = 1; i <= n; i++) {
            cur[0] = 0;
            for (int j = 1; j <= n; j++) {
                if (s[i - 1] == r[j - 1])
                    cur[j] = 1 + prev[j - 1];
                else
                    cur[j] = max(prev[j], cur[j - 1]);
            }
            prev = cur;
        }
        int lps = prev[n];
        return n - lps;
    }
};
```

### Java
```java
class Solution {
    public int minInsertions(String s) {
        int n = s.length();
        String r = new StringBuilder(s).reverse().toString();

        int[] prev = new int[n + 1];
        int[] cur = new int[n + 1];
        for (int i = 1; i <= n; i++) {
            cur[0] = 0;
            for (int j = 1; j <= n; j++) {
                if (s.charAt(i - 1) == r.charAt(j - 1))
                    cur[j] = 1 + prev[j - 1];
                else
                    cur[j] = Math.max(prev[j], cur[j - 1]);
            }
            int[] tmp = prev; prev = cur; cur = tmp;
        }
        return n - prev[n];
    }
}
```

class Solution:
    def minInsertions(self, s):
        n = len(s)
        r = s[::-1]

        prev = [0] * (n + 1)
        for i in range(1, n + 1):
            cur = [0] * (n + 1)
            for j in range(1, n + 1):
                if s[i - 1] == r[j - 1]:
                    cur[j] = 1 + prev[j - 1]
                else:
                    cur[j] = max(prev[j], cur[j - 1])
            prev = cur

        return n - prev[n]

## Key Takeaways
- Because insertions never remove characters, the problem is "how much of `s` is already palindromic?" — answer `n - LPS(s)`.
- `LPS(s) = LCS(s, reverse(s))`, so no new DP is needed, only the reduction.
- Each unmatched character costs exactly one insertion (its mirror), which is why the bound is tight rather than just a lower bound.
- Deletions-only to make a palindrome has the *same* answer, `n - LPS(s)` — the leftover characters are removed instead of mirrored.
