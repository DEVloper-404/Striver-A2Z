# Find peak element

**Difficulty:** Medium  ·  **Topic:** Binary Search [1D, 2D Arrays, Search Space] › BS on 1D Arrays

## Problem
A peak is an element strictly greater than both of its neighbours. Given an array `nums` where adjacent elements are never equal, return the index of any peak. Treat the positions just outside the array as negative infinity, so the first or last element can be a peak. The solution must run in O(log n).

Input: `nums = [1, 2, 3, 1]`
Output: `2`

Input: `nums = [1, 2, 1, 3, 5, 6, 4]`
Output: `5` (index 1 is also a valid answer)

## Approach 1: Linear Scan
Check every index `i` and return the first one where `nums[i]` is greater than both `nums[i-1]` and `nums[i+1]` (treating out-of-range neighbours as smaller). Because the ends are surrounded by negative infinity, a peak always exists.

- **Time:** O(n)
- **Space:** O(1)

## Approach 2: Binary Search on the Slope (Optimal)
Look at the middle element and the direction of the slope around it:

- If `nums[mid]` is greater than both neighbours, it is a peak; return `mid`.
- If `nums[mid] < nums[mid + 1]`, the array is climbing to the right. Somewhere on that side the values must stop climbing (at the latest at the end, which is followed by negative infinity), so a peak is guaranteed on the right: `low = mid + 1`.
- Otherwise `nums[mid] < nums[mid - 1]`, the array is climbing to the left, so a peak is guaranteed on the left: `high = mid - 1`.

Handle the trivial cases first: a single element is a peak, and either end is a peak if it beats its only neighbour. Then search `1 .. n - 2` so the loop never needs bounds checks.

- **Time:** O(log n)
- **Space:** O(1)

## Code (Optimal)

### C++
```cpp
#include <vector>
using namespace std;

class Solution {
public:
    int findPeakElement(vector<int>& nums) {
        int n = nums.size();
        if (n == 1) return 0;
        if (nums[0] > nums[1]) return 0;
        if (nums[n - 1] > nums[n - 2]) return n - 1;

        int low = 1, high = n - 2;
        while (low <= high) {
            int mid = low + (high - low) / 2;
            if (nums[mid] > nums[mid - 1] && nums[mid] > nums[mid + 1]) return mid;
            if (nums[mid] < nums[mid + 1]) low = mid + 1;   // climbing right
            else high = mid - 1;                            // climbing left
        }
        return -1; // unreachable: a peak always exists
    }
};
```

### Python
```python
from typing import List

class Solution:
    def findPeakElement(self, nums: List[int]) -> int:
        n = len(nums)
        if n == 1:
            return 0
        if nums[0] > nums[1]:
            return 0
        if nums[n - 1] > nums[n - 2]:
            return n - 1

        low, high = 1, n - 2
        while low <= high:
            mid = (low + high) // 2
            if nums[mid] > nums[mid - 1] and nums[mid] > nums[mid + 1]:
                return mid
            if nums[mid] < nums[mid + 1]:
                low = mid + 1   # climbing to the right
            else:
                high = mid - 1  # climbing to the left
        return -1  # unreachable: a peak always exists
```

## Key Takeaways
- Binary search does not need a sorted array; it needs a way to discard half the range with certainty. Here, following the rising slope guarantees a peak on that side.
- The "neighbours outside the array are negative infinity" rule is what guarantees a peak exists and is why the end checks are valid.
- Since adjacent values are never equal, `nums[mid]` is always strictly less than at least one neighbour when it is not a peak, so the two slope cases cover everything.
- Any peak is accepted; do not waste effort finding the global maximum.
