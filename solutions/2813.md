# Bipartite Graph (DFS)

**Difficulty:** Hard  ·  **Topic:** Graphs [Concepts & Problems] › Problems on BFS/DFS

## Problem
A graph is **bipartite** if its vertices can be split into two sets such that every edge joins a vertex in one set to a vertex in the other — equivalently, it can be coloured with two colours so that no edge has both endpoints the same colour. Given an undirected graph with `V` vertices as an adjacency list (possibly disconnected), decide whether it is bipartite.

```
Input:  V = 4, adj = [[1,3], [0,2], [1,3], [0,2]]     (a 4-cycle)
Output: true      colour 0,2 → red;  1,3 → blue

Input:  V = 3, adj = [[1,2], [0,2], [0,1]]            (a triangle)
Output: false
```

## Approach 1: Try every 2-colouring (brute force)
Enumerate all `2^V` assignments of colours to vertices and check whether any of them makes every edge bichromatic. Obviously correct, hopelessly slow past ~25 vertices, and it wastes the fact that colours are forced.
- **Time:** O(2^V · E)
- **Space:** O(V)

## Approach 2: Greedy 2-colouring by DFS (Optimal)
The saving observation is that **you never have a choice.** Pick any starting vertex and give it colour 0. Every neighbour is then forced to colour 1, every neighbour of those is forced back to 0, and so on. Within a connected component the whole colouring is determined by the single arbitrary choice at the root, and flipping that choice just swaps the two sets. So there is nothing to search: propagate the forced colours and look for a contradiction.

A contradiction shows up as an edge `u — v` where `v` is already coloured and `colour[v] == colour[u]`. That happens exactly when the graph contains an **odd-length cycle**: walking around a cycle the colours alternate 0,1,0,1,…, and only an odd number of steps can bring you back to the start with the same colour. This is the classical characterisation — *a graph is bipartite iff it has no odd cycle* — and the algorithm below is its constructive proof.

Algorithm:
1. `colour[0..V-1] = -1` (uncoloured).
2. For every vertex `s` with `colour[s] == -1` (the graph may be disconnected, and each component is coloured independently): set `colour[s] = 0` and run `dfs(s)`.
3. `dfs(node)`: for each neighbour `nb`:
   - if `colour[nb] == -1` → `colour[nb] = 1 - colour[node]` and recurse; if the recursion reports a conflict, propagate `false`;
   - else if `colour[nb] == colour[node]` → conflict, return `false`.
   - Return `true` when all neighbours are consistent.
4. If no component reports a conflict, the graph is bipartite.

Note `colour[nb] = 1 - colour[node]` is the whole "forced" rule — no branching, no backtracking, so a single pass suffices.

Dry run on the triangle `adj = [[1,2], [0,2], [0,1]]`:
- `colour[0] = 0`, `dfs(0)`. Neighbour 1 uncoloured → `colour[1] = 1`, `dfs(1)`.
- In `dfs(1)`: neighbour 0 has colour 0 ≠ 1, fine. Neighbour 2 uncoloured → `colour[2] = 0`, `dfs(2)`.
- In `dfs(2)`: neighbour 0 has colour 0, and `colour[2]` is also **0** → conflict → return `false`, which propagates all the way up. Correct: a triangle is an odd cycle.

Dry run on the 4-cycle `adj = [[1,3], [0,2], [1,3], [0,2]]`:
- `colour[0] = 0`; neighbour 1 → 1; from 1, neighbour 2 → 0; from 2, neighbour 3 → 1; from 3, neighbour 0 has colour 0 ≠ 1, fine. No conflict anywhere → `true`.

Disconnected graphs matter: colouring only from vertex 0 would leave other components uncoloured and could miss an odd cycle sitting there. Isolated vertices are trivially bipartite. Self-loops make a graph non-bipartite immediately (a vertex would need both colours), so add an explicit `nb == node` check if the input allows them.

The BFS version is identical in spirit — replace the recursion with a queue and colour on enqueue. Use it when `V` is large enough that a `V`-deep recursion is risky.
- **Time:** O(V + E) — each vertex is coloured once, each adjacency entry inspected once.
- **Space:** O(V) for the colour array plus O(V) recursion/queue depth.

## Code (Optimal)

### C++
```cpp
#include <vector>
using namespace std;

class Solution {
public:
    bool isBipartite(int V, vector<vector<int>>& adj) {
        vector<int> colour(V, -1);
        for (int s = 0; s < V; s++) {
            if (colour[s] == -1) {
                colour[s] = 0;
                if (!dfs(s, adj, colour)) return false;
            }
        }
        return true;
    }

private:
    bool dfs(int node, vector<vector<int>>& adj, vector<int>& colour) {
        for (int nb : adj[node]) {
            if (colour[nb] == -1) {
                colour[nb] = 1 - colour[node];     // forced opposite colour
                if (!dfs(nb, adj, colour)) return false;
            } else if (colour[nb] == colour[node]) {
                return false;                      // odd cycle
            }
        }
        return true;
    }
};
```

```java
class Solution {
    public boolean isBipartite(int[][] graph) {

        int[] colour = new int[V];
        Arrays.fill(colour, -1);

                if (!dfs(nb, graph, colour)) return false;
            } else if (colour[nb] == colour[node]) {
                return false;
            }
        }
        return true;
    }
}
```

### Python
```python
from typing import List

class Solution:
    def isBipartite(self, graph: List[List[int]]) -> bool:
        V = len(graph)
        colour = [-1] * V

        for s in range(V):
            if colour[s] != -1:
                continue
            colour[s] = 0
            stack = [s]                      # iterative DFS
            while stack:
                node = stack.pop()
                for nb in graph[node]:
                    if colour[nb] == -1:
                        colour[nb] = 1 - colour[node]
                        stack.append(nb)
                    elif colour[nb] == colour[node]:
                        return False
        return True
```

## Key Takeaways
- Two-colouring is forced, not searched: once the root gets colour 0, every other colour in the component follows.
- A same-colour edge is exactly an odd cycle — bipartite ⇔ no odd-length cycle.
- Restart the colouring in every component; a disconnected graph can hide the odd cycle away from vertex 0.
- BFS and DFS both work; BFS is safer when the graph can be ~10^5 vertices deep.
